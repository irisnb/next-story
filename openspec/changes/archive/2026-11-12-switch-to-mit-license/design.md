# Design: switch-to-mit-license

## Context

仓库现行许可是随 v0.1.0 首发定下的自定义声明《Next Story 版权与使用声明》（保留所有权利＋允许使用），出现在四个对外位置：`LICENSE`、`README.md` 第 133 行、`docs/ARCHITECTURE.md`、v0.1.1 Release 说明。用户 2026-11-12 拍板改为 MIT：他人可自由使用、修改、再分发（含闭源与商用），「别人改完当自己产品完全可以」。本 change 为纯文档级变更，无代码行为变化。

约束：一次只开一个 change（当前无其他活动 change）；历史归档与讨论记录不改写；已发布版本的授权不可追溯变更。

## Goals / Non-Goals

**Goals**
- `LICENSE` 成为标准 MIT 文本，GitHub 自动识别为 MIT。
- 四处对外口径（LICENSE / README / 架构文档 / 后续 Release 说明）一致为 MIT，无残留旧限制表述。
- 用户内容归属声明（用户写的文字权利完全属于用户）继续在场——写作软件用户最关心的是自己的字归谁，不能因许可证切换产生误会。
- 决策与理由入账本，方向记忆与仓库记录对齐。

**Non-Goals**
- 不改应用代码、构建、打包流程。
- 不改 `AGENTS.md`、`openspec/changes/archive/`、`方向/` 历史文档（历史如实）。
- 不追溯修改 v0.1.0 / v0.1.1 的 Release 说明或分发产物。
- 不注册商标、不动官网仓库内容（仅发布前人工核对一次，见 tasks）。
- 不引入贡献者协议（CLA/DCO）或行为准则（CoC）——社区治理是未来独立决策。

## Decisions

### D1: LICENSE 用标准 MIT 原文，一字不差，不翻译不加附款

标准文本（版权行 `Copyright (c) 2026 irisnb`）是全球通行、司法检验最充分的形态；GitHub 据此自动亮 MIT 徽标。
**备选与否决**：中文对照版或「MIT＋附加条款」——翻译可能制造法律歧义，附加条款会使其不再是标准 MIT，均否决。旧声明第四节「未来调整为开源协议将另行公示」由本替换直接兑现，无需过渡说明。
（Release 说明里那行中文「保留所有权利·允许使用」属于对外口径，按 D2 统一句式处理，不进 LICENSE。）

### D2: 对外口径统一句式，中文一句说清，保留用户内容归属

README「协作与协议」区与 `docs/ARCHITECTURE.md` 采用等价表述：「本仓库代码与文档以 MIT 协议开源，可自由使用、修改与再分发（含商业用途），需保留版权与许可声明；你在软件中创作的所有内容权利完全属于你，与仓库许可无关。」徽章排增加 MIT 徽章。
**备选与否决**：只写「见 LICENSE」——对非开发者访客不友好，且用户内容归属必须显式在场；否则「开源」二字容易让创作者误以为自己的稿子也进了开源范围。

### D3: 已发布版本按旧声明，不做任何追溯动作

v0.1.0 / v0.1.1 的副本与 Release 说明保持原样。这是开源许可的单向性质（用户决策时已知情），无需也无法收回；新旧版本各自按其发布时的声明授权，业界常态。

### D4: 残留清扫范围＝「面向访客的活文档」，历史档案不动

替换后用检索确认 `README.md`、`docs/`（DEVELOPMENT.md、ARCHITECTURE.md 等活文档）、Release 流程模板中不再出现「保留所有权利／未经书面许可不得复用、修改、再分发」口径。`openspec/changes/archive/` 与 `方向/` 中的历史引用如实保留——它们记录的是当时的事实，不是现行承诺。

### D5: 依赖合规靠「各自保留」而不是「统一口径」

DSH（MIT）、Basecoat（MIT）随 MIT 仓库分发无任何义务新增；SIL OFL 字体继续以 OFL 随包分发、保留 `public/fonts/LICENSE.txt`——OFL 要求的是字体文件自身的许可声明随附，与仓库主许可无关。不改动任何第三方许可文本。

## Risks / Trade-offs

- **[Risk] 有人闭源商用、做成竞品** → 用户知情拍板接受（MIT 的题中之义）；品牌名不受许可证保护但受商标法保护，将来可视需要注册商标，本 change 不做。
- **[Risk] 用户误以为「开源」= 自己写的稿子也公开/归公** → D2 把用户内容归属声明放在许可表述同一处，显式切断误会。
- **[Risk] 官网仓库残留旧口径造成两个口径并存** → tasks 列发布前人工核对项，核对结果记入验证记录；官网仓库不在本仓库范围，如需改动另行小改。
- **[Risk] 历史档案中的旧许可表述被误读为现行承诺** → 规格明确「活文档口径一致」与「历史档案不改写」两条并列；归档文档均带日期语境。

## Migration Plan

纯文档变更，合入即生效，无运行时迁移。回滚＝恢复旧 LICENSE 与相关表述（git revert 即可），无数据影响。

## Open Questions

无——协议选择（MIT vs Apache-2.0 vs GPL）已由用户在 2026-11-12 讨论中拍板为 MIT，理由已入账本任务。
