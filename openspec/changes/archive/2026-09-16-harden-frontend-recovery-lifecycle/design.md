## Context

AI 崩溃恢复由前端依次调用 `ai_start_session`、`ai_replay_history`、`ai_replay_done`。这些 Tauri 命令会以成功解析的 `{ ok: false, error }` 表达业务失败，但当前传输层只等待 Promise，不检查 `ok`，并在三步结束后无条件登记会话，导致编排层把失败恢复标成成功。

编辑器控制器在作品卸载时销毁查找、工具栏、链接弹层、右键菜单和快捷键模块；重新打开作品时只重建前三者。AI 功能控制器则安装编辑器 DOM 监听、传输层订阅与 AI 面板订阅，却没有统一销毁入口。传输层安装 Tauri 事件监听时既不保存异步返回的退订函数，也把“已安装”前置为永久状态。

本变更只收口这些既有前端生命周期，不改变作品数据、讨论档案、后端协议和 AI 取材边界。

## Goals / Non-Goals

**Goals:**

- 让 AI 恢复的三步命令遵守统一的业务结果检查，失败时不留下可复用的错误会话。
- 让同一编辑器控制器经历“打开作品 → 卸载 → 再打开作品”后恢复全部交互模块。
- 为传输层与 AI 功能控制器建立幂等、可测试的安装和销毁闭环。
- 用针对性测试固定业务失败、异步监听竞态、重复销毁和作品重开的行为。

**Non-Goals:**

- 不修改后端会话命令或事件载荷格式。
- 不改变崩溃恢复选择哪些讨论、哪些历史可重放的权限规则。
- 不把作品切换等同于应用控制器销毁；作品切换仍复用同一套应用级控制器。
- 不处理编辑器粘贴、链接或其他体验整顿事项。

## Decisions

### 1. 恢复会话只在三步全部成功后登记

`replaySession` 为本次恢复先生成局部 `sessionId`，逐步检查每个命令的 `GenerateAiResult.ok`。只有 `start`、`replay history` 与 `replay done` 全部成功后，才把 `conversationId → sessionId` 写入会话映射。

一旦任一步返回 `{ ok: false }` 或抛出异常，方法向上抛出错误。若 `start` 已成功，则以 fire-and-forget 方式尽力调用 `endSession(sessionId)`，清理驱动内可能存在的半成品会话；清理失败不得覆盖原始恢复错误。这样现有编排层的 `.catch()` 会进入 `failRecovery`，后续发送也会重新创建会话。

备选方案是让编排层逐个解释三个返回值，但会把命令级一致性和会话映射所有权泄漏到上层，因此不采用。

### 2. 作品重开通过统一重建函数恢复交互模块

编辑器在每次 `showProject` 开始新作品会话时统一重建查找、工具栏、链接弹层、右键菜单和快捷键模块。各 setup 函数继续先销毁旧实例，因此首次打开、未卸载时切换作品和卸载后重开都保持幂等。

备选方案是让 `unload` 不销毁快捷键和右键菜单，但这些模块持有作品期编辑器能力和 DOM 状态，保留会模糊卸载边界，因此不采用。

### 3. 传输层事件路由采用可重装的异步生命周期

`AiSessionTransport` 增加 `disposeSessionEventRouting()`。传输层保存两个 Tauri `listen` Promise 最终返回的退订函数，并用安装代次或等价令牌处理竞态：

- 同一安装周期内重复 `install` 只注册一次。
- `dispose` 清除当前路由状态并调用已取得的退订函数。
- 若 `dispose` 先发生、异步 `listen` 后返回，则返回的退订函数立即执行。
- 销毁后再次 `install` 可建立一套新的监听，旧周期的迟到结果不能覆盖新周期状态。

备选方案是只保存 `eventRoutingInstalled` 布尔值并在 Promise 完成后赋值，但无法同时解决重复安装和“销毁早于注册完成”的竞态，因此不采用。

### 4. AI 功能控制器统一拥有并释放其监听

`AiFeatureController` 增加幂等 `destroy()`，并保存以下资源的释放句柄：编辑器选区相关 DOM 监听、`onStreamText`、`onDriverLost`、`setupAiDock` 返回的控制器，以及选择入口控制器。销毁时先使控制器失效，再停止作品级请求与会话，随后释放这些监听和传输层事件路由；迟到异步结果不得再推进 UI 状态。

应用入口建立一个统一前端清理函数，在窗口真正关闭前调用 AI 与编辑器控制器的 `destroy()`；若关闭因未保存内容被用户取消，则不执行清理。作品返回欢迎页仍调用现有 `endProject`/`unload`，不销毁应用级 AI 控制器。

## Risks / Trade-offs

- [清理半成品会话本身也可能失败] → 保留原始恢复错误作为用户可见状态，结束命令仅尽力执行且不重新登记会话。
- [异步监听注册与销毁交错，可能泄漏或误退订新监听] → 使用每次安装独立的生命周期令牌，并为“销毁早于 Promise 完成”和“销毁后重装”增加测试。
- [控制器销毁后仍有在途 Promise 回调] → 销毁时先置失效标记并释放请求所有权；回调在写状态前遵守既有身份/代次检查，必要处补充销毁检查。
- [重建交互模块可能重复绑定] → 所有 setup 入口先 dispose 旧实例，并用一次操作只触发一次命令的测试验证。

## Migration Plan

无需数据迁移。先补失败测试，再按传输层、编辑器、AI 控制器与应用入口的顺序实现；全量前端测试通过后更新审计队列状态。若回退代码，作品与讨论数据不受影响。
