## 3. P2 实测：压缩后信封在场（任务 4.3）

- **装置**：`sidecar/driver/tests/manual/p2-compaction-envelope.test.mjs`（手动运行，不进 CI；`test:driver` 计数不变实测 21）。
- **口径**：真实 driver.mjs 子进程＋真实 DSH 容器装配＋真实 compaction-basic＋真实 agent loop；仅模型端点为本地 mock 记录仪（记录每个请求的 system 与 headers）。压缩由 `$DSH_HOME/settings.yaml` 预置 `defaultContextWindow: 3000` 触发。
- **结果**（运行 `node --test` 该文件，1/1 pass，测试体 1266ms）：历史越线后**压缩触发两次**；全部 6 个请求（对话 4＋压缩摘要 2）system 层**逐一核验**完整含身份句与红线；压缩后首请求历史首条为 checkpoint 消息（`CHECKPOINT_PREAMBLE`＋`<compacted-summary>`，证明确在压缩后）；driver 协议面 4 轮全 `message_done` 零失败。证据摘录（mock 记录）：`…DeepSeek Harness.⏎⏎你是陪伴剧本创作者思考与探索的助手。⏎⏎不直接修改用户文档，不代写正文…`——次序与信封契约一致。
- **结论**：摸底遗留项 P2 闭环——**框架压缩不吃信封**（机制上 system 每步由 section 重组装，压缩只动对话表面）。
