# automatic-story-context Delta

## MODIFIED Requirements

### Requirement: 候选词从本轮新增问题确定性提取

系统 SHALL 只从本轮用户新增问题文本确定性提取跨文档检索候选词，MUST NOT 调用模型提取候选词，MUST NOT 从作品反向抽词。候选词提取采用内部初始值（需真实效果验证，非产品效果保证）：规范化采用 Unicode NFKC 归一 + 英文小写 + 连续空白折叠，并保留规范化到原文的字符位置映射；候选分两类连续片段——中文连续片段 SHALL 确定性切分为连续二元组（段内每个起始位置产出长度恰为 2 的子串，长度恰为 2 的段即其本身；无词典、无实体识别、不调用模型），拉丁字母 / 数字连续片段按原样抽取；每个候选至少 2 个 Unicode 字符；去重按首次出现顺序，至多取 8 个词，溢出按出现顺序裁剪。

#### Scenario: 只从本轮新增问题提取

- **WHEN** 用户在常规讨论中发起首轮或追问
- **THEN** 候选词只从本轮新增的问题文本提取
- **AND** 不从历史问答或作品文档反向抽词

#### Scenario: 不调用模型提取

- **WHEN** 系统提取候选词
- **THEN** 提取过程是确定性文本处理，不调用模型或远端服务

#### Scenario: 中文问句切分为二元组命中短词

- **WHEN** 本轮问题包含连续中文片段如「林晓的性格怎么样」
- **THEN** 候选词包含其连续二元组（林晓、晓的、的性、性格、格怎、怎么、么样）
- **AND** 正文仅含「林晓」二字的文档可被检索命中

#### Scenario: 无可提取候选词记录 no_query_terms

- **WHEN** 本轮问题规范化后无任何至少 2 个 Unicode 字符的连续片段
- **THEN** 系统记录检索结果为 `no_query_terms`
- **AND** 不把该结果作为正文或材料内容

#### Scenario: 规范化保留原文位置映射

- **WHEN** 系统对问题与正文做 NFKC / 小写 / 空白折叠规范化
- **THEN** 规范化文本保留到原文的字符位置映射
- **AND** 命中位置可回映射到原文以截取片段

### Requirement: 讨论间材料隔离且及时召唤例外

系统 SHALL 让每个讨论独立持有关注文档、快照和本轮材料，讨论之间 MUST NOT 串用；并 MUST NOT 将常规现场材料准备或跨文档字面检索强制加入及时召唤首轮或其既定追问流程。及时召唤类讨论（首轮与既定追问）MUST NOT 提供「切换关注文档」入口，MUST NOT 展示「从下一轮开始使用关注文档」类提示——常规现场材料在该类讨论中不自动附带，该承诺无法成立。本要求只约束 A 部分自动取材：讨论经按需补读授权后，其追问（含及时召唤讨论的追问）SHALL 可按 `agent-on-demand-reading` 能力使用受控只读工具，该工具使用 MUST NOT 被视为常规取材材料的自动附带，也 MUST NOT 因此改变召唤首轮的快车道边界。

#### Scenario: 多讨论不串用材料

- **WHEN** 多个讨论窗口并存且各自绑定不同关注文档
- **THEN** 每个讨论只使用自己绑定的关注文档与本轮材料

#### Scenario: 及时召唤不经过常规取材

- **WHEN** 用户发起及时召唤
- **THEN** 召唤按冻结选区快车道发起
- **AND** 请求不包含常规现场材料、目录投影或跨文档检索片段

#### Scenario: 召唤追问经授权使用补读工具不算自动取材

- **WHEN** 及时召唤讨论的追问获得按需补读授权且 Agent 调用补读工具
- **THEN** 该读取按 `agent-on-demand-reading` 能力规则执行
- **AND** 不因此向该轮自动附带常规现场材料或检索片段

#### Scenario: 召唤讨论不提供关注文档切换入口

- **WHEN** 当前讨论为及时召唤类（首轮或追问）
- **THEN** 讨论界面不提供「切换关注文档」入口
- **AND** 不出现「从下一轮开始使用」类提示
