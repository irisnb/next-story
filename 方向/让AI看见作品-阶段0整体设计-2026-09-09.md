## 一、阶段 0 目标

阶段 0 的目标是：在「让 AI 看见作品」进入具体实现之前，先把会影响后续结构、界面和数据的整体关系想清楚、写下来、确认掉。它不实现任何功能，不修改已归档规格，也不创建一个包揽全部后续工作的 change。

本阶段要沉淀和明确：

- 两个入口（常规直接提问、AI 及时召唤）如何共存、各自承担什么职责；
- A（系统主动附带材料）与 B（Agent 按需补读）如何组合；
- 作品读取经过怎样的受控只读边界，AI 为何永远不能写作品；
- 材料如何按发送时刻取最新现场、标记版本、说明来源；
- 多窗口、讨论归属、关闭/停止/删除、保存与恢复、并发排队这些行为如何定义；
- 哪些技术问题本阶段还定不了，必须留给后续设计或 OpenSpec 提案决定。

完成标准见第十二节。

## 三、已确认的方向与关系

### 3.1 产品目标

用户直接用自然语言提问，系统自动准备有依据的作品材料，帮助用户重新看见故事。用户不必先配置上下文、整理参考文档，或把问题改写成搜索词；AI 仍只提供观察、问题、假设和可能性，不替用户判断，也不把假设冒充作品事实。

### 3.2 DSH 是 Agent 运行时基础

当初将核心更换为 DSH，就是为了它的 Agent 循环和插件能力；只是目前先使用了其中的会话能力。因此不能把 DSH 只定位成会话或上下文管理器。后续应优先复用 DSH 已有的 Agent Loop、工具注册、工具调用事件、取消与可恢复运行机制，再由 Next Story 的 Rust/Tauri 作品服务负责权限和数据边界；不另造一套 Agent 核心。

### 3.3 两个入口

- **常规直接提问**：用户在常驻面板直接自然提问，结合作品把问题想清楚；允许为取得依据多花一些时间，同时设明确停止条件。
- **AI 及时召唤**：围绕眼前选区、无需先输入问题，尽快开始陪想；冻结选区后直接生成首轮，不等待整篇或全作品检索、多轮补读。

两者进入同一种临时会话，共享讨论管理、保存、权限、版本和安全边界，但不强行共享首轮取材策略。选区始终是可选的重点提示，不是使用 AI 的前提。

### 3.4 A 系统主动附带材料与 B Agent 按需补读可组合

- **A：系统主动附带材料**。程序按明确规则准备当前稿件、作品结构，并可增加字面检索结果；模型不决定这一阶段读什么。
- **B：Agent 按需补读**。复用 DSH 已有运行机制，让模型通过受控只读工具请求材料，再根据读到的内容决定是否继续补读。

A 是程序准备材料，B 是陪想 Agent 按需使用工具；在同一段讨论中，它们共享材料记录并形成一份连贯回应，不必分别调用两个 AI 各答一遍。A 的自动跨文档字面检索是可选项，根据实际效果再决定，不作为 B 的前置门槛。

### 3.5 多窗口与讨论保留是目标

用户明确希望多个 AI 对话窗口可以同时显示、移动、并排对照，而不是只在一个面板里切换标签。常规讨论与及时召唤可能参考不同材料、沿不同路径形成解释，用户希望分别保留和比较，不因开启新讨论而丢弃旧讨论。

### 3.6 作品读取经过受控只读边界

无论采用哪种桥接方式，作品读取都必须经过 Rust 的受控只读接口，AI 运行环境不能绕过它直接访问作品目录。当前未保存内容须由前端提供，并通过同一读取边界校验，不能只读磁盘上的旧稿。A 与 B 应共享受控只读作品接口，统一处理允许读取的范围、回收站和稿件版本，避免形成两套权限或版本规则。

### 3.7 AI 不写作品

AI 永远不直接改用户文档，任何版本、任何授权都不例外；AI 输出永远是作品之外的临时材料，用户亲手复制、粘贴、编辑、保存后才进入作品文本。

### 3.8 用户保留判断权

内容权、解释权、评价权、方向权都在用户手里。AI 只提供观察、问题、假设和可能性。

### 3.9 常规追问按发送时刻取得本讨论关注文档最新现场（含未保存内容）

常规讨论每次追问重新取得发送时刻的**本讨论关注文档**最新快照，包括允许参与本次思考的未保存修改。关注文档是讨论创建时固定绑定的文档，不随编辑器切去别篇而改绑；系统必须取本讨论关注文档的最新可用稿，不能取错编辑器当前打开的别篇文档。发送后继续编辑，不改变已经发出的这一轮材料；下一轮再取得新稿。不能只在首轮读稿、后续沿用旧版。

### 3.10 可见性是开关，而非优先级

AI 可见性设置是已确认方向、尚未实现的功能。它是用户可理解的开关，不是四级参考优先级，也不采用继承、覆盖等旧用户概念。可见性规则一旦生效，必须覆盖目录信息、正文、当前未保存快照与选区，不能因材料来自编辑器而绕过权限。

## 四、两个入口与 A/B 配合流程

### 4.1 常规提问流程（未来设计草案，尚未实现）

```
用户自然提问
  → A 自动提供约定的当前稿件、作品目录与可选重点
  → 陪想 Agent 阅读问题与已有材料
  → 材料足够：直接回应
  → 需要补读：B 决定搜什么、读什么
      → 共同只读接口校验权限，返回原文与版本
      → Agent 根据新材料决定继续补读、回应或说明缺口
```

### 4.2 及时召唤快车道

- 及时召唤首轮以用户明确选择的文字快照为材料，不要求输入问题，不等待整篇或全作品检索、多轮补读。
- 首轮完成后，后续追问默认继续围绕首轮冻结选区；用户重新选择其他文字发起召唤时，开启另一段新的讨论，而非改变原讨论的取材范围。
- 用户希望在当前讨论内扩大到当前关注文档或其他文档时，需在讨论中明确提出；系统不悄悄把快车道升级成完整读稿流程。

### 4.3 A/B 配合需遵守的四条规则（方向性，细节待提案）

1. **权限共用**：主动附带与工具补读都经过同一读取边界。
2. **材料记录共用**：B 知道 A 已提供的文档、范围和版本；同版全文避免重复装入，片段不足时允许补读前后文。
3. **本轮版本一致**：常规追问重新取得约定的最新现场；同一轮 B 再读当前稿件时沿用本轮冻结版本，其他原文注明来源与版本，避免新旧稿混杂。
4. **允许停止**：材料足够时不强制搜索；达到限制、权限不允许或材料不可得时说明缺口，不为得出确定答案无限补读。具体限制待提案确定。

## 五、架构责任边界

- **Rust / Tauri 后端是作品数据的可靠保管者**：内容树、文档保存、格式校验、版本迁移、事务一致性和崩溃恢复等确定性工作由它负责。
- **DSH 是作品内容的智能使用者**：AI 推理、思考回应和陪想能力。AI 需要参考作品时，只能通过受控只读接口取得被允许提供的内容；AI 运行环境不获得写入用户文档的能力。
- **作品数据与 AI 路径必须隔离**：作品服务不能注册为 AI 可调用的写文件工具。任何 AI 输出都只能留在用户文档之外。
- **当前实现与能力定位分开判断**：DSH 已有的 Agent Loop、工具和插件扩展等运行时基础大多已存在，只是当前配置锁住或尚未接入；Next Story 的自主读稿产品能力仍未实现。不能把「框架有能力」写成「产品已实现」，也不能因当前配置锁住能力就另造一套 Agent 核心。

## 六、材料 / 版本 / 权限 / 恢复原则

### 6.1 材料原则（已确认方向）

- 常规每轮冻结约定写作现场，及时召唤冻结选区；每轮材料带可追溯的来源与版本。
- 原文、工具结果与 AI 推测保持区分，不能把 AI 此前的推测当成新稿事实。
- 「系统搜到的材料」不能写成「作品全集」；未命中、未读取或未完整提供的限制要如实说明。
- 参考说明轻量可查看，默认不打断对话。

### 6.2 版本与去重（方向已定，细节待提案）

- 常规追问用**本讨论关注文档**的未保存快照（含允许参与本次思考的未保存内容）配合其他文档的已保存正文；需标明文档身份、来源和本轮版本，避免把关注文档旧磁盘稿混进最新快照。关注文档固定绑定、不随编辑器切换改绑，不可取错编辑器当前打开的别篇文档。
- A 与 B 共用记录，防止同一篇旧磁盘稿混入新快照；同版全文避免重复装入。

### 6.3 权限（已确认方向与行为）

- 所有读取路径服从同一受控只读规则；读取时过滤不能自动撤回已经发给模型的文字。
- 目录信息、正文、当前未保存快照与选区都服从同一受控只读权限边界；AI 不能绕过作品服务直接访问文件系统。
- 用户关闭某篇文档的 AI 可见性后，已经引用过该文档的旧讨论仍可查看；应用不声称能够从已经发给模型的内容中撤回该材料。
- 关闭可见性后，之后的新追问不再引用该文档；必要时明确提示材料权限已经变化。新追问也不能通过历史重放或恢复重新发送已禁用材料，仅在新读取时过滤不够；具体隔离与重建方案未定，不假装已解决。
- 旧讨论中的历史文字与材料记录如何展示、哪些内容参与恢复，必须在后续保存与权限 change 中具体验证（见第九节）。

### 6.4 恢复（已确认方向，细节待提案）

- 当前主要恢复用户与助手文本；未来增加工具读取后，材料和工具事件怎样保存、怎样恢复需要提前验证。
- 不自动重发未完成请求；中断和失败不伪装为成功。

## 七、多窗口 / 归属 / 状态动作 / 保存 / 并发 / 等待原则

### 7.1 窗口呈现（已确认行为）

- **默认停靠，需要时脱离**：新讨论进入默认停靠区域，不替换已有讨论；用户可以把某个讨论窗口拖出停靠区，自由移动并与其他窗口并排对照。
- **可调整大小**：可拖拽窗口边缘或角落调整大小；窗口拥有合理的最小可用尺寸，避免标题、状态和操作被挤坏。
- **布局仅当前运行保留**：窗口位置和尺寸只在本次应用使用期间保留；关闭窗口或退出应用后，下一次打开恢复默认停靠布局。这不影响讨论内容的保存。

### 7.2 讨论归属与写作现场（已确认行为）

- 每个讨论归属于一部作品。
- 讨论创建时记录发起时的关注文档；窗口标题或参考说明中显示当前关注文档，避免用户不知道后续材料来自哪里。
- 用户在编辑器中切换当前文档时，已有讨论不会自动改绑，也不会因聊天窗口获得焦点而悄悄改变取材范围。
- 用户需要在讨论窗口内明确切换关注文档；切换后，下一轮才使用新的关注文档快照。
- 切换作品时，不允许把另一部作品的历史、材料或请求混入当前讨论。作品切换、作品移动和旧讨论重开所需的数据迁移与恢复细节在后续 change 中验证。

### 7.3 窗口状态动作（已确认行为，语义须区分）

| 动作 | 行为 |
|---|---|
| 关闭窗口 | 结束显示，不删除讨论；若本窗口正在生成，自动停止本轮生成 |
| 停止生成 | 只结束对应讨论的当前生成；已完成内容保留，未完成部分标记为中断或失败终态 |
| 重新打开 | 从会话列表或其他明确入口打开原讨论，不自动重发未完成请求、不重复生成 |
| 删除讨论 | 明确移除讨论记录；不能由关闭窗口或切换文档代替 |
| 调整窗口 | 改变本次运行中的尺寸或位置；不持久化布局偏好 |

关闭生成中的窗口自动停止请求，是本阶段已确认的用户行为。底层能否确认干净终止、如何记录取消和迟到结果，沿用既有取消安全边界并在多讨论实现中验证。

### 7.4 多讨论与保留（已确认行为）

- 多个窗口同时显示、移动、并排对照，各自保留讨论；新召唤开启另一段独立讨论，不替换旧对话。
- 各个窗口分别追问、停止与重试；对话历史、材料版本、生成状态和取消结果互不串用。
- 不同窗口的 AI 推测不自动混入另一段对话，也不自动合并为一份作品结论；可以保留不同解释，但同一处原文事实被说反时要核对原文。
- 窗口是讨论的显示容器，讨论本身不依赖窗口存活；关闭窗口不删除讨论，删除是单独的明确动作。

### 7.5 保存（方向已确认，位置与格式待提案）

- 讨论内容和窗口布局是两套不同数据：对话、轮次、生成终态、材料来源和必要恢复信息属于系统管理的讨论记录；窗口位置和尺寸只属于当前运行状态。
- 保存失败必须对用户可见，不能伪装成已经保存；保存 AI 对话不等于写入作品正文。
- 保存由受控应用服务完成，系统对话档案与用户作品正文分开。
- 应用重启后的讨论列表、旧窗口恢复、工具材料和事件恢复属于阶段 2 及后续 change 的范围。

### 7.6 并发、排队与取消（已确认行为，上限待实测）

- 不同讨论独立运行，不因某个常规请求较慢而锁住整个应用。
- 系统按设备和模型服务的实际能力运行；超出能力时，只在对应讨论窗口显示排队状态。
- 不承诺无限并发，也不预先假定固定的并发数量；阶段 1 仅完成离线确定性验证，真实 DSH 事件与真实等待尚未验证，须在后续真实接入验证取得基线后，再在实现 change 中确定技术上可验证的上限和排队细节。不可说阶段 1 已提供真实基线，也不回到已结束的阶段 1 补取。
- 用户停止、关闭、超时或重试一个讨论时，只影响该讨论的对应请求。
- 已结束请求的迟到事件不能污染其他讨论、其他作品或重新打开后的新请求。

### 7.7 等待（方向已确认，目标数值待实测）

- 主要在意用户使用时的等待；保留「AI 及时召唤」就是为了需要即时帮助时有快车道。
- 不承诺固定秒数，也不承诺应用能消除模型服务本身的排队；阶段 1 仅为离线确定性验证，未提供真实等待基线，真实等待目标须在后续真实接入验证取得实测后再与用户约定。
- 等待测量从早期验证开始，至少分开记录：提交到第一次实际模型回应的时间、提交到完整回答结束的时间、应用内排队与作品取材和额外模型往返分别造成的等待。

## 八、当前实现基线

以下以已归档规格为准，是本仓库当前真实已实现的能力：

- **常驻临时会话**：支持面板直接提问与选区「AI 及时召唤」两个首轮入口，两者进入同一种临时会话。
- **流式逐字回复**、首次回应成功后的**线性临时追问**、**可取消生成**。
- **上下文自动压缩**：长对话由框架压缩承接，超限报错提示新建对话，绝不静默砍历史。
- **崩溃恢复**：驱动进程意外退出后自动重启，重放显示历史恢复会话；临时对话不跨应用重启持久化，不提供历史会话列表。
- 当前只有一个临时对话，新召唤会结束并替换旧对话；追问锚定首轮冻结选区。

**尚未实现**（不在当前基线内，不得写成已实现）：

- 完整作品读取（自动提供当前文档全文、最新未保存内容、全作品结构）；
- Agent 按需补读其他文档；
- 持久化会话、会话列表、会话内快捷跳转；
- 多窗口、多对话保存、AI 可见性设置；
- 阶段 1「DSH 能力解锁与接入验证」已完成并归档（22/22 项任务，离线确定性验证通过），但它是离线验证材料，**不代表真实 Rust/Tauri/DSH 生产读稿链路已经接通**。

## 九、后续提案需确定的问题（含技术实现与产品细节）

以下问题在阶段 0 不拍板，必须进入对应的单一 OpenSpec change 决定，不得因为本文件已存在就假装已实现。已确认的用户行为不再列为未定；这些问题里既有技术实现，也有仍带产品取舍的交互细节：

2. **消息身份与真实 DSH 事件**（对应阶段 2 及后续真实接入验证；真实验证需在依赖其结果前取得）：多会话下对话、会话、轮次、消息的身份如何统一，避免多窗口消息编号冲突；真实 DSH 事件字段、工具调用事件、用户中断与恢复的错误终态采用什么协议。

4. **材料版本与去重 / 体积**（对应阶段 5 A 现场材料、阶段 6 B 补读）：本轮看的是哪一版，如何标明文档身份、来源和本轮版本；同版全文避免重复装入；材料体积控制、排序与参考说明；哪些材料需要保存以支持回看与恢复、怎样清理，不默认永久留存所有未保存全文。

6. **并发上限、优先级与等待基线**（对应阶段 3 多窗口与及时召唤快车道；真实验证需在依赖其结果前）：技术上可验证的同时生成上限、排队优先级、快车道安排；首字与完整回答的真实等待目标，在后续真实接入验证取得实测基线后与用户约定。
7. **作品移动、删除、重开**（对应阶段 2、阶段 4）：作品移动、删除、切换作品，以及旧讨论重开时的迁移与恢复行为，含产品层面的取舍。
8. **召唤讨论与更广范围的明确扩展方式**（对应阶段 5、阶段 6）：及时召唤首轮冻结选区后，后续追问如何明确扩展到当前关注文档或其他文档、怎样转入更广的作品讨论，不被悄悄自动升级；重新选区召唤是开启新讨论，不改变原讨论取材范围。

## 十一、阶段 0 典型使用走查

> 本节是**设计走查**，据已确认的整体行为整理的文字流程，用于核对已确认的交互行为是否自洽；**不是运行验收**，不代表任何功能已经实现，也尚未经用户逐条核对。

1. **常规讨论**：用户在写作空间打开常驻面板直接提问，系统取得发送时刻的当前关注文档最新快照（含未保存修改），必要时由陪想 Agent 通过受控只读接口补读其他允许内容；回应作为作品之外的临时材料呈现。
2. **及时召唤**：用户选中一段文字，点击 AI 及时召唤，首轮以冻结选区为材料、无需输入问题即开始陪想；首轮完成后追问继续围绕该冻结选区。
3. **切换文档**：用户在编辑器中切换到另一篇文档，已有讨论不自动改绑、不悄悄改变取材范围；只有当用户在讨论窗口内明确切换关注文档后，下一轮才使用新文档快照。
4. **第二个独立讨论**：用户再发起一个讨论（常规或召唤），它进入默认停靠区域，不替换已有讨论；两段讨论各自保留、各自生成、互不串用。
5. **关闭 / 重开**：关闭一个讨论窗口不删除讨论；若该窗口正在生成，自动停止本轮生成。之后从会话列表或其他明确入口重新打开该讨论，不自动重发未完成请求、不重复生成。
6. **应用重启后的保存边界**：应用重启后，窗口位置和尺寸恢复默认停靠布局；讨论内容的保存与恢复属于阶段 2 及后续 change 范围，不因本走查而声称已经持久化。
7. **可见性关闭后的旧材料边界**：用户关闭某篇文档的 AI 可见性后，已经引用过该文档的旧讨论仍可查看；新追问不再引用该文档，并在必要时提示材料权限已变化。应用不声称能从已发给模型的内容撤回。
8. **AI 永不写作品**：AI 输出始终停留在作品文档之外；所有进入作品的文字由用户自己复制、编辑、保存。AI 永远不直接改用户文档，任何版本、任何授权都不例外。

以上走查的每一步，都要进入后续对应 OpenSpec change 才能成为真实可运行行为。
