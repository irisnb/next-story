# verify-corrected-prompt-behavior：修正后提示底座的真机行为核验（最小路径）

> 前置：`2026-10-06-validate-prompt-foundation` 已归档合入（红线层两段过时限制已修正并进入主 spec）。本提案**只准备、不实现、不调用模型、不提交**；用户一次确认后进入 apply。历史 A/B/C 对照实验与 persona 替换**明确不恢复**（其设计底稿《提示底座验证-实验提案草案-2026-10-05.md》已按用户 2026-10-06 清理决定删除，方案随之移除）。

## Why

红线层两段修正（诚实材料边界、追问围绕当前问题）已合入生产，但其**实际行为效果没有任何真机观察记录**——现有测试只证明「拼进请求文本的字符串正确」，不证明模型按新条款表现。用户拍板：对「现有模型＋现有人设＋修正后提示」做一次最小真机核验，回答的问题是「修正后的提示在四个针对性场景里表现如何」，**不是**「新提示是否比旧提示好」（无对照、无换人设、无统计宣称）。

## What Changes

- **新增一项验证型测试能力（非产品功能）**：4 个独立合成场景 × 6 个预定回答，走真实驱动链路（生产 `driver.mjs`、生产 persona 零改动）：
  1. 完整短文·两事实（直接提问，1 轮）；
  2. 缺失结尾·不编造（直接提问，1 轮）；
  3. 召唤首轮＋自包含新问题追问（2 轮，追问保持快车道不取材）；
  4. 动机猜测＋事实核对（直接提问首轮＋追问，2 轮）。
- **实现形态＝最小路径**：`generate.rs` 测试模块内新增 `#[ignore]` 真机测试——模块内直接访问私有 `compose_message_text`（零可见性变化），复用 `pub(crate)` 材料组装与 `pub` 驱动/配置 API；隔离 DSH_HOME、合成作品（TempDir）、密钥只经 `load_llm_config`＋钥匙串注入且零打印；**不使用**可靠性 runner 的假历史种子，**不使用** `build_task_string`（legacy 链，不冒称常驻等价）。
- **预算口径（推导上界，非实测）**：外层零重试＋驱动内建重试默认上限 2（源码已核）→ 单轮最多 3 次上游尝试 → 6 轮 **≤18 次**；实现启动时逐项复核「无隐藏续跑」源码前提，任一不成立即不运行并启用仅计数的最小兜底方案。统一输出 2048 tokens、单轮 180 秒、总墙钟 15 分钟（推荐初值，随提案一次确认）。
- **评审＝agent 依据原文逐项评审并标明身份**（判定表随提案附档），**不冒称人工盲测**、不设盲标人力硬依赖；每场景 n=1，无统计结论宣称，阴性不证明可靠。
- **范围外**：工具授权流、崩溃恢复、上下文压缩、完整应用 E2E、任何 UI/产品行为变化；工具调用一律安全取消并记「未完成（工具请求）」——含拒读申请（story-request-reading），申请不是失败。
- **附档（提案即定稿，不留实施才定）**：`attachments/材料与题面.md`（合成作品结构、四场景题面全文、每轮组装参数）、`attachments/判定表.md`（逐轮检查项与三级判据）。

## Impact

- **源码**：`generate.rs` `mod tests` 内新增 `#[cfg(test)]` ignored 测试（无生产逻辑/可见性/签名变化；编译与 lint 进 `npm run check`，执行仅手动 `--ignored`）。
- **生产文件**：persona（`cordis.driver.yaml`）、驱动（`sidecar/driver/`）、前端、依赖——零改动、零副本、零派生。
- **真实模型调用**：≤18 次上游尝试（推导上界；无外层重试）。
- **用户资产**：合成材料全部住 TempDir 与 change 附档；不读不写任何真实作品；密钥零打印零落盘。
- **门禁**：实现后 `npm run check` 全绿；验证记录落本 change `verification/`。

## 收尾修订（2026-10-06，用户明确授权的清理收尾决定）

- **本能力是一次性验证器，不是长期产品功能**：六轮核验已执行完毕、证据落档后，按用户清理决定**移除执行器**（`generate.rs` 测试模块内 `verify_corrected` 子模块，929 行 `#[cfg(test)]` 代码），`generate.rs` 恢复与归档基线零 diff；**不存在可重跑的执行入口**——历史检查记录仍有效（证据与结果在档），但执行器删除后无法经此入口重跑。
- **归档处置**：`openspec archive verify-corrected-prompt-behavior --skip-specs`——**不**把 `corrected-prompt-behavior-verification` delta 合入主 spec、**不**新建同名主 spec：一次性验证器的能力描述不构成现行产品能力承诺，合入即虚构产品能力。历史 delta 随归档保留并标注非现行承诺。
- **保留的最小审计记录**：六轮原始 `round-*.json`、`batch-meta.json`（原始实跑版本，未回填未伪造）、纠正后评审报告与验证记录、材料题面与判定表附档、openspec artifacts。已删除：重复长 npm 日志、完成标记、过时方向草案（引用已同步更新）。S1/S2/S3 行为偏差的记录**原样保留**，不以清理掩盖。
