## 一、两个方向共用的页面原则

导航保持现有顺序，在末尾增加第四页：

```text
写作    文件管理    设置    制作模块
                            ■ 当前页
```

第四页独立占用主内容区，制作助手固定在本页内。日常 AI 面板及其浮动讨论不覆盖制作页面；返回写作后仍可继续原来的讨论。

页面顶部常驻一条简短状态：

> 当前链路：情节探索 · 第 3 版　｜　所有作品共用　　[停用]
> 从下一轮开始使用；正在生成的回复沿用发起时的版本。

没有启用链路时显示：当前未启用链路，使用日常陪想。

这条状态不随用户浏览别的链路而变化。**查看、制作、启用是三件不同的事。**顶栏作品名可保留作环境提示，但本页必须标注「所有作品共用」；保存与 AI 面板按钮建议在本页隐藏，避免误解。

视觉衔接（依据 styles.css）：沿用思源黑体（正文 15–16px、辅助 13–14px）；白底浅灰分区、`#2743e0` 蓝表主操作与选中；主区域 2px 结构线、内部细分隔；2–4px 小圆角、硬边偏移阴影仅用于浮层；间距 8/16/24px 三档；状态以文字为主颜色为辅（黄＝草稿未启用、红＝错误）；动效只保留悬停／按下／展开，导图不播放流动光点或「思考路径」动画。关键状态用正常对比度，不作次要淡化。深色模式需后续设计稿另核，不能假定现有令牌直接适配。

## 二、推荐方向：三栏并列，边制作边检视

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 写作    文件管理    设置    [制作模块]                                   │
├────────────────────────────────────────────────────────────────────────┤
│ 当前链路：情节探索 · 第3版   所有作品共用                     [停用]     │
├───────────────┬────────────────────────────┬───────────────────────────┤
│ 链路库        │ 正在查看：情节探索         │ 制作助手                  │
│ [新建链路]    │ [第4版 草稿 ▾] [版本记录] │ 正在制作：情节探索        │
│ 情节探索      │ 思维导图（组装结构）       │ 要求卡：反差与反转        │
│ 当前启用 第3版│ ┌ 链路可变区 ──────────┐ │ 对话正文                  │
│ 有第4版草稿   │ │ 要求类插槽           │ │ [查看本次草稿][查看试问]  │
│ 另一条链路    │ │ └ 反差与反转卡       │ │                           │
│ 未启用        │ └──────────────────────┘ │ 说说希望怎样调整……        │
│               │ ┌ 固定底座 · 所有链路共用┐│ [输入框]          [发送]  │
│               │ │ 红线/骨/工具/材料规则 │ │                           │
│               │ └──────────────────────┘ │                           │
│               │ 卡片检视（点卡后展开）     │                           │
├───────────────┴────────────────────────────┤                           │
│ 正在查看第4版草稿，尚未启用 [试用] [启用此链路版本]                     │
└───────────────────────────────────────────┴───────────────────────────┘
```

布局比例：链路库约 220px，制作对话约 380–420px，中间检视区用剩余宽度；左右不做自由漂浮窗口。三块职责：**链路库找成品**（名称／当前启用版本／有无新草稿；点击只查看）；**中间看成品与确定使用**（导图上方固定显示所查链路与版本；启用按钮写明作用对象）；**制作对话做零件**（新建链路只需简单命名或接受助手建议，不先填配置表）。点卡后在中间区下方展开检视面板，不再挤第四栏、不盖住制作对话。浏览另一条链路时制作对话不悄悄换对象（点「请制作助手修改」才切换）。

窄窗口两级收拢：中等宽度时链路库收为按钮；更窄时本页内切「结构检视／制作对话」，顶部状态条仍常驻；切换保留输入与浏览位置。

备选方向二（上下排列：上半结构检视、下半制作对话）阅读行长更宽、窄窗口更自然，但矮窗口下频繁滚动、长对话难回看，且「边反馈边看改动」不如并列直接——故未推荐。

> 2026-10-07 注：本节三栏同页为②已落地形态的记录；③的导图视图与制作对话**不必同页**（用户拍板），页面安排随③设计定。

## 三、思维导图 v0 的具体表达（2026-10-07 第三轮修订：形态放开，功能优先）

> 本节原为「有包含关系的结构图、固定排版、包含框表属于、无箭头短线表共用」的框式 UI 定稿方向，两轮视觉稿（2026-10-07）均被用户否决，框式定稿表述已按用户同日指示**删除**。以下为功能优先的新方向，**形态不锁定**，经设计迭代定：

- **主要功能**：把思维链路可视化，帮助用户**理解与更改**；不是把链路的全部信息塞进图里让人一次看完。
- **信息分层**：图上多数内容用**简称**表达；想细看时**点节点再看详情**；适用／不适用这类条件细节不直接标在图上。
- **要表达输出**：链路的输出＝**最终组装出的提示词**；导图要能展现「零件 → 组装 → 输出」的关系与查看路径，具体展现方式经迭代定。
- **交互分层展开**：不一次性全量显示；总览（简称）→ 点开（详情）→ 查看组装结果，逐层深入。
- 倾向**模块化 UI** 表达；导图与制作对话**不必同页**（页面安排随设计定）。

仍然有效的语义底线：固定底座为所有链路共用、不可修改，不得画成任何链路或卡片的下级；不用步骤编号与执行顺序暗示；不出现姿态／背景／方式的灰色占位与「解锁」入口；保留说明句「展示链路的组装结构与适用条件，不代表 AI 内部思考过程」。

**2026-10-07 概念骨架拍板（用户确认，v3 起生效）**：

1. 输出块＝**象征**：表达「零件每轮组装成一份完整指令发给模型」，点开看「组装剖视」示意（哪几段稳定、哪几段每轮不同），**不做全文预览**——提示词每轮不同，全文预览是假承诺。
2. **三类可改性，视觉与交互都区分**：固定底座（所有链路共用，只能看）；要求卡（可改、可删、可加，醒目）；每轮动态（系统自动拼，不可配置，可看懂它是什么）。
3. **加的入口常驻**：要求卡区永远有「＋加一张卡」入口（经制作对话口述建卡）；加／改／删在图上都有明确入口，实际修改动作仍走制作对话（图只读的边界不变，从看到改最多两步）。
4. 总览形态＝**模块块＋少量连线**（连线无箭头，表达「参与组装」）。
5. 页面安排＝**制作页内两个标签「导图／制作对话」**：链路库保留左栏，主导航不变；三态分离沿用（顶部状态条＝下一轮用什么；导图标题＝正在看什么；制作对话＝正在制作什么）。

**2026-10-07 第四轮补充（层级与阅读顺序规则，v4 起生效）**：

1. **模块本身可点**：底座、每轮动态在组装流的原位上即是点击入口，**不另设「点开」专门区块**（不做「把心脏从身体里拿出来另放」的布局）。
2. **阅读顺序**：全部流向按中文阅读顺序**从左到右、从上到下**——零件在左、组装居中、输出在右端；没有任何元素因版面方便被挪到违反阅读顺序的位置。
3. **信息按用户关心度分类定层级**（用户最关心的放最明显；理解是地板、快改是目标）：要求卡（看内容＋加／改／删）最显眼、路径最短；组装流向次之（轻量线索）；底座与每轮动态为原位小节点、点开即看；输出在末端象征。
4. **链路库行内信息同样分级**：链路名＞启用状态＞草稿／查看提示，排布统一，不「想放哪儿放哪儿」。

**2026-10-07 第五轮补充（用户拍板，v5 起生效）**：

1. **箭头解禁**：组装流连线使用箭头，表达「零件 → 组装 → 输出」的流向（用户拍板，推翻此前「连线无箭头」禁令）；箭头仅表达流向组装，**卡片与卡片之间仍不出现先后箭头**、无步骤编号（防「卡 A 执行完才轮到卡 B」的执行顺序误读）。
2. **组装／输出块在右侧垂直居中**（消除右上留白失衡）；组装剖视打开时**居中呈现**，不甩至图下远端。
3. **点卡详情跟随视觉焦点**：详情出现在所点卡的**近旁**（右侧邻接或原位展开），视线移动最小；不用下方远端面板、不整页替换（用户原意：人眼看东西有视觉焦点，被迫转来转去很累）。
4. **链路库瘦身**：信息太多太杂、空间浪费——改为一行一链路（名称＋至多一个轻量状态标识），次要信息仅在选中时呈现，列宽收窄。

**2026-10-07 第六轮补充（用户拍板，v6 起生效）**：

1. **零件区按插槽分组，防无限左增**：可变区按卡类型插槽组织（当前仅要求类插槽）。布局须容纳未来插槽（如姿态类）而不产生视觉失衡；**仍不显示姿态／背景／方式的占位或「解锁」入口**（v0 边界不变）。
2. **详情两级化**：点卡 → **固定居中的快捷小窗**（位置与尺寸统一，不随所点卡位置变化——用户指出 v5 小窗随上级位置被压缩的问题）；小窗内可**打开全页详情**（占满导图视图整页），便于细读与核对；返回路径明确。（2026-10-07 第七轮精确化：「居中」指**垂直固定居中**；**水平位置＝卡区右侧邻接**（同 v5 主方案位，左右视觉大致平衡）；不取整页几何居中。）
3. **修改／删除／添加统一进入制作对话**：操作入口在详情面底部，均转制作对话执行（图只读边界不变）。
4. **两条语义说明须有固定呈现位**：「箭头只表示流向组装，不表示卡片执行顺序」「启用对象是整个链路版本」——与免责句一并安排固定、可发现、不干扰主视图的位置（具体由设计定）。

**2026-10-07 第八轮补充（用户拍板，v8 起生效）**：

1. **居中基准修正（视觉平等 ≠ 绝对平等）**：组装／输出块的「垂直居中」以**图区为参照**——底部阅读说明（免责句＋两条语义说明）条**不参与居中计算**；避免脚注把图区重心拖歪造成的「一块在上一块在下」错位。快捷小窗的垂直居中同用图区基准。
2. **左侧层级修正（容器与子集）**：左侧大板块不是「要求类」，而是**链路可变区**＝用户可调整和改变的这一类；「要求类」只是其**子集**（插槽之一）。两级结构：链路可变区（容器）→ 要求类插槽（当前唯一有卡的插槽）→ 卡片；未来其他插槽类型（如姿态类）作为要求类的**兄弟插槽**加入可变区——v0 仍不显示占位或「解锁」入口。

**2026-10-07 第九轮补充（用户拍板，v9 起生效）**：

1. **三类零件各成左区、平行同构**：固定底座、每轮动态不再居于图区中部悬浮——改为与可调区**同构的左侧零件分区**：三个平行分区块（可调区／固定底座／每轮动态）堆叠于左侧，各自内部放条目，整区可点看详情，箭头汇入组装；三个区分别承载三种可改性外观（可调／只读／自动）。
2. **已更名「自定义要求」**：「链路可变区」拗口——用户选定新名**「自定义要求」**（2026-10-07，与「固定底座」「每轮动态」对仗：自定义／固定／每轮）；UI 与后续规格统一采用，「链路可变区」退为内部历史名。
3. **可调区定高＋内部滚动条**：应对卡片／插槽增多，防无限撑高左侧。

**2026-10-07 第十轮补充（用户拍板，v10 起生效）**：

1. **详情位置全局统一**：固定底座、每轮动态点开的详情与自定义要求卡片的详情**同一位置、同一形式**（统一快捷小窗（水平卡区右侧邻接、垂直图区居中、尺寸统一）→ 可开全页详情）；一切可点模块的详情呈现统一，不得各自另设位置（用户第九轮已要求视觉统一，v9 未落实，本轮补上）。
2. **组装剖视删除**：输出块的「剖视」详情页删除（用户判定无效信息）——输出块为**纯象征块**，不提供任何详情页；「稳定／每轮」的说明随剖视移除（每轮动态区本身已表达该信息）；底部两条语义说明与免责句保留。

## 四、状态、卡片检视与制作流程

三态三个位置表达，不用单一高亮承担全部含义：

| 位置 | 示例 | 含义 |
|---|---|---|
| 页面状态条 | 当前链路：情节探索 · 第3版 | 下一轮日常陪想将使用什么 |
| 链路库选中行、导图标题 | 正在查看：情节探索 · 第4版草稿 | 用户此刻在看什么 |
| 制作对话标题 | 正在制作：情节探索／反差与反转卡 | 当前反馈会修改什么 |

卡片显示「已装入此版本／草稿／历史版本」，不写「正在执行」。卡片检视面板含五项：身份（卡名／插槽／版本／链路版本）、何时用（适用与不适用）、怎么做（完整正文，不能只剩助手概括）、本版变化（相对上一版）、试问记录（本版试问、带卡／不带卡结果、用户反馈；未试用明确写「尚无试问记录」）。主操作＝「请制作助手修改」「查看试问记录」；卡片上不设独立全局启用开关，**启用始终落在链路版本上**。

制作过程用短状态提示，不做长向导：口述要求 → 适量澄清 → 草稿 → 过目试问 → 真实试用 → 反馈改卡 →（明确）启用。试问先供用户查看调整再点「开始试用」；试用区展示所用链路版本、试用作品与关注文档，并说明「试用通过日常陪想读取获准材料；制作助手不直接读取作品」；补读授权由真实链路呈现既有流程。试用不切换全局当前链路，结果与所试版本绑定。启用用具体文字承接（如「启用‘情节探索 · 第4版’，替换当前第3版；所有作品的下一轮提问开始使用」）；普通「这版不错」不得被静默推断为启用；保存失败不得显示已保存／已启用。版本记录完整可达；旧版只读；回退是独立明确动作；停用后回到日常陪想，链路、版本与试问档案保留。

## 五、v0 交互边界

**包含**：新建／查看链路；明确切换当前链路、停用；展开收起插槽与底座说明；点卡检视；经制作对话建卡改卡、看草稿与试问结果；看历史版本与证据、明确回退；键盘可达、焦点可见；空库直接引导口述（「说说你希望 AI 多做什么、少做什么」），不要求先学导图。

**不包含**：拖拽节点、拉线、自定义执行顺序、条件分支、循环、多助手编排；无限画布、缩略地图；卡片上手写整份配置；修改固定底座、按链路开关公共能力；姿态／背景／方式插槽；AI 面板快捷切换按钮；模型内部思维展示、自动冲突解决、自动启用草稿。

## 六、最容易做错的一点

**把「正在看的草稿」画得像「正在生效的配置」。**例如第3版仍在使用、第4版正在试用，用户点开第4版后整图变蓝加绿色「成功」，会被误读为第4版已生效甚至已验证有效。v0 最重要的检视标准：无论点哪张卡、看哪个历史版本，都能立即分清「下一轮用什么／我正在看什么／我正在改什么」。先把这三个事实画清楚，再迭代导图形态。
