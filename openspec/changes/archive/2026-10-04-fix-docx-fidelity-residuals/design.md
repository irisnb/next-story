## Decisions

- **D1 符号表以公开表为唯一依据。** 实施时逐条复核修正值（必要时经 @librarian 取权威来源留证）；FB 等缺失项按公开表补入；FC/FB 与冻结记录 :375–376 的出入按 F03 记录、不回改冻结清单。样本对照中与公开表冲突的旧字形预期（F0FC／F0FB；样本内 F0B7 属 Symbol 字体、为对照组不变——见 validation §4）如实标注为"记录瑕疵已按公开表修正"，不当作回归。
- **D2 字体按字符类别。** run 文本含东亚字符→取 `eastAsia`；纯拉丁→取 `ascii`，缺失按既有键序回退（`ascii`→`hiAnsi`→`eastAsia`，键名以代码为准）；主题键仍不解析（既有口径）。混排 run 取东亚字体（不拆 run；记为已知取舍，不计损耗）。替代方案（按字符拆分 run）：会触碰 run 结构与既有标记，风险大于收益，不取。
- **D3 仅对 `lineSpacing` 增加子属性合并。** 在 `overlay_map` 中与 `fonts` 并列处理；不做通用递归——各对象语义不同（审计 §3.2 明确警告）。输出侧沿用 `:971–1005`，合并修复后行距自然保留。
- **D4 损耗告知以"实际发生"为准。** 修复后重跑样本核定剩余真实样式损耗；凡无法保真者计入 `losses.style_degraded`（沿用既有输出形态）；零损耗时验证不虚报（保持既有"未触发不虚报"）。
- **D5 验收复用既有方法论。** 真机＋CDP＋截图；原生文件对话框需用户在场点选；证据义务按 `import-fidelity-acceptance`；`npm run check` 全绿；CI 双平台绿。
- **D6 测试策略。** 表函数逐条单测（全部修正条目）＋覆盖全部修正条目的符号样本集成断言；行距组合单测（仅 after 覆盖、直接覆盖、多子属性）；字体规则单测（拉丁／中文／混排）；WPS 金样本（55,331 字）复验。

## Risks / Trade-offs

- [公开表转写误差] → 实施时逐条对照权威源；修正条目全部入样本断言钉死。
- [字体规则影响 WPS 金样本或既有断言] → 全量回归＋金样本复验；受影响断言按公开规则修正并留痕。
- [行距合并副作用] → 仅 `lineSpacing` 分支＋组合单测。
- [冻结清单与公开表冲突项被误当缺陷] → F01/F03 已记录；验收记录明示裁定与出处。
- [真机验收依赖用户在场] → 提前备好 CDP 脚本与两分钟检查单。
