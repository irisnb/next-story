# 信封通道验证与选型证据（2026-10-06）

> 本文存档两份只读调查的完整结论，作为 change `wire-system-prompt-channel`（信封分层迁移）的证据基础：①外部调研（librarian，2026-10-06）；②驱动源码验证（explorer，2026-10-06，读穿 sidecar/node_modules 实际包源码）。facts 均带出处；「需实弹验证」单列。

## 一、外部调研：指令注入位置与遵循度（librarian）

### 1.1 system role vs user 前缀

**核心结论：三家官方一致认定指令层级由消息角色决定，system／developer 指令在冲突时优先于 user 文本——这是训练进模型的行为，不是提示词技巧。**

- OpenAI（一手官方，强）：Responses API 参考——「Instructions given with the `developer` or `system` role take precedence over instructions given with the `user` role.」https://developers.openai.com/api/reference/resources/responses/methods/create
- OpenAI Model Spec（一手官方，强）：指挥链 Root > System > Developer > User > Guideline；「roles determine the authority of instructions in the case of conflicts」；**Custom GPT 作者扮演 developer 角色**。https://model-spec.openai.com/2026-08-18.html
- Anthropic（一手官方，强）：「When the two conflict, system instructions take precedence」；并允许 messages 数组中途插入 system 消息。https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages
- Anthropic 反向细微差别（一手官方）：大块知识／长文档放第一条 user turn 表现最好，system 只留角色与规则。https://platform.claude.com/docs/en/about-claude/use-case-guides/customer-support-chat ；https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices
- DeepSeek（一手官方，中）：多轮对话由调用方拼接重发；**前缀缓存按前缀完全匹配命中**，官方示例把稳定内容放消息序列最前。https://api-docs.deepseek.com/guides/multi_round_chat ；https://api-docs.deepseek.com/guides/kv_cache

含义：拼在 user 前缀的指令模型会遵循（Anthropic 原文承认），但冲突时输给 system 层——无制度性保护。

### 1.2 长对话指令衰减

- 多轮衰减量化（研究，强）：arXiv 2505.06120《LLMs Get Lost in Multi-Turn Conversation》——顶级模型多轮比单轮平均掉 39%。https://arxiv.org/abs/2505.06120
- OpenAI Model Spec 官方承认长对话截断且用户可能不知情（一手官方，强）。
- Anthropic 工程博客（一手官方，强）：context rot；**过度压缩会丢掉事后才显关键的上下文**；缓解三件套＝压缩摘要／结构化笔记／子 agent 隔离。https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- Anthropic memory tool 文档：「memory preserves the information that must survive summarization」——官方承认压缩会吃旧内容，重要信息要么 system 层要么外置。https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- 中途补发指令的官方先例：Anthropic mid-conversation system message（补发不破坏前缀缓存）；OpenAI Live API `session.instructions.append`。

### 1.3 多指令叠加

行业两种惯例并存：Model Spec「同层后者覆盖先者」vs Cursor「Team→Project→User 先出现的来源优先」；**没有唯一标准，共识是显式声明优先级**。https://cursor.com/docs/context/rules

### 1.4 成熟产品注入位置

| 产品 | 注入位置 | 强度 |
|---|---|---|
| Claude Agent Skills | 渐进披露三级：name+description 常驻 system；正文按需；附属文件按需 | 一手官方 |
| Cursor rules | alwaysApply 每会话注入／glob 匹配／Agent Requested（description 常驻正文按需）／Manual | 一手官方 |
| OpenAI GPTs instructions | 层级＝developer 角色（位置属社区逆向） | 层级一手／位置中 |

本项目「系统预组装卡、每轮拼装」＝ Cursor alwaysApply 模式（常驻注入）而非 Skills 按需拉取——与主流分层一致。

### 1.5 可视化先例（为思维导图 v0）

- Langflow／Dify／Flowise 用 reactflow、n8n 用 @vue-flow（一手源码 package.json，强）——节点图画布是成熟标配。
- **LangSmith 把 trace 做成纯只读检视产品并商业化成功**（一手官方，强）——「看懂链路」有独立价值，不必先做编辑器。
- React Flow 官方一等支持只读画布：`nodesConnectable=false`／`nodesDraggable=false`／`elementsSelectable=true`；官方模板含 AI Workflow Editor 升级路径。https://reactflow.dev/api-reference/react-flow
- Zapier 面向小白长期用纵向步骤卡片列表而非自由画布（社区共识，中）。

## 二、驱动源码验证：system_prompt 通道（explorer）

### 2.1 死通道全貌（已核实）

- `driver.mjs:397` start_session 接受并存储 system_prompt 到 session.systemPrompt；`driver.mjs:421` 唯一读取点（replay_done 传给 buildSeedEvents）；`driver.mjs:257-301` buildSeedEvents 的 system 参数从未被引用（死参数）。
- 非重放路径（首条 send_message 建 Agent，driver.mjs:432）完全不用 systemPrompt。
- Rust 宿主对 start_session 的 system_prompt 零实现；宪法文本拼在 task 字符串（generate.rs:458-541）。
- git 出处：字段随 ab4c49a（常驻 AI 会话）引入；protocol.json 于 897ec16 文档化为预留。

### 2.2 dsh-system-prompt 组装机制（已核实）

- Config 四键：includeHarnessIdentity（默认 true）／includeRuntimeContext／persona／toolOrder（`dsh-system-prompt/lib/index.js:152-158`）。harness 段 order −100 固定；persona 段 order 0 来自 config（:166-175）；assemble 按 order 升序（:263）。
- **三条扩展口**：①`section()` 注册 scoped section——per-agent 生效，**同名段遮蔽全局段**（PERSONA_SECTION 导出即为遮蔽槽位，:10-18；README「creator plugins may register agent-scoped shadows」）；②`complete:true` 段成为唯一 system prompt（:264-289，慎用）；③`system-prompt/assemble` waterfall（:283）。
- YAML patch 只能改 persona／关 identity（config 面仅四键；patch 为整份替换不深合并），**追加段必须走代码**。
- per-agent 定制先例在本 driver 已存在：installModelSelection 在 setup 经 agentCtx 注册 scoped waterfall（driver.mjs:243）。

### 2.3 接活方案（已核实）

- **DSH Agent API 无会话级 system 入口**（AgentOptions 仅 provider/model/maxTokens，runtime-types.d.ts:20-28）；模型可见 system 唯一通道＝每步组装进 request/header（agent-loop lib/index.js:497,611,702-733）。
- **seed 不支持 system 角色**：表面白名单仅 user/message、assistant/message、tool/result（dsh-session surface.js:11-15；seed role 强校验 lib/index.js:1231）；seed 塞 request/header.system 语法合法但被 loop 首步覆盖（agent-loop :349,709-718）。
- **最小改法＝不动 buildSeedEvents**，在 `createAgentFor`（driver.mjs:236-251）的 setup 回调按 session.systemPrompt 注册 per-agent section（遮蔽 deployment:persona 或追加自定义段）——一处覆盖正常与重放两路。

### 2.4 风险清单（已核实）

1. KV 缓存：system 前缀变化从首个差异 token 起作废——**每会话恒定即安全**（README:67-69）。
2. 压缩：compaction-basic 的 summarizer 复用会话自身 system prompt 对齐前缀缓存（dsh-compaction-basic lib/index.js:640-653）——system 稳定则压缩前缀稳定。
3. **崩溃重放一致性（最大风险）**：session.systemPrompt 只活在驱动内存；Rust 宿主必须重发，否则崩溃前后行为不对称。
4. 协议自检：不改命令/事件词表不触发 assertProtocolCoherence；protocol.json 为两端契约真相源，改描述需同步 adapter（:82,:161）与测试。
5. invariant：每次 llm/stream 校验 options.system === header.system（agent-loop invariant.js:24-28）——走 section 正道自洽，私改请求会 fail loud。
6. complete:true 会压掉其余全部段与动态 context——不使用。
7. **双份投递**：宿主宪法已在 task 字符串——接 system 通道宿主不同步改会双份。
