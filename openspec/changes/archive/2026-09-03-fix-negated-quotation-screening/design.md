## Context

当前 `sidecar/reliability/screening.mjs` 对目标短语只取首次出现位置。它先判断该位置是否处于引号内，再判断短语前是否有否定词。因此，回答“林悦明确说‘我没有偷那本书’”时，目标词“偷”被分类为 `quoted`，而不是识别为引用内容中的否定，最终造成 `mustNegate` 的误报。

这次修改只针对离线回答可靠性测试器的保守初筛。模型回答仍是自然语言，初筛不能变成绝对裁判；生产 DSH driver、前端、Rust 后端和用户作品均不在范围内。

## Goals / Non-Goals

**Goals:**

- 分析目标短语的多个出现位置，而不是只依赖首次出现。
- 正确处理直接否定、引用中的明确否定，以及引用后又出现相反直接断言的回答。
- 让现有 `quotation-negation` 基线回答不再因评分器漏识别否定而产生无意义的 `NEEDS_REVIEW`。
- 用离线单元测试固定这些行为，保持人工复核出口。

**Non-Goals:**

- 不实现完整中文语义解析或 LLM-as-judge。
- 不把所有引用内容自动视为模型立场。
- 不改变四种自动结果、人工复核结论或证据格式。
- 不修改 DSH driver、测试案例材料和产品运行时。

## Decisions

### 1. 由单次分类改为多次出现的分类

新增内部遍历逻辑，收集目标短语在回答中的所有出现，并分别判断每个位置是 `asserted`、`negated`、`quoted` 或 `absent`。保留现有 `classifyPhrase` 的公开返回形状以降低影响面；评分器在需要判断整体事实边界时使用多次出现结果。

选择原因：同一目标词可能先出现在引用中，后面才出现模型自己的总结；只看首次出现必然丢失后续语义。

替代方案：扩大否定窗口或调整“引用/否定”的判断顺序。它们只能修复当前样例，无法处理多次出现和引用后反向断言，因此不采用。

### 2. 否定引用只在没有相反直接断言时满足否定边界

当 `mustNegate` 目标短语至少有一次明确否定，且没有一次未被否定、未被引用的直接断言时，将其视为满足否定边界。引用中的“我没有偷书”可以因此通过；“她说没有偷书，但她确实偷了”不能被误判为通过。

选择原因：目标是消除已确认的评分器误报，同时保留对冲突回答的保守性。

替代方案：引用中的否定永远只给 `NEEDS_REVIEW`。这会继续误报本次真实基线回答，失去自动初筛的实际价值，因此不采用。

### 3. 错误结论的引用仍不直接判模型失败

对于 `wrongConclusions`，如果错误短语只出现在引用中或只出现在被否定结构中，不直接返回 `FAIL_LIKELY`；只有存在明确的未被否定、未被引用的直接断言时才判失败。复杂混合回答仍可因事实边界不完整进入 `NEEDS_REVIEW`。

选择原因：引用原文和模型结论必须分开，避免修复否定时引入新的引用误判。

## Risks / Trade-offs

- [风险] 中文否定范围可能跨越复杂从句，字符窗口仍可能不准确。→ 只在结构清楚的局部否定上放宽结果，复杂冲突保留 `NEEDS_REVIEW`。
- [风险] 多次出现遍历可能改变既有案例结果。→ 先补充覆盖旧行为的单元测试，再运行完整可靠性测试套件和基线案例。
- [风险] 自动通过仍不等于模型绝对正确。→ 保留 `PASS_LIKELY` 命名、完整证据和人工复核字段，不引入确定性宣称。

## Migration Plan

先新增失败回归测试，再修改初筛实现；运行 `npm run test:reliability`。随后用官方 API 重新运行至少 `quotation-negation` 基线案例，检查自动结果和完整证据。若结果异常，可仅回滚本 change 的评分器与测试文件，不影响生产链路。

## Open Questions

- 更复杂的跨句否定、转折和反讽是否需要单独的第二阶段案例；本 change 暂不扩展。
- 是否把本次修复后的评分器版本号写入现有证据元数据；按当前证据结构暂不改变字段，只依赖 Git 提交追溯。
