# add-posture-slot 设计

## Context

第一刀三 change（信封分层迁移、制作模块核心、思维导图 v0）已归档。现行装配：链路卡文本经 `send_message.chain_cards` 轮级协议字段携带（**string|null，已包装好的最终文本**，包装唯一产地在 Rust `generate.rs::assemble_chain_cards`），驱动侧经 `dsh-system-prompt` 段注册机制（order 升序：harness −100 / persona 0 / constitution 10 / chain-cards 20）注入信封 `nextstory:chain-cards` 挂载位。要求类内容在该通道下已实证有效（② S3/S4）。

走通一例（`方向/制作模块/走通一例-傲娇搭档-2026-10-07.md`）关键事实：

1. 手工模拟（卡贴进用户消息）九轮：皮全换、干货不掉、代写红线零失守、回复长度反降——模型能力足够；
2. 真实装配补验 D/D2（卡经现行挂载位、用户消息干净）：**皮不换**（n=2，标准陪想腔回归），检索命中与裸问一致（装配路径零污染）；
3. 结论：**「内容进入上下文」≠「内容改变出场声音」**。走例⑤′明言：失败归因（挂载位置 vs 元数据包装 vs 措辞）**无法区分**——本设计把「身份邻接＋身份性措辞更有效」作为**待验假设**而非已证结论，用有界实验（D5）先行检验。

外部证据（librarian 核查）：2026 年人格回退研究给出同构现象（人格未锚定特权层→回退助手腔；特权层锚定 0/46 失败）；OpenAI/Microsoft 官方把 Identity 段（含沟通风格）列为系统提示首段；Anthropic/Cursor 把「触发描述（元数据）」与「指令本体」分层；行业人格/风格功能收敛为单选启用（Claude Code Output Styles 一次一个 active）。注意：system 层优先是概率倾向非保证，行为断言验收必须保留。

## Goals / Non-Goals

**Goals:**

- 姿态卡成为链路第二类插槽零件，与要求卡并存（纯姿态版本允许）；
- 姿态内容注入身份邻接挂载位，以身份性措辞装配，**换皮生效**；
- 骨不越：明文冲突处理原则（固定条款优先）＋验收把关；
- 制作对话能做姿态卡（含骨/衣服把关）；导图能看（分组呈现）；
- 存量链路行为逐字不变；数据降级有明确防护。

**Non-Goals:**

- 背景卡、方式卡（候补席，不动）；
- 多姿态卡并存与冲突消解（明确排除）；
- AI 面板快捷切换按钮（前端 UI 那块）；
- 姿态触发描述的自动切换（明确不做：触发描述仅供选择参考）；
- 宪章/AGENTS 方向文档的灰色地带同口径同步（独立后续，经用户授权）；
- 提示词全文预览/组装剖视（③已拍板删除，不恢复）。

## Decisions

### D1. 挂载位与次序（用户拍板：身份邻接＋明文冲突条款）

```
DSH harness 标识（不可移除，order −100）
陪想身份句（骨，固定）「你是陪伴剧本创作者思考与探索的助手。」（order 0）
→ 姿态挂载位 nextstory:posture（新，order 居 0 与 10 之间；无姿态卡时空段）
宪法红线（order 10）
→ 链路卡挂载位 nextstory:chain-cards（现行，order 20；仅要求卡）
```

- **如实声明：本变更修改了①的旧物理不变式「任何卡片内容不进红线上方」**——姿态文本物理上位于红线条款之前。替代保障为**明文冲突处理原则**：任何卡内容（姿态与要求卡）与宪法红线、陪想身份的固定条款冲突时，固定条款优先；该原则写入信封制度段与规格。①不变式的原意（卡不能制度性压过红线）由「原则明文＋验收」承接，不再依赖纯文本次序做唯一代理。
- 仍然保持的结构约束：任何姿态内容不得置于陪想身份之上；任何要求卡不得置于宪法红线之上。
- **为什么不是"留在卡段提前到要求卡之前"**：主假设是语用位置（贴近身份＝"这是我的样子"而非"文件堆里的一条要求"）；外部证据（身份居首惯例＋特权层锚定研究）同向。该假设经 D5 有界实验检验，不达则按 D5 兜底。
- 预登记备选（**不实施、只登记**）：「末端回声」变体（姿态要点在靠近生成点处重申，SillyTavern PHI 式）。外部证据显示靠近生成点可能是另一强位，但需单独设计如何与红线不变式协调；仅在主方案两轮措辞迭代失败、升级用户后按用户决定启用。

### D2. 协议：新增独立字段 `posture`，`chain_cards` 零改动

`send_message` 新增可选字段 `posture: string | null`——**Rust 侧渲染好的最终姿态段文本**；`chain_cards` 字段与语义原样不变（要求卡包装文本）。

- 包装常量保留 **Rust 单一来源**（消除跨语言双副本漂移风险）；驱动侧只做挂载（register/dispose）不做渲染；
- 驱动 session 增独立姿态状态（postureText/postureDisposer/applyPosture），与 chainCards 状态并列，各自字符串比较幂等；
- 兼容矩阵：旧驱动＋新宿主＝忽略未知字段（姿态不生效、不报错，如实记录）；新驱动＋旧宿主/旧消息＝无 `posture` 时该位为空；`chain_cards` 两端语义不变；
- `protocol.json` 同步文档两字段；`start_session` 零改动（姿态位空段占位是驱动侧行为，从不进 start_session 常量——explorer 已核）。
- 试问带卡路径（`trial_session.rs`）同步产出 `posture`（同一冻结来源）。

### D3. 姿态段包装：肯定式身份性表述，正文原样

- 承接句**以肯定式为主干**（外部一致建议"说要做什么"）：如「你的出场姿态由用户设定如下，以此声音陪伴讨论；判断与红线仍按后文宪法执行」——否定式限定（"不是职权"）压到最短；最终措辞实现期以装置文本定稿并入断言。
- 只注入卡的**正文**，且**原样传递**——装配不改写用户确认过的正文；第二人称与"底线不换皮"条款在**起草阶段**由制作守则与范本保证（D6）。
- **多张姿态卡拼接**（2026-10-07 修订）：承接句仅出现一次（常量），各卡正文（各自剥去开头【…】单行标题行）以空行依序拼接；不编序号、不加执行顺序暗示（与要求卡渲染口径一致）。
- **剥离**：触发描述（"何时用/不适用"）、卡名标记、栏目式标题不进模型上下文（元数据归管理与检视——Anthropic/Cursor 分工同构）。
- 保留可替换声明（共识 §5.3）。
- **姿态触发描述语义（明示）**：仅供用户选择链路时参考，不承担自动切换；详情页如实说明（防"其他问题会自动关姿态"的误解）。

### D4. 卡类型约束与存储防护（2026-10-07 修订：姿态卡多张）

- 要求卡可多张；**姿态卡每链路版本可多张**（用户拍板修订，否决原「至多一张」——该规则是设计者从外部证据倒推、未经用户认可的不对称约束）：多张全部注入，**不做冲突调和**（共识 §4.3-7「诚实兜底」路径：不假装解决，组合权在用户）；制作助手起草第二张姿态卡时**询问「替换还是并存」**，发现与已有姿态明显相抵（如相反语气）时**提醒、不阻止**；长度上限（版本合计 ≤6000 字，两类合计）自然约束张数。
- **纯姿态卡版本允许**：`validate_cards` 的"至少一张要求卡"改为"至少一张卡（任一类型）"。
- **存储格式版本与降级防护**：链路库 `format_version` 升至 2；load 路径**必须校验版本**——旧版本应用遇 v2 明确拒读报错（"由更新版本创建"），不误读、不重写（防止旧版把姿态卡当要求卡保存后类型永久丢失）；v1 数据新版读取视为全要求卡；保存一律写 v2。
- **回滚区分代码与数据**：代码回滚＝单 change revert；数据降级＝恢复对应备份（升级前提示备份位置）；删除"无数据迁移风险"的表述。

### D5. 验证设计：有界 2×2 实验＋预登记行为验收

**第一步·装置级有界 2×2（批量接线前）**：主假设归因检验——位置（身份邻接位 vs 现行卡段）× 包装（身份性 vs 现行元数据包装），固定卡（傲娇原文）、问题、材料、模型与会话条件，每格 n≥2。第 4 格（旧位置×旧包装）即 D/D2 已知基线。产出归因记录，选择有效组合进入接线；记录完整入 `verification/`，不挑样本。

**第二步·确定性装置断言（进测试常跑）**：

- 次序：harness < 身份 < 姿态段 < 红线 < 要求卡段；
- 姿态段含正文、不含触发描述/卡名/栏目头；承接句与包装常量逐字断言；
- 无姿态卡时姿态位空段；纯要求卡链路最终 system 层与改前**逐字一致**（Rust 组装措辞测试＋驱动侧渲染双向锚定）；
- `posture`/`chain_cards` 线缆形状、幂等、旧消息兼容；
- 崩溃重放：start_session 常量逐字一致；重放期间两位皆空、无模型调用；恢复后首轮按当前指针冻结分别装入，**不从历史 chain_rounds 复原旧姿态**。

**第三步·预登记行为验收（归档硬门槛，防挑样本）**：验收计划预先固定模型配置、重复次数、判分口径、失败条件；全样本入记录：

- **换皮生效**：真实制作流程（口述→成卡→启用）后常规轮次回复呈现可辨识姿态特征；**逐模型**：UI 列出的可调用模型至少覆盖主用模型跑换皮断言（persona 遵循度模型相关，AGENTS 红线 6 列表=实际可调用）；
- **骨考题**：Q3 代写诱饵拒绝且候选为观察/问题/方向（MUST NOT 提供可直接替换正文的文本）；Q2 评价诱饵按灰色地带口径（带依据评估＋判断权归还，或拒判，均合规；无依据裁决不可接受）；
- **长对话保持**：多轮追问后换皮保持抽检（外部证据：长对话中 system 层效力会漂移）；
- **检索零污染**：相同冻结环境（同作品版本/关注文档/权限/问题）下，带姿态卡轮次与裸问轮次的自动字面检索命中一致（不要求模型自主补读行为一致）。
- **多卡组合**（2026-10-07 修订）：并存「人设卡＋视角卡」的真机轮抽检——傲娇皮仍在＋视角生效；相抵组合的行为如实记录为用户组合责任，不承诺调和。

**兜底路径（用户已拍板主方案，失败时）**：先措辞迭代 ≤2 轮（仅装置文本级，不动架构；每轮重跑受影响装置测试）；仍不达→**停下升级用户**做方向决定（含是否启用预登记的「末端回声」变体），不归档为完成、不开并行 change、不以任何破坏结构约束的方式硬闯。

### D6. 制作守则增补（骨/衣服把关）

制作助手信封的制作守则段增加：姿态卡范围（人设／看剧本出发点／本身姿态）；起草姿态卡时澄清"要语气上的皮，还是真要它当裁判"（语气随便换，裁判权换不走）；姿态卡正文范本＝走例 v1（含"底线不换皮"段，第二人称在起草时落实）；姿态卡可多张并存（组合权在用户、不做冲突调和）——要第二张时先问替换还是并存、明显相抵提醒不阻止（7.2 修订）；**草稿完整性条款（7.5 修订，S9 首跑发现）：草稿代表新版本的完整卡清单——并存＝把既有卡原样重述＋新卡一起输出，替换＝只输出新卡；不知道既有卡内容时如实说明、不编造**；纯姿态版本允许；触发描述＝选择说明的文案口径。**新会话「链路现状」附言（7.6 修订）：开始新制作后自动发出首条 user 轮附言（含当前最新版本全部卡全文；无版本如实注明；继续会话不重复），经正常发送通道（助手自然确认）——解决新会话里助手不知道既有卡全文的上下文缺口；保存语义维持②既例：草稿面板即新版本完整卡清单。**

### D7. 导图分组呈现（designer 审查采纳）

- 「自定义要求」分区保留名称，标题下加说明性副标「包含要求卡与姿态卡」（副标不构成第二名称，不违反命名纪律）；
- 两组（要求类插槽/姿态类插槽）同级呈现；**两组添加入口统一为同种低强调 ghost 按钮**（同字号/行高/加号/焦点样式），各归各组、随分区滚动，**两组入口均常驻**（2026-10-07 修订：姿态卡可多张，有卡时仍可继续追加；多张姿态卡并列呈现卡行）；详情底部「添加」明确目标卡类型；
- **单一滚动区**：两组共用「自定义要求」分区的滚动区域，组内不设独立滚动；新增分组不改其他两区与组装输出块布局基准；
- 姿态卡沿用统一详情五项：身份（插槽＝姿态类）、「何时用」显示描述＋**明示「供你判断何时选择此姿态，不会据此自动切换」**、「怎么做」完整正文、本版变化、试问记录（无记录如实"尚无"）；
- 三态沿用版本级表达，**不设卡级启用开关**；「＋添加姿态卡」转入制作对话时明示目标链路与任务类型，不改全局当前启用链路；
- 窄窗（1024px）可达性与键盘焦点入验收（见 specs delta 场景）。

## Risks / Trade-offs

- **[主方案换皮不生效]** → D5 三步验证＋措辞迭代 ≤2 轮＋升级用户兜底；「末端回声」已预登记为备选，不擅自启用。
- **[物理次序变更后骨风险放大（姿态在红线上方）]** → 明文冲突处理原则进信封制度段与规格；包装承接句肯定式主干＋判断权指引；Q2/Q3 骨考题为归档硬门槛；走例已证卡内"底线不换皮"条款有效（Q3 全守）。
- **[姿态抢戏：要求卡弱化或长度膨胀]** → 验收含姿态＋要求卡并存场景（要求卡行为不回退）；长度上限两类合计 ≤6000 字继续压总量。
- **[长对话姿态漂移]** → D5 长对话保持抽检；如实记录，不承诺永久稳定。
- **[模型差异（persona 遵循度因模型而异）]** → 预登记验收逐模型覆盖主用模型；诚实记录未覆盖模型。
- **[缓存前缀失效（姿态位紧贴身份，换姿态即失效）]** → 姿态按版本变更、频次低，可接受；装置测试注释记一笔。
- **[数据降级误写]** → format_version 2＋旧版拒读防护＋回滚备份说明（D4）。
- **[Q2 条文协调的边界]** → 本 change 改规格条文与信封措辞；宪章/AGENTS 同步独立进行（经用户授权），提案与任务如实标注，防静默改宪。

## Migration Plan

1. 装置级 2×2 实验（D5 第一步，manual harness，沿① P2 惯例）→ 定措辞与确认位置假设；
2. 驱动侧：`posture` 字段＋姿态段注册＋独立幂等状态＋`protocol.json`；
3. Rust 宿主：格式版本 2 与 load 防护、validate_cards 类型规则、冻结拆分与姿态渲染器、信封评价条款常量（dsh 协调）、试问路径；
4. 前端：制作对话（类型标记/守则/替换引导）→ 链路库/导图（分组/副标/入口/详情/滚动）；
5. 确定性装置断言全绿 → 全量门禁 → 真机端到端（预登记行为验收）→ 用户真实点击视觉验收 → 归档。

回滚：代码＝change 内原子 revert；数据＝恢复升级前备份（旧版拒读 v2，故降级必须走备份）；两路径在验证记录中分别说明。
