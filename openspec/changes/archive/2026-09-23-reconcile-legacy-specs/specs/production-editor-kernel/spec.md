# production-editor-kernel 变更增量

> 旧世界（双本子）对账：删除本子状态隔离条款与结构化往返条款（职责归 `structured-notebook-storage`）；格式范围改为引用单一真相源（消除规格内部「版本 1 vs 版本 2」自相矛盾）；其余条目措辞单文档化。R8（依赖锁版）／R9（金样本）现行条款不动，不列。

## MODIFIED Requirements

### Requirement: 中文组合输入和常用编辑操作稳定
系统 SHALL 在 Windows Tauri 2 / WebView2 中支持中文输入法组合输入、光标移动、鼠标与键盘选区、复制、剪切、受控粘贴、撤销和重做。组合输入 MUST NOT 丢字、重复、乱序或生成与一次实际编辑不相符的异常历史步骤。

#### Scenario: 微软拼音组合输入
- **WHEN** 用户使用微软拼音完成拼音组合、候选选择和文字上屏
- **THEN** 编辑器只产生用户确认的中文文字
- **AND** 文字不丢失、不重复且顺序正确

#### Scenario: 组合期间删除和切换焦点
- **WHEN** 用户在中文组合输入期间使用退格或把焦点切到 AI 面板后再返回
- **THEN** 编辑器保持确定且可继续写作的文字与光标状态
- **AND** 不产生重复文字或损坏文档内容

#### Scenario: 撤销和重做用户编辑
- **WHEN** 用户通过常见 Windows 快捷键撤销或重做输入、删除、剪切、粘贴或格式命令
- **THEN** 编辑器按实际编辑历史恢复对应结构化文档

### Requirement: 编辑器实例随作品生命周期释放
系统 MUST 在作品卸载、成功打开另一作品或编辑器控制器销毁时解除编辑器实例（当前文档）的事件监听并销毁实例。已销毁的实例 MUST NOT 再改变当前作品的保存状态、选区入口或文档内容。

#### Scenario: 打开另一作品
- **WHEN** 用户成功离开当前作品并打开另一作品
- **THEN** 系统销毁原作品的编辑器实例
- **AND** 新作品只显示从新项目文件读取的当前文档

#### Scenario: 旧实例迟到事件
- **WHEN** 原作品编辑器实例已经销毁
- **AND** 旧实例相关的迟到回调随后发生
- **THEN** 系统忽略该回调
- **AND** 当前作品的保存状态和 AI 入口不受影响

### Requirement: 真实剧本长度下编辑保持可用
系统 SHALL 在 Windows Tauri 2 / WebView2 中以至少 20 万汉字且包含本轮格式组合的文档验证载入、连续输入、格式命令、选区、滚动、撤销重做和保存重开。连续输入延迟 p95 MUST 不高于 50ms，载入后的进程增量内存 MUST 不高于 300MB，并 MUST NOT 出现内容损坏、格式丢失或选区漂移。

#### Scenario: 载入并编辑 20 万字格式化文档
- **WHEN** 用户在 Windows 桌面应用中打开至少包含 20 万汉字和本轮格式组合的文档并连续输入
- **THEN** 连续输入延迟 p95 不高于 50ms
- **AND** 载入后的进程增量内存不高于 300MB
- **AND** 输入、格式命令、选区和滚动期间不发生内容损坏或选区漂移

#### Scenario: 长文档保存重开
- **WHEN** 用户编辑至少 20 万汉字且包含本轮格式组合的文档并手动保存后重新打开作品
- **THEN** 文档的文字、段落顺序和支持格式与成功保存时一致

### Requirement: 生产写作区使用 Tiptap 基础富文本内核
系统 SHALL 使用 Tiptap（底层为 ProseMirror）承载生产写作区的当前文档编辑。编辑器支持的内容与格式范围以 `structured-notebook-storage` 的现行格式 grammar（当前为版本 2）为准。

#### Scenario: 打开已有结构化作品
- **WHEN** 用户打开包含有效内容树文档正文的作品
- **THEN** 系统用当前文档的完整 Tiptap 文档初始化编辑器
- **AND** 编辑器显示已保存的文字、段落和支持格式

#### Scenario: 编辑基础富文本
- **WHEN** 用户在当前文档中输入、删除、换行或应用支持格式
- **THEN** 编辑器显示与用户操作一致的文字和支持格式
- **AND** 系统不因内部文档结构增加用户未输入的可见文字

#### Scenario: 不提供范围外富文本能力
- **WHEN** 用户使用本 change 完成后的编辑器
- **THEN** 编辑器不开放图片、表格或其它超出 `structured-notebook-storage` 现行格式 grammar 的格式命令
- **AND** 内部 schema 不接受范围外节点或标记

### Requirement: 外部粘贴只进入受控结构
系统 SHALL 按 `controlled-rich-text-paste` 能力处理普通粘贴，只接收可可靠提取的可见文字和本轮支持的结构与标记，并 MUST 丢弃或拒绝其它外部格式和内容。复制与剪切 MUST 保持用户选区的可见文字，并可提供本轮支持的受控格式表示。

#### Scenario: 从网页粘贴带格式内容
- **WHEN** 用户从网页或文字处理软件复制包含支持和未支持格式的内容并粘贴到文档
- **THEN** 编辑器只插入可可靠提取的可见文字和本轮支持格式
- **AND** 内部文档不保留外部样式或未开放结构

#### Scenario: 复制和剪切文档选区
- **WHEN** 用户复制或剪切文档中的一个选区
- **THEN** 剪贴板纯文本与用户实际选中的可见内容一致
- **AND** 受控格式表示只包含本轮支持的结构和标记
- **AND** 剪切只删除当前文档中用户实际选中的内容

## REMOVED Requirements

### Requirement: 两个本子的编辑状态和历史互相隔离
**Reason**: 对象已消失——草稿本／正文本标签切换不存在；现实为单一编辑器绑定当前文档，切换文档先静默保存。
**Migration**: 切换文档先静默保存且失败阻止切换由 `workspace-navigation`（本 change 新增条）承接；文档内容的结构化事实源与读写边界校验由 `structured-notebook-storage` 承接。

### Requirement: 结构化文档保持支持的内容和格式
**Reason**: 删并——「唯一格式版本 1 schema」与「一次保存提交 `draft`／`main` 两份完整结构化文档」均已死；往返保持语义已由 `structured-notebook-storage` 完整承接，保留将与该规格及本规格金样本条款（已写版本 2 grammar）自相矛盾并形成双真相源。
**Migration**: → `structured-notebook-storage`（带版本外层的 Tiptap JSON、schema 范围与读写边界校验）；编辑器格式范围的引用式表述见本规格「生产写作区使用 Tiptap 基础富文本内核」条。
