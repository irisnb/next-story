## Why

Next Story 已选择 DSH 作为 Agent 循环和插件能力的运行时基础，但当前产品只接通了会话与文本流式回应，尚未验证受控只读作品能力如何安全往返。阶段 0 已确定多讨论、权限、材料版本和取消边界，因此现在需要先用一个隔离的验证 change 暴露接入风险，再进入独立对话保存和产品化读稿。

## What Changes

- 建立一个可重复运行的 DSH 接入验证 harness，确认 Agent Loop 能在 Next Story 的会话边界内运行。
- 验证受控只读作品请求从确定性 Agent 替身发出，经离线受控只读边界校验后返回材料，并能继续完成回应。
- 验证工具调用开始、成功、失败、取消和超时等终态及结构化错误。
- 验证多会话请求隔离、单轮取消、迟到结果隔离，以及常规讨论和及时召唤并行时的归属。
- 验证需要扩大读取范围时的用户确认、中断和同一轮恢复。
- 验证当前未保存稿件以受控快照进入取材链路，且 AI 运行环境不能直接访问作品目录。
- 记录直接回应、一次补读和并行召唤的确定性等待基线（真实模型延迟不可用，明确标记为未验证），作为后续阶段验收依据。
- 明确失败、降级、恢复和证据记录，不把验证结果伪装成已交付的自动读稿能力。

## Capabilities

### New Capabilities

- `dsh-readonly-integration-validation`: 验证 DSH Agent Loop 与 Next Story 受控只读作品边界的接入契约、事件终态、取消恢复和证据记录。

### Modified Capabilities

无。现有归档规格描述当前临时会话行为，本 change 不提前修改已实现的用户功能规格。

## Impact

- 影响 DSH sidecar/driver（新增验证专用确定性适配器 adapter.mjs）、验证 harness 与 Rust 纯函数边界（story_material、capability_gateway 工具授权分类）；不改动生产 driver.mjs 的工具协议、不注册 Tauri 命令。具体修改范围在 design 与 tasks 中确定。
- 可能增加验证用 fixture、协议事件类型、测试配置和等待基线记录，但不开放通用文件、命令、网络或子代理工具。
- 不改变作品正文保存格式，不向 AI 提供作品写入能力，不承诺阶段 1 完成常规自动读稿或 Agent 自主补读产品功能。
