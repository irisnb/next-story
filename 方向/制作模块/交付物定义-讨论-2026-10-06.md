## 0. 一页摘要

- **层级**：成品是**链路**（可启用的制作成果）；**卡是零件**（≈最简 skill），插进链路的可变区。固定底座（红线、底线立场、工具平等开放、材料装配规则）永不开放。
- **制作方式**：**制作对话窗口＋制作助手 agent** 是制作模块的核心——口语描述 → 适量澄清 → 卡草稿 → 试问（先过目、走真实链路）→ 反馈改卡 → 用户点头启用。**用户不手写卡**。
- **读取边界**：制作助手默认**不读任何作品材料**；试用的「看」由真实日常陪想链路代劳（材料／检索／授权走既有规则）。此条解掉共识 §10 第一条未决。
- **启用模型**：专门管理区（思维导图那边）拥有**完整功能**（建、看、调整、切换、停用、版本）；当前链路**全局一条**，统一作用于日常 AI 面板的幕后组装；AI 面板小按钮只是快捷方式（归前端 UI 那块）；切换**下一轮生效**；轮次发起时冻结；逐轮记录链路＋版本。
- **UI 关系**：制作模块与日常 AI 面板在界面上**完全分开**，两个区域互不嵌套。
- **第一刀范围**：制作对话＋制作助手＋要求卡插槽＋链路库（全局多链路）＋**思维导图 v0（检视优先，形态逐刀迭代）**＋装配接线＋逐轮记录＋版本存档。姿态插槽＝第二刀第一顺位。

## 1. 交付物定义（§9.3）

### 1.1 层级：链路是成品，卡是零件

用户原意：「这张卡应该算是思维链路中的一个零件，按理来说这个思维链路应该可以放更多的东西。」

```
┌─ 日常 AI（现在的聊天面板）─────────────┐
│   平时提问的地方，和制作互不干扰          │
└───────────────┬──────────────────────┘
                │ 只在链路启用时发生关系（幕后组装层面）
┌─ 制作模块（独立区域）───────────────────┐
│  制作对话窗口＋制作助手（做卡的地方）       │
│  管理区（思维导图那边，完整功能）           │
│  ┌─ 思维链路 A（成品＝可启用的制作成果）┐  │
│  │   ├─ 零件插槽：要求卡 / 姿态卡 / …   │  │
│  └─────────────────────────────────┘  │
│  ┌─ 思维链路 B（另一套，互相独立）……     │  │
└────────────────────────────────────────┘
```

### 1.2 链路构造图：固定底座 / 可变区 / 每轮变量

依据技术摸底核实的现状（四页须知）：

```
 🔒 固定部分——所有链路共用，链路碰不了
 ├─ 第1页 红线页：不改文档、不代写、不冒充已读……（产品底线）
 ├─ 第2页 入场姿态页的「骨」：陪想不裁判、不代写、
 │   临时材料、假设不冒充事实（底线立场）
 ├─ 第4页 工具页：受控读取能力，对所有链路一律平等开放（不分档）
 ├─ 材料包装配规则：关注文档现场材料＋目录＋检索（系统定，不开放成配置）
 └─ 框架底座（DSH 系统层）

 🔲 链路可变区——预留空位（第3页 语境页）
 └─ 零件插槽（见 1.3）

 ⚡ 每轮都变的：用户问题、当轮材料、当轮入口
```

**链路与链路的区别只体现在可变区**；固定部分保证安全与一致。

### 1.3 插槽按概念定义，不按内容枚举

用户原意：「不一定非得是人设内容才是，符合入场姿态这个概念我觉得都可以放；骨肯定不能开放给用户更改，但入场姿态这个其实无所谓。」

- **插槽·要求类**：想让 AI 多做什么、别做什么（例：反差与反转）——**第一刀主角**；
- **插槽·姿态类**：AI 以什么姿态出场——人设、语气、风格，凡符合「入场姿态」概念的都算——**概念已认可开放，第二刀第一顺位**；
- **插槽·背景类**（候补）：固定交代的故事背景，免重复说明；
- **插槽·方式类**（候补）：怎么答——候选数量、检验角度、篇幅上限（走通一例试出的「压长度」即属此类）。

### 1.4 骨与衣服

姿态层拆两半：**骨**（底线立场）永远固定在系统层；**衣服**（风格人设）开放给用户。安全网三层：

1. 红线在第 1 页系统层——卡只能往上加要求，永远减不掉底线；
2. 骨不动——换任何皮，AI 依然是「只提观察、问题、假设和可能性」的陪想，判断权在用户；
3. 制作助手把关——做姿态卡时澄清「要语气上的皮，还是真要它当裁判」，语气随便换，裁判权换不走。

### 1.5 制作对话窗口与制作助手（制作模块的核心）

用户原意：「应该有一个专门的对话窗口负责制作模块的制作事宜……背后得有一套完整的 agent 机制。」

```
口语描述 → 适量澄清 → 卡草稿 → 试问（先给用户过目）
   → 走真实链路跑试用 → 用户反馈 → 改卡迭代 → 用户点头「就这样」＝启用
```

- 制作助手**全程不读用户作品**（见 1.6）；它只看试问结果和用户反馈；
- 对用户按其技术水平说话、不用术语；
- 容器形态（窗口／区域）未定（宪章 §2 加注），提案时定；
- 背后的 agent 承载技术（语境层空位注入／DSH skills／system_prompt 通道）属**选型问题**，在提案的设计文档里定，本文不预支结论；
- 日常聊天**不能**触发制作或修改链路配置；日常助手发现值得固化的要求时只**转介**到制作对话（共识 §4／§7-3，先例：Windsurf「记忆转规则」模式）。

### 1.6 制作助手不读作品；试用走真实链路【解共识 §10-1】

- 制作助手**默认不读任何作品材料**；
- 试问经**真实日常陪想链路**跑：带卡、带材料、走既有检索与授权规则——测的就是真实效果（当日走通一例九轮即此模式）；
- 将来某种卡（如背景卡）真需要读作品，再单独定授权：不白送、不继承日常聊天给过的授权。

### 1.7 启用与切换

- **管理区（思维导图那边）＝完整功能**：建、看、调整、确定、切换、停用、版本，全在那里。用户原意：「专门管这个玩意儿的地方才是完整的功能，AI 模块的小按钮只是一个便捷的快捷方式。」
- **当前链路全局一条**：所有作品共用；链路库本身**多条**、全局存、随软件走；
- 切换后**下一轮生效**（所有讨论跟着当前链路走；正在生成的轮次不受打扰——轮次发起时冻结）；
- 逐轮在讨论档案记「这轮按哪条链路＋哪个版本」（后台记录；怎么显示归前端）；
- AI 面板快速切换小按钮＝可选快捷方式，归前端 UI 那块，没有它功能也完整。

### 1.8 制作模块 UI 与日常 AI 完全分开

用户两次纠正，单列防混：制作模块在界面上是**完全独立的区域**，与现在的 AI 面板不在一起、互不嵌套。「链路套用到 AI 面板」指幕后组装层面，不是制作功能长在 AI 面板里。

**2026-10-06 提案启动时用户进一步确定**：制作模块是独立于「写作」「文件管理」「设置」之外的**第四个页面**，不挤进其他页面。

## 2. 保存、生效、版本与回退（§9.5）

1. **链路库全局、多链路、随软件走**；链路和卡**不进任何作品文件夹**（用户确认）；
2. **每次改卡存新版本**：历史版本可看、可回退；「启用」永远是显式动作——存了不等于生效，用户点头才生效；
3. **试问证据跟版本绑定存档**：每轮试问的对照结果存在对应版本下，改卡能翻旧账，防「越改越窄」没人发现（走通一例的 9 份记录即此物）；
4. **停用和回退都轻**：停用链路＝回到日常陪想，一切照旧；讨论档案记的是每轮的链路＋版本快照，链路以后删了改了，历史记录不丢。

## 3. 首个实现范围与排除项（§9.7）

```
第一刀（2026-10-06 用户确认）
 ├─ 制作对话窗口 + 制作助手
 │    澄清 → 出要求卡草稿 → 试用（走真实链路）→ 改卡 → 点头启用
 ├─ 要求卡插槽（只这一种零件）
 ├─ 链路库：全局、多链路、随软件走
 │    管理功能第一刀就全：建、看、切换、停用、版本
 ├─ 思维导图 v0 ★第一刀就进★

 │    形态要迭代好几版才找到合适的——v0 不追求一步到位，
 │    追求「能检视、能开迭代」（用户原意）
 ├─ 装配接线（注入预留空位；选型写进提案设计文档）
 ├─ 逐轮记录「这轮按哪条链路＋哪个版本」
 └─ 版本＋试问证据存档（§9.5 四条规则）

明确不进第一刀（排除项）
 ├─ 姿态类插槽（第二刀第一顺位）
 ├─ 背景卡、方式卡（候补席）
 ├─ AI 面板快速切换小按钮（前端 UI 那块的活）
 ├─ 制作助手读作品（不读；将来真需要再单独定授权）
 └─ 思维导图高级编辑形态（逐刀迭代，不承诺）
```

## 4. 先例调研结论（当日完成，供提案引用）

### 4.1 最重要先例：Anthropic skill-creator

官方仓库 [anthropics/skills](https://github.com/anthropics/skills) 里的 `skill-creator` 就是一个「用对话帮你做 skill 的 skill」：口语描述 → 四问澄清（做什么／何时触发／期望输出／要不要测试）→ 草稿 → 拟 2–3 条真实口吻试问**先给用户过目**、带／不带 skill 对照跑 → 用户逐条反馈 → 迭代直到满意。**与当日走通一例的流程几乎一致**（走通一例先于本次调研完成，属独立印证）。其负例要求（「应触发／不应触发」里的负例必须是近似但不该触发的难题）与「从反馈泛化、防过拟合」的警告直接适用。

### 4.2 可抄做法（精选）

1. 卡分两半：「何时用」触发描述（含负例）＋「怎么做」正文；当用则用的信息全放触发描述；
2. 试问先给用户过目再跑；带卡／不带卡对照；
3. 草稿 → 人审 → 启用是显式晋升（GitHub Copilot instructions 走 draft＋人工审查；LangSmith 有版本历史与 staging→production）；
4. 每条要求可溯源到用户口述实例，agent 不自创要求；「本次用了哪张卡」轻量可见（Copilot references 模式，同构于「本次参考了什么」）；
5. 硬上限防膨胀（各先例：500 行／6000 字符／2 页——卡短才被遵守）；
6. 底线永远在系统层，卡只能加不能减；
7. 按用户技术水平说话（skill-creator 沟通规范，与 AGENTS.md「给 AI 的话」同构）；
8. 日常助手「转介」而非「动手」（Windsurf 记忆转规则模式）。

### 4.3 要避的坑（精选）

1. 一坨自由文本式配置（GPTs 教训：无结构、无版本、无诊断）；
2. 依赖自动记忆当规则（Windsurf 官方明确：自动沉淀≠可靠复用；日常聊天内容不自动变成卡）；
3. 一开始就让用户建一堆卡（Cursor：只在反复出现的问题上加规则）；
4. 堆 ALWAYS／NEVER 管模型（解释为什么更有效且不僵化）；
5. 卡越调越窄的过拟合（只对试问有效的修改要警惕）；
6. 静默失败（卡格式坏／超长／没写触发描述要明确告知，给诊断）；
7. 假装解决了多卡冲突（无先例真正做过冲突检测；诚实兜底或强隔离）；
8. 把剧作教科书复制进卡（用户的例句就是最好的卡内容）；
9. 忽略长度－遵循度反比。

## 5. 当日关键纠偏（防压缩失忆，仿共识 §7）

1. **卡不是成品，链路才是**——链路是容器，能放多个零件（用户纠正「卡只是思维链路中的一个零件」）；
2. **卡不手写**——制作对话窗口＋制作助手才是主角；「让用户自己写不现实」（有共识文档背书，当日纠偏重申）；
3. **制作模块 UI 与 AI 面板完全分开**，不要混成一起；
4. **思维导图那边＝完整功能**，AI 侧小按钮只是快捷方式；
5. **姿态插槽按概念开放**（凡符合「入场姿态」概念都可放），骨永远锁死；
6. **链路库是多条的**、全局随软件走，不进作品文件夹；
7. **思维导图必须第一刀进**——「需要检视，需要迭代好几版可能才能找到合适的，不存在第二步一下到位」（用户原意）。
