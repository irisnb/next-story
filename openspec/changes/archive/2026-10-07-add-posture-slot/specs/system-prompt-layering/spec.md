# system-prompt-layering Delta

## MODIFIED Requirements

### Requirement: 信封内容与次序固定
系统 SHALL 在会话的 system 层（信封）组装制度性提示，内容与次序 SHALL 固定为：陪想身份（中文）→ 姿态挂载位 → 宪法红线（含诚实材料边界与追问语义条款）→ 链路卡挂载位。**本变更（change `add-posture-slot`，用户拍板）修改了既有物理不变式「任何卡片内容不进宪法红线上方」**：姿态卡文本物理上位于红线条款之前；替代保障为**明文冲突处理原则**——任何卡内容（姿态卡与要求卡）与宪法红线、陪想身份的固定条款冲突时，固定条款优先，该原则 SHALL 写入信封制度段。仍保持的结构约束：陪想身份 SHALL 永居姿态挂载位之上（任何姿态内容不得置于身份之上）；宪法红线 SHALL 永居链路卡挂载位之上（任何要求卡内容不得置于红线之上）。陪想身份 SHALL 顶替 DSH 默认部署 persona，英文默认 persona 文案 MUST NOT 出现在最终 system 层；DSH harness 标识段位于最顶且不可移除。姿态挂载位 SHALL 承载当轮冻结的姿态段文本（无姿态卡或该轮未携带时为空段）；链路卡挂载位 SHALL 承载当轮冻结的要求卡文本（change `add-making-module-core` 起接入；无启用链路或该轮未携带卡时为空）。姿态段 SHALL 由宿主统一渲染（身份性包装，见 chain-assembly），要求卡段 SHALL 由系统统一包装（含「可替换的讨论方法、非强制规则」声明）。

#### Scenario: 会话建立即含完整信封
- **WHEN** 任一会话建立
- **THEN** system 层包含陪想身份与宪法红线，次序为陪想身份先于姿态挂载位先于宪法红线先于链路卡挂载位

#### Scenario: 默认 persona 被顶替
- **WHEN** 会话的 system 层完成组装
- **THEN** 最终 system 层不含英文默认 persona 文案（"coding agent"表述不出现）
- **AND** 陪想身份文本位于姿态挂载位与宪法红线之前

#### Scenario: 次序与结构约束
- **WHEN** 任一轮携带姿态卡或要求卡文本注入对应挂载位
- **THEN** 姿态段位于陪想身份之下、宪法红线之上；要求卡段位于宪法红线之下
- **AND** 任何姿态内容不置于陪想身份之上；任何要求卡内容不置于宪法红线之上

#### Scenario: 明文冲突处理原则在场
- **WHEN** 审查任一携带卡内容的 system 层制度段
- **THEN** 含「卡内容与宪法红线、陪想身份的固定条款冲突时，固定条款优先」语义的明文条款

#### Scenario: 姿态卡注入姿态位
- **WHEN** 启用链路的当前版本含姿态卡且轮次发起
- **THEN** 姿态段文本注入姿态挂载位（陪想身份与宪法红线之间），不进入链路卡挂载位

#### Scenario: 无卡轮次挂载位为空
- **WHEN** 未启用链路的轮次发起
- **THEN** 姿态挂载位与链路卡挂载位均为空段，信封仅含陪想身份与宪法红线

#### Scenario: 无姿态卡但含要求卡
- **WHEN** 启用链路的当前版本只含要求卡且轮次发起
- **THEN** 姿态挂载位为空段，要求卡照旧注入链路卡挂载位，最终 system 层与本变更前逐字一致

#### Scenario: 崩溃重放信封一致
- **WHEN** 驱动进程崩溃后宿主恢复并重放某讨论
- **THEN** 新会话 start_session 携带的 system_prompt 仅含陪想身份与宪法红线常量（与原会话逐字相同，姿态位空段为驱动侧行为、从不进 start_session）
- **AND** 重放期间（历史 seed 注入）姿态挂载位与链路卡挂载位均为空且无模型调用
- **AND** 恢复后首个轮次按当前启用指针重新冻结、分别装入两挂载位，不从历史链路记录复原旧姿态

### Requirement: 崩溃重放携带相同信封
宿主在崩溃恢复重建会话时 SHALL 重发与原会话逐字相同的 system_prompt（身份＋红线常量部分）；姿态段文本与链路卡文本均不经 start_session 携带，且 MUST NOT 以在重放 user 文本中拼接提示词前缀的方式补投制度性内容。重放完成与下一轮请求之间 SHALL 无模型调用；恢复后的首个轮次 SHALL 按当轮冻结的链路版本携带姿态段与卡文本（冻结规则见 chain-assembly）。

#### Scenario: 重发逐字一致
- **WHEN** 驱动进程崩溃后宿主恢复并重放某讨论
- **THEN** 新会话的 start_session 携带与原会话逐字相等的 system_prompt

#### Scenario: 重放文本不再拼接前缀
- **WHEN** 崩溃恢复重放首轮 user 文本
- **THEN** 该文本不包含提示词前缀，制度性内容由 start_session 携带的 system 层提示与逐轮 `posture`／`chain_cards` 字段提供

#### Scenario: 恢复后首轮按冻结版本携带
- **WHEN** 崩溃恢复重放完成且用户发出新轮次
- **THEN** 该轮 send_message 按当轮冻结的链路版本携带姿态段与卡文本，重放期间无模型调用发生

### Requirement: 信纸职责划分
每轮差异内容 SHALL 保留在 user 消息层（信纸）：入口方式说明（直接提问／及时召唤的姿态差异）、工具使用的入口差异说明、用户问题、当轮材料（关注文档现场材料、目录投影、检索片段）。system 层的身份与红线 SHALL 不随入口方式与轮次变化；system 层可随当轮冻结链路版本变化的部分 SHALL 仅为姿态挂载位与链路卡挂载位两处（change `add-posture-slot` 起由一处扩展为两处）；除此之外 system 层不承载轮次差异。

#### Scenario: 入口差异留在信纸
- **WHEN** 直接提问与及时召唤两种入口分别组装请求
- **THEN** 两者的入口姿态与工具使用差异体现在 user 层
- **AND** system 层的身份与红线内容完全一致

#### Scenario: 材料装配位置不变
- **WHEN** 常规轮次自动附带现场材料
- **THEN** 材料块仍组装在 user 消息层，装配行为与既有要求一致

#### Scenario: 链路差异在信封且限于两挂载位
- **WHEN** 前后两轮使用不同的链路版本（姿态或要求卡变化）
- **THEN** 差异仅体现在 system 层姿态段与链路卡段，user 层消息结构保持既有形态，system 层其余内容不变
