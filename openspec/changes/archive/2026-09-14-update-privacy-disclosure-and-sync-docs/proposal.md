# 诚实告知与文档同步（update-privacy-disclosure-and-sync-docs）

## Why

阶段 5 A（2026-09-14 归档 `add-automatic-story-context`）之后，常规讨论会自动向所选模型发送关注文档现场材料（已保存正文或经校验的未保存快照）、允许目录投影与跨文档字面检索片段；但 LLM 配置页的用户可见告知与 README 仍停留在旧链路，写着「只发送问题、冻结选区或临时对话」——用户在发送前不知道正文会被发送（审计 P0-5，违反诚实边界）。同时 README 与多份方向文档的阶段状态落后归档现实最多两个阶段，README 的存储描述仍写已废弃的双本子模型（审计 P1-10），误导读者与下一步决策。本 change 只做诚实修复，不含任何行为扩展。

## What Changes

- **配置页告知文案重写**（`index.html` 设置页三段 `config-warning`）：
  - 区分三条链路的发送范围：测试连接（仅固定测试语句与凭据）、常规讨论、及时召唤（冻结选区）；
  - 常规讨论如实列出自动附带的关注文档现场材料、允许目录投影、跨文档字面检索片段，并说明可见性与回收站规则生效、第三方处理取决于用户与服务协议。
- **README 事实对齐**：
  - 状态段与里程碑表更新至阶段 4/5 A 已归档、下一步为阶段 6（应用级真实材料 E2E 与等待基线作为验证缺口单列，不与「未实现」混写）；
  - 「已实现能力」补受控只读、文档级 AI 可见性与常规讨论自动现场材料；「当前未实现」移除自动作品上下文，保留按需补读；
  - 修正隐私相关表述（第 49、69、153 行区域）与第 95 行「AI 参考优先级」措辞错误；
  - 「数据保存在哪里」从双本子文件路径改为内容树文档与 `next-story-system/` 会话档案；「AI 思考生成与追问流程」同步发送范围。
- **方向文档历史标注**（不删改历史原文，只加标注）：
  - `方向/第一版方向共识-2026-07-01.md` 第 6 节顶部加「2026-07 历史基线」说明；
  - `方向/行动计划-2026-08-27.md` 状态注释与事项 2 更新至阶段 4/5 A 已归档，修正指向不存在的活跃 change 路径；
  - `方向/让AI看见作品-阶段0整体设计-2026-09-09.md` 加「截至 2026-09-09 快照」文档头注记。
- **架构图治理**：`docs/diagrams/` v2 结构图标注为历史快照（遵循 `workspace-artifact-governance` 的源/导出物关系要求，同步更新 diagrams README 注记；不重绘）。
- **文档地图**：`AGENTS.md` 文档地图纳入《方向/全量地基审计-2026-09-14.md》；审计报告第八节队列状态列同步本 change。
- **测试**：更新/新增配置页告知文案断言，覆盖材料发送范围与链路区分（沿用 `tests/llm-config-form.test.ts` 读取 `index.html` 的既有模式）。

## Capabilities

### New Capabilities

（无——本 change 不新增产品能力。）

### Modified Capabilities

- `llm-configuration`：修改「LLM 配置页必须告知模型服务会收到哪些数据」要求——告知范围 MUST 覆盖常规讨论自动附带的现场材料（关注文档已保存正文或经校验的未保存快照、允许目录投影、跨文档字面检索片段），MUST 区分常规讨论与及时召唤（冻结选区）两条链路的发送范围，且 MUST NOT 声称只发送问题与选区。
- `project-readme`：修改三项要求——已实现能力清单（含永久边界场景措辞）补阶段 4/5 A 条目（受控只读、文档级可见性、自动现场材料与出处查看）并对齐「作品文档」命名；「数据保存在哪里」从双本子路径改为内容树文档（`作品文本/documents/`）与 `next-story-system/conversations/` 会话档案；「AI 生成与追问流程」补自动材料发送说明。
