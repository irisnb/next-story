# Proposal: resident-ai-session（常驻 AI 会话进程）

## Why

当前 AI 生成链路是"每条消息 spawn 一次 DSH headless 进程、用完即焚"：前端每轮手工重发全部历史、受 Windows 命令行约 3.2 万字符上限约束、只能非流式整段返回。这等于绕开 DSH 现成的会话基建（会话管理、自动压缩插件），手工搓一个阉割版，吃力不讨好还容易出问题。常驻会话是运行时地基：省去每条消息秒级的进程启动开销，解锁流式回复与上下文自动压缩，也是未来"后台 Agent 待命"愿景的第一块基石（`方向/行动计划-2026-08-27.md` 事项 1，2026-08-27 拍板）。

## What Changes

- **BREAKING** DSH 调用从一次性 headless 进程改为**对话期间常驻的会话进程**。形态选型（2026-08-28 探索拍板）：常驻 node 进程直接驱动 DSH JS API，stdin/stdout 管道通信，**无网络端口**；实现第一步先做 JS API 探底验证，不通过则停下汇报，退回 web profile 方案需用户确认。
- 会话生命周期与对话同寿命：用户召唤 AI 时懒启动确保会话就绪；新建对话、切换作品时结束当前会话；退出应用时结束进程。
- 前端不再每轮全量重发历史，只发增量消息；对话历史在会话内由 DSH 维护，前端仅保留显示历史。
- **BREAKING** 回复从非流式改为**流式**（面板逐字显示）。
- 进程崩溃时自动重启，前端用已有显示历史以**带角色方式注入**重建会话记忆（重放不触发重新生成）；若探底证实框架不支持无生成的历史注入，则诚实降级为"保留面板显示历史 + 提示新建对话"。**不落盘**——维持现有"后端不持久保存临时对话"边界（聊天记录持久化是后续独立事项）。
- 请求超时与协议异常不得污染会话：优先支持取消单次生成；框架无法干净中断时，该会话视为不可信并结束（提示新建对话），失败轮次不得残留进会话历史。
- 上下文超限改由 DSH compaction 插件自动承接，不再手搓截断规则；框架能力不足时兜底为中文报错提示新建对话，绝不静默丢弃历史。
- **BREAKING** 旧选区工具退场：`AI 及时召唤`、`思维扩展`、选区浮动 AI 入口及其小菜单从产品移除（代码保留不删，留作以后拆用）；选区快照冻结与纯文本投影机制保留，继续服务直接提问的"可选重点提示"。
- 安全边界不变式：17 项禁用工具照旧全部禁用、能力网关只放行文本生成、API Key 仅经环境变量注入不落盘、AI 进程不获得任何文档写入能力——常驻只是活得久，权力没有任何增加。

## Capabilities

### New Capabilities

- `resident-ai-session`: 常驻 DSH 会话进程能力：进程守护与生命周期（懒启动、崩溃重启、优雅退出）、会话与产品临时对话的映射、增量消息传输、流式回复事件、崩溃后历史重放恢复、超限压缩与兜底、安全边界在常驻模式下的维持。

### Modified Capabilities

- `dsh-headless-generation`: 生成链路进程模型从一次性 headless spawn 改为常驻会话；"每轮携带完整问答"改为会话内增量发送；非流式输出改为流式；错误契约、API Key 注入、版本锁定、能力网关边界要求保留。
- `dsh-sidecar-lifecycle`: sidecar 从"一次一销毁"改为"对话期间常驻守护"：懒启动、崩溃自动重启、优雅退出与资源回收。
- `persistent-ai-panel-entry`: "每轮发送此前完整问答"改为增量发送；非流式请求改为流式显示。
- `summon-ai-follow-up`: 随旧选区工具退场，单条线性临时追问的旧要求移除（追问能力由统一临时对话 + 常驻会话承接）。
- `selection-ai-invocation`: 浮动 AI 入口、`及时召唤`、`思维扩展`退场；选区快照冻结与投影规则保留，继续服务直接提问的可选重点提示。
- `ai-thinking-panel`: `思维扩展`预备态退场；回复显示从整段非流式改为流式逐字；其余面板行为（临时材料、只读、迟到隔离、重试语义）保留。
- `ai-feature-orchestration`: 请求载荷从全量历史改为增量；非流式改流式；旧工具编排移除。
- `ai-panel-state-structure`: 面板状态的事实源语义修订——显示轮次仍完整保存（用于显示与崩溃恢复），但请求载荷改为增量；三个首轮入口改为直接提问唯一入口；非流式语义改流式。
- `ai-panel-rendering-boundaries`: DOM 适配器与显示决策移除思维扩展等旧入口的渲染与交互；保留直接提问、选区提示、流式显示、追问、重试与只读边界。
- `llm-configuration`: 生成定义从"选区触发、非流式、全量重发、后端不建会话"修订为"直接提问触发、流式、增量发送、后端运行期会话（不落盘）"；隐私告知文案同步更新。

## Impact

- **后端 (Rust)**：`src-tauri/src/dsh_sidecar.rs`（一次性 spawn → 常驻进程守护 + 管道协议）、`src-tauri/src/llm_config/generate.rs`（全量 task 组装 → 增量消息）、`src-tauri/src/lib.rs`（Tauri 命令与应用生命周期 hook）、`src-tauri/src/capability_gateway.rs`（常驻模式下边界维持）。
- **Sidecar (Node)**：新增常驻驱动脚本（boot DSH 容器、装配会话与 compaction 插件、stdin/stdout JSON 协议、流式事件转发）；DSH 依赖保持锁定 `@deepseek-ai/dsh@0.1.0-rc.7` 不动。
- **前端 (TS)**：`src/ai-panel-conversation.ts`、`src/ai-panel-reducer.ts`（增量发送、流式渲染、会话身份）、`src/ai-feature.ts` 及编排模块（旧工具退场、流式接入）、`src/project-api.ts` / `src/types.ts`（IPC 契约）。
- **规格**：1 个新能力 + 7 个修订能力（见上）。
- **风险闸门**：任务第 1 项为 DSH JS API 探底验证（rc.7 可编程启动容器、装配会话与 compaction 插件、多轮增量收发、流式事件、工具禁用 patch 生效）；探底不通过则本 change 停下，向用户汇报后另行确认退路。
