# 设计：长上下文轮次冻结的归因与修复

> 证据起点：8b 会话清单 A7b/C4 与计时导出（42 条记录，4 条 165–292 秒异常值）。
> 本文先立归因路线，修复形状随归因结论在决策树内落位；两者都是本 change 交付物。

## Context

**现象（8b 实测）**：17 轮长上下文讨论（含按需补读工具循环、两篇全文读取）连续三轮冻结于「正在思考…」——无流式输出、无错误、状态点保持生成中，6 分钟以上需手动停止；后半夜自愈一轮，间歇性。同时段新建讨论同材料 3–6 秒正常收束。计时异常值 165／292 秒级别（常态总时长 5–40 秒）。

**已排除**：未保存快照材料（隔离轮同样携带且正常）；讨论身份接线（修复后其他讨论正常）；端点整体可用性（同时段其他讨论正常）。

**嫌疑链**：前端 → Rust `dsh_driver`（事件路由、请求等待）→ sidecar `driver.mjs`（DSH headless 宿主、按会话串行队列）→ DSH Agent Loop（`dsh-agent-loop`）→ 压缩插件（`dsh-compaction-basic` + `dsh-compaction-tool-result-pruner`）→ `dsh-llm-pi-ai` → 智谱 coding 端点。

**预研已发现的结构性线索（归因第一假设）**：`dsh_driver.rs:32` 已有 `REQUEST_TIMEOUT = 180 秒`，到期路径会先取消再宽限回收、返回超时错误（`:1113-1123`）。但 8b 冻结轮持续至 292 秒仍无超时错误、只能手动停止——**180 秒超时在这条轮次上没有生效**。`send_message_and_wait` 内唯一无超时的等待分支是 `:1095 is_suspended`（挂起中的轮次「阻塞等待工具结果回填／授权决定／停止生成带来的下一个事件」，授权等待按设计不超时）。若冻结轮因任何原因被标记为挂起（例如 DSH 在工具链中途内部停滞、或压缩发生在工具间隙），Rust 侧就会按「等待用户／工具」的语义无限等待——把「DSH 内部假死」误当成「等用户」。这是当前代码里唯一能同时解释「无事件、无错误、无限生成态、手动停止有效」四要素的结构洞。

## Goals / Non-Goals

**Goals:**

1. 归因落档：根因收敛到「我方配置／我方代码／DSH 内部／端点行为」四类之一（或如实的概率排序），证据入验证记录。
2. 用户可见契约兑现：任何非用户驱动的等待都有界——轮次不得无限停留在生成态；停滞在有限时间内被识别，或恢复或以中文可读错误收场，已完成内容保留、讨论仍可用。
3. 防回归：冻结检测与兜底路径有测试锁定；归因过程产出的观测能力（计时、事件时戳）尽量沉淀为可复用仪器。

**Non-Goals:**

- 不重写、不 fork、不 patch DSH 包源码（结论必须动包内部时，回到用户面前重定路线，例如评估 DSH 升级）。
- 不改并发上限（已定值 4）、不动 AI 只读边界与用户文档写路径。
- 不做回答质量工作（属「好问题验收」）；8c 评分器三条改进候选仅在自然交叠时顺带吸收，不为此扩范围。
- 不承诺「根治」：若根因在端点侧，交付的是检测＋兜底＋诚实记录，不是治愈。

## Decisions

### D1　归因先行：假设台账 + 可判死条件，先离线后实弹

间歇性 × 双外部因子的缺陷，盲目重跑烧配额且未必复现。归因分三步：

1. **离线源码研读（零 API 费）**：通读 `dsh-compaction-basic`／`dsh-compaction-tool-result-pruner` 的触发条件与压缩请求形态（压缩本身是否一次超长上下文请求？是否阻塞事件流？）；`dsh-agent-loop` 在压缩期间对外发不发协议事件；`driver.mjs` 按会话串行队列与压缩的交互；`dsh-llm-retry`／`dsh-timeout` 是否装配、默认值多少。产出：**假设台账**（每条假设附「怎样证明／怎样证伪」的判死条件与最便宜的验证手段）。
2. **台账驱动的定向实弹（少量）**：按 8b 复现路径（重上下文讨论 + 按需补读循环）跑差异化实验——同深度讨论换 DeepSeek 端点对照、卡在压缩阈值附近构造、开／关压缩对照（若配置暴露）。每次运行取证包：计时 JSON（既有导出口）＋驱动日志＋DSH 会话 JSONL（若可访问）。
3. **裁决落档**：四类归因 + 置信度 + 证据索引，写入本 change 验证记录。

**备选与否决**：「直接加超时兜底了事」——不否决兜底本身（D2 必做），但只做兜底不归因，等于把「间歇性假死」留给每个长对话用户，且无法区分「治好」与「没踩中」。

### D2　停滞检测落在 Rust 驱动层（与归因结论无关的必交付物）

**位置**：`dsh_driver` 的请求等待路径。理由：协议事件在此汇聚；请求生命周期、准入许可、取消路径都在这层；多窗口天然按 message_id 隔离；前端只渲染结果状态，不新增状态源（维持「reducer 唯一事实源」架构）。

**核心修法（针对预研发现的结构洞）**：

- **区分两类等待**：「等用户」（授权决定）保持无期限——这是既有规格语义（等待期间轮次挂起、不产生模型请求）；「等 DSH／端点」（工具结果回填、模型响应、压缩完成）必须有界。现状 `is_suspended` 把两者混在同一个无超时分支里，是结构洞所在。
- **判定信号**：事件间隔（自上一条协议事件起的静默时长）而非总时长——总时长会把「多轮工具循环的合法长轮」误杀，静默间隔只对「什么都不发生」报警。阈值从 8b 基线校准（常态首字中位约 3 秒、最长 59.7 秒含冷启动；阈值须显著高于合法静默上界，作为内部默认值而非用户承诺）。
- **触发后行为**：走既有取消路径回收轮次 → 中文可读错误（含「可重试」指引）→ 已完成内容保留、讨论可继续。不引入新错误通道，复用 `timeout_error` 一族的事件与前端映射。
- **REQUEST_TIMEOUT 与新静止 watchdog 的关系**：180 秒总时限对合法超长轮（大压缩 + 深工具链）可能过紧，对冻结轮又因挂起分支而不生效——实现时以基线数据重新校准两者分工（总时限管「太久的轮」，静止间隔管「死了的轮」），数值在任务内定并写入验证记录。

**备选与否决**：前端定时器检测——否决，前端只见流式增量，看不见工具／授权／回执事件，会把合法等待误报为冻结，且修复入口（取消、许可回收）不在前端。

### D3　修复形状：按归因结论走决策树

| 归因结论 | 修复动作 | 边界 |
|---|---|---|
| 我方配置（压缩阈值／重试与超时插件未装配或参数不当） | 调整 `cordis.driver.yaml`／`gen-config.mjs` 装配与参数 | 配置级，可回滚 |
| 我方代码（挂起语义过宽、串行队列与压缩交互死锁、事件路由洞） | 修代码 + 回归测试 | D2 的等待区分是已知必修项 |
| DSH 内部（压缩请求无超时、agent loop 停滞不吐事件） | 优先配置级缓解（压缩参数、装配 `dsh-llm-retry`／`dsh-timeout`）；评估 DSH 小版本升级；均不可行则 D2 兜底为主修复并如实记录「未根治」 | 动包内部须回用户重定路线 |
| 端点行为（智谱 coding 长上下文间歇挂起） | 差异化确认后：配置级重试缓解 + D2 兜底 + 记录「端点侧已知问题」 | 不改 UI 模型列表承诺 |

无论落在哪一格，D2（停滞检测＋诚实兜底）都是交付物；表格决定的是「除此之外还能不能治本」。

### D4　复现与取证协议（实弹阶段）

- 复现路径固定为 8b 形态：长上下文讨论 + 按需补读工具循环 + 全文读取，端点智谱 coding `glm-5.3`；对照实验按 D1-2 差异化。
- 冻结的操作化定义：is-generating 状态下，无流式增量且无任何协议事件静默 ≥ watchdog 阈值（与 D2 同一口径）。
- 每次运行三样取证：计时 JSON、驱动日志、DSH 会话 JSONL（若可访问——源码研读阶段确认路径与可行性）。
- 冻结发生时的第一动作是取证不是停止：先导出／拷贝三样，再手动停止。8b 的四条异常值已够立据，新运行以「验证假设」为目标而非「再冻一次」。
- 配额与在场：实弹需要智谱配额（有 429 前科）；需要用户在场的场景（原生对话框、抽查）提前约时段。

### D5　仪器沉淀与评分器顺带吸收

归因若产出「长上下文讨论自动驱动 + 事件时戳记录」的测试工具，8c 存量的评分器三条改进候选（对比句式确定性化、mustContain 等价机制、未知标记子句作用域）按既定顺带原则评估并入；工具不产出则本 change 不碰评分器。裁决与理由记入验证记录，避免「顺带」变「顺手扩权」。

### D6　规格修订形状（resident-ai-session）

新增要求「生成轮次停滞检测与诚实兜底」，场景至少覆盖：长静默被识别并诚实报错（内容保留、讨论可继续、可重试）；授权等待豁免（用户驱动不判停滞）；停止生成在停滞态仍有效。「上下文超限由框架压缩承接并诚实兜底」条目仅在归因结论要求改变压缩行为预期时修订——不预设结论。

## Risks / Trade-offs

- **[复现不出]** 间歇性缺陷可能整轮实弹都不冻 → Mitigation：D2 兜底与归因解耦必交付；归因允许「高置信推断」落档（源码证据 + 8b 既有量化），不伪造确定性。
- **[watchdog 误报合法长轮]** 阈值过紧会打断慢而正常的生成 → Mitigation：事件间隔口径 + 基线校准 + 阈值为内部默认；实弹阶段所有报警人工核对计时曲线后才算证据。
- **[归因指向 DSH 内部或端点，治本受限]** → Mitigation：D3 决策树前置，配置级缓解与 D2 兜底覆盖用户可见伤害；「未根治」如实写入验证记录与审计补充条目，不冒充治愈。
- **[智谱配额 429 复发]** → Mitigation：离线先行；DeepSeek 端点作对照变量兼备用链路；实弹窗口避开配额紧张时段。
- **[改动触碰请求等待路径，回归风险]** 该路径是队列 3a/3b 刚加固过的高压区 → Mitigation：既有 Rust 驱动测试全量复跑为门槛；新增冻结场景回归测试（挂起豁免、静止报警、停止有效）随修随锁。

## Migration Plan

配置级调整（若 D3 落在配置格）直接改 `cordis.driver.yaml`／`gen-config.mjs`，回滚＝还原配置；代码级改动走常规分支与测试门禁，无数据迁移；watchdog 阈值以常量落地，不引入用户设置项（内部行为，非用户承诺）。

## Open Questions

- 压缩期间 DSH 对外是否吐协议事件？（D1-1 源码研读直接回答，决定 watchdog 能否区分「压缩中」与「死了」。）
- DSH 会话 JSONL 能否作为冻结轮尸检材料？（研读 `dsh-session-persistence-jsonl` 确认存放路径与内容粒度。）
- `is_suspended` 的置位／清除条件全集（哪些事件解除挂起）——决定「等 DSH」与「等用户」的区分实现点。
- 阈值数值：静止间隔报警线与 REQUEST_TIMEOUT 总时限的分工与具体值（基线数据 + 实弹校准后在任务内定）。
