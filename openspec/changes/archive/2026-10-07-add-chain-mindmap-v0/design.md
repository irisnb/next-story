# add-chain-mindmap-v0 · 设计

## Context

②（`add-making-module-core`，2026-10-07 归档）交付的制作页为三栏并列：链路库｜结构检视（简版文字列表）｜制作对话。③把中间区升级为「导图视图」，视觉与交互以 `方向/制作模块/思维导图v0-视觉稿-2026-10-07/v10-详情统一/` 定稿为准（十轮用户拍板，记录见《第四页面与思维导图-设计方向-2026-10-06.md》§3）。

现状代码（exp-1 摸底核实）：

- `index.html:582-700` 静态骨架＋`src/making/making-module.ts` vanilla TS 控制器（闭包状态＋`replaceChildren` 全量重绘）；无前端框架；
- 数据来自 Tauri 命令（`chain_library_load` 等，`src/project-api.ts:647-769`），类型 `Chain／ChainVersion／RequirementCard／TrialRef`；
- 契约测试 `tests/dom-contract.test.ts:100-158`（现断言文字列表形态）；行为测试 `tests/making-module.test.ts`（30 项）；
- 全应用无任何绘图/图表依赖；`package.json` 仅 Tauri API＋TipTap；
- 响应式：≤1180px 链路库收拢，≤880px 页内「结构检视／制作对话」切换（`styles.css:4104-4167`）。

## Goals / Non-Goals

**Goals:**

- 按 v10 定稿实现：内容区双标签「导图｜制作对话」、导图三区同构（自定义要求／固定底座／每轮动态）、箭头汇入组装、输出纯象征块、图区基准居中、底部阅读说明条、统一详情（快捷小窗→全页详情）、三种可改性外观、「自定义要求」命名。
- 数据层、装配接线、制作助手、试问、链路库命令**零改动**（纯前端 change）。
- 契约测试与行为测试同步改写并全绿；真机视觉验收以定稿为基准。

**Non-Goals:**

- 后端命令、协议、存储格式改动；导图上直接编辑（加／改／删一律经制作对话）；姿态／背景／方式占位或「解锁」；输出全文预览／剖视（已删除）；步骤编号、执行顺序暗示、流动动画；拖拽／无限画布／缩放；深色模式专项设计（跟随现有令牌）。

## Decisions

1. **纯 DOM/CSS＋内联 SVG 连线，不引入图形库。**定稿本身即 DOM/SVG（`思维导图v0-v10.html` 35KB 自包含）；导图为固定排版、连线不承担交互，无自动布局需求；仓库保持零图形依赖。备选（引入 react-flow/d3）被否：为十几个固定节点引入整棵依赖树，且其交互能力（拖拽/画布）恰是禁令。
2. **标签为内容区内的视图切换，不新增路由/模块。**`ModuleId` 不变；制作页内容区改为 `导图｜制作对话` 两标签，控制器持运行期标签态（默认「导图」；制作对话标签复用现有会话控制器与 DOM，行为不变）。窄窗逻辑演进：≤1180px 链路库收拢（不变）；≤880px 标签成为唯一切换方式、状态条常驻、切换保留输入与浏览位置（承接既有 `data-making-view` 机制）。
3. **详情统一＝单一详情控制器、双呈现模式。**三类可点对象（卡／底座／每轮动态）产出同一种 `DetailModel`（内容＋可操作性不同），快捷小窗与全页详情是同一模型两种呈现——位置与尺寸统一由结构保证（小窗固定挂在图区容器右邻、垂直居中槽位），不由所点对象位置决定。备选（三类对象各自挂详情）被否：正是第十轮否决的「各自另设位置」。
4. **箭头语义由结构保证。**箭头仅出现在「分区→组装」「组装→输出」的 SVG 连线（`marker-end`）；卡片节点与 DOM 结构上不生成任何连线，契约测试断言卡间无箭头、无步骤编号——防「排列＝执行顺序」误读回归。
5. **居中基准用布局结构实现，不用测量。**图区容器独立（组装流＋输出块在其中垂直居中），底部阅读说明条在图区容器**之外**贴底——「脚注不参与居中计算」由 DOM 层级保证，避免运行时测量与窗口 resize 重算。
6. **「自定义要求」区定高＋`overflow-y:auto`；ghost「＋添加要求卡」在滚动内容尾部**（v10 拍板；可发现性弱一档为已接受取舍，入档备查）。
7. **命名分层：用户可见字符串统一「自定义要求」；代码标识符沿用既有英文（requirement card 等）**——同「作品/project」先例，一中文名一代码名，不新增第二套别名。
8. **视图模型重写而非修补。**`making-view-model.ts` 新增导图视图构建器（三区、卡行、连线数据、三态标题、三类 DetailModel）＋统一详情构建器；旧「简版列表」视图构建器删除。控制器渲染路径不变（`replaceChildren`），测试面清晰。

## Risks / Trade-offs

- [快捷小窗遮挡部分图区] → v10 已接受取舍：关闭即回；小窗尺寸统一，无跳位。
- [ghost 加卡入口在滚动折叠线下，可发现性弱] → v10 已接受；v0 后按真实使用反馈迭代。
- [底座说明较长，小窗内需滚动才见「打开完整详情」] → v10 已接受；全页详情入口同样存在于全页呈现。
- [双层分区（区＋插槽）视觉密度增] → 真机验收时核对定稿观感；间距令牌可调，不改结构。
- [SVG 连线随窗口尺寸变化的对齐] → 连线路径在单次布局函数中由分区几何生成，窗口 resize 时整图重绘（全量重绘本就是现有模式）；无自动布局引擎引入。

## Migration Plan

纯前端变更，无数据迁移；apply 后即生效（制作页直接呈现导图视图）；回滚＝revert 该 change 的提交。验收：全量门禁（`npm run check`）＋真机视觉比对（定稿 HTML 并排截图核对）＋三态场景亲验；不涉硬性冒烟门槛类目（无新窗口／权限／CSP／外部进程／文件对话框），但按②惯例做真机端到端走查（点卡／点底座／点动态／开全页／切标签／草稿查看）。
