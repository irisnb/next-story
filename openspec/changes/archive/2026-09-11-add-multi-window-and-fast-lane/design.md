# Design: 多窗口与及时召唤快车道（阶段 3）

## Context

阶段 2 已归档：讨论身份、按讨论隔离、保存与重开已实现。当前界面仍是单一 AI 面板、单活动讨论，关键单实例点：

- 面板 DOM 是 `index.html:127-196` 的单份静态节点，`src/dom.ts` 用全局 `getElementById` 一次性解析（`main.ts:16` 只调一次）。
- 流式增量经 `ai-session-transport.ts:52,190-196` 的 `onStreamText(listener: (text) => void)` 只携带文本，无讨论身份；`ai-panel-reducer.ts:571-599` 的 `append_stream_text` 写入「当前活动讨论」——并发生成会串台。
- 首轮请求被作品级单飞门禁串行化（`ai-feature-first-round.ts:22-41`，按作品令牌 owner）；全局 `conversationGeneration` 会因开新讨论/切讨论作废其他讨论的在途预检。
- `ai_cancel_message` 命令存在（`project-api.ts:252-258`）但前端无任何引用；用户没有停止入口。
- 驱动丢失恢复只重放当前活动讨论（`ai-feature.ts:401-415`）。
- 无等待测量基础设施。

底层已具备并发基础：`AiRequestCoordinator` 按 `conversationId` 加锁、transport 用 `Map<conversationId, sessionId>`、Rust `dsh_driver` 按 `msg:{message_id}` 路由终态、sidecar 按会话 Map 管理且每会话 busy。并发瓶颈在前端层，不在驱动层。

阶段 0 已确认（方向版 7.1–7.4、7.6–7.7）：窗口默认停靠、可脱离移动缩放并排、布局仅运行期；关闭窗口不删除讨论、生成中关闭自动停止；停止生成只结束对应讨论；多讨论各自追问/停止/重试、互不串用；并发按实际能力、超出只在对应窗口排队；等待目标待真实基线。阶段 1 的真实接入验证（真实 DSH 事件字段、等待基线、并发上限）尚未取得，本变更补齐。

## Goals / Non-Goals

**Goals:**

- 多窗口呈现：停靠区承载多个讨论窗口，可脱离为应用内浮动窗口，可移动、缩放、并排对照；一讨论至多一个窗口。
- 窗口状态动作：关闭（生成中先停止）、停止生成、重开（聚焦或新建、不自动重发）、删除（独立动作）语义互相区分；布局仅运行期。
- 窗口级请求呈现：每窗口独立呈现等待、排队、生成、已停止、失败；生成中切走再切回显示进行中状态。
- 快车道与调度：不同讨论独立发起；全局并发上限 + 先到先服务排队；排队状态只在对应窗口显示；限流如实提醒。
- 崩溃恢复：驱动进程丢失后恢复所有打开窗口的讨论。
- 真实链路验证：并发路由、停止隔离、迟到结果、关闭停止、队列、恢复与真实事件字段；取得等待基线并确定并发上限。
- 会话列表重做：按最后活动时间分组与排序、重命名、置顶、删除确认与撤销、过滤与空状态。
- 窗口与会话列表视觉：designer 自主出稿（已产出 `ui-design/`），实现按稿落地。

**Non-Goals:**

- 会话内快捷跳转；真实工具读取与作品补读（阶段 4–6）；AI 可见性设置（阶段 4）；全应用视觉全量更新。
- 系统级（OS）多窗口：窗口为应用内 DOM 窗口。
- 窗口布局持久化。
- AI 写作品能力：边界不变。

## Decisions

### D1 窗口模型：应用内 DOM 窗口，停靠区 + 浮动层

- 右侧停靠区承载停靠窗口（纵向排列，超出滚动）；窗口可拖出成为应用内浮动窗口，绝对定位、可移动、可缩放（最小可用尺寸）、点击置顶，支持并排对照；浮动窗口可拖回停靠区。
- 一讨论至多一个窗口：重开时若已打开则聚焦，否则新建停靠窗口。新讨论（召唤、直接提问首轮、新建对话）打开自己的窗口，不替换已有窗口；应用重启不自动重开历史窗口，从列表打开。
- 「新建对话」打开空讨论窗口；聚焦窗口若已是空窗口则复用它，避免空窗口堆积（细节可微调）。
- 关闭窗口只结束显示；生成中先停止该轮再关闭；讨论与档案保留，重开不自动重发。删除讨论同时关闭其窗口。切换作品关闭该作品全部窗口，档案保留在原作品目录。
- 布局（位置/尺寸/停靠或浮动/层叠）仅运行期保留；窗口关闭或应用退出后，重开恢复默认停靠。
- 停靠区整体可收起：收起隐藏停靠窗口但保留生成与状态；浮动窗口独立于停靠区。
- 备选：Tauri 系统级多窗口——用户确认为应用内窗口，排除。

### D2 状态与渲染边界：内容状态唯一，窗口结构入状态、几何留窗口层

- `AiPanelState` 继续是讨论内容与请求状态的唯一事实源；新增窗口结构状态（打开窗口：讨论 id + 停靠/浮动；当前聚焦窗口），替代单一 `activeConversationId` 的显示语义。
- 窗口几何（位置、尺寸、层叠）与拖动/缩放过程由窗口层本地持有，高频更新不进入 reducer、不持久化。
- 每窗口实例化自己的 DOM 契约（`AiPanelDom` 按根节点解析，替代全局 `getElementById`）与渲染管线；显示决策按窗口参数化（以该窗口的讨论为输入），仍保持纯派生与单一事实源。
- 输入草稿与待附带选区按窗口/讨论归属；编辑器选区作为可选重点提示附着到聚焦窗口的发送。

### D3 流式与终态按讨论身份路由

- `ai-session-transport` 的流式订阅携带讨论身份（`conversationId` 与消息身份）；reducer 按讨论写入增量，不再写入「当前活动讨论」。
- 这是多窗口并发的正确性关键：两个窗口同时生成时增量必须各自归属；终态与迟到隔离沿用既有讨论身份规则。

### D4 请求调度：独立发起 + 上限与排队

- 移除作品级首轮单飞门禁（`FirstRequestPreflightState` 的作品级 owner）：预检按讨论进行，不同讨论首轮可并发发起；预检有效性只随本讨论或作品失效，不因其他讨论新建/切换而作废。
- 新增调度器：全局并发上限（可配置）+ 先到先服务队列；未达上限立即发起；达上限时在对应窗口显示排队状态，名额释放后按序开始；停止或关闭窗口取消排队中的请求。排队中的请求仍占用该讨论的单请求锁（讨论内仍至多一轮）。
- 不设讨论间优先级；快车道的保证是「独立发起、不被全局忙碌阻塞」，不是插队。
- 上限数值不预设，按真实接入实测确定并记录；设计不把上限固定为 1，确保常规与召唤可并行（快车道前提）；若服务能力确实不足，按排队并如实提示。
- 服务商限流或能力不足：对应窗口如实提示，不自动重试风暴；可手动重试。

### D5 停止生成与关闭窗口

- 接线 `ai_cancel_message`：transport 增加按讨论取消的方法；每窗口提供停止动作（生成中或排队中可见）。
- 用户停止 → 该轮进入「已停止」终态，已完成内容保留为显示草稿，不产生成功轮次；只影响对应讨论。
- 关闭生成中的窗口 → 先停止该轮再关闭显示。
- 底层目前把取消映射为 Timeout 错误码；实现时区分用户停止与超时（或以前端发起意图为准），确保终态文案与语义正确。

### D6 崩溃恢复覆盖所有打开窗口

- 驱动进程丢失后，对所有已打开且有已保存轮次的讨论执行重放恢复；各窗口显示「恢复中」，完成后恢复追问；未打开讨论保持档案待重开。
- 在途请求因驱动丢失进入失败/中断终态，不伪装成功。

### D7 真实链路验证与等待测量

- 轻量计时采集（提交、首次真实模型回应、完成、排队时长；区分进度提示与实际回应），仅用于验证、不做产品承诺。
- 验证场景：并发双讨论、生成中召唤、停止隔离、迟到结果、关闭窗口停止、超队列行为、驱动丢失恢复、真实 DSH 事件字段核对。
- 实测确定并发上限与等待分项数据，如实记录、不承诺秒数；验证需要用户在场。

### D8 窗口与会话列表视觉

- 由 designer 自主出稿（用户不参与决策），设计稿已产出：`ui-design/README.md` 与三份自包含可视稿（`mockup.html`、`conversation-list-detail.html`、`window-anatomy.html`）。实现按稿落地；全应用视觉全量更新仍留在后续事项。

### D9 会话列表重做与档案字段扩展

- 列表按最后活动时间（`updated_at`）排序，分为「置顶 / 今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 更早」（空分组不显示，「更早」按自然月分节）；置顶区独立且默认展开；条目间轻分隔线；紧凑行、标题最多两行省略、关注文档与状态、相对时间、当前讨论标记；状态词与窗口一致；明确避开「最近 N 条 + 查看更多」截断。
- 入口常驻：停靠区头的「会话列表 / 新建对话 / 收起」不按讨论数量显隐（修掉现状「突然冒出」）；图标改为统一描边图标系统（inline SVG）。
- 交互：悬停出现重命名 / 置顶 / 删除；重命名就地编辑；删除需确认并提供短暂撤销；按标题与关注文档名即时过滤；空状态引导；列表覆盖停靠区并可收起，编辑区始终可见。
- 档案扩展可选字段：自定义标题（`title`）与置顶标记（`pinned`），由 `conversation_store` 读写；缺失按默认处理，向后兼容。
- 批量管理可后置，先以逐条删除 + 撤销兜底。

## Risks / Trade-offs

- [并发串台] → 流式与终态全部按讨论身份路由；真实验证覆盖并发双讨论。
- [移除作品级门禁后首轮并发压力] → 调度器上限 + 队列兜底；上限由实测确定。
- [快车道在低容量下退化为排队] → 设计保证常规与召唤可并行；服务能力不足时如实提示并调整目标。
- [窗口 DOM 多实例泄漏/错乱] → 窗口管理器统一创建/销毁与订阅退订；测试覆盖打开/关闭/重开。
- [拖动缩放高频更新影响性能] → 几何留在窗口层，不进全局状态。
- [关闭窗口停止请求的底层确认] → 沿用既有取消安全边界；无法确认干净终止时按会话不可信处理，不静默继续。
- [停靠区容纳多窗口后高度有限] → 纵向排列可滚动、鼓励拖出浮动并排；视觉稿阶段确认观感。

## Migration Plan

1. 规格变更先行：3 个新 capability + 12 个现有 capability 的 delta。
2. 实现顺序：流式/终态身份路由与状态结构 → 窗口管理与多实例 DOM → 调度与停止 → 恢复扩展 → 会话列表重做 → 真实链路验证与上限确定 → 视觉落地与文档同步。
3. 回滚：代码回滚后回到单面板单讨论显示；讨论档案仅新增可选字段（自定义标题、置顶标记），向后兼容，无强制迁移。
4. 验证：`npm run check`、`npm run test:rust`、AI 相关测试全绿；真实链路验证结果如实记录；方向文档阶段状态同步。

## Open Questions

- 空窗口复用规则（复用聚焦中的空窗口 vs 每次新建）：按复用实现，可微调。
- 队列是否需要召唤优先：先按先到先服务；实测后再评估。
- 等待目标数值：实测后与用户约定，本变更只交付基线数据。
- 列表搜索范围：先按标题与关注文档名过滤；正文全文搜索留待后续评估。
