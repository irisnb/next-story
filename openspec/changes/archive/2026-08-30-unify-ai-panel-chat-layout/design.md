# 设计：统一 AI 面板对话布局

## Context

当前实现（代码证据见探索报告）：

- `index.html:127-195`：面板内有三条渲染路径——`#ai-direct-question`（首轮直接提问区，含输入框、加载态、流式回答 `<pre>`）、`#ai-conversation`（多轮对话区）、`#ai-follow-up-form`（追问输入区）。
- `src/ai-panel-view-model.ts:203,233`：`buildAiPanelView` 用 `directQuestion` / `conversation` 两个互斥状态决定显示哪条路径。首轮成功瞬间 `directQuestion` 置空、`conversation` 建立，触发 DOM 整体切换。
- `src/styles.css:553-554`：`#ai-direct-question-response` 写死 `max-height: 32vh; overflow: auto`，嵌套在 `overflow: auto` 的 `.ai-panel-body` 内。
- `src/ai-panel.ts:183`：仅在 `scrollReset.shouldReset` 时滚回顶部；`append_stream_text` 渲染路径无任何滚动跟随。
- 首轮流式回答渲染在输入框下方（`index.html:179-185`），多轮消息渲染在输入框上方——视觉流向前后相反。

约束：

- 纯文本渲染边界不变（`<pre>` / `textContent`，不解析 HTML/Markdown）。
- AI 绝不写入用户文档的边界不变；本变更纯前端显示层。
- `ai-panel-reducer.ts` 的状态机语义（等待/生成中/成功/错误/缺配置/单请求锁/迟到结果隔离）不变。
- 用户已确认：AI 回复用无边框裸排样式；空状态只加一句欢迎语，不加建议提问。

## Goals / Non-Goals

**Goals:**

- 第一轮提问从发送那一刻起就在统一对话视图中呈现：用户问题立即上移为消息，生成中占位与流式回答在问题正下方原地展开。
- 输入框从空状态起固定在面板底部，任意轮次位置不变。
- 消除回答完成瞬间的容器切换跳变。
- 流式生成期间自动吸底滚动；用户向上滚动时暂停跟随。
- 消息样式：用户消息浅色底色块通栏，AI 回复无边框裸排。
- 空状态显示一句轻量欢迎语。

**Non-Goals:**

- 不引入 Markdown/HTML 渲染。
- 不添加建议提问、历史会话列表、持久化。
- 不改面板宽度、位置、抽屉形态。
- 不改状态机语义、请求协调层、常驻会话进程、后端。
- 不做消息头像、时间戳等附加元素。

## Decisions

### D1：单一对话视图，首轮即入流

把 `#ai-direct-question` 与 `#ai-conversation` 合并为一个对话容器 `#ai-conversation`。首轮直接提问被接受时，视图模型立即产出含一条用户轮次（问题文本 + 生成中状态）的对话视图，后续增量事件照常追加到该轮次的 assistant 文本上。原 `directQuestion` 渲染分支删除。

- 理由：跳变的根源是两条渲染路径在成功瞬间切换。让首轮从开始就走对话路径，切换点消失，而不是被动画掩盖。
- 备选：保留两条路径、加过渡动画掩盖切换——被否决，动画只是遮丑，双重滚动和视线流向颠倒仍然存在。
- 状态机影响：`begin_direct_question` 等迁移语义不变；变化仅在视图推导层——`buildAiPanelView` 在 `directQuestion` 存在时也产出对话视图（把冻结材料映射为用户轮次）。若 reducer 现有字段不足以表达「对话存在但首轮未成功」，允许最小限度调整 reducer 输出结构，但迁移语义（何时等待/生成中/成功/失败）不得改变。

### D2：输入区固定底部，面板体单滚动

面板改为纵向 flex：Header（不变）→ 对话区（`flex: 1; overflow-y: auto`，唯一滚动容器）→ 输入区（`flex: none` 固定底部）。空状态时对话区显示欢迎语，输入区显示直接提问输入（含可选重点提示框）；有对话后同一输入区切换为追问输入。删除 `#ai-direct-question-response` 的 `max-height: 32vh` 内层滚动。

- 理由：输入框位置恒定消除「上下流向颠倒」；单一滚动容器消除双重滚动条，回答可用整个面板高度。
- 备选：输入框跟随内容流（非固定）——被否决，长对话时输入框会滚出视野，违背成熟产品惯例。

### D3：消息样式

- 用户消息：浅色底色块（`var(--color-surface-subtle)` 或等效低对比底色）、圆角、通栏，移除现有左侧 3px 强调竖线。
- AI 回复：无底色、无边框、无圆角，裸排 `<pre>` 纯文本，与用户消息靠底色差和间距区分。
- 轮次间距（用户消息到上一轮 AI 回复）明显大于轮内间距（用户消息到本轮 AI 回复），形成「对话单元」节奏。
- 字号维持现有 `0.95rem` 量级，不引入新字号体系（420px 面板下现状可读性可接受，本变更不扩大排版范围）。

### D4：吸底滚动与用户滚动暂停

在对话区滚动容器上实现：

- 生成期间每次 `append_stream_text` 渲染后，若用户视口处于「贴底状态」（滚动距底部小于阈值，约 40px），自动 `scrollTop = scrollHeight` 跟随。
- 用户向上滚动脱离贴底状态后，停止自动跟随，保持视口不动；重新滚回底部（或点击「回到底部」入口，若实现成本低则加，否则滚到底部即恢复）后恢复跟随。
- 面板收起期间不滚动（无可见性，无意义）；重新展开时若在生成中，直接置于贴底状态。

- 理由：解决「最新字被遮挡」；用户回看时强制吸底是成熟产品都避免的干扰行为。
- 实现注意：用 rAF 或直接在渲染后同步设置均可，面板窄、文本量小，无性能压力；阈值判断放在滚动事件监听里维护一个布尔标记即可，不引入滚动库。

### D5：空状态欢迎语

对话区无任何轮次且无进行中请求时，显示一句静态中文欢迎语（如「想聊点什么？直接提问就好。」——最终文案实现时定，保持轻量、不承诺能力、不出现「帮你写」类表述）。有选区待附带时重点提示框照常显示在输入区上方。

- 理由：空状态中段完全空白会让视线没有落点；一句欢迎语把视线自然引向下方的输入框。不加建议提问，避免扩大产品范围和暗示 AI 能力边界。

### D6：生成中占位锚点

首轮或追问被接受后，用户问题消息正下方立即显示生成中状态（沿用现有「正在思考…」文案与位置语义，但渲染在对话流内该轮次位置，而非输入框下方的独立区块）。首个增量到达后占位平滑过渡为流式文本（同一位置，无跳变）。错误/缺配置/未接受状态同样渲染在该轮次位置，语义与现有 spec 一致。

## Risks / Trade-offs

- [视图模型合并后遗漏边缘状态（如首轮失败后重试、收起期间完成、迟到结果隔离）的渲染] → 实现时逐条对照 `ai-thinking-panel` spec 既有 scenario 建立验证清单；这些状态语义不变，只验证渲染位置正确。
- [吸底滚动与用户手动滚动竞争造成抖动] → 贴底阈值判断只在滚动事件中更新标记，跟随动作只在增量渲染后执行；用户脱离贴底后完全不干预滚动。
- [删除 `#ai-direct-question` 分支牵连 `dom.ts` 契约与事件绑定] → 任务拆分时把 DOM 契约调整列为独立步骤，先改契约再改渲染，保持每步可编译。
- [纯 CSS 布局改动影响窄窗口抽屉形态] → 抽屉形态（`<=760px`）复用同一 flex 结构，仅外层定位不同；验证清单包含窄窗口场景。
- [欢迎语文案不当造成能力承诺暗示] → 文案审查对照宪法红线（不承诺能力/结果），实现后由用户过目。

## Migration Plan

纯前端显示层变更，无数据迁移、无持久化影响。回滚即 git revert。实现顺序：DOM 契约 → 视图模型 → 渲染层 → 样式 → 滚动逻辑，每步保持可编译可运行。

## Open Questions

- 「回到底部」悬浮入口是否需要：先不做（滚到底部即恢复跟随已满足需求），实现中若吸底恢复体验差再补。
- 欢迎语最终文案：实现时给出候选，用户确认。
