## Why

二阶段方向已确认要用成熟的结构化富文本编辑器内核替换当前的纯文本 `textarea`（见 `.omo/二阶段-01-编辑器、项目结构与UI方案/二阶段文本编辑器及相关功能的探讨和确定.md` 第二节第 2 条）。研究阶段（`.omo/ulw-research/20260810-214721/`）已把候选收敛为 Tiptap/ProseMirror（首选）与 Lexical（对照），且与外部模型的独立推荐相互印证。但三个最高风险项——Windows Tauri/WebView2 下的中文输入法、真实剧本长度的性能、冻结选区的恢复——纸面研究无法证明，只能真机验证。本 change 只做这一次范围收窄的原型验证，为最终内核选型提供可验收的证据，不替换现有编辑器。

## What Changes

- 新增一个独立、可丢弃的编辑器内核验证原型（不接入现有欢迎页/编辑器主流程，不改动现有 `textarea` 生产代码）。
- 原型在同一套 Windows Tauri/WebView2 目标环境中，为 Tiptap/ProseMirror 与 Lexical 各搭一个最小实例，接入相同的"纯文本投影 + 冻结选区快照"适配层。
- 原型执行一组事先定义、可二元判定的验收测试：纯文本保存重开一字不差、中文输入法组合输入、冻结选区捕获与恢复、真实剧本长度的输入/撤销/内存表现、AI 边界（输出永不写回）、依赖与许可审查。
- 产出一份对比验收报告，记录每项测试的实测结果（通过/失败/证据），作为最终选型的依据。
- 明确回滚与决策规则：若两个候选都在关键项失败，则暂缓内核迁移并回到方案讨论，不强行选一个。
- **不做**：不选定最终内核、不实现二阶段富文本能力（粗体/标题/列表等）、不实现项目树、不实现 DOCX、不改 AI 写回边界、不做任何面向用户发布的编辑器替换。

## Capabilities

### New Capabilities
- `editor-kernel-prototype`: 定义一次性内核验证原型的目标、范围边界、必须执行的验收测试项、每项的通过/失败判定、证据要求，以及"两候选都失败则暂缓迁移"的回滚决策规则。

### Modified Capabilities
<!-- 无。本 change 不改动任何现有 spec 的需求级行为；现有 textarea 编辑器、选区 AI、保存流程和 AI 不写回边界保持不变。 -->

## Impact

- **新增代码**：一个隔离的原型目录（例如 `prototype/editor-kernel/`），含 Tiptap 与 Lexical 两个最小实例及共享的选区投影适配层。原型代码与 `src/` 生产代码隔离，不进入现有构建产物的用户可见路径。
- **依赖**：原型会引入 Tiptap/ProseMirror 与 Lexical 相关 npm 包用于评估；这些依赖在原型阶段隔离，是否进入生产依赖由验收结果和后续独立 change 决定。
- **不受影响**：现有 `src/editor.ts` 等生产编辑器、`selection-adapter.ts` 选区快照、保存/重开流程、`llm_config` AI 链路、`AGENTS.md` 中"AI 不写回草稿本/正文本"的铁律——本 change 全部保持不变。
- **验证环境**：需在 Windows + Tauri 2 + WebView2 目标环境构建并真机运行原型，包含简体中文输入法实测。
