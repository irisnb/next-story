# AI 面板多窗口改版 + 会话列表重做 · 设计方案

> 面向 change：`add-multi-window-and-fast-lane`（阶段 3）
> 交付物：本说明 + `mockup.html`（总览可视稿）+ `conversation-list-detail.html`（会话列表细节稿）+ `window-anatomy.html`（窗口头与交互细节稿）+ `interaction-rules.md`（交互状态与冲突规则）
> 视觉基调：安静、专注的写作工具。写作区是主角，AI 是配角。
> 本方案由设计方自主决策，已给出唯一主推结论，不设「请用户选择」。

---

## 0. 一句话结论

把「一个 AI 面板」改成「右侧停靠区里一叠各自独立的讨论窗口」，窗口可拖出成应用内浮动窗口并排对照；会话列表从「一堵卡片墙」改成「天 / 周 / 月分组、条目间有轻分隔线、能改名、能置顶、操作在悬停时才出现、图标统一」的紧凑列表；入口按钮常驻、不再按讨论数量忽隐忽现。

---

## 1. 设计目标与原则

1. **写作区永远是主角。** 编辑区的边框和阴影保持全窗口最重（沿用现有 `--shadow-editor`）；AI 停靠区和窗口只用较轻的边框与小偏移硬阴影，绝不盖过正文。
2. **一个讨论 = 一个窗口。** 用户同时看到多个讨论各自的标题、关注文档和状态，不必来回切换。
3. **状态看得见，不用猜。** 排队中 / 生成中 / 已停止 / 失败 / 恢复中 直接放在窗口头，生成中能就地停止，失败能就地重试。
4. **安静但不隐形。** 窗口默认停靠、不抢焦点、不置顶；只有当前操作的窗口有清晰的边框强调。
5. **图标是一套，不是一堆。** 统一描边、统一网格、统一颜色来源，不用 emoji 或随手字符。
6. **破坏性操作退后一步。** 关闭 ≠ 删除；删除要确认且可撤销；删除按钮不再常显在每行。
7. **能用现有技术栈落地。** 全部基于原生 TypeScript + CSS + 现有设计令牌；复杂交互都标注了复杂度和更轻的替代做法。
8. **绝不出现「把 AI 输出写进作品」的入口。** 窗口里只有复制用的纯文本，没有「应用到正文」。

## 2. 现状诊断：会话列表为什么「体验极差」

先诊断，再改。以下问题都能在现有代码里对上号。

| # | 问题 | 证据 / 原因 | 后果 |
|---|------|------------|------|
| 1 | 显示的是**创建时间**，不是最后活动时间 | `ai-panel-conversation-list.ts` 用 `summary.created_at` 格式化时间；档案里其实有 `updated_at` 没用上 | 反复回来的讨论仍显示很久以前的时间，排序也不可靠 |
| 2 | 每行是一张**带边框 + 硬阴影的卡片** | `.ai-conversation-list-item` 有 `border` + `box-shadow` + 行间距 | 420px 面板里视觉噪音大，一屏放不下几条 |
| 3 | **没有分组** | 列表是平铺的 | 讨论一多只能靠记忆和滚动找 |
| 4 | 标题**自动生成且不能改**，只显示一行 | `deriveConversationTitle` 取首轮前 40 字；`.ai-conversation-list-item-title` 是 `white-space: nowrap` | 标题经常认不出是哪个讨论，长标题被硬切 |
| 5 | **删除按钮每行常显** | `.ai-conversation-list-delete` 一直渲染 | 破坏性操作和「打开」抢注意力，容易误点 |
| 6 | **没有置顶** | 无此概念 | 正在跟进的讨论会被新讨论淹没 |
| 7 | 状态词偏弱、有「状态未知」 | `describeConversationStatus` 对 `null` 回退「状态未知」 | 看不出哪些需要我继续 |
| 8 | 列表是**整块替换面板内容** | `conversationList` 与对话内容互斥显示 | 打开列表就看不见当前讨论，像切了个页面 |
| 9 | **没有搜索、没有批量清理** | 无此功能 | 旧讨论只增不减，越用越乱 |
| 10 | **图标是 emoji / 字符** | 列表与面板用 `☰ ＋ ⇥ ✎ 📌 🗑 ✓ ▾` 等字符拼图标 | 风格不统一、随系统字体变化、显得廉价 |
| 11 | **入口按钮忽隐忽现** | `ai-panel.ts:301` 在 0 条时隐藏「会话列表」；`ai-panel-view-model.ts:330` 在空白空闲时隐藏「新建对话」 | 第一条讨论开始后按钮「突然冒出」，像多余控件 |

## 3. 关键决策一览（主推结论 + 理由）

| 决策 | 主推结论 | 理由 | 简述备选（已排除） |
|------|---------|------|-------------------|
| 停靠区布局 | 420px 单列纵向堆叠，每讨论一张窗口卡，超出滚动 | 窄列里单列最稳；保留「同时看到多个讨论状态」 | 标签页合并——会丢状态，排除 |
| 多面板并排 | 只在**浮动**后做左右并排；停靠区内是上下分栏 | 420px 放不下两个可用宽度的面板 | 停靠区内左右分栏，排除 |
| 窗口形态 | 要么**固定停靠**，要么**真正自由浮动**，没有中间态 | 吸取 Figma 教训：看起来能拖但不能拖最伤信任 | 「半浮动」预览态，排除 |
| 拖出方式 | 拖出停靠区即浮动（VS Code 式） | 符合桌面软件肌肉记忆 | 先点按钮再拖动，多一步 |
| 回停靠方式 | 拖回停靠区 **或** 双击标题栏 | 两种都直觉；双击同时兼作「还原」 | 只留菜单项，太隐蔽 |
| 布局记忆 | 仅本次运行保留；提供「恢复默认布局」 | 项目约束；异常时一键回正 | 持久化布局——被约束明确排除 |
| 关闭语义 | 关闭只结束显示，生成中先停止该轮；讨论仍在列表 | 项目约束 | 关闭即删除——被铁律排除 |
| 删除语义 | 独立动作，需确认，可撤销 | 关闭≠删除，防误删 | 关闭顺带删除，排除 |
| 置顶 | 独立置顶区，默认展开，排在最上 | 避开 ChatGPT「置顶混桶且默认折叠」的坑 | 置顶与普通混排，排除 |
| 列表时间 | 用**最后活动时间**，相对时间 + **天/周/月分组** | 修掉现状 #1；分组提升可扫读性 | 只显示绝对时间，可读性差 |
| 分组粒度 | 今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 更早（更早展开按月） | 用户要「天、周、月」三档；空分组不显示 | 只做今天/昨天/更早，太粗 |
| 条目分隔 | 条目之间一条极轻 1px 横线（`rgba(23,23,23,.1)`） | 用户要求「小横线不用太重」；不加重边框感 | 每行加边框/卡片，正是现状 #2 的毛病 |
| 列表操作 | 悬停才出现「重命名 / 置顶 / 删除」 | 减少常显噪音；但仍放在显眼的行尾 | 全部藏进 `⋯` 菜单——可发现性差，排除 |
| 图标 | 自建一套统一描边图标（inline SVG），弃用 emoji/字符 | 用户反馈「图标丑」；统一风格 | 用 emoji 或字体图标，排除 |
| 列表与当前讨论 | 列表覆盖停靠列，可一键收起回到窗口 | 不再「切换页面」，编辑区始终可见 | 整页替换，排除 |
| 入口规则 | 停靠区头「会话列表 / 新建对话 / 收起」**常驻**，永不按数量隐藏 | 修掉现状 #11 的「突然冒出」 | 维持按数量显隐，排除 |
| 批量清理 | 提供「批量管理」，标为复杂，可后置 | 旧讨论清理是真需求 | 不做清理，排除 |

## 4. 布局、尺寸与间距

### 4.1 停靠区（Dock）

```
┌─ 编辑区（主角，最重边框） ──────────────┬─ 停靠区 420px ────────────┐
│  工具栏 │            正文                │ 停靠区头 44px              │
│         │                               │ ┌─ 窗口 A ──────────────┐ │
│         │                               │ │ 标题栏 32px           │ │
│         │                               │ │ 内容（独立滚动）       │ │
│         │                               │ │ 输入区                │ │
│         │                               │ └───────────────────────┘ │
│         │                               │ 间距 8px                   │
│         │                               │ ┌─ 窗口 B ──────────────┐ │
│         │                               │ │ …                     │ │
└─────────┴───────────────────────────────┴───────────────────────────┘
```

| 元素 | 尺寸 | 说明 |
|------|------|------|
| 停靠区宽度 | 420px（沿用现值） | 窄窗口下变覆盖式抽屉 |
| 停靠区头 | 高 44px | 标题 + 窗口数 + 会话列表 / 新建对话 / ⋯ / 收起（四个入口常驻） |
| 停靠区提示区 | 高自适应 | 停靠区头下方的轻提示条：保存失败（提醒色）、删除撤销（成功色） |
| 窗口间距 | 8px | 窗口之间的呼吸 |
| 窗口最小高度 | 200px | 低于此值内容不可用 |
| 停靠区内边距 | 8px | 上下左右 |
| 窗口头 | 高 32px | 整条可拖 |
| 窗口内容内边距 | 12px | 与现面板一致 |
| 窗口圆角 | 4px（`--radius-md`） | 沿用 |

- 两个窗口时各占一半高度；三个以上时每窗保持最小高度，停靠区整体滚动。
- 停靠区头常显，即使只有一个窗口——它是「会话列表 / 新建对话 / ⋯ / 收起」的稳定入口。
- **停靠区 `⋯` 菜单**：收纳全局显示层动作——「停靠所有浮动窗口」「恢复默认布局」。它始终显示，与窗口头 `⋯` 用同一套图标。
- **停靠区提示区**：保存失败与删除撤销都显示在停靠区层（停靠区头下方），**不依赖列表是否打开**。停靠区收起时，在窄轨上显示一个小圆点标记（保存失败为提醒色、可撤销为成功色），展开后可见完整提示。

### 4.2 窗口（停靠态）

- 一讨论至多一个窗口。
- 窗口内容区独立滚动，输入区固定在窗口底部（沿用现有面板的滚动策略）。
- 窗口是讨论的**显示容器**；关闭窗口不删除讨论。

### 4.3 浮动窗口

| 属性 | 值 | 说明 |
|------|----|------|
| 默认尺寸 | 380 × 460 | 拖出时的初始大小 |
| 最小尺寸 | 300 × 200 | 小于此值不可用 |
| 定位 | 应用窗口内的绝对定位 | 不是系统级窗口 |
| 边界 | 拖动时限制在应用窗口内 | 不允许拖出应用 |
| 吸附阈值 | 8px | 靠近时吸附 |
| 层叠 | 点击置顶；「始终置顶」默认关闭 | 不遮挡写作区 |

## 5. 窗口头（标题栏）与动作规范

标题栏高 32px，整条可拖动，双击 = 停靠 / 浮动切换。

```
┌──────────────────────────────────────────────────────────────────────┐
│ ● 第三幕主角动机的追问   第三幕.md        [生成中] [停止] [⋯] [×]      │
└──────────────────────────────────────────────────────────────────────┘
  ↑状态点  ↑标题(省略号)   ↑关注文档        ↑次要动作菜单  ↑关闭
```

| 区域 | 内容 | 规则 |
|------|------|------|
| 左 | 状态点（8px 圆点） | 颜色对应状态，生成中 / 恢复中呼吸动画 |
| 左 | 讨论标题 | 单行省略号；超长 `text-overflow: ellipsis` |
| 左 | 关注文档名 | 小号弱化文字，无关注文档时不显示 |
| 右 | 状态徽标 | 仅非「已完成」时显示文字徽标 |
| 右 | 停止 | 仅**生成中 / 排队中**出现 |
| 右 | ⋯ 更多 | 常显；收纳重命名 / 置顶 / 浮动或停靠 / 并排对照 / 恢复默认布局 / 删除 |
| 右 | × 关闭 | 常显，最右 |

**动作优先级**：停止、更多、关闭常显在右侧；重命名、置顶、浮动/停靠、并排、恢复默认布局、删除收进 `⋯` 菜单。

**活动 / 非活动**：

- 活动窗口：主色边框（2px）+ 更重硬阴影 + 标题栏左侧 3px 主色竖条。
- 非活动窗口：弱化结构线（`rgba(23,23,23,.35)`）+ 1px 轻阴影 + 标题栏轻微降低对比。
- **刻意不整体降透明度**：写作工具里正文需要一直清晰可读，只弱化窗口头做区分。

## 6. 窗口状态呈现

| 状态 | 状态点 | 徽标 | 窗口头动作 | 内容区 | 输入区 |
|------|--------|------|-----------|--------|--------|
| 排队中 | 琥珀色常亮 | 「排队中」 | 停止、关闭 | 「排队中，前面还有 N 个请求，轮到会自动开始」 | 禁用 |
| 生成中 | 主色呼吸 | 「生成中」 | 停止、关闭 | 流式文字逐字追加 + 「正在思考…」 | 禁用 |
| 已停止 | 灰色 | 「已停止」 | 关闭 | 已完成内容保留 + 「已停止」分隔 + 「重试」 | 可用 |
| 失败 | 红色常亮 | 「失败」 | 关闭 | 中文错误说明 + 「重试」 | 可用 |
| 恢复中 | 主色呼吸 | 「恢复中」 | 关闭 | 重放中 + 「恢复对话中…」 | 禁用 |

- 状态同时出现在**窗口头**和**会话列表的状态点**，两处一致。
- **只有这五个统一状态词 + 「已完成」**；任何过渡文案（如「正在停止…」）只是内容区的一行文字，**不是第六种状态**，徽标始终用统一状态词。
- 排队**绝不显示成生成中**；用户停止后进入「已停止」而不是「失败」。
- **「重试」是一个动作一个名字**：已停止与失败都用「重试」，不另造「重新生成」。
- 失败可手动重试，不做自动重试风暴。

## 7. 浮动窗口交互（拖 / 缩 / 吸 / 回）

| 交互 | 做法 | 反馈 |
|------|------|------|
| 拖出停靠 | 按住窗口头拖离停靠区 | 停靠区出现虚线放置区；越过边界即转为浮动 |
| 移动 | 按住窗口头拖动 | 光标 `grabbing`；窗口实时跟随 |
| 缩放 | 拖右下角手柄（14px）；四边亦可 | 到最小尺寸 300×200 时停止 |
| 吸附对齐 | 靠近停靠区边缘 / 其他窗口边缘 / 应用边缘 8px 内自动吸附 | 出现对齐参考线 |
| 并排对照 | 显式动作：`⋯` →「与…并排对照」→ 选另一个已打开讨论 | 两窗等宽、顶边对齐（停靠区内上下分栏，浮动后左右并排） |
| 回停靠 | 拖回停靠区 **或** 双击标题栏 | 停靠区高亮放置区；松手归位 |
| 恢复默认布局 | 停靠区头 `⋯` 或窗口 `⋯` →「恢复默认布局」 | 所有窗口回到默认停靠、默认尺寸 |
| 边界 | 拖动限制在应用窗口内 | 到边界停住，不越界 |

- 拖动、缩放只改**本次运行**的位置和尺寸，不写档案、不持久化；重启回默认停靠。
- 「始终置顶」默认关闭，避免浮动窗口挡住写作区。

## 8. 会话列表重做方案

列表覆盖停靠列（宽 420px），可一键收起回到窗口；编辑区始终可见。

```
┌─ 讨论 ─────────────────────────── 新建对话  收起 ─┐
│ 🔍 筛选讨论…                                       │
│ ── 📌 置顶 ──────────────────────────────────────  │
│ ● 第三幕主角动机的追问                3 分钟前      │
│    第三幕 · 生成中                                 │
│ ───────────────────────────────────────────────   │  ← 1px 轻分隔线
│ ● 结尾两版处理哪个更收得住            昨天 21:05    │
│ ── 今天 ────────────────────────────────────────   │
│ ● 开场白节奏                          14:20        │
│ ───────────────────────────────────────────────   │
│ ● 关于结尾的两版处理                  11:02        │
│ ── 昨天 ────────────────────────────────────────   │
│ ● 林砚这个人物的前史…                 昨天 09:15    │
│ ── 本周 ────────────────────────────────────────   │
│ ● 门廊那场戏的空间关系                周一          │
│ ── 上周 ────────────────────────────────────────   │
│ ● 第一稿结尾的备选                    上周五        │
│ ── 上月 ────────────────────────────────────────   │
│ ● 第二幕转场的两种接法                8月28日       │
│ ── 更早 ────────────────────────────── 12 条 ⌄ ──  │
└───────────────────────────────────────────────────┘
```

### 8.1 分组（天 / 周 / 月三档）

顺序固定，**每个讨论只落入第一个命中的分组**；**空分组不显示**：

| 分组 | 含义 |
|------|------|
| 置顶 | 被置顶的讨论，独立分区、默认展开、永远在最上 |
| 今天 | 当天 00:00 起 |
| 昨天 | 昨天 00:00–24:00 |
| 本周 | 本周一至今，不含今天 / 昨天 |
| 上周 | 上周一至上周日 |
| 本月 | 本月 1 日至今，不含以上 |
| 上月 | 上一个自然月 |
| 更早 | 再往前；**展开后按自然月分节**（2026 年 7 月、2026 年 6 月…） |

- 不用「只显示最近 5 条 + 查看更多」这种把列表截断的坑；「更早」折叠只折叠、可展开。
- 优先级顺序保证同一条不会重复出现在两个分组。

### 8.2 条目分隔与行结构（紧凑）

- **条目之间**：一条极轻的 1px 横线（`--hairline: 1px solid rgba(23,23,23,.1)`），不加重边框感；分组标题本身就是更强的分隔，分组首行不加线。

| 元素 | 规范 |
|------|------|
| 行高 | 基础 44px；标题一行时 40px，两行时最多 56px |
| 状态点 | 8px 圆点，行首 |
| 标题 | 最大 2 行，超出省略号（中文断行友好，`line-clamp: 2`） |
| 第二行 | 关注文档名 · 状态词（小号弱化） |
| 时间 | 右对齐，相对时间 |
| 当前讨论 | 行左侧 3px 主色竖条 + 浅底 |

### 8.3 操作（悬停出现）

- 悬停行尾出现三个图标按钮：**重命名 / 置顶 / 删除**（统一描边图标，非 emoji）。
- 键盘与触屏也能到：`⋯` 或右键菜单提供同样动作，保证可发现。
- **删除**：先弹一句确认 → 删除后**在停靠区层**出现「已删除「标题」· 撤销」提示（约 6 秒），不依赖列表是否打开。
- 删除与撤销的语义：删除**立即**从列表与档案移除；前端内存保留一份副本；提示期内「撤销」= 用副本**重新写入档案**并恢复列表条目；**提示期结束或应用退出后不可恢复**。撤销**不自动重开窗口**（避免突兀），用户需要时从列表点开。
- 重命名：点标题或铅笔 → 就地变输入框，回车保存、Esc 取消。

### 8.4 置顶

- 置顶条目独立分区，永远排最上，默认展开。
- 置顶是**列表组织偏好**，建议存进讨论档案（新增 `pinned` 字段），重启后保留。

### 8.5 相对时间规则

| 距今 | 显示 |
|------|------|
| < 1 分钟 | 刚刚 |
| < 60 分钟 | N 分钟前 |
| 今天 | HH:MM |
| 昨天 | 昨天 HH:MM |
| 本周 | 周X（周一…周日） |
| 上周 | 上周X |
| 本月 | M月D日 |
| 上月 / 更早 | M月D日 / YYYY年M月D日 |

### 8.6 搜索与清理

- 顶部筛选框：按**标题 + 关注文档名**过滤（客户端即时过滤，简单）。
- **过滤时保留天/周/月分组结构**：只显示命中的条目；某分组无命中则不显示该分组标题；置顶区同样保留；全部无命中时显示「无匹配结果」空态。过滤后仍是分组列表，不是一条平铺结果流。
- 「批量管理」：进入多选，底部条显示「已选 N 项 / 删除」。标为复杂，可后置；先用「逐条删除 + 撤销」兜底。
- **列表收起时的处置**：删除确认**取消**；撤销提示**保留**（它在停靠区层，不随列表收起消失，仍可撤销）。切换作品时：重命名与删除确认**取消**，撤销项**清空**。

### 8.7 空状态

> 「还没有讨论。在正文里选中一段，点旁边的『AI』，或者直接在面板提问，就会开始第一个讨论。」

空状态用统一的对话气泡图标（描边），不用 emoji。

### 8.8 中文细节

- 标题用 2 行省略，避免把中文长句硬切成单行截断。
- 时间用相对时间 + 天/周/月分组，比 `MM-DD HH:MM` 更容易扫。
- 状态词统一：已完成 / 生成中 / 排队中 / 已停止 / 失败 / 恢复中；不再出现「状态未知」。
- 行内动作文字用中文（重命名 / 置顶 / 删除），不用图标替代所有含义（图标 + `title` 提示并存）。

## 9. 图标系统

用户反馈列表图标「有点丑」。改为**自建一套统一描边图标**，内联 SVG（无外部依赖、不随系统字体变化）。

### 9.1 规范

| 项 | 规范 |
|----|------|
| 网格 | 16 × 16 viewBox |
| 描边 | 1.5px |
| 线帽 / 连接 | 方角（square / miter），呼应新粗野主义的硬边 |
| 颜色 | `currentColor`（跟随按钮文字色，选中/禁用自动一致） |

| 命中区 | 按钮最小 24×24；停靠区头按钮 28×28 |

### 9.2 图标清单

| 右 / 左 / 下箭头 | 收起 / 展开 / 折叠 | 垃圾桶 | 删除 |

## 10. 交互状态与冲突规则

详见 **`interaction-rules.md`**（**88 条规则 + 4 张按钮状态表**）。要点：

- **拖动/缩放同规则**：除三点差异（吸附只用于拖动、拖动才改停靠/浮动、拖动才能拖出/拖回）外完全一致。
- **拖动/缩放进行中**：生成完成、失败、排队开始、停止、他窗关闭、驱动恢复、新讨论插入——**都不打断手势**，只更新内容与徽标；只有「关闭自己、收起停靠区、切换作品、删除自己、恢复默认布局」会**中断**手势。
- **操作套操作**：关闭与停止串行、重开不自动重发、重命名中冻结排序、删除确认不被其他事件关闭、撤销只保留最近一条且**不自动重开窗口**、并排是瞬时布局、队列请求可停止/关闭、恢复期间禁用发送。
- **切换作品 / 列表收起**：切换作品时取消重命名与删除确认、清空撤销项；列表收起时取消删除确认，但**撤销提示保留**（在停靠区层）。
- **按钮不打架**：停止/重试是条件**显示**（不是禁用）；发送/输入框忙碌时**禁用**；`⋯` 与 `×` 常显；「与…并排对照」少于两个打开讨论时**禁用**；行操作点击不打开讨论。
- **入口常驻**：停靠区头四个入口（含 `⋯`）永不按讨论数量隐藏。
- **提示在停靠区层**：保存失败与删除撤销都显示在停靠区，不依赖列表是否打开。
- **过滤保留分组**：搜索时仍按天/周/月分组显示。

## 12. 交互复杂度与落地建议

| 功能 | 复杂度 | 说明 / 轻量替代 |
|------|--------|----------------|
| 停靠区多窗口纵向堆叠 + 滚动 | 简单 | flex column + `overflow: auto` |
| 停靠区收起 / 展开（不停止生成） | 简单 | 仅切换显示 |
| 窗口头（标题 / 关注文档 / 状态 / 动作） | 简单 | 纯 DOM + CSS |
| 状态徽标与状态点（含恢复中） | 简单 | 状态类名切换 |
| 图标系统（inline SVG sprite） | 简单 | 一份 `<symbol>` 表 + `<use>` 引用 |
| 列表条目间轻分隔线 | 简单 | `.row + .row { border-top: var(--hairline) }` |
| 列表天/周/月分组 + 相对时间 | 简单 | 纯派生函数 |
| 停止生成按钮接线 | 中等 | 接线已有 `ai_cancel_message`；需区分「用户停止」与「超时」 |
| 浮动窗口拖动 | 中等 | Pointer Events + `transform` |
| 浮动窗口缩放（含最小尺寸） | 中等 | Pointer Events + 尺寸钳制 |
| 吸附对齐 | 复杂 | **轻量替代**：只吸附应用边缘 + 停靠区边缘 + 对齐其他窗口顶/左边 |
| 拖回停靠（放置区判定） | 中等 | 命中测试 + 高亮 |
| 并排对照 | 中等 | 布局计算；停靠内上下、浮动后左右 |
| 恢复默认布局 | 简单 | 重置窗口几何 |
| 状态点 / 悬停操作 | 简单 | CSS `:hover` + `:focus-within` |
| 重命名 | 中等 | 需后端加标题字段或重命名命令 |
| 置顶 | 中等 | 需持久化（建议档案加 `pinned`） |
| 删除确认 + 撤销 | 中等 | 撤销需内存保留记录并重新保存 |
| 搜索筛选 | 简单 | 客户端过滤 |
| 批量清理 | 复杂 | **轻量替代**：逐条删除 + 撤销 |
| 入口常驻（不再按数量显隐） | 简单 | 去掉 `hidden` 切换即可 |
| 停靠区头 `⋯` 菜单（全局动作） | 简单 | 一个常驻按钮 + 菜单（复用窗口头菜单样式） |
| 停靠区提示区（保存失败 / 撤销） | 简单 | 停靠区头下方一条轻提示条，与列表是否打开无关 |
| 空状态 | 简单 | 静态文案 + 图标 |

**后端依赖提示**（需在实现时一并考虑）：
1. 列表改用 `updated_at` 做时间与排序——档案已有该字段，前端即可改。
2. 重命名——需要能保存自定义标题的字段或命令。
3. 置顶——需要能持久化置顶状态。

## 14. 与项目铁律的对照

- 窗口内只有**纯文本**展示，没有「应用到正文」「插入文档」等任何入口。
- 讨论档案与作品正文分开存放；AI 输出始终是临时材料。
- 关闭窗口不删除讨论；删除是独立动作且可撤销。
- 判断权、内容权、方向权仍在用户手里：界面只提供观察与操作入口，不替用户决定。
