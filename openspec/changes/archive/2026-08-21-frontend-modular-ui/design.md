## Context

内容树存储（`content-tree-storage`）与命令层（`content-tree-commands`）已完成：后端可读取整棵树、按文档 ID 读写正文、执行创建/重命名/移动/排序/删除进回收站/恢复，全部事务化。但前端仍是旧的固定双槽位编辑器——`open_project` 返回 `draft_content`/`main_content` 两篇，`save_project` 存这两篇，`editor.ts` 用两个固定 textarea + 两个 `EditorAdapter` 来回切 tab。前端看不到内容树，也无法管理作品组织。

本 change 拆除这个双槽位过渡，把前端重构成三模块，并让后端配合「新建一篇」与「打开返回整棵树」。

约束：Rust/Tauri 是作品事实唯一写入者；AI 永不写用户文档；单篇文档 Tiptap 格式（版本 2）不变；「作品 / project」「文件管理 / content_tree」两层命名规则沿用。

## Goals / Non-Goals

**Goals:**
- 前端三模块导航（写作 / 文件管理 / 设置），打开作品默认落在写作页。
- 写作页从「双固定 tab」改为「当前文档」单编辑器，顶部显示当前文档名并可极简切换。
- 文件管理页：文件树展示 + 全部结构操作 + 回收站二级页。
- 设置页收纳现有 LLM 配置。
- 后端：新建作品默认一篇文档；打开作品返回整棵树（不再硬性要求「草稿本」「正文本」）；移除旧双槽位命令与过渡 requirement。
- 记住每个作品上次编辑的文档，重新打开回到那篇。

**Non-Goals:**
- 不在写作页塞文件树（方案甲已定：文件树只在文件管理页）。
- 不做拖拽排序的具体交互（排序命令已存在，界面交互另行评估，首版以简单方式表达）。
- 不做回收站永久清空（后端无此能力，本 change 只做恢复）。
- 不改单篇文档 Tiptap 格式，不改迁移框架，不改 AI 面板逻辑。
- 不实现「文档被删除后记忆自动迁移」之外的复杂多设备同步（记忆仅 localStorage 本地）。

## Decisions

### D1：打开作品返回整棵树，正文按需读

后端把 `open_project` 的返回从 `ProjectOpenResult { metadata, draft_content, main_content }` 改为 `{ metadata, tree }`（`tree` 为 `ContentTree`）。打开时仍保留全量校验：所有被引用文档正文（含回收站内）必须合法，否则拒绝打开。前端拿到树后确定当前文档 ID，再用已有 `read_document` 按需读正文。

**备选**：打开时一并返回当前文档正文。**否决**：把「当前文档选择」耦合进后端，破坏「选择是前端偏好」的边界；且正文按需读复用已有命令，职责更清晰。

### D2：新建作品默认一篇文档，默认名「未命名文档」

`create_project` 从创建「草稿本」「正文本」两篇改为创建一篇文档，默认名复用 `content_tree` 的 `create_document` 默认名「未命名文档」，无特殊逻辑。旧作品的 `2 → 3` 迁移逻辑保持不变（迁移出的「草稿本」「正文本」仍是两篇普通文档，那是历史事实，不动）。

**备选**：新作品仍建两篇但改名。**否决**：违背「新建 = 一张白纸开始写」的直觉，且「草稿本/正文本」是已被撤除的旧概念，不应再注入新作品。

### D3：当前文档确定 + 上次编辑记忆（localStorage）

前端用 localStorage 记录每个作品的「上次编辑文档 ID」，键按作品路径区分。打开作品流程：

1. `open_project` 拿树；
2. 读记忆的 documentId，若该 ID 仍在树中（不在回收站）则选中它；
3. 否则回退到树中第一篇文档（按 `root_children` 顺序找到的第一个 `Document`）；
4. 无任何文档时显示空态（写作页不可写，提示去文件管理新建）。

每次切换文档时更新记忆；记忆指向的文档已被删除时回退并清除失效记忆。

### D4：写作页切换入口形态（极简扁平列表）

写作页顶部显示当前文档名，做成可点入口，点开一个扁平文档列表（树中所有文档，扁平列出名称，不展示文件夹层级），点选即切换。不引入树形结构到写作页，保持轻量。

### D5：模块导航结构

编辑器页内部拆成三个模块视图：写作 / 文件管理 / 设置。顶部标签式导航（方案 A）。LLM 配置从独立 page 改为设置模块内的一个区域。`views.ts` 的页面模型相应调整：欢迎页、新建作品页保持独立，编辑器页承载三模块。

### D6：回收站是文件管理页的二级页

文件管理页内，文件树底部一行「回收站」入口，点击切换到回收站二级视图（列出被删子树 + 恢复操作）。回收站不混入主文件树。

### D7：保存策略 —— 切换文档时自动保存当前文档

多文档下，「未保存」状态只属于当前正在编辑的文档。切换文档前静默保存当前文档（复用 `save_document`），切换后进入新文档。手动「保存」按钮保留，仍保存当前文档。离开/关闭时的 guard 逻辑只 guard 当前文档。

**备选**：切换时提示是否保存。**否决**：打断创作，与写作软件「随手切换」的惯例相悖，增加学习成本。

### D8：移除旧双槽位命令

移除 `open_project` / `save_project` 命令、前端旧 `openProject`/`saveProject` 封装，以及 `desktop-project-lifecycle` 中「前端最小适配仍返回/保存两篇迁移文档（过渡边界）」requirement。前端编辑器从「两编辑器切换」改为「单编辑器 + 按文档 ID 加载/保存」。

## Risks / Trade-offs

- [editor.ts 从双编辑器改单编辑器是本次最大改动面] → 分步推进：先接通打开返回树 + 按 ID 读写，再引入模块导航，最后加文件管理页；每步保持可运行。
- [切换文档自动保存可能引入保存失败静默丢失] → 保存失败时阻止切换并显示错误，不静默丢弃；与现有 `EditorSaveState` 的失败标记机制衔接。
- [记忆失效（文档被删）需回退] → D3 已定回退到第一篇；记忆存储为轻量偏好，丢失只影响「回到哪篇」，不影响作品数据。
- [移除双槽位命令是 BREAKING] → 前后端同 change 内一起改，不留中间断裂态；旧作品迁移产物「草稿本」「正文本」作为普通文档仍能正常读写。
- [新建作品只有一篇，但旧 UI 假设两篇] → 本 change 前端同步改为按树渲染，不残留对「草稿本/正文本」名字的依赖。

## Migration Plan

- 无数据迁移、无磁盘格式变化、作品结构版本仍为 `3`。
- 旧作品（含迁移出的「草稿本」「正文本」两篇）打开后按内容树正常显示，用户可自由改名/删除。
- 回滚策略：本 change 前后端耦合，回滚需整体回退到上一个 change 归档后的提交点；无部分回滚。

## Open Questions

- 文件管理页「移动」「排序」的首版交互形态（下拉菜单移动 vs 拖拽；排序是否首版提供界面）——首版以最简实现（菜单式移动、暂不提供排序界面，排序命令保留待用），如需要更丰富的交互再评估。
- 切换文档时若保存失败，是「阻止切换」还是「允许放弃当前修改」——首版选择「阻止切换并提示」，避免静默丢字。
