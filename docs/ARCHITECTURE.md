# 架构：AI 陪想本地内容的安全边界

本文档回答「这是什么、框架能做什么、基础功能有哪些」。怎么构建、检查、打包、发布见 [DEVELOPMENT.md](DEVELOPMENT.md)。文中每条能力都标注了对应的正式规格（`openspec/specs/`），那里是行为真相源。

## 一个普遍问题

所有「AI + 本地文件」的应用都撞同一堵墙：**怎么让模型看得见你的内容，又不给它任何写权限？** 放任不管，模型迟早替用户改稿；一刀切断，AI 就帮不上忙。

Next Story 是这题的一套已全部落地、有规格背书的参考答案。它目前以剧本创作软件的形态存在，但边界设计本身不绑定剧本——任何「AI 陪想本地内容」的桌面应用（笔记、文档库、任意文件夹）都面对同一个问题。

## 保管者 / 使用者分离

```
┌────────────────────────────────┐
│ 保管者：Rust / Tauri 后端        │ 内容树 · 文档保存 · 格式校验
 │ （唯一能写文件的一方）           │ 版本迁移 · 事务一致性 · 崩溃恢复
 └──────────────┬─────────────────┘
                │ 受控只读接口
                │  · 目录投影（允许的目录结构）
                │  · 正文读取（已保存正文 / 经校验的未保存快照）
                │  · 跨文档字面检索（NFKC 规范化，输出硬上限：
                │    8 候选词 / 5 文档 / 10 片段 / 命中前后各 120 字符）
                │  · 文档级 AI 可见性 · 隐藏/回收站/越权一律拒绝
                ▼
 ┌────────────────────────────────┐
 │ 使用者：DSH 驱动进程（sidecar）   │ AI 推理 · 常驻会话 · 流式回复
 │ （拿不到任何写文件的能力）         │ 授权补读：模型请求多读几篇，
 │  AI 输出永远只落在用户文档之外     │ 用户允许才读，随时可关
 └────────────────────────────────┘
```

- **Rust / Tauri 后端是项目数据的可靠保管者**：内容树、文档保存、格式校验、版本迁移、事务一致性和崩溃恢复等确定性工作。
- **DSH 是项目内容的智能使用者**：AI 推理、思考回应和陪想能力。AI 需要参考项目时，只能通过受控只读接口取得被允许提供的内容。
- **项目数据与 AI 路径隔离**：项目服务不注册为 AI 可调用的写文件工具。任何 AI 输出都只能留在用户文档之外，用户亲手复制、编辑并保存后才成为项目内容。

## 基础能力清单（六组）

### 1. 内容保管

- 「项目」即文件夹：新建、打开、最近项目；内容树只有文件夹与文档两种节点，可创建、重命名、移动、排序；删除进回收站，可恢复。
- 文档手动保存：结构化正文按稳定文档 ID 落盘；切换文档前先保存当前文档，保存失败保留内容并提示、不切换。
- 格式校验与版本迁移：打开项目时校验结构与格式版本，旧版本自动迁移；事务一致性与崩溃恢复由后端兜底。
- 规格依据：`desktop-project-lifecycle`、`content-tree-commands`、`content-tree-storage`、`structured-notebook-storage`、`shared-document-models`、`project-reliability-boundaries`

### 2. 受控只读接口

AI 取材只有三条只读通道，全部由后端裁决：
- **目录投影**：允许查看的目录结构，不含隐藏与回收站内容。
- **正文读取**：已保存正文，或经校验的未保存快照（用户正在写、尚未保存的内容也能安全地问）。
- **跨文档字面检索**：NFKC 规范化后的确定性字面匹配（非语义/向量检索），输出有硬上限：8 候选词 / 5 文档 / 10 片段 / 命中前后各 120 字符——这是检索输出上限，不是模型上下文上限。
- 规格依据：`controlled-story-read-visibility`、`automatic-story-context`

### 3. 可见性与授权

- **文档级 AI 可见性**：每篇文档可单独设置是否允许 AI 查看；隐藏、回收站与越权读取被统一边界拒绝。
- **材料权限变化隔离**：使用过后来被隐藏材料的讨论永久只读，旧出处脱敏显示。
- **授权补读**：材料不足时模型经授权请求发起「想多读几篇」；用户允许后它围绕问题自主调用只读工具（`story-list` / `story-read` / `story-search`）。授权属于当前讨论：允许 / 拒绝 / 随时关闭、跨重启保留；等待授权期间轮次挂起、不产生模型请求。非关注文档只读已保存正文，轮内版本固定、同轮去重；连续读取失控时有保险丝熔断（非配额）。
- 规格依据：`controlled-story-read-visibility`、`agent-on-demand-reading`

### 4. 常驻会话可靠性

- 常驻 AI 会话：两种首轮入口（面板直接提问、选区「AI 及时召唤」冻结选区发起）；回复流式逐字呈现；首轮成功后线性追问，只发送增量问题。
- 可取消、可停止生成：停止只结束对应讨论，已完成内容保留、不产生成功轮次。
- 多讨论并存：同一项目下多个讨论并发生成，按全局同时生成上限先到先服务排队；讨论级隔离——已删除或已离开讨论的迟到结果被丢弃。
- 长对话由框架自动压缩承接；超限明确报错提示新建讨论，绝不静默砍历史。
- 生成停滞有界：非用户驱动的等待连续 180 秒无协议事件即判停滞，中文报错、可重试、并发名额释放；等待用户授权的挂起轮次豁免、不设时限。
- 崩溃恢复：驱动进程意外退出后自动重启，重放显示历史恢复所有在途讨论的业务状态。
- 规格依据：`resident-ai-session`、`ai-request-scheduling`、`conversation-management`、`conversation-persistence`、`conversation-list`、`discussion-windows`、`persistent-ai-panel-entry`、`dsh-sidecar-lifecycle`

### 5. 材料可追溯

- 「本次参考了什么」轻量可查看：常规讨论自动附带的现场材料、目录投影、检索片段与按需补读的文档出处（文档 / 版本 / 阅读程度）都记录在案。
- 材料出处持久化，随讨论档案保存；`message_sent` 发送回执折算为轮级确认，无回执不伪造。
- 规格依据：`automatic-story-context`、`agent-on-demand-reading`

### 6. 隔离边界

- **AI 永远不写用户文档**：不插入、不追加、不替换、不改写、不删除、不移动、不整理；界面上也没有「应用到正文」入口。AI 输出永远是临时材料，用户亲手复制、粘贴、编辑、保存后才进入作品。
- **项目服务不注册为 AI 可调用的写文件工具**：写路径在架构上不存在，不是靠提示词约束。
- **日常与制作相互隔离**：制作模块（链路库、制作对话、试问）与日常 AI 讨论在会话和上下文上相互隔离；日常聊天不能修改链路配置。
- 规格依据：`ai-module-boundaries`、`ai-feature-orchestration`、`making-conversation`、`tauri-security-baseline`、`project-mission-governance`

## 不是什么（诚实边界）

- 这不是可安装的框架或库：能力嵌在本应用内，他人可以阅读代码、借鉴模式，但许可是保留所有权利（详见仓库 [LICENSE](../LICENSE)），未经书面许可不得复用、修改、再分发。
- 以下方向未实现且已明确撤出当前项目范围（不是待办）：附近上下文（光标周边取材）、全文摘要、语义 / 向量检索、完整作品认知、后台预加载、记忆、Agent 循环、AI 内容库、思考收束、安全返回写作。
- 作品正文没有自动保存、自动备份或版本快照（讨论档案由应用自动保存，与正文不同）；整个应用只有一份 API 配置。
