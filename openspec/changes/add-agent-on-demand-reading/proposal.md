# 按需补读（阶段 6 / B：Agent 按需补读）

## Why

「让 AI 看见作品」A 部分（系统自动附带材料）已于 2026-09-14 交付：常规讨论自动携带关注文档现场、目录投影与跨文档字面检索片段。但材料不足时模型只能凑合回答——生产 DSH 驱动只有文本生成协议，阶段 1 离线验证过的只读作品工具未接入生产，`resident-ai-session` 正式规格也明确禁止任何工具类插件。阶段 6（2026-09-14 全量地基审计修复队列第 7 项）让模型经用户按讨论授权后，通过受控只读工具围绕问题自主搜索与阅读作品；这是「让 AI 看见作品」计划最后一个开发阶段，之后进入阶段 7 联合产品验收。

## What Changes

- **新增「按需补读」讨论级授权**：AI 先使用既有自动材料；确实不足时说明原因与权限边界（仅本讨论、只读、后续不重复询问、可随时关闭、不修改作品），请求开启本讨论的按需补读。允许后自动继续原问题；本讨论内不再重复询问（换话题、切换关注文档、关窗、重启均不重问、不失效）；其他讨论不继承。用户可随时关闭：立即阻止后续读取，不伪称撤回已送达材料，不清除已读内容。拒绝后当前问题内不再追问，基于现有材料有限回答并明示不确定；新问题确有需要可再请求；用户也可主动开启。
- **Agent 自主阅读**：授权后 Agent 自行决定搜索、局部或完整阅读，不设「最多几篇」的产品上限，不逐次询问；过程以轻量状态显示、可展开详情。
- **读取约束**：非关注文档只读已保存版本（本阶段不建多文档未保存快照）；一轮内版本固定，读到一半文档保存出新版则本轮停在旧版、下一轮读新版；同轮内同版本同范围内容不重复装入（去重）；单篇不可读（隐藏/回收站/删除/权限变化）跳过并继续；失控保险丝按后台时间与调用阈值熔断——仅防异常循环（模型反复搜索读取迟迟不回答），非阅读配额，触发后基于已有材料回答并说明补读未完整完成，阈值由技术验证确定。
- **参考记录与可见性联动**：「本次参考了什么」记录文档与阅读程度（搜索片段/局部/完整）；使用过后来被隐藏文档的讨论沿用既有永久只读与脱敏规则；关闭文档 AI 可见性前提示受影响讨论。
- **及时召唤边界不变**：首轮仍只看冻结选区（快车道），不请求授权、不补读；其后续追问按普通讨论规则。
- **等待授权期间退出的处理**：等待用户授权期间退出应用，该轮按既有「中断轮」语义处理（与生成中退出一致）：重开后显示为中断、不自动重发、可重试；用户经讨论内授权开关开启后重新发送或重试即可。不新增跨重启待决状态，不改变既有调度规则。
- **后端编排模块拆分（审计 P2-1）**：动工 `src-tauri` 前从 `lib.rs` 提取 `ai_host` / `ai_orchestration` 编排模块（AI 会话与驱动生命周期、请求装配与调度接线），纯移动不改行为，不重构作品领域层。
- **生产工具链路**（审计队列 7 必含项）：
  - 生产驱动接入受控只读工具调用协议，`capability_gateway` 从声明变为真实 ToolCall 授权与宿主执行器，配失败关闭测试（P2-10）。
  - 统一 Agent 工具面命名：`story-list` / `story-read` / `story-search` 三个只读工具，授权请求经专用控制工具 `story-request-reading`（不携带作品数据）；`story-snapshot` 保留给系统自动取材路径，不进入 Agent 工具面（P2-6、P2-7）。
  - 驱动协议单一真相源：生产与验证替身共用同一协议定义，验证对齐生产已有的 `message_sent` 等事件（P2-5）。
  - `max_tokens` 可按端点配置，由配置经宿主传入驱动（P2-8）。
  - 禁用能力清单单一真相源，两端配置与测试由同一清单生成（P2-9）。
  - `resident-ai-session` 安全边界规格改为「仅允许受控只读作品工具，仍禁止通用文件/命令/网络/写入/子代理」（P1-9）。
- **明确不做**：语义/向量检索、多文档未保存快照读取、跨重启待决授权恢复（等待中退出按既有中断轮处理）、任何写入口、及时召唤首轮取材、AI 修改作品的任何形式。

## Capabilities

### New Capabilities

- `agent-on-demand-reading`: 按需补读——讨论级授权模型（请求/允许/拒绝/关闭/跨重启持久化）、Agent 自主阅读行为（已保存版本、轮内版本固定、同轮去重、跳过不可读、无产品配额）、失控保险丝、阅读程度参考记录、及时召唤边界、等待中退出按中断轮处理、零写回。

### Modified Capabilities

- `resident-ai-session`: 安全边界从「禁止任何工具类插件」改为「仅允许受控只读作品工具，仍禁止通用文件/命令/网络/写入/子代理」；驱动协议新增工具调用通道、授权等待与取消语义（P1-9、P2-5、P2-10）。
- `controlled-story-read-visibility`: 统一后端授权与严格只读路径明确覆盖 Agent 按需补读工具读取；关闭文档 AI 可见性前提示受影响讨论。
- `automatic-story-context`: 明确 A（自动附带材料）与 B（按需补读）边界：A 部分行为不变；及时召唤追问不自动附带 A 部分材料，但经授权可使用 B 部分工具。
- `conversation-persistence`: 讨论档案记录按需补读权限状态与补读读取出处（文档、版本、阅读程度）。

## Impact

- `sidecar/driver/driver.mjs`：工具调用协议接入（Agent 工具注册、工具调用桥接到宿主、授权等待、熔断计数）。
- `sidecar/driver/`：协议单一真相源模块（生产驱动与验证替身共用，P2-5）；`adapter.mjs` 对齐生产协议。
- `sidecar/driver/gen-config.mjs` 与 `src-tauri/src/capability_gateway.rs`：禁用清单单一真相源（P2-9）；网关补真实协议、宿主执行器与失败关闭测试（P2-10）。
- `src-tauri/src/lib.rs`：按审计 P2-1 先行拆出 `ai_host` / `ai_orchestration` 编排模块（纯移动，不改行为）。
- `src-tauri/src/`：工具执行器只注入窄化 `StrictStoryReader`（含 `story_search` 复用为 Agent 可调用工具，P2-7）；轮内版本固定与同轮去重；读取出处与权限状态写入 `conversation_store.rs`；`dsh_driver.rs` / `generate.rs` 增加 `max_tokens` 传递（P2-8）。
- 前端：授权提示（原因 + 权限边界）、讨论内权限开关（明示不清除已读内容）、轻量过程状态与可展开详情、「本次参考了什么」扩展阅读程度、关闭可见性前的影响提示。
- 验证：离线驱动回归对齐生产工具协议；真实链路驱动级回归纳入工具循环与授权流程；失败关闭测试（隐藏/回收站/越权/待恢复事务下工具读取全部拒绝且零副作用）。
