# 第一版方向共识（2026-07-01）

> 本文档记录第一版的方向共识，并区分当前实现、已确认产品方向和尚未讨论事项。
> 它不是实现计划，也不是最终规格。任何实现仍须单独提出 OpenSpec change 并由用户确认。
> 产品不可轻易改变的核心方向见 `方向/核心方向宪章.md`。本文不得与核心方向宪章冲突。
> 旧项目材料位于 `反面案例/`，仅作教训与反例参考，不作本项目规范。

## 0. 一句话定位

第一版是一个**辅助剧本创作的陪想软件**：用户在**写作空间**里亲手创作，**常驻 AI 面板**像一个随时可对话的聊天窗口与写作区并列存在、可收起；用户直接提问，AI 陪想，帮助用户重新看见故事，但永远不直接改动用户文本。

更短地说：

> 用户写作，AI 陪想。写作空间让人愿意继续写，常驻 AI 面板在卡住时打开问题和可能性，创作者判断、选择并亲手完成。

长期使命是"把认真讲述自己故事的权利，交给每一个想创作的人"。完整理由、知识原则和永久权力关系只由 [`方向/核心方向宪章.md`](核心方向宪章.md) 定义，本文只把它转成第一版取舍。

## 1. 第一版目标

- **只解决一件事：在写作现场降低起步与求助门槛。** 用户想不出来或需要另一个视角时，工具提供有依据的问题和可能性，帮助用户重新看见故事。
- **写作空间先立住。** 第一版不仅要证明 AI 能陪用户想，还要证明用户愿意待在这个编辑器里持续写：打字、阅读、定位、保存、重开，不被打断。
- **常驻 AI 面板 / 直接提问的产品体验是第一版优先验证的核心。** 用户不先配置上下文、不先选中文字，打开面板直接提问，获得有依据的回应；面板与写作区并列、可收起。这条体验是否成立，是第一版首先要验证的问题。常驻 Agent 的完整后台能力（后台预加载、检索、摘要、记忆、Agent 循环等）**当前未实现，也不必然进入第一版**，须单独拆分并逐个 OpenSpec change 确认，不得因"面板已常驻"就假定这些能力已经存在。

## 2. 当前主链路

第一版验证的主链路：

```text
用户写作
  -> 需要另一个视角或遇到卡点
  -> 在常驻 AI 面板直接提问（选区可选地作"请重点看这里"）
  -> 陪想 Agent 自动理解作品、准备上下文并回应
  -> 获得有依据的观察、问题和可能性
  -> 用户判断、选择，回到写作，亲手完成
```

任何功能如果让这条链路变重、变乱、变不可信，就要暂停。

## 3. 常驻 AI 面板与直接提问方向

- **常驻 AI 面板**与写作区并列存在，可收起；收起后写作区恢复主要可用空间。
- 用户**直接提问**，不需要先配置上下文，也不需要先选中文字。
- 面板像一个随时可对话的聊天窗口；AI 回应永远只在面板里显示。
- **上下文说明轻量可查看**：默认不打断对话；必要时用户可以查看这次大致参考了什么。
- AI 输出是**临时材料**：用户自己复制、粘贴、编辑、保存后才进入作品。
- AI 只提供观察、问题、假设和可能性：不替用户判断，不把假设当作品事实，不直接改用户文档。

第一版应优先验证常驻面板 / 直接提问的产品体验是否成立。具体后台能力（Agent 如何准备上下文、需要哪些已保存内容、未保存内容如何处理）的范围若未足够明确，写成**待 OpenSpec 确认**，不预先承诺。

## 4. 内容树的第一版定位

内容树由**文件夹**（只负责组织，可含子文件夹和文档）和**文档**（只负责写作，不含子节点）组成。

- 内容树是帮助 Agent 理解作品的**后台基础设施**，不是给用户增加的操作负担。
- 用户**不必掌握内容树**，也不必配置任何 AI 参考优先级。
- 旧「四级 AI 参考优先级」（核心 / 一般 / 弱 / 不参考）及继承、覆盖等设计**已从用户概念中移除**，不进入第一版，也不写成已确认方向；未来 Agent 如何选择上下文是未定的内部方案。
- 内容树的数据存储、旧作品迁移等确定性工作由 Rust/Tauri 后端承担（见 `openspec/changes/establish-content-tree-storage`），但内容树的存在是为了作品本身和未来的陪想能力，不是为了让用户管理配置。

## 5. 选区角色

选区保留为**可选的重点提示**："请重点看这里"。

- 它不是 AI 使用前提，也不是入口。
- 有选区时，Agent 把选区当作重点提示优先考虑。
- 无选区时，用户直接提问，Agent 根据对作品的自动理解回应。
- 当前选区触发的 `AI 及时召唤`、`思维扩展` 是旧形态的过渡工具，不再是长期产品形态。

## 6. 当前实现与未来目标的区别（诚实边界）

当前代码里**已经真实存在、但不再是长期产品形态**的旧能力：

- 从**选区**触发的两个临时 AI 工具：`AI 及时召唤`（无文字输入，冻结选区后立即请求）与 `思维扩展`（可填写一个可选方向）。
- 首次回应成功后的**单条线性临时追问**，锚定原冻结选区。
- 非流式回复。
- 临时对话只在本次应用打开周期内存在，切换作品或关闭应用后清空。

完整行为以 `openspec/specs/`（尤其 `selection-ai-invocation`、`ai-thinking-panel`、`summon-ai-follow-up`、`ai-feature-orchestration`）为准。这些旧工具是过渡形态：产品方向是常驻 AI 面板 + 直接提问，选区只是可选重点提示。

当前**没有**常驻面板直接提问、Agent 自动上下文、后台预加载、检索、摘要、记忆、Agent 循环、多对话或历史列表、持久化会话、附近上下文、AI 内容库或用户确认的作品信息——这些都不是当前能力，不能写成已实现。

**目标方向**（长期，不是第一版已交付）：

```text
写作空间 + 常驻 AI 面板
用户直接提问（不需要先配置上下文，不需要先选中文字）
陪想 Agent 自动理解作品、准备上下文并回应
上下文说明轻量可查看：默认不打断对话，必要时可查看大致参考了什么
```

Agent 未来可以利用内容树、当前文档、当前写作位置、必要的已保存作品内容和允许参与本次思考的当前未保存内容。后台预加载、检索、摘要、记忆和 Agent 循环机制都是**未来方向**，当前未实现，须逐个 OpenSpec change 定义。

## 7. 明确不做（Non-Goals）

1. **AI 自动改用户文档。** 不插入、不追加、不替换、不改写、不删除、不移动、不拆分、不合并、不就地分类，也不以其他方式整理用户文档内容。**即使用户明确授权或确认，这条永久边界也不改变。**
2. **AI 输出直接写回。** 不存在"一键应用到文档""替换选区""自动整理文档""自动润色并写回"这类入口。
3. **把四级 AI 参考优先级、继承、覆盖重新做成用户概念。**
4. 专业多轨剧本编辑器、复杂剧本排版、自动格式门禁。
5. 自动判断用户当前创作阶段。
6. 五模块结构化、复杂世界观/角色卡自动维护。
7. 用户自建内容库、LightRAG、复杂检索、长期记忆。
8. 矛盾检测、心流自动识别、多 Agent 展示。
9. 双文档 `main` / `screenplay` 语义（旧双本子不是现行模型）。
10. 多 LLM provider 分裂配置（前端列一堆、后端不支持是旧项目 P0 雷）。
11. 把专业理论设为用户开始创作或获得帮助前必须通过的资格门槛。
12. 宣称 AI 理解完整故事、能够转移专业创作能力，或保证用户写出优秀作品。
13. 用单一理论裁判所有故事，或把 AI 的假设写成作品事实。

## 8. 核心概念命名（一个概念只能有一个名字）

| 概念 | 名称 |

| 一部作品的容器 | 作品 |

| 与写作区并列、可收起的 AI 对话区域 | 常驻 AI 面板 |
| 常驻 AI 面板给人的对话体验 | 聊天窗口 |

| 用户框选一段文本给 AI 看（可选重点提示） | 选中 / 选区 |
| 用户从选区触发的旧工具（过渡，非长期形态） | AI 及时召唤 |

## 9. 数据事实源（谁说了算）

- **用户文档是作品内容事实源**：用户写进文档、留下来、保存下来的文字，就是当前作品正文。
- **用户文档只能由用户亲手改动**：文档可以混乱、临时、矛盾，但同样只能由用户亲手改动。
- **一个作品对应一个本地文件夹**：第一版采用文件夹形态保存作品，用户文本和系统数据分开放。
- **AI 面板输出不是事实源**：它是临时材料、候选、发散，不自动进入任何文档。
- **临时对话不是事实源**：它是旧形态承载临时材料的空间；不叫历史或记忆；当前不持久化，未来是否保存需另行确认。
- **用户复制 / 粘贴 / 编辑是唯一采纳路径**：AI 给出的任何文字，只有被用户亲手放进用户文档后，才成为作品文本的一部分。
- **不追踪 AI 来源标签**：用户从 AI 面板复制内容并粘贴、编辑、保存后，系统不记录该段文本来自 AI。
- **版本控制保护用户文本**：版本记录的是用户保存过的文本状态，不是 AI 替用户改稿的痕迹；恢复旧版本是用户主动重放自己写过的稿子，恢复前要提示影响范围。

## 10. 验证路径（怎么证明第一版成立）

第一版的验证分两层：工程链路能稳定跑通，产品回应是否站在陪想而非代写或裁判的位置。验证不以自动生产作品、提高写作速度、输出文字多少或用户是否继续写为成功条件。

### 10.1 工程验收（核心闭环能跑通）

1. **写作链路**：用户打开作品 -> 在文档里写字 -> 保存 -> 重新打开后内容还在。
2. **基础编辑体验链路**：用户能在文档里持续打字、阅读、定位，不因布局、宽度、焦点、面板遮挡或位置丢失而被迫停下。
3. **常驻 AI 面板链路（第一版优先验证）**：用户不先配置、不先选区，打开面板直接提问 -> 获得有依据的回应；面板可收起，收起后写作区恢复可用空间。
4. **选区作为重点提示**：有选区时，AI 把它当作"请重点看这里"；无选区时，用户仍可直接提问。
5. **手动使用链路**：用户复制 AI 面板里的某句话 -> 自己粘贴到文档 -> 保存后可回读。
6. **不越界验证**：AI 全程不自动插入、不自动替换、不自动整理任何文档。
7. **配置链路**：填入 API 地址 / API Key / 模型名 -> 保存 -> 测试连接成功 -> 能成功调用一次模型。

### 10.2 产品验收（灵魂是否成立）

工程能跑通，不等于产品方向成立。工具应提出有依据、清楚而不武断的问题，帮助用户重新看见故事，这一层必须单独验：

8. **好问题验收**：拿 3 到 5 个用户真实卡住的片段来测。对每个片段，AI 的输出必须满足：
   - 给出**有文字依据的问题 + 开放的可能性**，让用户能指出回应依据了作品中的什么，而不是收到套话。
   - 表达清楚，区分文字事实、AI 假设和可选方向，不把推测说成作者本意。
   - **不替用户判断**：不默认整段替用户续写正文，不评价故事高级/低级/正确/错误，不把故事塞进剧作模板后命令用户照做。
   - 用户能因此看见此前忽略的关系、情绪、矛盾或方向。用户可以继续想、继续写、修改、搁置或拒绝，任何一种选择都不使验证失败。
   - 只要 AI 变成"普通聊天窗"或"默认代写机"，这一条就算不合格。

   注：不以回答长度、生成数量、写作速度或是否立刻多写一段来判断。这里只检查它是否帮助用户重新看见故事，并把判断权留给用户。

### 10.3 后台能力验证（不必然进入第一版）

常驻 Agent 的后台预加载、检索、摘要、记忆和 Agent 循环机制若进入实现，必须各自以独立 OpenSpec change 确认范围与验收标准；第一版阶段不得因为"面板已常驻"就假定这些后台能力已经实现。

## 11. 尚未讨论、留待后续

- 常驻 AI 面板直接提问的具体范围：第一版是否只做"当前文档 + 当前写作位置 + 必要的已保存内容"，未保存内容如何处理——待 OpenSpec 确认。
- Agent 如何选择上下文的具体机制（不进入用户概念，内部方案待定）。
- 上下文说明（"这次大致参考了什么"）的呈现形式。
- 选区作为重点提示时，如何告知 Agent 与用户。
- 视觉设计、字体、颜色、空间布局、动效和整体 UI 气质。
- 编辑器组件具体选型与实现方式。
- 写作专注能力（当前句子聚焦、打字机模式、稳定写作宽度等）的优先级和默认开关。
- 自动保存、崩溃恢复、版本记录的先后顺序。
- 旧选区 AI 工具（AI 及时召唤、思维扩展、临时对话）的保留、迁移或下线方式。
- 旧作品迁移到内容树的具体行为。
- API Key 正式版安全存储方案。
- 工程基建：git、npm、环境隔离、代码规范、测试用例的具体落地。

这些进入实现前会另行讨论，不在本方向文档拍板。
