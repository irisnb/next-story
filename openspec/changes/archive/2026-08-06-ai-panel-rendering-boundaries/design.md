## Context

`src/ai-panel.ts` 是当前 AI 面板的 DOM 适配器。它接收 `AiPanelState` 和 `AiPanelActions`，创建或查找页面节点、订阅状态变化、根据请求与临时对话状态决定可见内容、绑定操作，并协调面板滚动。

状态职责已经有较清楚的边界：`AiPanelState` 是面板状态事实源，`TemporaryConversationState` 管理临时对话，`PanelRequestState` 表达请求阶段，`AiPanelScrollResetController` 决定新请求何时重置滚动。剩余问题是 `ai-panel.ts` 仍直接解释这些状态并同时修改 DOM，使显示规则只能主要通过 fake DOM 集成测试验证，也让一次显示规则修改容易影响同文件内不相关的事件或节点操作。

本次是保持行为不变的内部重构。现有产品规格、`setupAiPanel()` 接入方式以及 AI 永不写入草稿本或正文本的永久边界都不改变。

## Goals / Non-Goals

**Goals:**

- 建立一个纯显示决策边界，把面板状态与临时对话转换成不可变、可直接测试的 view model。
- 让 `src/ai-panel.ts` 聚焦 DOM 节点、事件绑定、显示结果应用和既有滚动协调。
- 保持 `AiPanelState` 为唯一状态事实源，不在渲染层复制可变业务状态。
- 用直接单元测试覆盖主要状态到显示结果的映射，并用现有 DOM 测试锁定最终页面行为。
- 保持当前用户可见行为、文字、操作可用性和对外接口不变。

**Non-Goals:**

- 不新增或改变 AI 请求、临时对话、追问、重试、编辑重发、配置引导或滚动行为。
- 不改变面板视觉、HTML 结构或显示文案。
- 不抽取或共享测试用 fake DOM helper；该工作仍属于独立候选 D-04。
- 不修改 `src-tauri/src/project/operations.rs` 或任何后端、项目文件格式及网络协议。
- 不实现历史、持久化、思考收束、安全返回写作或其他未来能力。

## Decisions

### 1. 提取纯 view model 构建函数

新增一个聚焦的 AI 面板显示决策模块。它只接收 `AiPanelState` 暴露的只读视图和只读临时对话，返回描述当前面板显示结果的判别联合类型或等价的严格类型结构。它不得读取 DOM、调用 action、发起请求或持有可变状态。

选择纯函数而不是新的控制器类，是因为当前需要隔离的是状态解释，不需要第二套生命周期。纯函数可以直接用普通对象测试，也不会与 `AiPanelState` 形成两个事实源。

备选方案是继续在 `render()` 内按请求种类分支。该方案改动最少，但不能解决显示规则与 DOM 操作耦合的问题。

### 2. 保持 `AiPanelState` 和 `setupAiPanel()` 的现有边界

`AiPanelState` 继续拥有面板开关、请求阶段、冻结选区和临时对话；view model 只派生数据，不缓存或反向修改状态。`setupAiPanel(dom, state, actions)`、`AiPanelActions` 及其返回控制接口保持稳定，让 `src/ai-feature.ts` 无需承担本次内部重构。

备选方案是同时重做 `AiPanelState` 或 `AiPanelActions`。这会扩大影响面，并把状态架构调整与渲染拆分混为一个 change，因此不采用。

### 3. DOM 层只消费显示结果并保留交互归属

`src/ai-panel.ts` 继续负责必需节点校验、事件监听、输入值读取与清理、焦点、面板开合，以及调用 `AiPanelActions`。渲染时先取得纯 view model，再集中把文字、可见性、禁用状态和操作区域应用到既有节点。

事件仍留在 DOM 层，因为它们依赖真实输入元素和用户动作；把事件也塞进 view model 会让纯边界重新依赖浏览器对象。

### 4. 两层测试共同锁定行为

新增 view model 直接测试，覆盖 idle、首次预览或加载、思维扩展、首次成功、首次失败、配置缺失、追问加载、追问成功、追问失败及编辑重发等现有显示分支。现有 `tests/ai-panel-dom.test.ts` 保留，用于验证显示结果被正确应用到页面并且事件仍调用原 action。

测试必须断言当前行为，而不是为重构创造新行为。已有状态、临时对话和滚动测试继续运行。

## Risks / Trade-offs

- [view model 变成 DOM 节点的一比一镜像，只是搬代码] → 以“用户看到的显示状态和可用操作”建模，避免暴露元素引用、CSS 操作步骤或事件实现。
- [渲染拆分时遗漏稀有错误或追问状态] → 先用测试枚举现有判别联合类型的全部分支，再迁移渲染逻辑；TypeScript 使用穷尽检查，不用类型忽略。
- [同一显示判断在 view model 与 DOM 层重复] → DOM 层只应用结果，不再根据 `PanelRequestState.kind` 二次决定业务显示。
- [内部文件增加带来理解成本] → 只新增一个聚焦模块和对应测试，不建立通用 UI 框架或多层抽象。
- [行为不变重构仍可能产生视觉或交互回归] → 保留现有 DOM 回归测试，并在实施阶段运行完整前端测试、类型检查和构建。

## Migration Plan

1. 先为当前状态到显示结果的映射增加失败测试，固定现有行为。
2. 实现纯 view model 构建函数，使新增测试通过。
3. 让 `src/ai-panel.ts` 消费 view model，逐步删除其中重复的状态解释分支，同时保留事件和滚动逻辑。
4. 运行 AI 面板聚焦测试、完整前端测试、类型检查和构建，并实际检查关键面板流程。
5. 若重构无法保持既有行为，则回退本 change 的实现改动；本 change 不需要数据迁移或兼容层。

## Open Questions

无。具体 view model 类型名和文件名可在实施时遵循仓库现有命名，但不得改变本设计规定的责任边界。
