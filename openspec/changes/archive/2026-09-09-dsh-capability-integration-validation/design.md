## Context

当前 Next Story 通过 Rust/Tauri 守护 Node DSH driver，已经支持临时会话、流式文本、追问、取消和崩溃后的文本历史重放。DSH 侧已存在 Agent Loop、工具注册和工具事件基础，但当前 driver 配置禁用了具体工具，应用也没有把作品读取接入 Agent 运行链路。

阶段 0 已确认：作品数据由 Rust 受控管理；AI 只能使用只读材料；未保存稿件必须以受控快照传递；不同讨论的请求必须隔离；取消、超时和迟到结果不能污染其他请求；任何 AI 输出都不能写回作品。

本 change 是验证 change。它要产生可重复的证据和明确的接入结论，不把验证 fixture 当成面向用户的自动读稿功能。

本 change 的验证是离线的：确定性适配器（sidecar/driver/adapter.mjs）不启动实机 DSH，也不调用真实模型/API。Rust 侧只落地纯函数边界——project/story_material.rs 的 read_material 与 capability_gateway.rs 的 authorize_tool，均为自由函数 + 单元测试，不是注册的 Tauri 命令，也未接入生产 driver.mjs 的工具协议（生产 driver 不含 story 工具协议）。

## Goals / Non-Goals

**Goals:**

- 验证一个 DSH Agent Loop 能在 Next Story 的会话身份和生命周期边界内运行。
- 验证只读作品请求经过离线受控只读边界（JS 桥接对固定 fixture + Rust story_material 纯函数）后返回结构化材料，并能继续当前轮回应。
- 验证工具调用开始、成功、失败、取消、超时和用户拒绝等事件及终态。
- 验证两个会话的消息、工具结果、取消和迟到事件不会互相串扰。
- 验证读取范围扩大时可以暂停等待用户确认，并从同一轮继续或以明确拒绝终止。
- 验证前端提供的未保存快照能沿受控路径传递，不暴露目录文件系统访问。
- 记录固定 fixture 下的首字、完整回答、排队和一次补读等待数据。

**Non-Goals:**

- 不实现常规讨论的自动现场材料、完整作品自主补读或多窗口 UI。
- 不开放 `tool-fs`、`tool-bash`、`tool-web`、网络检索、子代理、泛化多 Agent 或无限目标循环。
- 不实现讨论持久化、会话列表、窗口布局保存或跨应用重启的完整恢复。
- 不修改作品正文、内容树或用户文档保存流程。
- 不把验证结果描述为已经交付 Agent 读稿能力，也不承诺固定等待秒数。

## Decisions

### 1. 以受控只读桥接作为唯一作品入口

验证 harness 使用最小的只读能力集合，例如列出允许范围、读取指定文档和传递未保存快照。请求由离线受控只读边界校验作品身份、文档身份、可见性和版本，再返回结构化结果：JS 侧 bridge.mjs 对固定 fixture 校验，Rust 侧 project/story_material.rs 以纯函数（非注册 Tauri 命令）落地同一边界并通过单元测试；生产 driver.mjs 不含 story 工具协议。

选择这一方式，是因为作品服务是可靠保管者，AI 运行环境不能绕过权限直接读磁盘。MCP 可以作为后续候选桥接，但本 change 不把 MCP 锁定为唯一实现，也不为了验证引入通用文件系统工具。

替代方案：让 Node driver 直接读取作品目录。放弃原因：绕过 Rust 权限和版本边界，无法证明产品安全接入。

### 2. 为每次运行建立明确的请求身份

每个验证运行携带作品身份、讨论/会话身份、轮次、消息身份和请求身份。事件路由按请求身份和会话身份匹配，不能只依赖容易重复的局部消息编号。结束、取消或超时后，迟到事件必须被丢弃或记录为迟到，不得改变已结束请求状态。

替代方案：复制现有 transport 连接给每个窗口。放弃原因：当前连接使用单一 active session 和从 `msg-1` 开始的消息编号，直接复制会产生同名冲突。

### 3. 用事件终态驱动验证，而不是只检查最终文本

验证记录至少包含请求开始、工具调用开始、工具成功/失败、用户确认等待、确认/拒绝、取消、超时、模型文本增量、完成和错误等事件。测试既检查最终回应，也检查事件顺序、归属和终态唯一性。

替代方案：只检查 driver 最终返回的助手文本。放弃原因：无法发现工具越权、取消后迟到结果或恢复状态污染。

### 4. 先用固定 fixture 建立可重复基线

测试使用固定的小型作品 fixture、固定模型配置或可控替身，并分别测直接回应、一次受控补读、需要确认后继续、拒绝、并行请求和取消。真实模型等待可作为环境记录，但功能判定不依赖某个不可重复的秒数。

替代方案：只用一次真实作品和人工观察。放弃原因：难以复现版本、权限和竞态问题，也不能作为后续阶段的可靠证据。

### 5. 未保存内容只通过显式快照进入验证

验证 harness 提供带作品、文档和版本标识的未保存快照（固定 fixture，非真实前端/编辑器）；Rust story_material 纯函数与 JS 桥接层离线验证其来源和允许范围。确定性替身只收到被允许的快照结果，不获得编辑器对象、作品路径或写入 API。

替代方案：测试时直接读取磁盘上的文档。放弃原因：会漏掉用户尚未保存的最新内容，且无法验证作品与 AI 路径隔离。

## Risks / Trade-offs

- [DSH 版本或插件事件形态与预期不同] → 在实际固定版本上做最小探针，记录可复用能力和必须新增的桥接，不另造 Agent 核心。
- [模型或本地服务等待不可重复] → 将功能正确性与等待基线分开；用固定 fixture 和可控替身判定协议，用真实配置补充时间记录。
- [取消后仍有迟到事件] → 使用请求身份、终态闸门和隔离测试；无法确认干净终止时将会话标记为不可信并明确降级。
- [工具返回越过可见性或作品边界] → 所有请求只允许通过离线受控只读边界（JS 桥接 + Rust story_material 纯函数）；对未知工具、越权文档、回收站文档和错误作品身份做拒绝测试。
- [验证范围意外扩展为产品功能] → 只保留 fixture、协议验证和证据记录；阶段 2 至 6 的产品功能继续按独立 change 推进。
- [恢复记录不足以承接工具材料] → 明确记录当前能恢复的字段和降级边界；不把缺失的工具语义伪装成完整恢复。

## Migration Plan

1. 在不改变当前用户路径的前提下加入验证 fixture、探针和受控测试配置。
2. 运行协议、权限、事件、并发、取消、恢复和等待基线测试，保存证据与失败样本。
3. 根据结果确定可复用的 DSH 接入面和需要新增的 Next Story 桥接；若关键安全边界无法证明，则保留当前能力并明确降级，不开放读稿。
4. 完成验证后归档本 change。后续独立对话保存、只读作品接口和自动读稿必须重新 propose。

回滚方式：移除或禁用验证配置和 fixture，不触碰现有作品数据与已归档会话行为；当前生产路径继续使用现有临时会话能力。

- 受控只读桥接最终采用内部协议、MCP 还是其他方式？本 change 只验证契约，不做产品层锁定。
- 工具材料和确认等待状态在后续持久化讨论中的最小恢复记录是什么？
- 真实模型和本地设备的并发、首字及完整回答基线是多少？
