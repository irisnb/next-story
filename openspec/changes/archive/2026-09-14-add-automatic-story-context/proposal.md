## Why

常规讨论目前只发送问题，长篇作品中的人物小传、世界观与角色设定无法支撑自然提问。阶段 4（`controlled-story-read-visibility`）已建立 Rust/Tauri 统一受控只读入口与文档级 AI 可见性事实源，但该入口尚未接入常规讨论。本 change 把阶段五的 A 部分——关注文档现场 + 允许目录投影 + 后端跨文档字面检索——接入常规首轮与追问，为长篇作品提供可追溯、受权限保护的自动材料入口；明确不实现 Agent 自主补读（B）、文件上传与语义/向量检索。

## What Changes

- 常规首轮与追问自动取得讨论明确绑定的关注文档（发送时刻的已保存正文，或经校验的当前编辑器未保存快照），并附带允许读取的作品目录投影。
- 复用既有作品/文档/版本/快照身份契约（前端 `projectPath`/`documentId`/`documentVersion`/`bodySnapshot`，`bodySnapshot` 为 `canonicalNotebookJson` 输出；Rust 侧对应 `work_id`/`document_id`/`version`/`MaterialSnapshot`），不另造第二套 ID；无选区仍可提供关注文档快照，非当前编辑器关注文档只用已保存稿，快照校验失败拒绝且不静默回退。
- 后端跨文档字面检索的候选词只从本轮新增问题确定性提取（不调用模型、不从作品反向抽词），在正文中搜索（标题不冒充正文、只用于来源显示）；命中片段带来源文档身份、版本与位置；未命中记录为 `not_found`，不表述为"不存在"。
- 关注文档只能显式切换，查看其他文档不改变关注对象；切换下一轮生效，每个讨论独立；材料身份在冻结时点固定，排队前复验权限，后续编辑不改变该轮。
- 明确区分材料准备与实际发送状态（prepared / sent / omitted / rejected / failed）；只有实际发送证据才标 sent，DSH 接收不等于 provider 已发送。
- 记录每轮实际进入模型上下文的材料出处（只存最小元数据，不存全文）与限制状态，提供不打断对话的轻量"本次参考了什么"说明。
- 超限诚实处理：本轮材料预算按当前选定模型/API 声明的上下文容量计算（复用既有模型配置，不新建第二套模型表），预留既有历史与系统提示安全余量，无法获得可靠容量时保守拒绝；组装后超过预算则不发送本轮、给出中文说明并只记录限制元数据；不静默截断、不做选择器或自动缩减重试、不文件上传；8 候选词/5 文档/10 片段为检索输出硬上限，非模型上下文上限。
- 与阶段 4 对齐：使用过后来被隐藏材料的讨论永久只读、不可继续追问/恢复，重新可见也不解除；查看旧讨论时旧出处脱敏，不泄露被隐藏文档身份。
- 及时召唤保持快车道，不经过常规取材流程。

## Capabilities

### New Capabilities

- `automatic-story-context`: 常规讨论的关注文档现场材料、允许目录投影、后端跨文档字面检索、材料出处与限制记录、轻量参考说明与讨论隔离。

### Modified Capabilities

- `ai-feature-orchestration`: 常规讨论预检/请求编排允许按规则加入受控作品现场材料；及时召唤保持例外；零写回不变。
- `resident-ai-session`: 轮次材料与权限变化后的历史重放/新请求语义需覆盖自动附带材料的出处与身份。
- `conversation-persistence`: 讨论档案的材料出处扩展为覆盖现场材料、目录投影与跨文档命中片段及其限制状态。
- `controlled-story-read-visibility`: 跨文档字面检索与自动附带材料继续服从统一可见性边界，历史材料不因权限变化被抹除且旧出处脱敏。

## Impact

影响 Rust/Tauri 作品读取与请求组装（关注文档现场、目录投影、跨文档字面检索）、前端讨论关注文档切换与未保存快照状态、DSH task 文本注入、会话材料出处与恢复记录、常规讨论 UI 轻量参考说明及相关规格与测试。不注册 Agent 读稿工具，不开放写入、文件系统、命令、网络或子代理能力；不实现 Agent B 自主补读、文件上传或语义/向量检索。检索候选词与片段上限等数值为内部初始值，需真实效果验证，非产品效果保证；本轮材料预算按当前选定模型/API 声明的上下文容量计算，容量来源复用既有模型配置。
