# add-posture-slot 提案：姿态类插槽

> 方向依据：《制作模块与思维链路·讨论共识-2026-10-05》§1（姿态插槽＝第二刀第一顺位）、《交付物定义-讨论-2026-10-06》§1.3/§1.4（插槽按概念定义、骨与衣服）、《走通一例-傲娇搭档-2026-10-07》（全部实证与本提案的直接依据）。
> 本文为提案，**未实现**；经用户确认后才进入 apply，一次只开一个 change。
> 2026-10-07 四路审查（oracle/explorer/librarian/designer）后修订：次序不变式如实改写（用户拍板：身份邻接＋明文冲突条款）、协议改为独立 `posture` 字段、存储降级防护、姿态触发描述语义、Q2 灰色地带规格协调（用户拍板：本 change 顺带改条文）、UI 修补入规格。

## Why

姿态插槽是第一刀明列的"第二刀第一顺位"。走通一例（手工模拟九轮）证明价值假设成立：皮换成功、干货不掉、回复不长反短、代写红线零失守，且用户已拍板评价球按灰色地带口径接受。但真实装配补验（D/D2 两轮）发现关键负发现：**姿态内容经现行链路卡挂载位（远离身份句、带元数据包装）装配时不换皮**——卡进入了上下文，模型的出场声音没变。姿态卡若不换皮则无意义（用户原话）。外部证据与该发现同构（2026 年人格回退研究：人格未锚定特权层时模型回退助手腔；特权层锚定 0/46 失败）。本变更把姿态卡接入为第二类插槽，注入**身份邻接挂载位**（陪想身份之后、宪法红线之前），以身份性措辞装配，使换皮生效且不越骨。

## What Changes

- **姿态类插槽与姿态卡**：链路版本内新增姿态卡，与要求卡并存；**每链路版本可多张姿态卡**（2026-10-07 用户拍板修订，视觉验收中否决原设计的「至多一张」——多张全部注入，系统不做冲突调和（无先例，按「诚实兜底」处理，不假装解决），组合权在用户；制作助手起草第二张姿态卡时询问「替换还是并存」，发现与已有姿态明显相抵时提醒、不阻止）；**纯姿态卡版本允许**（每版本至少一张卡，任一类型）；卡结构沿用触发描述＋正文，长度上限沿用（触发 ≤400 字、正文 ≤2000 字、版本合计 ≤6000 字，两类合计，多张姿态卡自然受此限）。
- **姿态触发描述语义（明示，防空头支票）**：姿态卡的"何时用/不适用"**仅供用户选择链路时参考，不承担自动切换**——装配永远注入正文；详情页如实说明。
- **信封结构（用户拍板：身份邻接＋明文冲突条款）**：新增**姿态挂载位**，物理次序为 harness → 陪想身份 → 姿态位 → 宪法红线 → 要求卡位。**如实声明：本变更修改了①的旧物理不变式「卡内容不进红线上方」**；替代保障为明文冲突处理原则——**任何卡内容（姿态与要求卡）与宪法红线、陪想身份的固定条款冲突时，固定条款优先**；陪想身份句（骨）保持固定，任何姿态内容不得置于身份之上，任何要求卡不得置于红线之上。
- **装配协议（独立字段，不重构既有字段）**：`send_message` 新增可选字段 `posture`（string|null，Rust 侧渲染好的最终姿态段文本）；`chain_cards` 字段与语义**原样不变**（仍为要求卡包装文本）；包装常量保留 Rust 单一来源（跨语言双副本风险由此消除）；驱动侧新增姿态挂载段与独立幂等状态，旧驱动忽略新字段（姿态不生效、不报错），新驱动无 `posture` 时该位为空。
- **每轮冻结、切换下一轮生效、崩溃重放规则沿用**（chain-assembly 既有语义；重放期间两挂载位皆空、恢复后按当前指针重新冻结，不从历史档案复原旧姿态）。
- **制作对话支持姿态卡**：制作助手可按口述起草姿态卡（范围：人设、看剧本的出发点、AI 本身姿态）；制作守则增加骨/衣服把关（澄清"要语气上的皮还是真要它当裁判"，裁判权换不走）；正文第二人称在**起草阶段**落实（范本保证），装配不自由改写用户确认的正文。
- **导图与链路库 UI**：「自定义要求」分区加说明性副标（包含要求卡与姿态卡，副标不构成第二名称）；零件区按插槽分组（要求类＋姿态类并列，多张姿态卡并列呈现）；两组添加入口统一同种轻按钮样式且**均常驻**（2026-10-07 修订：多张姿态卡可继续追加）；统一详情对姿态卡「何时用」加"不会自动切换"说明；两组共用分区单一滚动区；1024px 窄窗与键盘可达入验收。
- **Q2 灰色地带规格协调（用户拍板：本 change 顺带改条文）**：`dsh-headless-generation` 的「不评价故事／不判断故事好坏/正确错误/高级低级」条文细化为灰色地带口径——**评价可以带依据的观察与假设形式给出（讲清线索、说明依据、判断权归还用户），不得无依据裁决、不得用单一标准判定故事对错或优劣**；信封相应条款与逐字保留清单同步更新。宪章/AGENTS 方向文档的同口径同步为独立后续（经用户授权，不混入本 change 代码范围，提案如实标注）。
- **数据降级防护**：链路库存储格式版本升至 2；旧版本应用遇 v2 **明确拒读报错**（不误读、不重写丢类型）；v1 数据新版读取视为全要求卡；回滚说明区分代码回滚与数据降级（恢复备份）。
- **硬验收**：真机端到端以**傲娇搭档案例为试金石**——换皮生效（预登记验收计划：模型配置、重复次数、判分口径、失败条件事先固定，全样本入记录）＋骨考题通过（Q3 拒代写且候选为观察/问题/方向、不提供可直接替换正文的文本；Q2 按灰色地带口径）＋检索零污染维持（限定相同冻结环境下的自动字面检索一致）；多轮追问后换皮保持抽检。

## Capabilities

### New Capabilities

（无——全部为既有能力的修改。）

### Modified Capabilities

- `system-prompt-layering`：信封次序新增姿态挂载位与明文冲突处理原则（如实声明修改①物理不变式）；信纸职责划分的 system 层可变范围扩展为两挂载位。
- `chain-assembly`：`posture` 独立字段与姿态段挂载；姿态卡身份性包装（肯定式承接、剥元数据、正文原样）；姿态生效的确定性契约与预登记行为验收。
- `chain-library`：卡类型约束（要求卡多张、姿态卡每版本可多张〔7.2 修订〕、纯姿态版本允许）；存储格式版本与降级防护。
- `making-conversation`：制作流程支持姿态卡；制作守则增骨/衣服把关、触发描述语义、单卡引导。
- `making-module-page`：导图插槽分组与副标、统一添加入口规则、姿态卡详情适配、单滚动区、窄窗与键盘可达。
- `dsh-headless-generation`：评价类边界条文按灰色地带口径细化（信封条款与逐字保留清单同步）。

## Impact

- **Rust 宿主**：链路卡冻结拆分为姿态段与要求段两产物；姿态段渲染器（肯定式身份性包装，常量管理）；链路库 schema 卡类型字段＋格式版本 2＋旧版拒读防护（`chain_library.rs` 的 `validate_cards`／load 路径）；信封评价条款常量更新（`generate.rs` 宪法常量，含逐字断言测试同步）；试问带卡路径（`trial_session.rs`）同步产出 `posture`。
- **驱动（sidecar/driver）**：`system-prompt-sections.mjs` 新增姿态段常量与空段占位（order 位于身份 0 与红线 10 之间）；`driver.mjs` session 增姿态幂等状态与 `applyPosture`；`protocol.json` 文档两字段。
- **前端**：制作页（分组＋副标＋入口规则＋详情适配）、制作对话草稿类型标记（标记块协议与 Rust 模板同步）。
- **协议**：`send_message` 新增 `posture` 可选字段；`chain_cards` 零改动；`start_session` 零改动。
- **存量行为**：既有链路（全要求卡）装配结果逐字不变（Rust 锚点＋驱动侧双向断言）；v1 库数据向前兼容读取。
- **验收依赖**：有界 2×2 位置×措辞实验（装置级）先行；真机 CDP 端到端＋傲娇试金石＋用户真实点击视觉验收（沿账本第 21 条惯例）；证据归档 `verification/`。
