## 三、回滚路径说明

代码按 change 原子 revert 后的行为（依据：存储格式 v2 序列化形状、serde 字段兼容性、旧代码校验路径）：

1. **旧代码读新数据中的零卡版本：展示正常。** `Chain.versions` 与 `ChainVersion.cards` 均 `#[serde(default)]`，空数组在格式 v2 下解析无恙；链路库读取、版本列表、导图零卡空分区（空数组渲染为无卡行）均正常展示。存量零版本链路的读取补版只发生在内存并随链路库下一次写入落盘——revert 后旧代码读到该落盘数据（链路含一个零卡版本）同样正常展示。
2. **旧代码保存零卡被拒：失败关闭、不静默。** revert 恢复 `validate_cards` 的「至少需要一张卡」拒绝路径，任何试图保存空卡清单的操作（编辑零卡版本后再保存、删至零等）将被明确报错拒绝，不会静默截断或写坏数据。
3. **`has_cards` 字段兼容。** 旧代码的 `ChainRoundRecord` 无该字段：serde 默认忽略未知字段，旧代码读新档案不损坏；旧代码窄更新写入的轮次记录不带 `has_cards`，前端旧代码按缺省＝有卡处理（`undefined` 语义与后端 default=true 对齐），「本轮链路」行显示行为与本变更前一致。
4. **回滚后的验证口径。** revert 后跑既有 `chain_library` 装置测试（旧「至少一张卡」用例随 revert 一并恢复）即可确认失败关闭路径在位；建议在验证记录外的回归里附一条「旧代码读本冒烟产生的数据正常展示」的人工抽查（本冒烟数据已清理，可用任意手工构造的零卡版本 JSON 复核）。
