# 设计：annotate-operations-module

## Context

`src-tauri/src/project/operations.rs` 是作品数据的唯一写入通道：建档、内容树变更、文档保存、迁移回滚与崩溃恢复都经它落地。当前 2955 行 ＝ 生产代码约 1419 行 ＋ 内联测试约 1536 行，是全仓库最大的单文件；它也是核心文件中唯一没有模块头注释的一个（migration.rs / notebook.rs / story_material.rs / story_search.rs 均有 `//!` 模块头与职责说明）。

"拆不拆"已有三次正式评估，结论一致为**不拆**：

- 2026-09-14《全量地基审计》队列 8a：operations.rs 判定不动（无干净缝）；
- 2026-09-21 `extract-ai-logic-seams` 设计："恢复与提交共享同一套清单/前滚机制，没有不拖家带口的真缝"；
- 2026-09-23《开发前全面工程复核》：“包含大量故障注入与恢复测试；主测试区在约 1419 行后。事务一致性强相关，不因总行数机械拆分。”

用户指示（2026-09-27）：稍微整理；如果真不好整理，就不要整理，不要为了整理而整理。本 change 取"能干净做的那一层"——注释与导航，不动一根代码。

## Goals / Non-Goals

**Goals:**

- 零行为变化：只新增或调整注释，不改任何代码、签名、常量、测试与数据格式。
- 为 operations.rs 建立模块头：职责、安全不变式清单（逐条核实后写入）、分区地图、"为何保持单文件"的结论记录。
- 按现有函数聚类插入分区横幅注释；不重排代码。
- 补齐关键条目的缺失文档注释（只增量，不改既有注释）。
- 规格：新增 `operations-module-map`，固化模块地图与结构决策延续契约（不改既有行为规格）。

**Non-Goals:**

- 不拆分文件（三次评估均判无干净缝，硬拆会制造假边界）。
- 不搬迁内联测试（全仓 Rust 测试均为内联惯例，无外部测试文件先例；主测试区之外还有 5 处散落的 `#[cfg(test)]` 测试辅助，只搬大块会形成"测试脑裂"）。
- 不抽取文件系统工具到共享模块（相关函数已 `pub(crate)` 经 `mod.rs` 复用于讨论档案存储，搬家只增加改动面）。
- 不改任何行为、IPC 协议、存储格式；规格增量仅登记模块地图契约（见 Capabilities），不改动任何既有规格的 Requirement。

## Decisions

### D1：只做注释层整理（备选方案否决记录）

| 备选 | 判定 | 原因 |
|---|---|---|
| 按功能拆成子模块（lifecycle / tree / document / transaction / fs） | 否决 | 三次评估：恢复与提交共享同一套清单/前滚机制，无干净缝；假边界风险 |
| 内联测试搬出为独立文件 | 否决 | 全仓无先例；5 处散落测试辅助留在原地会形成"测试脑裂"；属"因总行数机械拆分" |
| 抽取 FS 工具（原子写、有界读、路径校验）成独立模块 | 否决 | 已 `pub(crate)` 复用中；纯搬家无收益，徒增改动面 |
| 重排函数顺序 | 否决 | 纯 diff 噪音，增加 review 与 blame 成本 |
| 注释层整理（本 change） | 采纳 | 唯一"干净且有用"的一层：降低维护者重建上下文的成本，风险为零 |

### D2：模块头内容与"不变式"写作纪律

模块头（`//!`，与 migration.rs / notebook.rs 等既有风格一致）结构：

1. **职责**：一句话——作品数据的唯一写入通道（建档 / 内容树变更 / 文档保存 / 迁移回滚 / 崩溃恢复）。
2. **安全不变式清单**（编号；每条必须经代码与测试核实后才写入，核实不了的不写）。候选条目：
   - 唯一写入路径：所有写盘经 `write_file_atomically`（tempfile + persist）或保存事务（暂存 → 清单 → 提交/回滚）；
   - 完成标记：多文件提交按固定顺序替换，`project.json` 最后替换，作为"这一代已完成"的判定依据；恢复据此前滚或回滚；
   - 恢复先于读取：读取路径先消化未完成事务（`recover_then_read_content_tree`）；
   - 失败关闭：事务未决时严格读取拒绝且不触碰文件；校验失败返回结构化中文错误，不静默修复；
   - 有界读取：`MAX_METADATA_BYTES` / `MAX_CONTENT_TREE_BYTES` / `MAX_NOTEBOOK_BYTES` 约束所有入读规模；
   - 路径安全：拒绝 reparse point / 符号链接跳转；校验路径留在作品根内；
   - 锁归属：作品锁由命令层（`lib.rs`）持有；本模块为自由函数，不自行取锁；
   - 恢复与迁移幂等：崩溃后重开可安全重跑。
3. **分区地图**：按现有代码顺序列出分区，便于定位。
4. **"为何保持单文件"**：记录三条评估结论，防止未来重复评估或误拆。

### D3：分区横幅与插入方式

- 风格与仓库一致：`// ========== 分区名 ==========`（参照 `lib.rs` 的 "Tauri Commands" 横幅）。
- 仅在现有函数聚类边界处插入注释行；不移动、不删改任何代码或既有注释。
- 分区草案（最终边界以 apply 时对照现状为准，"只加注释、不挪代码"）：
  1. 作品生命周期与结构校验
  2. 内容树与文档读取
  3. 内容树结构变更
  4. 文档保存入口
  5. 迁移辅助校验
  6. 保存事务与恢复（暂存 / 清单 / 前滚 / 回滚）
  7. 文件系统工具（原子写 / 有界读 / 路径安全）
  8. 测试（故障注入 / 恢复 / 并发）

### D4：验收方式

- 全量门禁：`cargo test`、`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`（教训：`cargo test` 不显示全部编译警告）。
- diff 审计：`git diff` 只允许出现注释行与空行的新增；不出现任何代码行变更或删除。
- 不变式核对表：逐条记录核对依据（代码位置 / 测试名）。

### D5：规格增量＝新能力 `operations-module-map`（否决挂靠既有规格）

- 新增能力 `operations-module-map`，把本次整理确立的三件事固化为可核对契约：模块地图须存在且完整、每条不变式可核对到实现/测试/规格、后续拆分须重新评估共享机制前提。
- **备选否决 1**：不设 delta、纯注释落地——`openspec validate` 要求 change 至少一条 delta，且仓库全部既有归档变更均遵循此约定；地图契约也值得成为持久事实。
- **备选否决 2**：把地图要求挂到 `project-reliability-boundaries`——该规格管行为边界，文档契约挂进去会稀释其主题；新能力与 `ai-module-boundaries` / `editor-module-boundaries` 同族。
- 说明：地图只做"索引"，不复述行为要求，避免与既有规格形成第二事实源。

## Risks / Trade-offs

- [写入的不变式与代码事实不符] → 逐条以代码与测试核实后写入；无法核实的条目不写。
- [模块头膨胀] → 只写四块（职责 / 不变式 / 地图 / 结论），控制篇幅。
- [横幅注释未来引起合并冲突] → 注释插在既有无代码行处，冲突面最小。
- [被误读为"拆分的前奏"] → 提案与设计均明确 Non-Goals；归档时重申。
