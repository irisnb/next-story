## Context

第二轮已建立格式版本 1 的严格 grammar，并在前端 `src/structured-notebook.ts`、Rust `src-tauri/src/project/notebook.rs` 与共享样例 `tests/fixtures/notebook-samples.json` 三处同步校验，任何未知 mark / 节点 / 属性都会被拒绝。第三轮在此基础上把 grammar 从「正文、两级标题、粗斜体、两种扁平列表」扩展到「下划线、删除线、颜色、高亮、字体、字号、对齐、行距、段间距、缩进、一到六级标题、嵌套列表、链接」，并新增查找替换、右键菜单和粘贴选项。

本轮改动的一半成本不在「加按钮」，而在**三处同步的严格 grammar 与选区/快照投影**：带属性的 mark、段落 attrs、嵌套列表这三类结构都是第二轮从未出现过的形态，会穿透校验、规范输出、工具栏状态分析和 AI 纯文本投影的每一层。设计先把这些结构形态和规则定死，实现再按步骤落地。

## Goals / Non-Goals

**Goals:**

- 把格式版本升到 2，一次性定义本轮全部字符标记（含带值标记）、段落属性、一到六级标题、嵌套列表与链接标记的规范形态，保持三处校验一致。
- 让字符格式、段落格式、嵌套列表、查找替换、链接、右键菜单、粘贴选项作为可靠、可撤销、可保存重开的能力落地。
- 保持 AI 冻结纯文字快照的准确性，用缩进表达嵌套列表层级，继续丢弃所有格式。
- 保持 AI 永不写稿、格式不扩大普通选区 AI 输入内容这两条永久边界。
- 大型文档（含新格式）下输入、滚动、查找、撤销重做和保存保持可用。

**Non-Goals:**

- 表格、图片、DOCX 导入导出、分页与页边距、页眉页脚页码、脚注尾注、批注修订、多人协作、宏、专业剧本格式识别。
- 不引入 `manuscript`/`screenplay` 等第二套代码标识；双本子继续用 `draft` / `main`。

## Decisions

### 1. 格式版本 2：一次定义完整 grammar，v1 作为子集就地升级

单篇文档 `version` 从 `1` 升到 `2`。版本 1 的文档是版本 2 的严格子集（v1 只使用 v2 允许的词汇的子集），因此「迁移」不是转换内容，而是：**打开时接受 `version` 为 `1` 或 `2`，统一按版本 2 grammar 校验，内存中的版本字段记为 `2`，用户下次保存时以版本 2 写回，正文与格式一字不改。** `version > 2` 的未来版本仍拒绝打开。这避免了重造测试项目，也避免引入「读取两种格式」的第二条路径——版本 1 只是版本 2 的一个历史前缀。

新增/放宽的 grammar 形态（精确字段、允许值、默认省略规则写入 `structured-notebook-storage` delta spec）：

- 字符标记按固定 rank 排序：`bold`、`italic`、`underline`、`strike`、`textStyle`、`highlight`、`link`。
- `textStyle` 是**单个**带属性 mark（对应 Tiptap 的 TextStyle 扩展），其 `attrs` 为 `{ color?, fontFamily?, fontSize? }` 的可选键子集；文字颜色、字体、字号都是它的属性而非三个独立 mark。这样 mark 排序只有一处 textStyle 位置，颜色/字体/字号的独立清除靠对单键的 unset。
- `highlight` 带 `attrs: { color }`（多彩高亮），`link` 带 `attrs: { href }`；`underline`、`strike` 无属性。
- 颜色统一规范为小写 `#rrggbb` 六位十六进制；字号为固定档位的字符串（如 `12pt`）；字体为固定的字族名。Rust 侧只需做模式/白名单校验，无需解析 CSS。
- `paragraph` 允许可选 `attrs`：`{ textAlign?, lineHeight?, spacingBefore?, spacingAfter?, textIndent?, indentLeft?, indentRight? }`，全部缺省时省略 `attrs`。
- `heading` 的 `attrs` 为必需 `level`（现在允许 `1..6`）加上述可选段落属性。
- 嵌套列表：`listItem` 的 `content` 从「恰好一个 `paragraph`」放宽为「一个 `paragraph` 加可选的 `bulletList` 或 `orderedList`」。

### 2. 带属性 mark 的合并与去重规则

「相邻文本节点必须合并」与「marks 去重、固定顺序」规则要推广到带属性 mark：

- mark 的身份由 `type` **加完整 `attrs`** 共同决定；两个 `textStyle` 只要 `color`/`fontFamily`/`fontSize` 任一不同，就是不同 mark 集。
- 相邻文本节点仅在**完整 mark 集（含每个 mark 的 attrs）完全一致**时才合并；否则保持边界。
- `canonicalMarks` 按 rank 排序并去重时，对带属性 mark 用其规范化后的 attrs 做身份比较。

### 3. 嵌套列表：结构放宽 + 投影改递归

`listItem.content = [paragraph, list?]`，其中 `list` 只能是 `bulletList` 或 `orderedList`。这带来三处必须从扁平改成递归的投影：

- `structured-notebook.ts` 的 `collectLines`（AI 快照）与 `format-commands.ts` 的 `collectBlocks`（工具栏状态）目前都假设列表只有一层，需改为递归展开，并给每个列表项记录深度。
- `list-numbering.ts` 的 `fixSplitOrderedListStart` 与有序列表 `start` 保留逻辑要覆盖嵌套有序列表：任何一层列表拆分/抬出后，未触及片段仍保持操作前的实际显示编号。
- 升降级用 `Tab`（进入子级）与 `Shift+Tab`（回到父级）；命令作用范围与「只转换触及的完整项目」保持一致。

### 4. AI 纯文字快照：嵌套列表用缩进表达层级

沿用「完整非空列表项加 `- ` 或 `N. ` 前缀」的既有规则，并新增：每个列表项在投影时，先按其**嵌套深度**输出 `2` 个空格 × 深度，再接列表前缀与文字。顶层深度为 0（不缩进）。部分选中的列表项与嵌套子列表仍遵循「部分不加前缀、不补结构信息」的旧规则。快照继续丢弃标题等级、全部字符标记（含颜色/字体/字号/链接）和所有段落属性。

### 5. 清除格式拆成三档

保留第二轮「清除格式」的「清除全部」语义（清节点类型 + 清 marks + 清段落属性），新增两档：

- 清除字符格式：移除全部字符标记（bold/italic/underline/strike/textStyle/highlight/link），不动节点类型与段落属性。
- 清除段落格式：重置段落属性（对齐/行距/段间距/缩进）并把标题、列表降回正文，不动字符标记。

三档均作为单个可撤销操作。具体作用范围与「选区触及完整段落」规则写入 `basic-rich-text-editing` 与 `character-formatting` / `paragraph-formatting` delta。

### 6. 粘贴：白名单扩展 + 明确选项

受控粘贴的白名单从第二轮的支持集扩展到第三轮正式支持且能稳定表达的格式：`h1`–`h6` 映射为对应标题、`u`/`s`/`del`/`ins` 映射下划线与删除线、带 `style="color"` 或 `background-color` 的有限字体/颜色映射到 textStyle/highlight、链接 `a[href]` 映射为链接标记。嵌套列表从「扁平化」改为**保留嵌套结构**（按 HTML 的真实层级重建 `listItem` 嵌套）。仍丢弃字体、字号、对齐、行距、缩进、表格、图片等未支持内容（或按既有规则降级为文字），并继续执行 HTML 与 `text/plain` 的完整性比较，无法保证时整次拒绝。

新增明确的粘贴选项：常规粘贴走白名单；「粘贴为纯文本」（`Ctrl+Shift+V` 与右键菜单入口）只插入可见文字、清除一切格式、保持插入位置段落/列表上下文。两条路径的差异写入 `controlled-rich-text-paste` delta。

### 7. 查找与替换：装饰高亮 + 单事务替换

查找在**当前本子可见文字**上进行，字面匹配、支持区分大小写开关；匹配位置用 ProseMirror Decoration 高亮，支持上一个/下一个、显示命中总数。替换当前项与替换全部均作为可撤销编辑，替换全部合并为单个事务。查找不改变文档结构（高亮是装饰，不是内容）。大型文档下的查找性能随第 9 条一起验收。

### 8. 链接：点击不导航，走弹层

链接为带 `href` 的 mark。创建用「选中文字 → 链接命令 → 输入地址」；光标/选区落在链接上时显示弹层，提供「打开 / 编辑 / 移除」。普通点击**不**直接导航（桌面写作场景避免误触），只通过弹层的「打开」主动触发，且只允许 `http:`/`https:` 通过系统默认浏览器打开。

### 9. 大型文档性能策略

当前每次编辑都完整序列化两份文档（`syncCurrent` 调 `canonicalNotebookJson`），对大型文档是每次击键 O(n)。本轮先建立带格式的基准（如 20 万字符 + 混合格式），实测输入、滚动、查找、撤销重做与保存；若序列化成为瓶颈，把「完整序列化」从编辑路径移到保存路径，编辑路径只标记脏。性能目标与验收写入 tasks。

### 10. 抽屉 UI 与写作背景板颜色

扩展格式控件收纳进**侧边抽屉**：字符格式组（下划线/删除线/字体/字号/文字颜色/高亮/清除字符格式）与段落格式组（对齐×4/行距/段前后间距/首尾缩进/标题层级/列表升降级/清除段落格式）。抽屉布局、混合三态与窄窗口收纳由 designer 出方向并实现，后续机械性修改变更不得破坏其视觉意图。写作背景板颜色是界面偏好，放在与文字颜色区分的设置入口，不进入文档结构。

## Risks / Trade-offs

- [三处 grammar 校验漂移（前端/Rust/共享样例）] → 本轮新增的 mark 与 attrs 全部先写进共享样例，再由两侧测试锁定；格式版本 2 样例覆盖每个新 mark/attrs 的合法与非法形态。
- [带属性 mark 的合并/去重出错导致保存后格式合并或丢失] → 用「相邻不同 color 文本保持分离」「相同 attrs 才合并」的专项样例与前后端往返测试锁定。
- [嵌套列表把扁平投影改递归引入位置错位] → 为 AI 快照与工具栏状态分别加嵌套列表专项测试（含缩进前缀、部分选中、跨层选区）。
- [版本升级破坏现有测试项目] → v1 是 v2 子集，打开即按 v2 接受，无内容转换；用「v1 样例在 v2 校验下仍合法」的样例锁死该不变式。
- [字体缺失/颜色格式不一致] → 字体用固定白名单、颜色规范为 `#rrggbb`，字体缺失时仅渲染回退、存储值不变。
- [大型文档性能回退] → 第 9 条先测量再优化，不预先引入未经验证的缓存。

## Migration Plan

1. 先把共享样例升级为版本 2 全集（新 mark/attrs/标题层级/嵌套列表/链接的合法与非法形态），前端与 Rust 校验同步升级并通过往返测试——此时不开放任何 UI。
2. 打开路径接受版本 1 与版本 2；保存路径统一写版本 2。
3. 依次实现字符格式、段落格式与嵌套列表、查找替换与链接与右键菜单与粘贴选项，每步通过自动检查。
4. 完成真机中文输入与真实写作流程验收后归档；若中途失败，通过 Git 回退整个 change，不发布混合版本。
