## Why

删除当前文档后，文件管理器已经获得新内容树，但编辑器在切换到剩余文档或进入空态的分支中没有保存这棵新树。这样会让编辑器内部的文档列表、`getTree()` 和后续树判断继续使用已删除节点，造成文件管理视图与写作空间状态不一致。

## What Changes

- 在编辑器接受文件管理器传入的新内容树时，确保当前树状态在所有接受路径中同步更新。
- 保持删除当前文档时已有的未保存内容确认、切换到第一篇剩余文档或显示空态行为不变。
- 增加回归测试，验证删除当前文档后编辑器对外提供的新树不再包含已删除节点，并覆盖有剩余文档和无剩余文档两种路径。

## Capabilities

### New Capabilities

- `editor-tree-synchronization`: 文件管理结构变更后，写作空间同步其内部内容树状态。

### Modified Capabilities

无。内容树命令与其现有行为规范不变；新增契约只描述写作空间对结构刷新结果的状态同步。

## Impact

- 受影响代码：`src/editor.ts` 的 `applyTree` 状态更新逻辑。
- 受影响测试：`tests/editor.test.ts` 的文件管理树刷新与当前文档删除回归测试。
- 不修改 Rust/Tauri 命令、持久化格式、前端 API 或用户文档内容。
