## Context

审查确认：单线程串行路径（保存崩溃恢复、AI 身份隔离、reducer 纯函数）设计扎实，但**后端缺少并发模型**，默认「同一时间只有一个调用者」，Tauri 命令层却没有保证这一点。最严重的是同一作品并发保存会互相破坏事务，威胁用户正文。此外 LLM 配置的钥匙串与磁盘文件分两次写、API Key 明文回流前端、代码里「正文本」叫 `main` 违反命名铁律。本设计给出每条修复的技术方案与取舍。

## Goals / Non-Goals

**Goals:**
- 同一作品的打开/保存/迁移在进程内串行化，杜绝并发保存破坏正文。
- LLM 配置保存原子化，消除「新密钥 + 旧服务地址」分裂窗口。
- 密钥不回流前端；AI 生成请求在协议层拒绝未知字段。
- 迁移回滚原子化、失败显式上报；大小限制改为句柄限量读取。
- 前端三个竞态修复 + `showProject` 事务式替换。
- 统一「正文本」命名为 `manuscript`。
- 补齐并发保存、端到端零写回、请求白名单三类测试。

**Non-Goals:**
- 不做跨进程文件锁（第一版不支持两个应用实例同时打开同一作品；进程内锁 + 唯一事务 ID 已足够）。
- 不做增量保存协议 / 后端持有编辑快照（第一版仍每次 IPC 传全文，大小上限内可接受）。
- 不改产品功能与铁律语义（AI 仍零写回；判断权仍在用户）。
- 不引入通用存储抽象或迁移备份保留策略（当前生产迁移表为空，先保证框架安全即可）。

## Decisions

### 1. 作品级串行化（P0：并发保存）
- **决策**：在应用状态里维护 `ProjectLocks = Mutex<HashMap<PathBuf, Arc<Mutex<()>>>>`，键为规范化后的作品根路径。`save_project`、`open_project`、迁移在**整个操作期间**持有对应作品锁。
- **理由**：进程内串行化是消除保存互相破坏的最小可靠手段；按路径分锁让不同作品仍可并行，不牺牲吞吐。
- **替代方案**：跨进程文件锁（`fs2`）更彻底但引入新依赖 + 锁残留清理复杂度，第一版单窗口场景收益低，故列为 Non-Goal。
- **配合**：每次事务生成唯一 `transaction_id` 写入清单；提交前确认事务目录未被替换。双保险，即使锁有遗漏也能检测到世代错位。

### 2. LLM 配置事务化（P0：密钥/地址分裂）
- **决策**：保存顺序改为「读旧密钥 + 旧磁盘配置 → 写磁盘临时文件 → 更新钥匙串 → 原子替换磁盘文件」；任一步失败按相反顺序恢复（磁盘临时文件直接丢弃，钥匙串回滚为旧值）。
- **理由**：把「先改钥匙串再写磁盘」的窗口反转，使磁盘始终是提交点，失败时钥匙串可回滚到与旧磁盘一致的状态。
- **替代方案**：给每份配置生成 ID、钥匙串 account 用该 ID、磁盘文件最后原子切换——更稳但改动更大，第一版用顺序反转 + 回滚即可。
- **并发**：`save_llm_config` 也纳入全局（或配置级）互斥，避免两个保存交错。

### 3. 密钥不回流前端（P1）
- **决策**：`load_llm_config` 返回不含 `api_key` 的配置 + `has_api_key: bool`。前端显示固定掩码。用户未输入新密钥时，`test_llm_connection` 与生成由后端直接复用钥匙串内密钥；用户输入新密钥时只把候选值发给一次测试/保存命令，之后不回读。
- **理由**：钥匙串只保护静态落盘，保护不了「前端能读」。CSP 再严也不该把密钥交给渲染层。
- **影响**：前端 LLM 配置表单的「回填」逻辑需要改成「掩码 + 空则用旧密钥」模式。

### 4. AI 请求协议收紧（拒绝未知字段）
- **决策**：`GenerateAiRequest` 及子结构加 `#[serde(deny_unknown_fields)]`，解析用 `serde_json::from_value` 直接失败而非忽略。
- **理由**：让「生成命令只接受冻结选区与临时对话」从「前端没发」变成「协议拒绝」，形成后端强约束（配合铁律零写回）。

### 5. 迁移框架加固（P1）
- **决策**：回滚复用项目保存的事务式暂存/恢复机制，不再用三次裸 `fs::copy`；`rollback_backup` 返回 `Result`，原始迁移错误与回滚错误都保留；回滚失败时保留备份并给出人工恢复路径。迁移步骤要求幂等，并新增「中途崩溃后再次打开」测试。
- **理由**：裸 copy 中途失败会留下部分回滚状态；当前生产迁移表为空所以还没触发，但框架不能带病上线。

### 6. 大小限制加固（P1）
- **决策**：文件读取改为「打开一次句柄后用 `take(max+1)` 限量读取，超限拒绝」，不再依赖读前的 `metadata.len()`。
- **理由**：消除「先看长度再读」之间的 TOCTOU 竞态，杜绝无界内存分配。
- **配合**：IPC 入参层面，前端在调用前先做同一上限检查（后端命令层若可配置请求体上限则一并设置，作为纵深防御）。

### 7. 同步 I/O 移出异步执行线程（P1）
- **决策**：项目与 LLM 配置的同步目录/文件/钥匙串操作包进 `spawn_blocking`（或专用串行工作线程），作品锁在阻塞线程内覆盖完整事务。
- **理由**：慢磁盘/云同步目录/钥匙串卡顿不应占住 Tauri 异步执行线程，且与决策 1 的锁粒度协同。

### 8. 前端竞态修复（P1）
- **决策**：AI 预检开始时冻结作品 token，所有 `await` 之后重新校验 token，不符则丢弃；离开流程改为「先选并读候选作品 → 真正替换前确认 → 立即替换」；打开作品加忙碌锁 + 操作序号，只允许最新操作提交；`showProject` 改为「先解析两份文档并构造完整新编辑器组合，全部成功后一次性交换状态再销毁旧组合」。
- **理由**：这些是「发请求之前/替换之前的异步窗口」竞态，用 token/序号/顺序调整即可，不需要通用事务框架。

### 9. 能力最小化（安全基线）
- **决策**：`capabilities/default.json` 把 `dialog:default` 收窄为 `dialog:allow-open`，移除未使用的 `window:allow-destroy`（先确认确无调用）。
- **理由**：最小权限，与 `tauri-security-baseline` 的既有要求一致。

### 10. 测试加固
- **决策**：新增三类测试：① 同一作品并发保存（屏障制造确定性重叠，断言无混合世代/暂存丢失）；② 真实端到端零写回（真实 WebView 完成召唤→成功→失败→重试→追问→切换作品，断言两本子磁盘字节不变且未调用 `save_project`）；③ 后端 AI 请求白名单（注入 `draft_content`/`main_content`/`project_path` 等未知字段，要求稳定拒绝）。
- **附加**：把 `tests/` 纳入 typecheck（或在 tsconfig 增加对测试的检查），修正测试文件里已失效的类型引用（如 `SelectionSnapshot.start`、`GenerateAiRequest.messages`），消除「typecheck 假绿」。

## Risks / Trade-offs

- **[Risk] 进程内锁遗漏某个入口（如迁移、恢复）仍可能并发破坏** → Mitigation：所有触碰作品目录的命令统一走「取锁 → 操作 → 释放」助手函数，代码评审强制检查新增命令是否绕过。
- **[Risk] 钥匙串回滚本身可能失败（系统凭据库异常）** → Mitigation：回滚失败时返回带明确说明的错误，不静默；配置以磁盘为准，下次加载自愈。
- **[Risk] 把同步 I/O 移到 spawn_blocking 可能引入新竞态（锁作用域穿越线程）** → Mitigation：锁的获取与释放都在阻塞线程内部完成，不在 async 上下文持锁跨 await。
- **[Risk] 端到端测试依赖真实 WebView/磁盘，CI 环境可能不稳定** → Mitigation：E2E 用例单独标记，允许在无显示环境跳过并显式上报，不作为唯一守护（与单测白名单测试互补）。
