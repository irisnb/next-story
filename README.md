# Next Story

Next Story 是一个带 AI 思考辅助的剧本写作桌面编辑器。它希望降低开始创作和获得帮助的前置门槛，把认真讲述自己故事的权利交给每一个想创作的人。

知识不是用来证明 AI 懂得多，而是用来减少用户必须先懂多少。工具希望把复杂创作知识转成贴合故事的观察、问题和可能性，帮助用户重新看见故事。最终判断、选择和故事完成属于创作者。它不替代创作所需的感受、思考、实践与坚持，不承诺转移专业创作能力，也不保证必然写出优秀作品。

**当前状态：** 已完成常驻 AI 会话：直接提问是唯一首轮入口（选区作为可选重点提示自动附带），回复流式逐字呈现，首次回应成功后可继续线性追问，追问只发送增量问题，可取消生成。驱动进程崩溃后自动重启并重放显示历史恢复会话。临时对话只在本次应用打开周期存在，新建对话或切换作品后清空，不跨重启持久化。旧选区工具（AI 及时召唤、思维扩展、浮动入口）已退场。没有历史、持久化、附近上下文、摘要、完整作品认知、AI 内容库或用户确认的作品信息。

## 已实现能力

下面只列已经进入 `openspec/specs/` 正式规格的能力。

### 作品与写作

- 启动后显示欢迎页，提供“新建作品”和“打开作品”入口。
- 可以输入作品名、选择保存位置并创建作品。系统会拒绝空名称、当前操作系统不允许的文件名、不可访问的位置和已有的同名文件夹。
- 可以选择并打开结构有效的 Next Story 作品文件夹。打开前会校验必要文件，成功后进入编辑器并默认显示草稿本。
- 编辑器提供草稿本和正文本两个标签页，可以切换并编辑文字与基础格式（一级/二级标题、粗体、斜体、无序/有序列表）。
- 手动保存时，无论当前在哪个标签页，草稿本和正文本都会一起保存。
- 重新打开已保存的作品时，两个本子的内容会从各自结构化本子文件读回编辑器。

### LLM 配置

- 整个应用只有一份 LLM 配置，包括兼容 OpenAI 接口格式的 API 基础地址、API Key 和模型名。当前不展示多个服务提供方（provider）、多个模型槽位或预设模型列表。
- 配置可以保存到本地，关闭并重新打开应用后可以再次加载。
- “测试连接”会向填写的基础地址追加 `/chat/completions`，发起一次真实的兼容 OpenAI 接口格式的模型请求。只有响应是有效 JSON，并且包含合法、非空的 `choices` 模型回复，才算连接成功。仅返回 2xx 状态并不够。
- 远程 API 地址必须使用 HTTPS。本机回环地址 `localhost`、`127.0.0.1` 或 `::1` 可以使用 HTTP。
- 从编辑器进入 LLM 配置页再返回时，当前作品、当前本子和未保存文本会保留。
- 配置加载、保存或测试等异步操作不会并发覆盖输入，过期的加载结果也不会盖掉用户后来填写的内容。

### AI 思考（常驻会话）

AI 通过常驻会话提供思考辅助：直接提问是唯一首轮入口，回复流式逐字呈现。

- 在 AI 面板直接输入问题即可提问；编辑器选区会作为可选重点提示自动附带，无选区也可直接提问。
- 首轮消息由后端集中组装：围绕用户问题与重点材料提供观察、问题和思考方向。**不代写正文，不附带任何前后文、全文、摘要或 AI 内容库。**
- 回复流式逐字显示，以纯文本呈现，保留换行、可复制，不解析 HTML 或 Markdown。
- 首次回应成功后可继续追问；追问只发送新增问题，此前对话由常驻会话在驱动进程内维护。
- 同一时间只允许一个请求；生成期间仍可写作，但不能发起第二个请求。可取消生成。失败保留原问题并提供重试或修改后重发，不自动重试。
- 长对话由框架自动压缩承接；超限时报错提示新建对话，绝不静默砍历史。
- 驱动进程崩溃后自动重启，并重放显示历史恢复会话记忆。
- 缺少完整 LLM 配置时不发起网络请求，面板引导前往配置页；返回后不自动请求。
- **AI 只产出临时材料，永远不直接写入、插入、替换、改写、删除或移动草稿本与正文本内容，界面也不存在“应用到正文”之类入口。**
- 旧选区工具（`AI 及时召唤`、`思维扩展`、选区浮动入口）已退场，代码保留未删。

## 当前未实现

以下内容可能属于后续方向，但现在都不能使用：

- 多个临时对话、历史记录和持久化（当前临时对话只在本次应用周期内存在）
- 附近文本、整本摘要等上下文（当前 AI 只使用用户问题、可选选区重点材料和当前会话中的对话）
- 对完整故事、人物长期轨迹、世界观、主线、主题或作者完整意图的理解
- 自动保存、自动备份、版本快照
- 内置 AI 内容库
- 多服务提供方或多模型选择界面

这些是当前“还没做”的功能，不等于以后都必须补上。下一节说明已确认的未来方向；再下一节才是永久 AI 边界。

## 已确认的未来方向

旧选区工具 `AI 及时召唤` 与 `思维扩展` 已退场（代码保留）。未来方向里仍保留更完整的两种开启工具：`AI 及时召唤`可从选区或位置快速开始，`思维扩展`可接收更自由的用户文字或问题，也可用默认角度开始。未来完整形态仍须另开 change 确认。

`思考收束`是共享结束动作，不是第三个开启工具。它只整理当前临时对话中的核心问题、已打开方向、关键差异和未知信息，帮助用户自己判断，不以生成对白或场景为目的，也不替用户决定方向。用户可以直接触发，无需再次确认；AI 可以建议进行收束，但只有用户接受建议才会触发。

收束后要支持`安全返回写作`：结果保持可见、可复制，基于选区时可查看冻结原文，用户能回到相关写作位置，不被 AI 结果挡住，也不必跨窗口寻找。这里的“返回”绝不表示应用或写回。

世界、情节、人物等未来只能先形成`作品信息候选`，由用户审阅、编辑、接受或拒绝；只有接受项成为`用户确认的作品信息`。它与供 AI 使用方法和资料的`AI 内容库`分开。说明性文档以后可以呈现确认信息，但当前未实现。

以上是已确认方向，不代表已经实现，不保证全部进入第一版，也不自动成为下一个 change。任何实现仍须单独提出 OpenSpec change 并由用户确认。

## 永久 AI 边界

> **AI 永远不能插入、追加、替换、改写、删除、移动、拆分、合并、就地分类或以其他方式整理用户文档中的任何字符。**

AI 输出永远只是临时材料，不是作品事实。即使用户明确授权或确认，AI 也只能在用户文档之外提供候选。只有用户亲手复制、粘贴、编辑并保存后，文字才会进入作品，成为作品内容。AI 可以提供观察、问题和可能性，不能替创作者定义、解释、评价或决定故事。即使未来能力增加，这条边界也不会改变。

> 注：早期「草稿本 / 正文本」两个固定本子已废弃（2026-08），由「作品内容树 + AI 参考优先级」取代；当前代码仍以草稿本 / 正文本存储，向内容树迁移是后续方向。详见 `AGENTS.md`。

## 数据保存在哪里

Next Story 把用户文本、作品元数据和 LLM 配置分开保存，避免系统配置混进作品文本。

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 草稿本 | `<作品文件夹>/作品文本/草稿本.json` | 用户文本（结构化文档），由手动保存写入 |
| 正文本 | `<作品文件夹>/作品文本/正文本.json` | 用户文本（结构化文档），由手动保存写入 |
| 作品元数据 | `<作品文件夹>/next-story-system/project.json` | 保存作品名、时间和结构版本，不包含草稿本或正文本内容 |
| 唯一 LLM 配置 | Tauri 应用本地数据目录中的 `llm-config.json` | 位于作品文件夹之外，不写入草稿本、正文本或 `project.json` |

系统和 Tauri 会决定应用本地数据目录的实际位置，因此这里不虚构一个适用于所有电脑的绝对路径。

**安全提醒：** API Key 保存在操作系统的凭据存储（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service）中，不会以明文写进 `llm-config.json`。点击“测试连接”时，API Key 会发送给配置的 API 服务用于身份验证；HTTPS 可以保护传输过程，但目标服务仍会收到 API Key。只在可信设备上使用，只填写可信的 API 地址，也绝不要把真实 API Key 写进 README、源码或版本记录。

## 架构与数据流

Next Story 的界面用 HTML、CSS 和 TypeScript 编写，文件位于 `src/`。本地文件读写和模型连接由 Rust 处理，Tauri 把两部分装进同一个桌面应用。

- **桥接层（bridge）：** `src/project-api.ts` 像总机，把前端动作翻译成后端能接收的调用。
- **Tauri 桌面命令（Tauri command）：** `src-tauri/src/lib.rs` 暴露一组窄入口，分别负责作品的新建、打开、保存，LLM 配置的加载、保存、测试，以及常驻 AI 会话（启动会话、增量发送、取消、结束、历史重放）。
- **业务领域模块（domain）：** 两个 Rust 目录分别封装作品规则和 LLM 配置规则，真正执行校验、文件读写或网络测试；AI 思考生成在 `src-tauri/src/llm_config/` 内由唯一保存配置驱动，常驻驱动进程管理器在 `src-tauri/src/dsh_driver.rs`。

一次请求的责任传递链是：

```text
src/ 前端界面与状态
  → src/project-api.ts 桥接层
  → src-tauri/src/lib.rs 中的一组 Tauri 桌面命令
  → src-tauri/src/project/ 或 src-tauri/src/llm_config/ Rust 业务领域模块
  → src-tauri/src/dsh_driver.rs 常驻驱动管理器 → sidecar/driver/ 驱动进程
```

箭头表示一次请求怎样逐层交给下一层，不代表调用后没有回应。处理结果和错误会沿原路返回前端，再由界面显示给用户。

### 作品新建、打开、保存流程

1. 用户在前端新建、打开或手动保存作品。
2. `src/project-api.ts` 调用对应的 `create_project`、`open_project` 或 `save_project` Tauri 桌面命令。
3. 桌面命令把任务交给 `src-tauri/src/project/`。
4. 作品业务领域模块校验作品名、保存位置或作品结构，并创建、读取或保存作品目录。
5. 路径、作品内容、成功结果或可读错误返回前端。

### LLM 配置加载、保存、测试流程

1. 用户在 LLM 配置页加载、填写、保存配置，或点击测试连接。
2. `src/project-api.ts` 调用对应的 `load_llm_config`、`save_llm_config` 或 `test_llm_connection` Tauri 桌面命令。
3. 桌面命令把任务交给 `src-tauri/src/llm_config/`。
4. LLM 配置业务领域模块校验唯一配置。加载和保存会读写应用本地数据目录中的 `llm-config.json`，测试会使用当前表单配置发起真实的兼容 OpenAI 接口格式请求。
5. 成功状态或可读错误返回配置页。

这层分工保护了两个本子的边界。在应用内部，前端不能绕过限定用途的桌面命令随意碰硬盘，作品文本只能经过作品业务领域模块的明确保存流程，LLM 配置和网络测试则留在独立的 LLM 配置业务领域模块，不会把 API Key 或 AI 输出写进用户文档或作品元数据。

### AI 思考生成与追问流程

1. 用户在 AI 面板直接输入问题（编辑器选区会作为可选重点提示自动附带）。前端为本次对话分配会话身份并启动常驻会话。
2. `src/project-api.ts` 调用 `ai_start_session` 与 `ai_send_message` Tauri 桌面命令：首轮消息由后端组装（固定系统提示词 + 用户问题 + 可选选区材料），追问只发送新增问题。
3. 桌面命令把消息交给常驻驱动进程（`sidecar/driver/`），由它维护会话历史并发起真实流式 `chat/completions` 请求；流式增量经 `ai-delta` 事件逐字转发前端。会话上下文只在驱动进程内存中，不落盘。
4. 合法非空的 assistant 回复作为纯文本返回前端（完成全文为最终事实），显示在独立 AI 面板；失败返回稳定 `code` 与中文可读 `message`，不含 API Key、Authorization、请求正文或完整远端响应。
5. 首次回应成功后，用户可在面板里继续追问、取消生成；新建对话或切换作品会结束当前会话。驱动进程意外退出时自动重启并重放显示历史恢复会话。AI 生成和追问会把上述创作内容发送给用户配置的 API 服务；测试连接只发送固定测试语句和身份凭据，不发送用户剧本文字或临时对话。
6. 这条链路不持有任何写入草稿本或正文本的入口，AI 面板只显示临时材料。

## Windows 开发准备

本项目使用 Tauri 2。按 2026 年 7 月核对的官方 Windows 前置条件，需要准备：

1. **Microsoft C++ Build Tools**，安装时勾选 **Desktop development with C++** 工作负载。
2. **Microsoft Edge WebView2**。Windows 10 1803 及以后版本通常已经安装，缺失时再从微软安装。
3. **Rust**，通过 rustup 安装，并使用稳定版 `stable-msvc` 工具链。
4. **Node.js LTS 和 npm**。

官方说明见 [Tauri 2 Prerequisites](https://v2.tauri.app/start/prerequisites/)。不要照 README 硬装固定版本，使用官方当前支持的稳定工具即可。

`VBSCRIPT` 不是一般开发的必装项。只有构建 MSI 安装包时报出相关错误时，才按 Tauri 官方故障排查说明启用它。

### 首次安装

打开终端进入仓库根目录，然后安装前端和 Tauri CLI 依赖：

```bash
npm install
```

## 运行、检查与打包

命令分两类。第一类完成后会自己返回终端，第二类会持续运行，必须由用户停止。

### 会执行完并返回的命令

| 命令 | 用途 |
| --- | --- |
| `npm run check` | 依次运行类型检查、前端测试、前端构建和 Rust 测试，适合日常总检查 |
| `npm run typecheck` | 只检查 TypeScript 类型，不生成文件 |
| `npm run test:frontend` | 运行 `tests/*.test.ts` 前端状态测试 |
| `npm run build` | 执行 TypeScript 检查并构建前端产物 |
| `npm run test:rust` | 运行 `src-tauri/Cargo.toml` 对应的 Rust 测试 |
| `npm run tauri:build` | 构建桌面应用安装包，耗时通常比前端构建长 |

### 会持续运行的开发命令

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 只启动 Vite 前端开发服务器，不启动桌面外壳 |
| `npm run tauri:dev` | 启动完整 Tauri 桌面开发模式，可操作应用窗口 |

持续运行、不自动返回是正常行为。`npm run dev` 需要回到终端按 `Ctrl+C` 停止。`npm run tauri:dev` 可以关闭桌面应用窗口，也可以在终端按 `Ctrl+C` 停止。

第一次运行 `npm run tauri:dev` 时，Rust 需要编译依赖，可能等待几分钟。期间暂时没有新日志不一定表示卡住，只要没有明确报错，可以继续等待。

| `openspec/changes/` | 正在提议或实现中的 change，内容可能尚未进入当前实现真相 |
| `openspec/changes/archive/` | 已完成 change 的实现历史，记录当时为什么改、怎么改 |

归档 change 负责回答“过去发生了什么”，主规格 `openspec/specs/` 负责回答“现在已经做成什么”。两者冲突或表述不同的时候，以当前主规格描述已实现状态。
