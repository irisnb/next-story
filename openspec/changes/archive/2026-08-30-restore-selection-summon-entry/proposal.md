# 提案：恢复选区 AI 及时召唤入口

## Why

2026-08 常驻会话改造时，「AI 及时召唤」「思维扩展」「选区浮动入口」在未与用户对齐的情况下被移除，且文档把「直接提问是唯一首轮入口」写成用户接受过的结论——用户从未说过、从未接受过。经 2026-08-30 探索轮（见 `.omo/选区AI入口恢复决策-及时召唤与思维扩展-2026-08-30.md` 第八节），用户确认：

- **及时召唤以正式功能身份恢复**：它承担「选中一段文字、不知道该问什么、不打字直接以选区开始想」的快速反应职能，是产品「降低获得帮助前置门槛」使命的入口级能力，未来还会丰富迭代。
- **思维扩展正式退场**（经用户确认，区别于上次的擅自退场）：其「带选区打字」路径已被「重点提示 + 直接提问」完整承接。
- 所有「唯一入口」「旧选区工具已退场」的记录必须一并修正。

## What Changes

- **恢复「及时召唤」为正式功能**：选中文字时编辑器旁浮出「AI」按钮，点一下直接以选区为材料发起首轮，无需打字。
- **召唤走常驻会话流式通道**：不复活旧的一次性 legacy 通道；召唤发起的对话与直接提问发起的对话是同一种统一临时对话（流式、可追问、可取消、可新建对话替换）。
- **召唤遇已有对话时替换**：语义与「新建对话」按钮完全一致（无确认直接替换）。
- **后端组装召唤首轮任务**：常驻协议要求问题文本非空；召唤首轮由后端把选区材料组装成合法首轮任务，前端不造假文本。
- **系统提示词结构改造**：拆掉两块刻死的 `const` 提示词，改为「空位 + 现场填入」结构——红线层（每次照抄）+ 入口层（按调用方式）+ 语境层（按本次可见材料）。本次不实现动态机制，只立结构。
- **思维扩展退场收尾**：移除其保留的 DOM 与相关死代码；浮动菜单不再存在（单动作按钮，无菜单）。
- **记录修正**：`AGENTS.md` 与相关规格中「直接提问是唯一首轮入口」「旧选区工具已退场」的表述全部更正。

## Capabilities

### New Capabilities

- `selection-ai-summon`: 及时召唤功能——浮动入口的出现与点击行为、以选区为材料无打字发起常驻会话首轮、替换语义、流式呈现与后续追问衔接、召唤场景的选区冻结与预检门禁。

### Modified Capabilities

- `persistent-ai-panel-entry`: 直接提问不再是唯一首轮入口；及时召唤作为第二首轮入口进入同一统一临时对话，共享同一事实源。
- `selection-ai-invocation`: 选区快照冻结要求的适用范围从「附带选区的直接提问」扩展到「及时召唤发起」；预检冻结作品身份要求覆盖召唤入口。
- `ai-feature-orchestration`: 撤销「退场工具不得接入编排」中关于及时召唤与浮动入口的部分；思维扩展保持不得接入。
- `ai-panel-rendering-boundaries`: 渲染边界允许及时召唤入口状态；思维扩展预备态仍禁止出现。
- `ai-panel-dom-contract`: 「直接提问唯一首轮入口」表述修正为统一临时对话服务两个首轮入口。
- `llm-configuration`: 受限 AI 思考生成的触发范围从「直接提问触发」扩展为「直接提问或及时召唤触发」。
- `project-mission-governance`: `AGENTS.md` 摘要要求更新——两个首轮入口、思维扩展退场、召唤恢复的如实表述。
- `project-readme`: README 中「旧选区工具已退场」表述更新为「思维扩展已退场、及时召唤已恢复」。

## Impact

- **前端**：`src/selection-entry.ts`（重新装配，去掉菜单改为单动作）、`src/ai-feature.ts`（接线恢复）、`src/ai-feature-first-request.ts` 及其测试（legacy 流程随通道决策退役删除）、`index.html`（思维扩展 DOM 移除）、`src/ai-panel-state.ts` / `src/ai-panel.ts`（召唤发起的对话状态复用）。
- **后端**：`src-tauri/src/llm_config/generate.rs`（提示词结构改造为空位+填入；召唤首轮任务组装；常驻会话消息路径支持召唤语义）。
- **文档**：`AGENTS.md`「当前实现的诚实边界」、`.omo/选区AI入口恢复决策-*.md`（已更新）。
- **不受影响**：AI 绝不写入用户文档等安全边界；多对话/会话列表（明确出范围）；Agent 自动上下文等未来能力。
