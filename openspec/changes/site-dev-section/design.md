# 设计：官网开发者区与仓库链接

## Context

官网（`Wangye/index.html`，黑白纸墨·印章红·章节式滚动·动效系统·按需画廊）已上线且定稿（archive/2026-10-24-site-and-readme-launch）。本次为增量：加 GitHub 仓库链接＋「给开发者」板块。全部内容事实来自已归档规格（AGENTS.md 与 openspec/specs），技术细节公开无新增暴露（openspec 本就在公开仓库里）。

## Goals / Non-Goals

**Goals:**
- 访客一键可达 GitHub 仓库页（页眉＋页脚常驻）
- 技术同行在官网能读到三件事：实现思路、系统提示词组装、每轮最新文本装配
- 视觉延续定稿语言（纸墨、发丝线、四级灰、等宽点缀），不另起炉灶

**Non-Goals:**
- 不做多页文档站/博客；不动产品代码；不动 README；不改既有章节与动效

## Decisions

**D1 位置**：「给开发者」章节放在第四章（导入与导出）之后、判断权行之前——写作者的主叙事先走完，开发者内容殿后，不抢普通访客动线。GitHub 链接两处：页眉导航（「GitHub ↗」，与「下载 Windows 版」并列）＋深色页脚版权行旁（等宽小字）。

**D2 内容三块（事实清单，文案按此展开，不得超出）**：

1. **实现思路**——三层事实：
   - Rust/Tauri 后端＝项目数据的可靠保管者：内容树、文档保存、格式校验、版本迁移、事务一致性、崩溃恢复（重放恢复所有在途讨论）
   - DSH 驱动＝项目内容的智能使用者：AI 推理与陪想回应；取材只经统一受控只读边界
   - 数据与 AI 路径隔离：项目服务不注册为 AI 可调用的写文件工具；AI 输出永远是用户文档之外的临时材料，用户亲手复制粘贴
   - 佐证：规格驱动开发——79 项已归档规格、125 个归档变更、Linux＋Windows 双平台全量门禁 CI

2. **系统提示词组装**——两条装配线：
   - 日常陪想（每轮后端集中组装）：公用基础提示词（红线／基本立场／工具／材料规则）＋本次问题与材料（关注文档现场／允许目录投影／跨文档字面检索片段／选区重点提示）＋提问方式；首轮与追问同构
   - 制作模块（链路装配）：固定底座＋回应要求卡＋回应风格卡（可改可加）＋每轮动态注入；版本不可变、可回退，启用指针下一轮生效；制作对话与日常讨论、上下文相互隔离
   - 材料不足时：按需补读——模型发起授权请求，用户允许后经 `story-list`/`story-read`/`story-search` 受控只读补读，出处入「本次参考了什么」

3. **每轮输入最新文本**：
   - 每轮自动附带关注文档「现场」：已保存正文，或**经校验的未保存快照**——不是缓存旧文
   - 材料出处持久化，「本次参考了什么」轻量可查看，不打断对话
   - 追问只发送增量问题，历史由常驻会话在驱动进程内维护；长对话自动压缩承接，超限报错不静默砍史
   - `message_sent` 回执折算发送确认，无回执不伪造

**D3 视觉**：章节延续内容自适应＋背景交替节奏；三主题用「01/02/03」编号或发丝线分节；关键术语（公用基础提示词、未保存快照、story-read 等）可用等宽字体点缀；不加新动效种类（沿用既有 reveal/揭幕），不新增图片。

**D4 文案红线**：三块内容讲「怎么做」，不讲「多聪明」；不出现能力/结果承诺；与既有章节同一人称语气（「你／AI」）。

## Risks / Trade-offs

- [技术表述失真] → 事实清单写死在 D2，设计师只做排版组织；验收时逐条对照规格
- [开发者板块拉长页面、稀释主叙事] → 放四章之后、判断权之前，视觉密度收紧（三块紧凑排布）；手机端折叠为与画廊同款的 details 收起式可选——设计师定，但默认展开或轻收起均可接受
- [GitHub 链接破坏页眉节奏] → 与「下载 Windows 版」同款式文本链接，加 ↗ 视觉提示

## Migration Plan

提案确认 → designer 按事实清单实现（仅 `Wangye/index.html`）→ 渲染验收（桌面＋手机＋观察员过目，逐条对照 D2 事实）→ 用户实况确认 → Wangye 提交推送（Pages 自动上线）→ 主仓库 openspec 文档提交推送 → 归档。
回滚：revert Wangye 提交即下线。
