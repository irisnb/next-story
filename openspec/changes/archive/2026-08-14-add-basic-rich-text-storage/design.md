## Context

当前生产写作区已经使用 Tiptap 2.27.2，但只注册 `Document`、`Paragraph`、`Text` 和 `History`，并把内存文档投影为 `.txt`。Rust 后端把两个本子作为字符串，与 `project.json` 组成同一保存世代；选区 AI 也依赖整篇纯文本的 UTF-16 偏移。

本 change 首次让格式成为作品事实，因此编辑器 schema、前后端契约、磁盘格式、保存基线、粘贴和 AI 选区投影必须一起改变。两个本子的 `draft` / `main` 代码标识和事务保存边界保持不变。开发期旧项目没有发布兼容责任，不引入 `.txt` 迁移分支。

## Goals / Non-Goals

**Goals:**

- 可靠编辑、保存并重开正文、两级标题、粗体、斜体和两种列表。
- 用有版本、可校验的 Tiptap JSON 作为每个本子的唯一事实源。
- 保持两个本子与元信息的同世代事务保存、未保存保护和失败恢复。
- 对外部粘贴执行确定的格式白名单和内容完整性保护。
- 从结构化选区生成冻结纯文本 AI 快照，不扩大模型输入范围。
- 提供已确认的固定工具栏、混合状态、无选区禁用和 A2 窄窗口行为。

**Non-Goals:**

- `.txt` 旧项目迁移或双格式兼容。
- DOCX、HTML 事实源、表格节点、图片节点、链接、更多文字或段落格式。
- 内容树、取消双本子、自动保存、复杂剧本排版或 AI 写回。

## Decisions

### 1. 每个本子保存一份带薄外层的 Tiptap JSON

磁盘文件为 `作品文本/草稿本.json` 和 `作品文本/正文本.json`：

```json
{
  "format": "next-story-tiptap",
  "version": 1,
  "document": {
    "type": "doc",
    "content": [{ "type": "paragraph" }]
  }
}
```

`version` 只描述单篇文档格式。空白文档固定为一个空 `paragraph`，与 Tiptap 默认 `Document` 的 `block+` 约束一致。项目整体结构版本由 `project.json` 管理并从 1 升为 2。相比裸 Tiptap JSON，薄外层能在进入编辑器前识别错误文件和不支持版本；相比 HTML，JSON 能保留明确节点与标记而不增加解析和净化事实源的负担。

前端与 Rust 共享等价的文档 DTO 和规范 JSON 样例。相同 marks 的相邻文本必须合并为最大文本节点，文本节点不保存 CR/LF 且不含孤立代理项；首尾和连续空段落原数保留。`orderedList` 起始值和实际编号限制在 JavaScript 安全整数 `2^53-1` 以内。Rust 不解释视觉效果，但必须按 `structured-notebook-storage` 定义的格式版本 1 grammar 严格校验外层、节点类型、属性、标记、Unicode 合法性和整数域，防止损坏或未来 schema 被当前版本静默改写。保存入口先校验两份文档，再开始事务暂存。

### 2. 编辑器 schema 只注册正式支持的能力

在现有扩展上增加标题、粗体、斜体、无序列表、有序列表和列表项扩展。格式版本 1 的列表项只包含一个正文段落，不接受嵌套列表或多段列表项。工具栏命令只通过 Tiptap transaction 修改当前本子；初始化、切换本子和状态查询不生成用户编辑。

文档完整 JSON 是保存状态基线。比较采用稳定的结构值，而不是 HTML 或纯文本；因此只改格式也会正确标记为未保存。保存期间冻结两份完整文档快照，成功后仅将该快照设为基线，晚于快照的编辑继续显示未保存。

### 3. 工具栏状态由明确的选区分析产生

工具栏固定在本子标签下方。无非空文字选区时，段落样式、粗体、斜体、列表和清除格式禁用；撤销重做按当前本子历史启用。段落样式下拉框显示正文、一级标题、二级标题或“多种格式”。

粗体和斜体区分未启用、混合、完全启用三态。未启用或混合时点击统一应用格式，完全启用时点击统一移除。块级命令作用于选区触及的完整段落。列表命令先把标题降为正文，并把正文、同类或另一类列表项统一成目标列表；全部同类时重复点击恢复正文。部分选中列表只拆分并转换选区触及的项目。清除格式把涉及内容统一为普通段落并移除粗斜体与列表结构。

宽窗口为完整单行；窄窗口采用 A2：保留段落样式、粗体、斜体和两种列表，把清除格式、撤销和重做放入“更多”菜单。快捷键仅支持 `Ctrl+B`、`Ctrl+I`、`Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z`，前两者无选区时不生效。

### 4. 粘贴先解析，再归一化到白名单 schema

有 HTML 时使用浏览器 DOM 解析器读取语义元素，只映射本轮支持的标题、段落、粗斜体和列表；`br` 拆成同类型块或同级列表项，嵌套列表按最近列表类型和显示顺序扁平化为相邻列表段，同一 `ol` 被打断后各段按原起始值加偏移保留编号，`li` 嵌套列表后尾随文字追加到该 `li` 自身文字，所有样式属性及未支持标记被丢弃。表格按行转普通段落、单元格用 Tab 分隔，单元格内多块扁平化为空格连接的纯文本。普通容器和嵌入结构按明确元素集合判定，含可见文字的嵌入结构整次拒绝。HTML 与 `text/plain` 同时存在时，两侧各自独立完成 CRLF/CR 规范、NBSP 转空格、行尾空白删除、末尾至多一个 LF 删除和列表前缀去除后比较行数组；无法得到相同文字、顺序和段落边界时整次拒绝。无 HTML 时使用纯文本，清除粗斜体但保持插入位置所属的段落或列表上下文。

图文混合保留文字、忽略图片并提示；纯图片不产生 transaction。解析结果必须覆盖全部可可靠提取的可见文字；不能保证时整次拒绝，不插入残缺结果。所有结果在插入前由同一 Tiptap schema 校验。

### 5. AI 快照使用选区切片的专用纯文本序列化

AI 不再用整篇纯文本 UTF-16 `start/end` 作为结构化文档中的权威定位。触发时冻结 `draft` / `main`、Tiptap 选区位置和由该选区切片生成的 `selectedText`。序列化只用单个 LF 表示块边界，投影不产生前导或尾随 LF；完整非空列表项固定添加 `- ` 或 `实际编号. `，部分列表项不添加前缀，空块保留为空行。标题等级与行内标记始终丢弃。

后续请求只读取已冻结的 `selectedText`。位置只用于当次运行期来源和界面锚定，不持久化，也不作为重新读取编辑器的依据。

### 6. 继续使用现有三文件事务

事务暂存文件和可见文件改为 `.json`。系统先只读确认项目结构版本为 2，只有受支持版本才运行可能写盘的恢复；恢复流程在提交暂存世代前校验两份结构化文档和元信息。损坏、不支持版本、超限或 schema 不合法都在进入编辑器前返回中文错误。系统绝不把失败内容替换为空文档。

## Risks / Trade-offs

- [Rust 与 Tiptap schema 校验规则漂移] → 用共享 JSON 样例、白名单契约测试和前后端往返测试锁定格式版本。
- [结构化 JSON 比纯文本更大] → 保留读取大小上限并用 20 万汉字及格式组合重新验证内存、载入和保存性能。
- [复杂剪贴板 HTML 差异大] → 只承诺明确白名单；无法证明文字完整时拒绝整次粘贴并给出中文提示。
- [清除格式可能一次改变多个段落] → 只在非空选区启用，并将整个操作作为一个可撤销 transaction。
- [不迁移旧 `.txt` 项目会使开发样本无法打开] → 这是正式发布前有意的 breaking change；测试夹具重建为新格式，不维护双读取路径。

## Migration Plan

1. 升级项目结构版本并切换新建项目为两份空白结构化 JSON。
2. 同步切换前端 DTO、Rust DTO、路径、校验和事务暂存文件，不保留中间可发布状态。
3. 将现有开发测试夹具重建为新版结构；旧 `.txt` 文件不自动转换。
4. 验证创建、打开、保存中断恢复和重新打开后，再开放工具栏和富文本粘贴。
5. 若实施未完成，不发布混合格式版本；通过 Git 回退整个 change，现有开发项目需重新创建，不自动降级 JSON 为 `.txt`。
