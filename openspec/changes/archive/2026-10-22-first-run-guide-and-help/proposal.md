# 提案：首次启动引导与帮助分区（first-run-guide-and-help）

## Why

软件概念多（项目、讨论、链路、补读授权、手动保存……），新用户第一次打开全程零介绍，全靠摸索。产品负责人拍板：需要一份首次启动的软件介绍与操作指引，且随时可在设置页复习，并配一份常见问题指南。

方向经两轮外部调研校准（业界写作/创作软件案例 + NN/g 等一手研究）：首启弹窗只讲**价值**与**唯一核心概念**（项目＝你电脑上的一个文件夹，不使用类比），界面与操作细节全部下沉到帮助分区与既有空状态/就地提示，按用户需要时再查。

## What Changes

- **新增首次启动引导**：首次启动在欢迎页弹出**四卡向导**（分步卡片、可跳过、可后退、带进度点）：①价值与产品灵魂（你写，AI 陪想，不改稿）②「项目」＝你电脑上的一个文件夹＋马上动手（新建/打开）③AI 怎么用（直接问；自动看你在写的那篇；圈选提问）④开始之后（新项目自带空文档；AI 去设置连接；帮助入口指路）。完成或跳过后记录标记，此后启动不再自动弹出。
- **设置页新增「帮助」分区**（默认收起的抽屉）：「重看软件引导」按钮（重放同一向导）＋「常见问题」十一条内嵌可展开问答（新增「API 是什么？怎么获取？」附国内 AI 服务商官网直达链接；四个标签各管什么／会自动保存吗／AI 怎么连／AI 怎么用·追问停止排队／它看了我哪些东西／补读授权／有没有它不能看的／AI 会改我的稿子吗／制作页详解／怎么重看软件引导）。帮助分区必须与向导**同版本**交付（向导卡 4 与 FAQ 互相指向）。
- **设置页三分区统一抽屉化**：「AI 连接」更名「API 连接」，与「写作显示」「帮助」统一为默认收起的抽屉（左侧三角指示一致）；表单元素 id 全部不变，行为不变。
- **术语统一**：界面「新建对话」按钮统一为「新建讨论」（三处按钮＋读屏 aria 标注＋README 相关说明），消除「讨论／对话」双名；行为完全不变。
- **文案全文定稿**：四卡与 FAQ 文案经多模型议会评审＋逐条事实核对（三处失实、一处方向误导已修正），全文见 design.md 附录；文案与代码分离，集中存放便于修订。
- **非目标（明确不做）**：情境触发小卡、聚光式高亮导览、任何新的自动弹窗机制、AI 行为或上下文策略的任何改动、引导内容个性化。

## Capabilities

### New Capabilities

- `first-run-guide`：首次启动四卡引导的触发时机（仅首次）、跳过与完成标记、卡片顺序与内容边界、从设置页重看的规则。
- `settings-help-section`：设置页「帮助」分区的构成（重看入口＋常见问题问答列表）、FAQ 内容与真实行为的一致性要求、与向导同版本交付。

### Modified Capabilities

（仅术语统一「新建对话」→「新建讨论」，全部为措辞级增量，行为要求不变）

- `clear-current-ai-conversation`：入口名称更新
- `ai-panel-dom-contract`：新建对话控件命名更新
- `conversation-list`：常驻入口清单中的命名更新
- `conversation-management`：触发入口命名更新
- `discussion-windows`：触发入口命名更新
- `resident-ai-session`：错误提示中入口名称更新
- `project-readme`：README 对该入口的描述更新

## Impact

- **前端**：`index.html`（向导 dialog DOM、设置页帮助分区、三处按钮改名）；`src/` 新增引导模块与帮助模块（文案集中在独立内容文件，与逻辑分离）；`src/main.ts` 装配。
- **本地存储**：沿用显示偏好的 localStorage 机制新增首启完成标记（键名设计阶段定，`next-story.` 前缀）；清缓存后向导重新弹出属预期无害行为。
- **测试**：前端单测覆盖向导状态机（首次/跳过/完成/重看）、帮助分区渲染、FAQ 折叠交互、按钮改名后的既有断言更新。
- **不触碰**：Rust 后端、sidecar/DSH、AI 会话与取材行为、项目数据格式、文档写入路径。不涉新窗口、插件权限、CSP、外部进程、文件对话框——归档前硬性真机冒烟条款不适用，但须产品负责人对引导视觉与文案做真机验收。
- **验收基线**：议会评审留下的五条事实核验（A 文档讨论问 B 仍以 A 为重点／非打开文档仅已保存正文可读／链路库初始为空无官方预置／制作对话不读作品材料／导图为提示词组装结构图）作为文案与行为一致性的上线抽查。
