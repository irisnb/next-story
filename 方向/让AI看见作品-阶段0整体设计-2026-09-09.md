## 一、阶段 0 目标

阶段 0 的目标是：在「让 AI 看见作品」进入具体实现之前，先把会影响后续结构、界面和数据的整体关系想清楚、写下来、确认掉。它不实现任何功能，不修改已归档规格，也不创建一个包揽全部后续工作的 change。

本阶段要沉淀和明确：

- 两个入口（常规直接提问、AI 及时召唤）如何共存、各自承担什么职责；
- A（系统主动附带材料）与 B（Agent 按需补读）如何组合；
- 作品读取经过怎样的受控只读边界，AI 为何永远不能写作品；
- 材料如何按发送时刻取最新现场、标记版本、说明来源；
- 多窗口、讨论保留、保存与恢复、并发排队这些目标如何定义；
- 哪些问题本阶段还定不了，必须留给后续设计或 OpenSpec 提案决定。

完成标准见第十节。

## 三、已确认的方向与关系

### 3.1 产品目标

用户直接用自然语言提问，系统自动准备有依据的作品材料，帮助用户重新看见故事。用户不必先配置上下文、整理参考文档，或把问题改写成搜索词；AI 仍只提供观察、问题、假设和可能性，不替用户判断，也不把假设冒充作品事实。

### 3.2 DSH 是 Agent 运行时基础

当初将核心更换为 DSH，就是为了它的 Agent 循环和插件能力；只是目前先使用了其中的会话能力。因此不能把 DSH 只定位成会话或上下文管理器。后续应优先复用 DSH 已有的 Agent Loop、工具注册、工具调用事件、取消与可恢复运行机制，再由 Next Story 的 Rust/Tauri 作品服务负责权限和数据边界；不另造一套 Agent 核心。

### 3.3 两个入口

- **常规直接提问**：用户在常驻面板直接自然提问，结合作品把问题想清楚；允许为取得依据多花一些时间，同时设明确停止条件。
- **AI 及时召唤**：围绕眼前选区、无需先输入问题，尽快开始陪想；冻结选区后直接生成首轮，不等待整篇或全作品检索、多轮补读。

两者进入同一种临时会话，共享讨论管理、保存、权限、版本和安全边界，但不强行共享首轮取材策略。选区始终是可选的重点提示，不是使用 AI 的前提。

### 3.4 A 系统主动附带材料与 B Agent 按需补读可组合

- **A：系统主动附带材料**。程序按明确规则准备当前稿件、作品结构，并可增加字面检索结果；模型不决定这一阶段读什么。
- **B：Agent 按需补读**。复用 DSH 已有运行机制，让模型通过受控只读工具请求材料，再根据读到的内容决定是否继续补读。

A 是程序准备材料，B 是陪想 Agent 按需使用工具；在同一段讨论中，它们共享材料记录并形成一份连贯回应，不必分别调用两个 AI 各答一遍。A 的自动跨文档字面检索是可选项，根据实际效果再决定，不作为 B 的前置门槛。

### 3.5 多窗口与讨论保留是目标

用户明确希望多个 AI 对话窗口可以同时显示、移动、并排对照，而不是只在一个面板里切换标签。常规讨论与及时召唤可能参考不同材料、沿不同路径形成解释，用户希望分别保留和比较，不因开启新讨论而丢弃旧讨论。

### 3.6 作品读取经过受控只读边界

无论采用哪种桥接方式，作品读取都必须经过 Rust 的受控只读接口，AI 运行环境不能绕过它直接访问作品目录。当前未保存内容须由前端提供，并通过同一读取边界校验，不能只读磁盘上的旧稿。A 与 B 应共享受控只读作品接口，统一处理允许读取的范围、回收站和稿件版本，避免形成两套权限或版本规则。

### 3.7 AI 不写作品

AI 永远不直接改用户文档，任何版本、任何授权都不例外；AI 输出永远是作品之外的临时材料，用户亲手复制、粘贴、编辑、保存后才进入作品文本。

### 3.8 用户保留判断权

内容权、解释权、评价权、方向权都在用户手里。AI 只提供观察、问题、假设和可能性。

### 3.9 常规追问按发送时刻取得最新现场（含未保存内容）

常规讨论每次追问重新取得发送时刻的当前文档最新快照，包括未保存修改。发送后继续编辑，不改变已经发出的这一轮材料；下一轮再取得新稿。不能只在首轮读稿、后续沿用旧版。

### 3.10 可见性是开关，而非优先级

AI 可见性设置是已确认方向、尚未实现的功能。它是用户可理解的开关，不是四级参考优先级，也不采用继承、覆盖等旧用户概念。可见性规则一旦生效，必须覆盖目录信息、正文、当前未保存快照与选区，不能因材料来自编辑器而绕过权限。

## 四、两个入口与 A/B 配合流程

### 4.1 常规提问流程（未来设计草案，尚未实现）

```
用户自然提问
  → A 自动提供约定的当前稿件、作品目录与可选重点
  → 陪想 Agent 阅读问题与已有材料
  → 材料足够：直接回应
  → 需要补读：B 决定搜什么、读什么
      → 共同只读接口校验权限，返回原文与版本
      → Agent 根据新材料决定继续补读、回应或说明缺口
```

### 4.2 及时召唤快车道

- 及时召唤首轮以用户明确选择的文字快照为材料，不要求输入问题，不等待整篇或全作品检索、多轮补读。
- 首轮完成后，后续追问默认继续围绕首轮冻结选区；用户重新选择其他文字发起召唤时，范围自然改为新选区。
- 用户希望扩大到当前关注文档或其他文档时，需在讨论中明确提出；系统不悄悄把快车道升级成完整读稿流程。

### 4.3 A/B 配合需遵守的四条规则（方向性，细节待提案）

1. **权限共用**：主动附带与工具补读都经过同一读取边界。
2. **材料记录共用**：B 知道 A 已提供的文档、范围和版本；同版全文避免重复装入，片段不足时允许补读前后文。
3. **本轮版本一致**：常规追问重新取得约定的最新现场；同一轮 B 再读当前稿件时沿用本轮冻结版本，其他原文注明来源与版本，避免新旧稿混杂。
4. **允许停止**：材料足够时不强制搜索；达到限制、权限不允许或材料不可得时说明缺口，不为得出确定答案无限补读。具体限制待提案确定。

## 五、架构责任边界

- **Rust / Tauri 后端是作品数据的可靠保管者**：内容树、文档保存、格式校验、版本迁移、事务一致性和崩溃恢复等确定性工作由它负责。
- **DSH 是作品内容的智能使用者**：AI 推理、思考回应和陪想能力。AI 需要参考作品时，只能通过受控只读接口取得被允许提供的内容；AI 运行环境不获得写入用户文档的能力。
- **作品数据与 AI 路径必须隔离**：作品服务不能注册为 AI 可调用的写文件工具。任何 AI 输出都只能留在用户文档之外。
- **当前实现与能力定位分开判断**：DSH 已有的 Agent Loop、工具和插件扩展等运行时基础大多已存在，只是当前配置锁住或尚未接入；Next Story 的自主读稿产品能力仍未实现。不能把「框架有能力」写成「产品已实现」，也不能因当前配置锁住能力就另造一套 Agent 核心。

## 六、材料 / 版本 / 权限 / 恢复原则

### 6.1 材料原则（已确认方向）

- 常规每轮冻结约定写作现场，及时召唤冻结选区；每轮材料带可追溯的来源与版本。
- 原文、工具结果与 AI 推测保持区分，不能把 AI 此前的推测当成新稿事实。
- 「系统搜到的材料」不能写成「作品全集」；未命中、未读取或未完整提供的限制要如实说明。
- 参考说明轻量可查看，默认不打断对话。

### 6.2 版本与去重（方向已定，细节待提案）

- 常规追问用当前文档未保存快照配合其他文档的已保存正文；需标明文档身份、来源和本轮版本，避免把当前文档旧磁盘稿混进最新快照。
- A 与 B 共用记录，防止同一篇旧磁盘稿混入新快照；同版全文避免重复装入。

### 6.3 权限（已确认方向）

- 所有读取路径服从同一受控只读规则；读取时过滤不能自动撤回已经发给模型的文字。
- 关闭可见性后，已有运行会话和保存记录中的旧材料如何处理，待后续提案明确（见第九节）。

### 6.4 恢复（已确认方向，细节待提案）

- 当前主要恢复用户与助手文本；未来增加工具读取后，材料和工具事件怎样保存、怎样恢复需要提前验证。
- 不自动重发未完成请求；中断和失败不伪装为成功。

## 七、多窗口 / 保存 / 等待原则

### 7.1 多窗口与讨论保留（目标已确认，行为细节待提案）

- 多个窗口同时显示、移动、并排对照，各自保留讨论；新召唤开启另一段独立讨论，不替换旧对话。
- 各个窗口分别追问、停止与重试；对话历史、材料版本、生成状态和取消结果互不串用。
- 不同窗口的 AI 推测不自动混入另一段对话，也不自动合并为一份作品结论；可以保留不同解释，但同一处原文事实被说反时要核对原文。
- 窗口是讨论的显示容器，讨论本身不依赖窗口存活；关闭窗口不删除讨论，删除是单独的明确动作。

### 7.2 保存（方向已确认，位置与格式待提案）

- 讨论内容和窗口布局是两套不同数据：对话、轮次、生成终态、材料来源和必要恢复信息属于系统管理的讨论记录；窗口位置和尺寸只属于当前运行状态。
- 保存失败必须对用户可见，不能伪装成已经保存；保存 AI 对话不等于写入作品正文。
- 保存由受控应用服务完成，系统对话档案与用户作品正文分开。

### 7.3 等待（方向已确认，目标数值待实测）

- 主要在意用户使用时的等待；保留「AI 及时召唤」就是为了需要即时帮助时有快车道。
- 不承诺固定秒数，也不承诺应用能消除模型服务本身的排队；真实等待目标根据阶段 1 实测与用户约定后再定。
- 等待测量从早期验证开始，至少分开记录：提交到第一次实际模型回应的时间、提交到完整回答结束的时间、应用内排队与作品取材和额外模型往返分别造成的等待。

## 八、当前实现基线

以下以已归档规格为准，是本仓库当前真实已实现的能力：

- **常驻临时会话**：支持面板直接提问与选区「AI 及时召唤」两个首轮入口，两者进入同一种临时会话。
- **流式逐字回复**、首次回应成功后的**线性临时追问**、**可取消生成**。
- **上下文自动压缩**：长对话由框架压缩承接，超限报错提示新建对话，绝不静默砍历史。
- **崩溃恢复**：驱动进程意外退出后自动重启，重放显示历史恢复会话；临时对话不跨应用重启持久化，不提供历史会话列表。
- 当前只有一个临时对话，新召唤会结束并替换旧对话；追问锚定首轮冻结选区。

**尚未实现**（不在当前基线内，不得写成已实现）：

- 完整作品读取（自动提供当前文档全文、最新未保存内容、全作品结构）；
- Agent 按需补读其他文档；
- 持久化会话、会话列表、会话内快捷跳转；
- 多窗口、多对话保存、AI 可见性设置；
- 阶段 1 的离线验证 change 已完成（22/22 项任务，离线确定性验证通过），但它是离线验证材料，**不代表真实 Rust/Tauri/DSH 生产读稿链路已经接通**。

## 九、尚未确定的细节（需后续设计 / OpenSpec 提案决定）

以下问题在阶段 0 不拍板，必须进入对应的单一 OpenSpec change 决定，不得因为本文件已存在就假装已实现：

1. **对话归属与当前写作现场**：对话如何按作品归属、记录起点文档与材料来源；多窗口下常规追问的「当前文档」是否跟随写作空间、切文档或切作品后如何处理；不能让窗口焦点隐式决定读取范围。
2. **窗口关闭 / 停止 / 删除**：关闭窗口、停止本次生成、删除对话分别意味着什么；生成中关闭窗口是否继续运行；关闭后能否重新打开已有讨论。
3. **保存位置和恢复**：记录存在哪里、按什么归属；作品目录搬迁后怎样找回；保存失败、中断、进程崩溃与应用重启分别怎样处理，不自动重发未完成请求。
4. **并发与排队**：同时生成的上限、应用内排队与快车道安排；单个停止、超时或迟到结果只能影响对应讨论。
5. **材料版本记录和旧材料处置**：本轮看的是哪一版；哪些材料需要保存以支持回看与恢复、怎样清理；不默认永久留存所有未保存全文。
6. **可见性变化对历史材料影响**：关闭可见性后，已有运行会话和保存记录中的旧材料怎样处理；读取时过滤不能自动撤回已经发给模型的文字。
7. **召唤追问范围**：及时召唤首轮冻结选区后，后续追问是否继续保持局部取材、怎样转入更广的作品讨论。
8. **检索 / 体积 / 停止规则**：自动字面检索的抽词、排序、体积控制；补读的次数/时间/权限停止条件；基础材料超限如何处理。
9. **真实等待目标**：首字与完整回答各接受怎样的等待；如何比较单独使用与常规、召唤同时使用的结果。
10. **DSH 生产桥接协议**：真实 DSH 事件字段、工具调用事件、用户中断与恢复的错误终态采用什么协议；是否采用 MCP 及其具体接口，须在提案中核对，不锁成唯一答案。

## 十、阶段 0 完成标准与下一步

**完成标准**：

- 已确认的方向与关系（第三至七节）已经写清并得到用户确认；
- 当前实现基线（第八节）与已归档规格一致，没有把未实现能力写成已实现；
- 尚未确定的细节（第九节）已经明确列出、没有被误写成已决定；
- 典型使用过程能走通、用户看得懂并确认。

**下一步**：

- 阶段 1「DSH 能力解锁与接入验证」的离线验证 change 已完成（待归档）。
- 阶段 1 归档后，待阶段 0 完成确认，再进入阶段 2 提案（或按阶段 0 决定调整顺序）。
- 每一步都单独 propose → 用户确认 → apply → archive，一次只开一个 change。
