# design：提示底座两段过时限制的小范围修正

> 决策来源：用户 2026-10-06 拍板「先修正才是正事，不先做 ABC 实验」。两段候选新文字沿用用户已见过的 2026-10-05 草案 §3.1 逐字文本。本 design 核读并锁定：精确改动文本、条款覆盖映射（证明无永久边界丢失）、候选文字宽窄评估、受影响路径与定向测试计划。**不写代码；apply 授权后按 tasks 执行。**

## Context

- 红线层 `constitution_prompt()`（`generate.rs:28-33`）每次组装照抄，拼进**首轮 user 消息文本**（`compose_message_text`，非 system 角色）；追问轮只发增量问题、无提示前缀（历史由常驻会话在驱动内维护）。崩溃恢复重放经 `replay_prompt_prefix`（`generate.rs:382-387`）复用同一 `compose_system_prompt`——**无独立副本**，改一处即全链一致。
- 两段旧文过时的实证（对照现行行为，均已核读）：
  - 旧段一写于阶段五 A（automatic-story-context，2026-09-14）与阶段六（agent-on-demand-reading，2026-09-21）之前；现行常规请求**实际附带**关注文档现场材料（已保存正文或经校验快照）、目录投影、跨文档字面检索片段，授权后还有 story-list/read/search 返回——「不能声称读取或使用当前文档全文／选区前后文」与实况直接矛盾，且未区分「提供给你的」与「没提供的」。
  - 旧段二写于旧选区锚定流程；现行有直接提问（可无选区）、关注文档显式切换（下一轮生效）、召唤快车道追问（不取材）——「追问仍锚定首次冻结选区」错误绑死新问题。
- 2026-10-05 草案曾为此设计 A/B/C 隔离实验；用户 2026-10-06 拍板直接修正，实验当前不实施（草案顶部已注记）。

## Goals / Non-Goals

**Goals**
1. 两段旧文精确替换为用户已见的两段候选新文（逐字，不改一字）；其余条款逐字不动。
2. 永久边界零丢失（映射表逐条证明）；定向测试把新语义钉住、旧措辞钉死为不存在。
3. `npm run check` 全绿；除 `generate.rs` 一处字符串常量＋doc 注释外零生产改动。

**Non-Goals**
- 不改身份句／不修改文档／不代写／不润色／不提供替换文本／不判断好坏对错高低／纯文本条款（原样保留）。
- 不改入口层立场句、工具使用层、驱动 persona（`cordis.driver.yaml`）、材料包装文本（`story_search.rs`）。
- 不改权限与取材流程（受控只读、自动材料、按需补读、快车道、消息角色结构）。
- 不增加函数可见性、不建实验代理或测试平台、不发起付费模型调用、不做 A/B/C 实验、不改前端与 sidecar、不加依赖。

## 精确改动文本（apply 时逐字执行）

**改动点＝`constitution_prompt()`（`src-tauri/src/llm_config/generate.rs`）内两次精确替换＋doc 注释同步；其余字符零改动。**

替换一：旧段一 → 新段一（逐字）

```text
不能声称读取或使用选区前后文；不能声称读取或使用当前文档全文；不能声称读取或使用摘要；不能声称读取或使用作品元数据；不能声称读取或使用AI 内容库；不能声称读取或使用历史会话；不能声称读取或使用记忆；不能声称读取或使用用户确认的作品事实。
```

→

```text
只依据本次实际提供的作品材料及经授权工具实际返回的内容，说明参考范围。未提供、未读取或未取得的内容，不得声称已经读过；目录不等于正文，检索片段不等于全文。不得声称具有跨讨论长期记忆。
```

替换二：旧段二 → 新段二（逐字）

```text
追问仍锚定首次冻结选区；只把已有轮次当作当前临时线性对话，不当作持久历史，不当作作品事实。
```

→

```text
追问围绕用户当前问题回应；首次选区仅在与当前问题相关时继续参考。当前讨论中的既有问答可用于承接对话，但 AI 先前提出的猜测和候选不能当作作品事实。
```

doc 注释同步（`constitution_prompt` 上方，现文「红线层：两块旧碑文的边界条款逐字合并，每次组装照抄，一条不删。/ 这是铁律 2/3 在提示词层的落地，不得在组装中弱化或省略。」）：改为如实描述新结构——身份与永久边界条款逐字照抄；材料与追问语义按诚实材料边界声明（2026-10-06 修订，取代旧读取禁止与强制锚定）。

## 条款覆盖映射（永久边界零丢失证明）

| 旧条款 | 去向 |
|---|---|
| 你是陪剧本创作者思考的助手（身份句） | **原样保留** |
| 不直接修改用户文档／不代写正文／不润色／不提供替换文本／不判断故事好坏／正确错误／高级低级 | **原样保留**（铁律 1/3 提示词落地） |
| 不要输出 Markdown 或 HTML 格式，使用纯文本回答 | **原样保留** |
| 八连「不能声称读取或使用……」（选区前后文/全文/摘要/元数据/AI 内容库/历史会话/记忆/用户确认事实） | 新段一覆盖且修正：「只依据实际提供与授权返回＋未提供不得声称已读」取代一刀切禁令；「目录不等于正文、检索片段不等于全文」精确对齐目录投影与检索片段的实际形态；「不得声称跨讨论长期记忆」承接旧「历史会话/记忆」禁令 |
| 追问仍锚定首次冻结选区 | 新段二：「追问围绕当前问题；首次选区仅相关时参考」 |
| 只把已有轮次当作当前临时线性对话，不当作持久历史，不当作作品事实 | 新段二：「既有问答可用于承接对话」（线性对话承接）＋「AI 先前猜测和候选不能当作作品事实」（不当作事实）；新段一「不得声称跨讨论长期记忆」（不当作持久历史／跨讨论） |

## 候选文字宽窄评估（用户要求：若过宽则清楚说明）

- **结论：不过宽，可逐字采用**；一处合读关系须记录在案：
  - 新段一「只依据……」的适用面是**材料来源维度**（本次提供的材料＋授权工具返回），不含对话承接维度——后者由新段二「当前讨论中的既有问答可用于承接对话」明示允许。两段是同一红线层的相邻两句，模型合读；单独摘引段一可能被读窄，属措辞固有属性、不构成改动理由（apply 时不加字）。
  - 新段二「首次选区」仅在有选区的讨论有意义；无选区直接提问讨论中该句空转但无害（旧句「追问仍锚定首次冻结选区」有完全相同的适用面，未引入新问题）。
  - 新段一「说明参考范围」是对模型的行为要求（回应时说明依据了什么），与既有「本次参考了什么」轻量可查看方向一致，不构成新能力承诺。
  - 新段一允许声称「实际提供的作品材料」——这正确反映了阶段五 A 以来系统确实提供关注文档现场材料的实况；「经授权工具实际返回的内容」精确对应阶段六按需补读的授权语义。
- 旧措辞两个失真点（一刀切禁读、强制锚定）即用户所指「过时限制」，本次删除/修正的正是它们。

## Decisions

- **D1 改动收敛在一处字符串常量**：`constitution_prompt()` 是两段旧文的唯一生产出现点（`src/`、`sidecar/` 已全仓核读：旧措辞仅存在于该常量、其测试断言、方向草案与归档历史）；`replay_prompt_prefix` 与 legacy `build_task_string` 都调用 `compose_system_prompt`，无第二副本需要同步。
- **D2 逐字采用用户已见候选文字**：不做再润色（草案 §9 推荐默认的措辞即此两段）；宽窄评估见上节。
- **D3 测试改写为诚实材料边界断言，永久边界保留**：见下方测试计划；不改测试之外的生产代码。
- **D4 主 spec 修订点（已核对 `openspec/specs/` 全目录）**：逐字旧措辞在主 spec 中不存在；语义级受影响者恰好两个——`dsh-headless-generation` 的 requirement「DSH headless 生成与现有链等价」（组装提示语义归属地，补入诚实材料边界与追问语义）与 `selection-ai-summon` 的 requirement「召唤发起进入新讨论」（钉死「追问仍锚定首轮冻结的选区材料」，需改为围绕当前问题）。其余命中的 spec 均为流程级（不重发选区、失败重试用原冻结选区、增量发送等），与提示措辞正交，不改。本 change 原 `prompt-foundation-experiment` delta 已删除，不新建能力。
- **D5 不做效果预验证**：本 change 不发起任何真实模型调用；新文效果经日常使用观察。如实记录：合入前没有关于新文效果的实验或真机数据。

## 受影响路径与定向测试计划

**受影响路径**（全部经 `compose_system_prompt`，一处改动自动一致）：直接提问首轮（`First`）、召唤首轮（`SummonFirst`）、崩溃恢复重放前缀（`replay_prompt_prefix`，两入口）、legacy 一次性链（`build_task_string` 三分支）。追问轮（`FollowUp`）无提示前缀，结构不变（既有测试覆盖）。

**测试改写（`generate.rs` 测试模块，apply 时执行）**：
1. `compose_system_prompt_keeps_all_constitution_clauses_for_both_entries`（现钉死全部旧条款，`generate.rs:880-913`）→ 改写断言清单：**保留**永久边界句（身份句、不修改文档、不代写、不润色、不提供替换文本、三个不判断、纯文本条款）；**移除**八连与旧锚定句；**新增**新段一/新段二关键句；**新增负断言**：不含「不能声称读取或使用」、不含「追问仍锚定首次冻结选区」。
2. `direct_question_compose_declares_grounding_and_output_boundaries`（`:804-835`）→ grounding 断言改为新段一关键句（「只依据本次实际提供的作品材料及经授权工具实际返回的内容」「未提供、未读取或未取得的内容，不得声称已经读过」「目录不等于正文，检索片段不等于全文」「不得声称具有跨讨论长期记忆」）；删除八连循环；永久边界句断言保留。
3. `summon_compose_declares_summon_stance_and_output_boundaries`（`:839-876`）→ 移除「追问仍锚定首次冻结选区」「只把已有轮次当作当前临时线性对话」与八连；新增新段二关键句（「追问围绕用户当前问题回应」「首次选区仅在与当前问题相关时继续参考」「AI 先前提出的猜测和候选不能当作作品事实」）；召唤立场句与永久边界断言保留。
4. `replay_prompt_prefix_follows_replay_origin`（崩溃恢复路径）→ 现断言保留，**新增**：两个 origin 的前缀都含新段一/新段二关键句（钉住「恢复链与首轮同源一致」）。
5. 不动：`build_task_string_*` 系列（断言 `contains(compose_system_prompt(...))`，与措辞解耦，自动过）、`first_and_follow_up_still_require_non_empty_question`、`compose_message_text_injects_context_only_for_regular_entries`、`tool_reading_prompt_is_composed_for_both_entries`（工具层未改）、`summon_first_message_*`。
6. 门禁：`npm run check` 全绿（typecheck/lint/前端/reliability/driver/validation/build/fmt/clippy/test:rust 全链）。

## Risks / Trade-offs

- [新提示词对模型行为的实际影响未经实验或真机预验证] → D5 如实记录；效果经日常使用观察，若出现失真再另行立项（用户已拍板此路径，属有意取舍）。
- [两段合读语义可能被单独摘引读窄] → 宽窄评估已记录合读关系；两段在生产中物理相邻于同一常量，逐字钉死。
- [旧措辞残留于历史文档] → 方向草案已加「已被取代」注记；归档 change 属只读历史，不改。
- [测试改写遗漏导致旧句复活] → 负断言（旧句不得存在）钉死；`compose_system_prompt` 是唯一生产出现点（D1 全仓核读）。

## Migration Plan

单 change 顺序：apply（字符串替换＋doc 注释＋测试改写）→ `npm run check` 全绿 → 归档（主 spec 两 requirement 更新随归档合入）。回滚＝还原两段字符串与对应测试（一处常量，无数据迁移）。

## Open Questions

无。措辞＝用户已见并拍板的两段候选文字（逐字）；范围＝本 design 的精确改动文本；验证＝`npm run check`，不含真实模型调用。
