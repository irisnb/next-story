# 验证记录：锁定主窗口最小尺寸

日期：2026-09-30 ／ 环境：Windows，2560×1440@100%（DPI=96），调试版 `src-tauri/target/debug/next-story.exe`（配置改动后重新 `cargo build`，1m14s）。

## 方法

无手工拖拽条件，采用 Win32 系统契约级验证：`GetClientRect`/`GetWindowRect` 测实际几何，`SendMessage(WM_GETMINMAXINFO)` 读窗口登记给系统的最小跟踪尺寸（Windows 拖拽钳制循环读取的正是该值，等价于拖拽路径的判定依据）。

## 已知边界（如实记录）

- **程序化 `SetWindowPos` 可绕过最小跟踪尺寸**（实测缩至 184×111 仍生效）。这是 Win32 标准行为：MINMAXINFO 约束交互式拖拽，不约束编程式改尺寸。应用内无任何缩放主窗口的代码路径，用户不可达；影响面＝外部程序干预，与本 change 目标（防用户拖坏）无关。网易云音乐等原生应用同等性质。
- 跨进程 MINMAXINFO 探针中 `ptMaxSize`/`ptMaxTrackSize` 读值为乱数，系探针缓冲未清零＋跨进程填充不完整的产物；真实最大化行为（探针 1）正常，不构成疑点。
- 前端与 Rust 代码零改动（仅 tauri.conf.json），`cargo build` 通过即编译级验证；未跑全量 `npm run check`（无 TS/JS 变更，无相关性）。
