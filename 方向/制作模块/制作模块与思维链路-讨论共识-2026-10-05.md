## 0. 一页摘要

**这次谈了什么**：围绕两个暂定概念展开——**思维链路**（系统预组装提示词的过程；多套相互独立的组装方式即多思维链路）与**制作模块**（用户把反复要交代的陪想要求做成可明确启用的成果的地方，具体交付物形态未定），以及它们与现行日常陪想体验（本文工作称谓「日常AI模块」）的关系。

**已确认的方向**（详见 §2–§5、§7、§11）：

- 核心价值：减少求助过程中准备材料、解释背景、反复交代要求的时间和注意力成本；默认体验须独立好用；不承诺模型更聪明或创作结果。
- 思维链路严格定义为系统预组装提示词的过程；不是模型内部思维，不天然等于多 agent 工作流；目标始终是给用户文字回应，且更贴合问题。
- 制作模块与日常AI模块职责、对话、工作状态独立，只经用户明确启用的制作成果联系；不是一个助手两种模式（指职责/对话隔离，不预定进程、模型、布局）；日常聊天不能修改链路配置；制作模块不直接改作品正文。
- 四项共同边界：既有 AI 基础设施向所有链路开放、不分档；共同底线（不写用户文档、读取授权、不冒充事实、判断权留给用户、制作与使用分离）；官方方法可替换而非强制理论；缺失能力如实说明。
- 八条已纠偏理解单列（§7），防止长对话压缩后失忆。

**当前事实**（§8，附来源）：受控读取、关注文档现场材料（已保存正文与经校验未保存快照）、目录与有限字面检索、授权补读、可见性、选区召唤、参考出处、讨论历史保存与隔离均已存在；选区召唤首轮不自动常规取材、不补读是**现行入口规则**；代码中 `llm_config/generate.rs` 有硬编码提示分层、`ai_orchestration.rs` 负责材料装配；现无用户制作入口、链路管理与可视化；DSH skill 当前禁用。

**已认可实验、机制未拍板**（§6 标注处、§9、§10）：用户已认可开展实验（原话「具体的执行和实验我觉得没有问题」）；低风险先出草稿是助手建议，具体草稿 / 试用 / 生效机制未定；版本绑定、生效时机、存储隔离、试用读取授权、应用范围、可视化形态、最终名称、总成本阈值与验证标准均未决；§9 是建议工作清单，**不是批准排期**。

**与既有文档的关系**（§11）：遵守核心方向宪章的核心使命与永久边界。2026-10-05 拍板后，剩余建设范围＝三块拼图（制作模块与多思维链路定制、前端 UI 全量更新、小助手）为当前项目**最后的建设范围**，其余未实现规划已撤出、不再是待办，三块先后顺序未定；AGENTS、宪章、第一版共识与行动计划已按拍板同步（见 §11「后续拍板」；早段时间语境保留为历史）。本次另确认：减少材料准备、解释背景、重复交代要求的成本是 Next Story 核心实用价值（新的方向认识，账本第 18 条已加修订注）。

## 2. 思维链路：严格定义【已确认】

- **定义**：思维链路＝系统**预组装提示词的过程**。多思维链路＝相互独立、服务不同用途的多套组装方式（「日常陪想」「阶段检查」仅为用途举例，不是既定清单）。
- **目标**：无论哪条链路，最终都为用户提供**文字回应**，并让回应更贴合用户的问题。
- **不是什么**：
  - 不是模型内部思维，不展示也不伪称模型「怎么想」；
  - 不天然等于多 agent 工作流；
  - 提示文本的排序不保证程序执行顺序。
- **可视化（方向共识，形态未定）**：帮助用户看懂组装要求、关系、条件；不默认做成拖拽节点编辑器；不伪称展示内部思维实况。
- **执行支持【未决】**：真正的循环或多调用需要额外的执行支持；是否做，未定。

## 3. 核心价值【已确认】

- **要减少的成本**：求助过程中**准备材料、解释背景、反复交代要求**的时间和注意力成本。
- **用户已经省去的**（用户自身情况，如实记录）：访问 ChatGPT 网页与 VPN、反复上传版本的成本。网络便利取决于服务提供，**不承诺普遍免 VPN**。
- **诚实边界**：模型并不因外壳更聪明；提示词非万能；不保证创作结果。
- **默认体验须独立好用**：不制作、不启用任何制作成果时，日常陪想体验自身必须成立，不能依赖制作模块存在。
- **制作模块的定位**：减少用户反复解释陪想要求，**不把这份负担转嫁回用户**（例如让用户先学一套配置概念才能获得帮助）。

## 4. 制作模块与日常AI模块的关系【已确认（方向）；实现细节未决】

- **独立**：职责独立、对话独立、工作状态独立；两者只经**用户明确启用的制作成果**联系。
- **不是一个助手两种模式**：指**职责与对话的隔离**，不预定进程、模型或界面布局的实现形态。
- **分开的理由（原对话明确）**：专人专事——避免日常对话污染链路配置，也避免制作过程中断正在使用的体验。
- **隔离**：制作过程或失败草稿**不影响**正在使用中的成果；日常聊天**不能修改链路配置**——即便用户在日常聊天中提出要求，也不能；不得从日常聊天提取偏好回写链路配置，也不把聊天内容自动流回制作模块。
- **边界**：制作模块不直接改作品正文（见 §5 共同底线）。
- **实现层面【未决】**：具体版本绑定、切换生效时机、存储隔离的实现尚未决定；**不把「每任务版本固定」当作已拍板**。

## 5. 四项已确认的共同边界【已确认】

1. **基础设施全链路开放**：所有既有 AI 基础设施向所有思维链路开放，不按链路人为分档或锁功能；用不用由任务决定；用户权限与 AI 可见性约束照常有效。理由（原对话明确）：已建成的能力不用人为锁功能；开放不是收费式分档。
2. **共同底线**：AI 不直接写入、修改或整理用户文档，即使用户授权也不例外；输出是临时材料，由用户亲手复制、编辑、保存后才进入作品。读取遵守可见性与相应授权规则，不意味着每次正常读取都要弹窗确认；不把假设冒充事实，不假装读过未取得的材料。内容、解释、评价与方向的判断权留给用户。制作与使用职责分离，日常聊天不能修改链路配置。
3. **官方方法可替换**：角度、表达、条件、互动顺序等都是可替换的方法，不是强制创作的理论。理由（原对话明确）：创作者目标多样，官方不能假定唯一方法；官方默认项保留可用、可被替换。
4. **缺失能力如实说明**：不用提示词虚构尚需定义或不存在的软件能力，例如跨讨论长期记忆、定时任务、可定制多 Agent 并行任务编排、长任务断点续跑等；多讨论并发、驱动崩溃恢复、对话历史承接**已经存在**，不在缺失之列。是否需要这些缺失能力，尚未拍板。

## 6. 制作模块如何理解模糊需求【方向共识；标注处为建议·未拍板】

- 不机械扩写，也不宣称比用户更懂用户。
- **适量澄清关键歧义**：关注**总沟通负担**，不只「每次一个问题」；此处「适量提问」指制作需求理解环节，不混同日常聊天（见 §7）。
- 清楚实际软件能力：反馈无法实现之处，不假装能做。
- 【已确认】用户认可开展实验（原话：「具体的执行和实验我觉得没有问题」）。
- 【建议·未拍板】按低风险、可撤回的理解**先出草稿**：这是助手的建议，不是用户拍板；具体草稿 / 试用 / 生效机制未定，也不是自动永久生效的机制。
- **适用范围重要**：喜欢反转 ≠ 每轮反转；不把一次反馈固化为长期偏好。
- **制作成本不能超过收益**。
- **例子（用户原意）**：希望情节讨论多探索反差与反转，但别把台词情绪问题都往反转拽——这个例子用来说明**适用条件**，不是设定唯一的喜剧方法。

## 7. 已纠偏的理解（单列，防压缩后失忆）【已确认】

长对话压缩容易丢失纠偏过程、只留下错误印象，故单列：

1. 本次讨论的问题**不只是回答风格**。
2. **不是通用 multiagent 平台**。
3. **日常聊天不能修改链路配置**：即便用户在日常聊天中要求，也不能。
4. **图（可视化）不把所有内容强制为线性步骤**。
5. **公共能力不分档**（对应 §5 第 1 条）。
6. **「适量提问」指制作需求理解环节**，不混同日常聊天。
7. **多套链路不是多人开会**。
8. **提示词不创造能力**。
