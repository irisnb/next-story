Next Story 是一个 Windows 桌面应用，给想写剧本（或任何故事）的人。写作空间里你亲手创作，旁边的常驻 AI 面板随时回应提问——直接问就行，不需要先配置上下文。AI 只提供观察、问题、假设和带依据的可能性；什么进入作品、故事往哪里走，判断权永远在你手里。它不替代创作所需的感受、思考、实践与坚持；工具降低的，是开始创作和获得帮助的门槛。

界面一览与更多介绍：https://irisnb.github.io/next-story-site/

## 核心特性

### 写作空间与项目

- 「项目」就是一个文件夹：新建、打开、最近项目列表；内容以文件夹和文档组织，删除进回收站、可恢复。
- 富文本编辑器：标题、字符格式、字体字号、颜色与高亮、四种对齐、行距与段间距、缩进、可嵌套列表（五种编号样式）、查找替换、链接、撤销重做；粘贴受控清洗，未知格式与脚本混不进来。
- 写作宽度三档（窄 / 标准 / 宽），稿纸化显示，偏好自动记住。

### AI 陪想

- **未保存也能问**：正在写、还没保存的内容，经快照校验后 AI 也能看到。
- **授权补读**：材料不够时，AI 会请求多读几篇——你允许才读，随时可关，跨重启保留。
- **参考出处可查**：AI 这次参考了什么，轻量可看，不打断对话。
- 两种问法进入同一个讨论：面板直接提问（选区作为可选重点提示附带）；或选中文字点「AI」即时召唤，无需先输入问题。
- 回复流式逐字呈现；可追问、可取消、可停止；多个讨论并存互不阻塞，讨论记录随项目保存、重开可查。
- 每篇文档可单独设置是否允许 AI 查看；隐藏与回收站内容 AI 读不到。
- API 自己配：设置页填一份 OpenAI 兼容接口的地址、Key 与模型名即可，可真实测试连接。

### 制作模块

- 独立页面，定制 AI 的回应方向与说话方式：多链路并存、版本可回退、显式启用下一轮生效。
- 与日常讨论在会话和上下文上相互隔离：日常聊天不会改动链路配置。

### 导入导出与基础

- 导出 Word / PDF / Markdown；导入 Word / Markdown / Final Draft（.fdx）。
- 首启引导与帮助分区（含「API 是什么？怎么获取？」常见问题）。
- 应用单实例：重复启动只唤起已有窗口。

**AI 永远不写你的文档**——AI 输出永远是临时材料，界面上也没有「应用到正文」之类的入口；你亲手复制、粘贴、编辑、保存后，文字才算进入作品。

## 如实说明

- 作品正文为手动保存：没有自动保存、自动备份或版本快照（讨论记录由应用自动保存，与正文不同）。
- 全应用只有一份 API 配置（OpenAI 兼容接口）：没有多服务方、多模型选择界面。
- 仅发行 Windows 版。

## 给开发者

所有「AI + 本地文件」的应用都撞同一堵墙：**怎么让模型看得见你的内容，又不给它任何写权限？**

Next Story 的答案是一套全部落地、有规格背书的边界设计：

- **保管者 / 使用者分离**：Rust / Tauri 后端是项目数据的唯一保管者（内容树、保存、校验、版本迁移、崩溃恢复）；AI 运行在独立的驱动进程里，拿不到任何写文件的能力。
- **受控只读接口**：AI 只能经目录投影、正文读取（含经校验的未保存快照）、跨文档字面检索三条通道取材，输出有硬上限。
- **文档级可见性与授权补读**：每篇文档可单独关闭 AI 可见性；AI 想多读几篇必须经用户授权，随时可关。
- **AI 输出永不入文**：项目服务不注册为 AI 可调用的写工具；界面上不存在「一键应用」入口。

```
┌──────────────────────────────┐
│ 保管者：Rust / Tauri 后端      │ 内容树 · 保存 · 校验 · 版本迁移
 │ （唯一能写文件的一方）         │ 事务一致性 · 崩溃恢复
 └─────────────┬────────────────┘
               │ 受控只读接口
               │  目录投影 · 正文（含未保存快照）
               │  字面检索（输出有硬上限）
               │  文档级可见性 · 越权一律拒绝
               ▼
 ┌──────────────────────────────┐
 │ 使用者：DSH 驱动进程           │ AI 推理 · 常驻会话 · 流式回复
 │ （拿不到任何写文件能力）        │ 授权补读：用户点头才多读，随时可关
 └──────────────────────────────┘
```

这套边界设计不绑定剧本创作——任何「AI 陪想本地内容」的桌面应用（笔记、文档库、任意文件夹）面对的是同一个问题。本仓库是一个可阅读、可借鉴的参考实现（许可见文末）。

## 协作与协议

本项目用 OpenSpec 做规格驱动开发：propose（写清要做什么）→ 用户确认 → apply（实现）→ archive（归档进真相源），一次只开一个 change。能力真相源是 [`openspec/specs/`](openspec/specs/)，版本历史见 [Releases](https://github.com/irisnb/next-story/releases)；项目红线与协作规则见 [`AGENTS.md`](AGENTS.md)。
