## Why

固定的「草稿本 / 正文本」两个本子由产品预设了作品文本的组织方式，用户无法按自己的判断组织角色、世界观、大纲等不同内容。作品内容树（文件夹 + 文档）把组织权交还用户。在陪想方向上，内容树只是帮助陪想 Agent 理解作品的**后台基础设施**：用户在写作空间里亲手写，通过常驻 AI 面板直接提问，不需要配置任何 AI 参考优先级（旧「四级 AI 参考优先级」及继承、覆盖模型已撤出用户概念，未来 Agent 如何选择上下文是未定的内部方案）。本 change 先把内容树在 Rust/Tauri 侧落成可靠的作品事实存储地基，为后续界面与陪想能力提供基础；不实现任何 AI 读取、上下文选择或写文档的能力。

## What Changes

- **BREAKING**: 作品结构从固定双本子（`作品文本/草稿本.json`、`作品文本/正文本.json`）改为作品内容树（文件夹 + 文档），作品结构版本升级。
- 新增内容树存储地基：两种节点（文件夹只负责组织、文档只负责写作），父子层级，以及混合排序（文件夹与文档在同一父级内共享一个排列顺序）。
- 提供创建、重命名、移动、删除（进入回收站）与恢复的确定性存储操作；回收站的具体位置与保留策略在 design 中确定。
- 旧作品迁移：现有草稿本 / 正文本自动转换为内容树根层两篇普通文档，名称保留「草稿本」「正文本」，但仅作为普通文档名称，不保留特殊本子身份，也不恢复双本子模型；保留原有文字与格式，不额外包裹一层迁移文件夹。
- 保存事务、写入前校验与崩溃恢复扩展到内容树结构，保持「一次保存 = 一个一致世代」的既有原则。
- 本 change 只做 Rust/Tauri 作品事实存储地基：不含作品结构页 / 写作空间 UI（另行 change），不含 DSH 读取作品，不含上下文选择、预加载、检索、摘要、记忆或 Agent 循环；AI 永不写用户文档的永久边界不变，本 change 不新增任何 AI 写文档的能力。

## Capabilities

### New Capabilities
- `content-tree-storage`: 作品内容树的 Rust/Tauri 事实存储：文件夹与文档节点、父子层级与混合排序、创建 / 重命名 / 移动 / 删除回收站 / 恢复、保存事务与校验、崩溃恢复，以及旧双本子作品的迁移。

### Modified Capabilities
- `desktop-project-lifecycle`: 作品结构版本升级；新建作品创建内容树而非两个固定本子；打开作品校验内容树结构；保存与事务恢复覆盖内容树；迁移框架注册首个迁移步骤（旧双本子 → 内容树）。
- `structured-notebook-storage`: 单篇文档的 Tiptap JSON 格式保持不变；「草稿本 / 正文本是唯一用户文本文件」的要求改为「内容树中的文档是用户文本事实源」。

## Impact

- Rust/Tauri 后端：`project/` 模块的作品结构、创建、打开、保存、迁移与事务逻辑。
- 作品结构版本与磁盘布局变化（具体格式与版本号在 design 中确定）。
- 前端 IPC 契约：作品结构相关命令的载荷变化（本 change 不实现新 UI，前端适配另行 change）。
- 现有 specs：`desktop-project-lifecycle`、`structured-notebook-storage` 的需求变更。
- 不涉及 DSH、AI 面板、LLM 配置；本 change 不实现任何 AI 上下文选择相关能力，未来 Agent 上下文选择完全留给后续 change。
