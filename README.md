**辅助剧本创作的陪想软件。** 你在写作空间里亲手写；常驻 AI 面板像聊天窗口一样随时可问——AI 陪你想，不替你写。

Next Story 是一个 Windows 桌面应用，给想写剧本（或任何故事）的人。写作空间里你亲手创作，旁边的常驻 AI 面板随时回应提问——直接问就行，不需要先配置上下文。AI 只提供观察、问题、假设和带依据的可能性；什么进入作品、故事往哪里走，判断权永远在你手里。它不替代创作所需的感受、思考、实践与坚持；工具降低的，是开始创作和获得帮助的门槛。

界面一览与更多介绍：https://irisnb.github.io/next-story-site/

## 核心特性

### 写作空间与项目

- 「项目」就是一个文件夹：欢迎页提供新建、打开与最近项目列表（至多 8 条，按路径去重，失效条目自动移除，点击即开）。
- 内容树组织：只有文件夹与文档两种节点，可创建、重命名、移动、排序；删除进回收站，可恢复。
- 富文本编辑器：一至六级标题；粗体、斜体、下划线、删除线；九种字体、八档字号；文字颜色与背景高亮；左对齐、居中、右对齐、两端对齐；行距与段前、段后间距；首行、左、右三种缩进；无序与有序列表（支持嵌套，有序列表五种编号样式：数字、大写字母、小写字母、大写罗马、小写罗马）；查找替换；链接；撤销重做。粘贴受控清洗，未知格式与脚本混不进来。
- 写作宽度三档：窄 640 / 标准 720 / 宽 860，稿纸化显示，偏好自动记住。

### AI 陪想

- 两种问法进入同一个讨论：面板直接提问，编辑器选区作为可选重点提示自动附带，无选区也可直接问；或选中文字点「AI」即时召唤，以冻结的选区直接发起，无需先输入问题。
- **未保存也能问**：正在写、还没保存的内容，经快照校验后 AI 也能看到。
- **授权补读**：材料不够时，AI 会请求多读几篇——你允许才读，随时可关，授权跨重启保留。
- **参考出处可查**：AI 这次参考了什么（关注文档现场、目录、检索片段、补读的文档），轻量可看，不打断对话。
- 回复流式逐字呈现，纯文本可复制；首次回应成功后可线性追问，只发送新问题；可取消、可停止生成，已完成内容保留。
- 多个讨论并存并发生成，互不阻塞；同时生成数达到上限时先到先服务排队；长对话自动压缩承接，超限明确报错提示新建讨论，绝不静默砍历史。
- 每篇文档可单独设置是否允许 AI 查看；隐藏与回收站内容 AI 读不到。
- 崩溃恢复：驱动进程意外退出后自动重启，所有在途讨论自动恢复状态。
- API 自己配：设置页填一份 OpenAI 兼容接口的地址、Key 与模型名，「测试连接」发起真实请求校验。

### 讨论管理

- 会话列表按最后活动时间分组：置顶 / 今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 更早。
- 支持重命名、置顶、删除（有确认与撤销）、按标题或文档名过滤，入口常驻。
- 讨论记录随项目自动保存，重启后可重开查看；删除讨论是独立动作，关闭、切换文档或切换项目都不会误删。

### 制作模块

- 独立页面，定制 AI 的回应方向与说话方式：左侧链路库多链路并存，版本不可变、可回退，显式启用/停用，下一轮生效。
- 右侧「导图｜制作对话」双标签：导图把提示词的组装结构可视化；制作对话里起草卡与试问走真实会话，保存须你确认。
- 零卡链路：链路可以不含任何卡，新建即含零卡第 1 版，可直接启用。
- 与日常讨论在会话和上下文上相互隔离：日常聊天不能改动链路配置，制作页也不显示正文保存按钮。

### 导入导出与基础

- 导出 Word（.docx）、PDF、Markdown；导入 Word、Markdown、Final Draft（.fdx），导入保真经过专项验收。
- 首启引导与帮助分区：首次启动四卡引导，可跳过、可重看；帮助含常见问题（含「API 是什么？怎么获取？」）。
- 应用单实例：重复启动只唤起已有窗口，不弹第二个。

**AI 永远不写你的文档**——AI 输出永远是临时材料，界面上也没有「应用到正文」之类的入口；你亲手复制、粘贴、编辑、保存后，文字才算进入作品。

## 如实说明

- 作品正文为手动保存：没有自动保存、自动备份或版本快照（讨论记录由应用自动保存，与正文不同）。
- 全应用只有一份 API 配置（OpenAI 兼容接口）：没有多服务方、多模型选择界面。
- 仅发行 Windows 版。

## 给开发者

所有「AI + 本地文件」的应用都撞同一堵墙：**怎么让模型看得见你的内容，又不给它任何写权限？**

Next Story 的答案是一套全部落地、有规格背书的边界设计：

- **保管者 / 使用者分离**：Rust / Tauri 后端是项目数据的唯一保管者（内容树、保存、校验、版本迁移、崩溃恢复）；AI 运行在独立的驱动进程里，拿不到任何写文件的能力。
- **受控只读接口**：AI 只能经目录投影、正文读取（含经校验的未保存快照）、跨文档字面检索三条通道取材，输出有硬上限。
- **文档级可见性与授权补读**：每篇文档可单独关闭 AI 可见性；AI 想多读几篇必须经用户授权，随时可关。
- **AI 输出永不入文**：项目服务不注册为 AI 可调用的写工具；界面上不存在「一键应用」入口。

```
┌──────────────────────────────┐
│ 保管者：Rust / Tauri 后端      │ 内容树 · 保存 · 校验 · 版本迁移
 │ （唯一能写文件的一方）         │ 事务一致性 · 崩溃恢复
 └─────────────┬────────────────┘
               │ 受控只读接口
               │  目录投影 · 正文（含未保存快照）
               │  字面检索（输出有硬上限）
               │  文档级可见性 · 越权一律拒绝
               ▼
 ┌──────────────────────────────┐
 │ 使用者：DSH 驱动进程           │ AI 推理 · 常驻会话 · 流式回复
 │ （拿不到任何写文件能力）        │ 授权补读：用户点头才多读，随时可关
 └──────────────────────────────┘
```

这套边界设计不绑定剧本创作——任何「AI 陪想本地内容」的桌面应用（笔记、文档库、任意文件夹）面对的是同一个问题。本仓库是一个可阅读、可借鉴的参考实现（许可见文末）。

## 协作与协议

本项目用 OpenSpec 做规格驱动开发：propose（写清要做什么）→ 用户确认 → apply（实现）→ archive（归档进真相源），一次只开一个 change。能力真相源是 [`openspec/specs/`](openspec/specs/)，版本历史见 [Releases](https://github.com/irisnb/next-story/releases)；项目红线与协作规则见 [`AGENTS.md`](AGENTS.md)。
