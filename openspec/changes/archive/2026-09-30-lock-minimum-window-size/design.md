# 设计：锁定主窗口最小尺寸

## Context

- 现状：`src-tauri/tauri.conf.json` 主窗口仅配置 `width: 1024, height: 768, center: true`，无任何最小尺寸限制；Rust 侧亦无 `set_min_size` 调用。窗口可被拖到极小。
- 布局实测（逻辑像素，`src/styles.css`）：AI 停靠面板展开 420px（`--dock-width`）、收起窄轨 46px、竖排格式工具栏 88px（5.5rem）、正文标准留白 2rem×2＝64px、顶部页头＋标签栏约 132px。
- 外部实证（2026-09 查证）：网易云音乐 Windows 端最小＝默认＝1022×670（官方安装包反查，亿级分发验证小屏兼容）；VS Code 400×270（侧栏开 600，源码）；Notion 640×480；ChatGPT 480×600；Obsidian 不设最小值（官方论坛有「窗口缩没」抱怨，反面案例）。
- 无窗口状态持久化插件，不存在「恢复到小于最小尺寸」的边缘情况。
- 目标平台仅 Windows（方向共识 2026-09-22）。

## Goals / Non-Goals

**Goals:**

- 主窗口不可缩小到 1024×670（逻辑像素）以下，保证「写作区＋AI 面板并排」的核心画面在任何用户可达到的窗口尺寸下成立。
- 默认尺寸＝最小尺寸（打开即是设计的样子，只能放大）。
- 最大化、还原、居中行为不受影响；1366×768 笔记本屏幕可完整容纳默认窗口。

**Non-Goals:**

- 不做随 AI 面板开合变化的动态最小值（VS Code 式）。
- 不改动应用内 AI 讨论窗口自身的 300×200 最小值（独立机制）。
- 不清理、也不复活 `styles.css` 中「<760px 时停靠区变覆盖式抽屉」的媒体查询（本 change 后成为不可达死代码，留待将来另行处置）。
- 不做窗口状态记忆（记住上次大小与位置）。
- 不做「小窗专注模式」；若将来需要，另立 change。

## Decisions

1. **静态最小值，min＝default＝1024×670。**
   - 弃 VS Code 动态式：前端已有「窄窗口时停靠区转覆盖层」的响应式机制，动态最小值与它解决同一问题、彼此打架，且引入开合时机的状态复杂度。
   - 弃 Notion 式 640×480：该宽度下 AI 面板只能覆盖正文——「AI 坐在旁边看活稿子」变成「挡在前面」，与产品立场冲突。
   - 高度取 670 而非沿用 768：1366×768 屏幕去任务栏可用高约 728px，768 放不下（现状暗坑）；670 经网易云大规模分发验证安全。
   - 宽度取 1024（沿用现有默认）：现有 760~970px 的「面板挤压正文区」随最小宽度提到 1024 一并消失，无需另调断点。
2. **用 `tauri.conf.json` 声明式配置（`minWidth`/`minHeight`），不用 Rust 运行时 `set_min_size`。**
   - 声明式在窗口创建时即生效，无「先变大再收紧」的启动闪烁窗口期；配置即文档；改动面最小（一个文件、四行）。
3. **尺寸以逻辑像素表达。**
   - Tauri 2 的 `minWidth`/`minHeight` 即逻辑像素，DPI 缩放下自动换算为物理像素，布局保证（正文列每行约 28 字）不随缩放漂移，无需额外代码。

## Risks / Trade-offs

- [失去「缩成窄条边看资料边写」的用法] → 有意接受：想专注的作者更可能全屏/最大化；小窗若真有需求，应作明确设计的功能另立 change，而非拖拽副作用。
- [<760px 覆盖式抽屉媒体查询成为死代码] → 保留无害，已在 proposal 与本设计记录在案，不扩大本 change 范围。
- [高 DPI 小逻辑屏（如 1366×768@150% → 逻辑约 911×512）上窗口正常态超出屏幕] → 与网易云同级风险、同类屏幕配置；最大化仍按系统工作区铺满。在验收时于可用硬件实测确认无恶性表现。
- [默认高度从 768 变 670，老习惯可感知] → 尚未正式分发，无存量用户包袱；属一次性切换成本。

## Migration Plan

单处配置提交，无数据迁移、无版本兼容问题；回滚＝还原 `tauri.conf.json` 中四个数值。
