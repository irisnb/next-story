# 长上下文轮次冻结：归因与修复

> 对应审计队列第 9 行（收尾路线 Change B）。8b 应用级验证沉淀的复现样本与计时量化是本 change 的证据起点。

## Why

长上下文讨论的轮次会间歇性冻结：界面停在「正在思考…」，无流式输出、无错误、状态点保持生成中，持续 6 分钟以上只能手动停止。8b 验证中，累计轮次最重、上下文最重的讨论（17 轮，含按需补读工具循环与两篇全文读取）连续三轮冻结，同时段新建讨论同材料 3–6 秒正常收束；后半夜同讨论自愈一轮，呈间歇性。计时数据将现象量化为四条 165–292 秒异常值（常态总时长 5–40 秒）。

这是修复队列余下**唯一的真实用户可感缺陷**，且压在产品核心路径上：陪想场景恰恰是长对话，聊得越深越容易踩中。嫌疑方向（8b 已排除未保存快照材料与讨论身份接线两项）：DSH 框架上下文自动压缩 × 智谱 coding 端点在长上下文下的交互。归因未做，修复无从谈起。

## What Changes

- **归因（先离线后实弹）**：源码级研读 DSH 压缩链（`@deepseek-ai/dsh-compaction-basic` 及关联插件、触发条件、压缩请求形态、与流式输出的阻塞关系），产出可判死的假设清单；再按假设做少量定向真实链路复现（8b 已留复现路径与计时导出口），把根因收敛到「我方代码 / DSH 配置 / DSH 内部 / 端点行为」四类之一并落档证据。
- **修复（随归因结果定形状）**：根因在我方或配置则直接修；根因在 DSH 内部或端点侧无法根治时，交付**检测与诚实兜底**——轮次不得无限冻结无反馈，系统须识别停滞并给出中文可读的失败与恢复指引（对齐既有「绝不静默」原则），杜绝 6 分钟假死。
- **防回归**：把「冻结可被检测」与「兜底路径正确」锁进测试；若归因过程产出可复用的长上下文测试工具，8c 存量的评分器三条改进候选按既定「顺带吸收」原则视情况并入（不承诺）。
- **诚实记录**：归因结论、修复边界（治本还是兜底）、剩余风险全部写入验证记录与审计文档补充条目，不夸大为「已根治」。

## Capabilities

### New Capabilities

（无——本 change 是既有能力内的缺陷修复，不引入新能力。）

### Modified Capabilities

- `resident-ai-session`：新增「生成轮次停滞检测与诚实兜底」要求——无论根因落在哪一层，用户可见的契约是：轮次不得无限期停留在生成态而无流式输出、无错误；停滞须在有限时间内被识别，或恢复或以中文可读错误收场并保留已完成内容。「上下文超限由框架压缩承接并诚实兜底」一条若因归因结论需要调整压缩行为预期（触发阈值、压缩请求形态），一并在此修订。

## Impact

- **Rust 驱动层**（`dsh_driver.rs` 一带）：事件流停滞的观测点、超时判定与错误上报（当前无任何停滞检测）。
- **sidecar / DSH 配置**（`sidecar/driver/`：`cordis.driver.yaml`、`gen-config.mjs`）：压缩插件参数、模型请求层（`dsh-llm-retry`／`dsh-timeout` 一类既有插件的装配）视归因结论调整。
- **前端传输层**：若兜底需要用户可见提示，涉及 `ai-session-transport` 与面板状态的既有错误通道，不新增状态源。
- **DSH SDK（`@deepseek-ai/dsh` 0.1.0-rc.7）**：只读研读 + 配置级调整；不 fork、不 patch 包源码（若结论必须动包内部，回到用户面前重新定路线）。
- **测试与验证**：需要少量真实链路复现（智谱 coding 端点、API 配额、部分场景可能需用户在场）；离线部分零 API 费用。
- **不触碰**：用户文档写路径、AI 只读边界、讨论身份接线（8b 已修）、并发调度数值（已定值 4）。
