# 提案：官网开发者区与仓库链接

## Why

官网已上线，但没有 GitHub 仓库入口，访客想看源码无处可去；同时项目的实现思路（架构分层、系统提示词组装、每轮材料装配）散落在仓库规格里，技术同行无从在官网侧了解。用户 2026-10-24 拍板：官网连接 GitHub 仓库页，并增设「给开发者看」的内容——项目的实现思路、系统提示词组装、每轮输入最新文本的机制。

## What Changes

- 官网新增 **GitHub 主仓库链接**（`github.com/irisnb/next-story`）：页眉与页脚常驻可达
- 官网新增 **「给开发者」板块**，三个主题，全部以 `openspec/specs/` 已归档规格为据，不发明事实：
  1. **实现思路**：Rust/Tauri 后端是项目数据的可靠保管者（内容树、保存、校验、迁移、事务与崩溃恢复）；DSH 驱动是内容的智能使用者（AI 推理与回应）；数据与 AI 路径隔离——项目服务不注册为 AI 可写工具，AI 输出永在用户文档之外；规格驱动开发（79 项已归档规格、全量门禁 CI）
  2. **系统提示词组装**：日常陪想每轮由后端集中组装——公用基础提示词（红线、基本立场、工具、材料规则）＋本次问题与材料（关注文档现场、允许目录投影、跨文档字面检索、选区重点）＋提问方式；制作模块按链路装配——固定底座＋回应要求卡＋回应风格卡＋每轮动态注入，版本不可变、启用指针下一轮生效、制作与日常隔离
  3. **每轮输入最新文本**：每轮自动附带关注文档「现场」——已保存正文或经校验的未保存快照（不是缓存旧文）；材料出处持久化、「本次参考了什么」轻量可查；追问只发增量、历史由常驻会话维护、超限自动压缩不静默砍史

- 仅改官网（`Wangye/`，推送 next-story-site 仓库）；主仓库只动 openspec 变更文档

（无）

## Impact

- 官网仓库（`Wangye/` → `next-story-site`）：index.html 新增板块与链接，Pages 推送后自动上线
- 主仓库：仅 `openspec/changes/site-dev-section/` 变更文档（提交推送）
- 不动产品代码、不动 README（README 已有仓库自身链接语境）、不动主规格其他能力
