## Context

阶段 1 已验证了受控只读材料的纯函数边界，但它尚未成为真实的 Tauri 作品服务，也没有接入用户可操作的 AI 可见性状态。当前内容树没有文档可见性字段，前端选区请求只有裸文本，讨论保存与 DSH 恢复主要围绕显示历史和用户/助手文本，无法判断某段历史是否依赖后来被隐藏的文档。

本 change 位于“安全读取基础”和后续自动读稿之间。它必须让文件管理、普通请求、及时召唤、未来 A 现场材料和 B Agent 补读共享同一权限入口，但不负责把材料自动发送给模型，也不负责生产 DSH 工具协议。

## Goals / Non-Goals

**Goals:**

- 在作品数据中持久化每篇文档的二元 AI 可见性，默认允许，且由 Rust/Tauri 作为唯一授权事实源。
- 通过统一受控只读服务校验作品、文档、回收站、可见性、版本、范围、未保存快照和选区来源。
- 向未来 AI 读取路径提供过滤后的目录投影：隐藏文件只贡献匿名数量提示，不暴露名称、ID、路径或正文。
- 使权限变化可以标记受影响讨论，阻断旧材料通过 DSH 历史重放或原会话继续发送。
- 保持作品正文、讨论档案和 AI 运行环境之间的写入隔离，并覆盖迁移、错误和并发状态测试。

**Non-Goals:**

- 不在本 change 中自动附带当前文档或全作品正文到普通提问。
- 不在本 change 中注册生产 DSH 读取工具、启用 Agent Loop、采用 MCP 或实现跨文档搜索。
- 不实现摘要、语义检索、向量检索、预加载、长期记忆或材料排序。
- 不保存未保存全文作为讨论档案的长期副本，不尝试从已发送给模型的内容中撤回文字。
- 不给文件夹设置独立权限，不引入分级、继承、覆盖或“参考优先级”。

## Decisions

### 1. 文档级二元开关，默认允许

在文档节点上保存 `ai_visible` 布尔状态；旧作品和新建文档均按允许处理，用户可在文件管理区域切换。文件夹不保存该状态，也不向用户呈现权限继承模型。

备选方案是文件夹继承或多级优先级，但会增加用户判断负担，并重新引入已经撤出的旧概念。文档级开关更容易解释、迁移和测试。

### 2. 后端统一授权，前端只提供事实

Rust 作品服务负责读取内容树、持久化开关、过滤目录、验证版本和校验快照。前端只能提供当前编辑器中的未保存快照和选区来源身份，不能自行判断是否允许读取。所有入口复用同一个授权核心，并在作品锁保护下完成权限检查与内容读取。

备选方案是让前端先过滤、DSH 再直接读取文件，但这会让编辑器内存和磁盘形成绕过路径，也会把作品路径暴露给 AI 运行环境，因此不采用。

### 3. AI 目录保留匿名隐藏数量

提供给 AI 或未来读取工具的目录投影只列允许查看的节点；隐藏文档不返回名称、ID、路径和正文，但可以返回“还有 N 份文件已隐藏”的匿名汇总。用户自己的文件管理界面仍显示完整文件树和真实开关状态。

这样既不假装作品结构完全公开，也不泄露用户明确隐藏的文件身份。只含隐藏后代的文件夹不以路径形式暴露；匿名计数不得能反推出具体文件。

### 4. 权限变化使旧讨论进入永久历史受限状态

关闭文档可见性后，已经显示给用户的旧讨论保留，系统不声称可以撤回模型已经收到的文字。若讨论的材料出处记录表明它曾使用该文档，则讨论被永久标记为历史受限：用户可以查看历史，但原 DSH 会话不能继续追问，崩溃恢复或重开不得把该讨论历史重放给模型。该受限状态是永久的，用户只能新建干净讨论按当前允许范围继续。

重新打开可见性只影响之后新建的讨论，不解除任何已被永久标记为受限的旧讨论，避免开关成为隐蔽的历史重放开关。旧版本档案没有材料出处时采取保守迁移：可查看但不可自动重放。

### 5. 最小材料出处记录，不复制正文

讨论档案只增加能判定影响关系的材料出处：文档身份、材料类型、版本、所属轮次和是否进入模型上下文等元数据，不保存完整正文。阶段 4 不填充 Agent 工具事件或自动现场材料，只为后续阶段保留可迁移的记录位置。

### 6. 阶段边界与生产接入分离

本 change 可以提供生产级 Rust/Tauri 只读命令和测试，但不把它注册为 DSH 工具。生产 DSH 工具接入涉及真实事件、取消、超时、恢复和等待基线，应在阶段 6 单独验证，避免与权限模型同时改变两个失败面。

## Risks / Trade-offs

- **[旧材料不能撤回]** → 明确只阻止后续发送和恢复重放，旧显示历史保留并向用户诚实提示。
- **[历史档案缺少材料出处]** → 旧档案按保守策略只允许查看，不自动重放；新档案从本 change 起记录最小出处。
- **[内容树格式迁移]** → 使用现有版本迁移机制，旧文档默认允许；迁移失败不得静默改写正文。
- **[前端编辑器与关注文档不一致]** → 快照必须携带作品、文档和版本身份，后端校验失败关闭；不能使用当前打开的另一篇文档替代讨论绑定文档。
- **[并发权限变化]** → 排队请求在实际派发前重新授权；已经发送的请求不承诺撤回，后续读取一律重新检查。
- **[匿名目录仍泄露数量]** → 只提供汇总数量，不提供名称、路径、ID、文件夹位置或逐项状态；提案验收应覆盖多种树形结构。
- **[范围膨胀到自动读稿]** → 任务清单和能力网关测试明确不注册 DSH 工具，不改普通提问的材料组装流程。

## Migration Plan

1. 增加作品结构版本迁移：已有文档缺少可见性字段时按 `允许 AI 查看` 读取，迁移写入使用原子方式。
2. 发布文件管理开关和后端查询/更新命令；开关更新成功后刷新树与受影响讨论状态。
3. 启用统一受控只读入口和目录投影，但暂不让普通 AI 请求自动调用它。
4. 为新保存的讨论记录材料出处；读取旧档案时按保守重放策略处理缺失出处。
5. 若迁移或开关更新失败，保留原作品数据和原权限行为，向用户显示失败，不部分更新。

## Open Questions

- UI 中开关的具体图标、文案和确认交互由实现任务按现有文件管理设计确定，不改变本设计的二元语义。
- 讨论材料出处元数据的最终字段名可在实现时与现有 serde 版本契约统一，但不得退化为保存正文副本。
