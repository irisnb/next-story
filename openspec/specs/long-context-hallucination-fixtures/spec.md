## Requirements
### Requirement: Deterministic long materials
The fixture set SHALL provide deterministic synthetic Chinese materials at approximately 10,000, 30,000, and 50,000 characters, each with a stable identity, version, actual character count, estimated token count, and content hash.

#### Scenario: Regenerate a tier
- **WHEN** the generator is run with the recorded seed and tier
- **THEN** it SHALL produce the same material hash and factual anchors as the checked-in tier

#### Scenario: Validate tier sizes
- **WHEN** the fixture validation runs
- **THEN** it SHALL reject a missing tier, a hash mismatch, or a material outside the documented size tolerance

### Requirement: Separate factual oracle
Each long-context tier SHALL have oracle metadata separate from the material sent to the model, identifying expected facts, source locations, relevant entities, wrong conclusions, and question category; the oracle SHALL NOT be included in replayed material or model prompts.

#### Scenario: Check a known answer boundary
- **WHEN** a query references an oracle fact
- **THEN** the case SHALL contain enough expected-boundary data to determine whether the response supports, contradicts, or leaves that fact unresolved

### Requirement: Risk-stratified query matrix
The fixture set SHALL provide 12 queries for the 10k tier, 18 for the 30k tier, and 24 for the 50k tier, covering distant recall, cross-chapter relations, similar entities, version conflicts, unknown facts, false-premise correction, and multi-turn recall.

#### Scenario: Verify matrix coverage
- **WHEN** the matrix validator runs
- **THEN** every tier SHALL meet its query count and SHALL include every required risk category at least once

### Requirement: Repeatable trial plan
Every query SHALL declare a planned trial count of three and a stable query identity so separate runs can be compared for systematic errors, intermittent errors, and response consistency.

#### Scenario: Run one tier independently
- **WHEN** an operator selects one size tier
- **THEN** the runner SHALL be able to execute only that tier without requiring other tiers or changing the oracle

### Requirement: Safe staged execution
The documentation SHALL describe staged execution order, expected API call volume, evidence location, and the distinction between model-answer outcomes, scorer uncertainty, and runtime failures.

#### Scenario: Preserve long-run evidence
- **WHEN** a tier trial completes or fails at runtime
- **THEN** existing evidence rules SHALL preserve the complete response or runtime diagnostic without writing the API key or oracle metadata into the model material

### Requirement: Coherent narrative comparison tier
The fixture set SHALL provide one hand-authored, approximately 10,000-character coherent narrative tier whose prose has scene continuity, stable characters, and causal flow, and whose facts are expressed in natural sentences rather than verbatim-marked anchor statements. Its query matrix SHALL mirror the 10k template tier (12 queries, all seven risk categories, planned trial count of three) so the two tiers are directly comparable.

#### Scenario: Coherent tier is hand-authored
- **WHEN** the fixture set is validated
- **THEN** the coherent tier SHALL be marked as handwritten, SHALL NOT be regenerated by the seeded generator, and SHALL pass hash, size, anchor, matrix, trial, and oracle-separation checks

#### Scenario: Template and coherent tiers are compared
- **WHEN** results from the template 10k tier and the coherent tier are reported
- **THEN** the report SHALL present them as separate, non-conflated evidence of adversarial upper-bound and real-proximity behavior
