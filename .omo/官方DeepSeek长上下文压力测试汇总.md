# 官方 DeepSeek 长上下文压力测试汇总

更新日期：2026-09-01

## 一、为什么做这次测试

这次测试的目的，是确认 Next Story 当前的 DSH 常驻会话链路能否把较长的剧本材料可靠交给真实模型，并观察模型在以下场景中的表现：

1. 阅读完整的长篇剧本后，能否回答材料中的事实问题。
2. 面对 v1 和 v2 两个版本时，能否区分当前版本，不把旧版本事实带进来。
3. 从 v1 切换到 v2 后，旧会话内容是否会污染新版本判断。
4. DSH 驱动、流式回答、会话切换和进程退出是否正常。

此前使用其他配置时，曾出现 `STREAM_CLOSED`，没有拿到有效的模型回答。因此这次首先确认官方 DeepSeek 配置真的可调用，再进行内容层测试。

## 二、怎样测试

### 使用的模型和链路

- 模型：`deepseek-v4-pro`
- API：官方 DeepSeek API
- 运行方式：通过 Next Story 的真实 DSH driver 运行
- 测试对象：常驻会话的行分隔 JSON 通信链路
- 测试材料：《锈海之下》v1、v2 两个版本

API 密钥只通过测试进程环境传递，不写入测试报告或证据文件。

### 测试场景

- v1 独立会话：检查旧版本事实和不确定信息。
- v2 独立会话：检查改稿后的新事实。
- v1 到 v2 的切换会话：先建立 v1 上下文，再切换为 v2，检查旧内容是否残留。
- 会话协议检查：确认模型回答可以流式返回、会话可以正常结束。

本轮共运行 23 轮。每一轮都收到了真实模型回答，驱动进程正常退出，运行错误为空。

## 三、测试结果

自动判分汇总如下：

| 结果 | 数量 | 大白话解释 |
|---|---:|---|
| PASS | 8 | 自动判定回答符合预期 |
| FAIL | 5 | 自动判定有问题，但其中多项后来发现是判分器误判 |
| UNREVIEWED | 7 | 自动程序无法可靠判断，不能算通过或失败 |
| N/A | 3 | 只是注入材料或切换版本，不参与内容评分 |

### 对结果的正确理解

这 23 轮不是全部失败。更准确的结论是：

- DSH 后端链路成功，模型确实收到了材料并返回了回答。
- 模型大多数时候能找到当前版本中的关键事实。
- v1 切换到 v2 后，没有发现大量旧版本内容被错误带入的证据。
- 目前自动判分器不能完全理解自然语言，因此不能单独用它给模型下结论。

## 四、判分器暴露的问题

本次使用的是我们自己写的简单自动判分程序，主要通过查找关键词或短语来判断答案。它不是另一个 LLM，也不是 DeepSeek 的内部评分系统。

这种做法容易出现以下问题：

- 模型说“严铎没有死”，判分器只看到“死”这个词，可能误以为模型说严铎死了。
- 模型引用剧本对白或复述题目，判分器可能把引用内容当成模型自己的结论。
- 模型回答“无法确定”，但回答标题中包含“是否死亡”，判分器可能因此误判为“断言死亡”。

典型例子是严铎这一轮。模型引用了 v2 第 20 场“严铎没有死”，随后说明剧本没有交代他后来最终的生死，所以回答“最终生死不确定”。判分器因为看到了题目和回答中的“已经死亡”等字样，把它判成了“断言严铎死亡”。

因此，自动结果中的 FAIL 不能全部理解成模型答错。关键结果需要结合完整回答人工复核。

## 五、基础设施结果

本次运行可以确认：

- 23 轮均得到非空模型回答。
- DSH driver 正常结束，退出码为 `0`。
- 没有出现本轮范围内的运行错误。
- 流式回答和常驻会话的基本通信链路可用。
- 测试证据文件及捕获的 driver `stderr` 中未发现完整 API key。
- 测试产生的临时目录和临时配置已在整理阶段删除。

## 六、这次测试没有覆盖什么

本次测试不等于完整验证了所有长上下文能力，以下内容没有充分覆盖：

- 对话特别长以后，自动压缩历史是否仍然准确。
- 压缩之后继续追问时，关键事实是否保持不变。
- 更长材料、更多版本和更多轮切换。
- 复杂事实之间的冲突、否定和模糊表达。
- token 用量和模型实际上下文窗口使用情况。

## 七、后续测试建议

### 1. 先改判分器，再继续扩大测试

判分器至少应该做到：

- 识别“没有”“不是”“未说明”等否定词。
- 区分模型自己的结论、题目复述和剧本引用。
- 不用单个关键词直接决定 PASS 或 FAIL。
- 对无法判断的答案明确标为“需要人工复核”。

### 2. 保留少量固定回归题

以后每次升级 DSH 或更换模型，都可以重复测试一组固定问题，重点检查：

- v1 与 v2 的事实是否混淆。
- 旧版本被明确否定后，模型是否仍坚持旧结论。
- 剧本没有说明的内容，模型是否会老实说“不确定”。
- 否定句和引用对白是否被正确理解。

### 3. 增加人工复核记录

自动判分只做初筛。对于 FAIL 和 UNREVIEWED 项，应保存：

- 测试问题。
- 模型完整回答。
- 对应剧本原文位置。
- 人工最终判断。
- 判分器为什么判断错误或无法判断。

### 4. 每次运行记录测试版本

后续测试应记录测试脚本的版本号或文件哈希，避免出现“证据文件和当前判分代码不完全对应”的情况。

## 八、最终结论

这次压力测试证明了 Next Story 通过真实 DSH driver 调用官方 DeepSeek 模型的基础链路已经能够运行，并且模型大部分时候能够处理长剧本和版本切换。

但这次测试还不能证明模型在所有复杂事实判断上都完全可靠。主要原因有两个：

1. 我们自己的自动判分器过于简单，存在明显误判。
2. 仍有 7 项结果无法由自动程序可靠判断，需要人工复核。

所以本次测试的结论应表述为：

> **基础调用链路通过；长上下文和版本切换初步可用；自动判分器需要升级；模型事实可靠性还需要更好的判分方法和更多人工复核。**
