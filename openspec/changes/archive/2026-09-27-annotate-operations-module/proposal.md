# 提案：annotate-operations-module（operations.rs 注释层整理）

## Why

`src-tauri/src/project/operations.rs`（约 2955 行）是作品数据的唯一写入通道：建档、内容树变更、文档保存、迁移回滚与崩溃恢复都经它落地。它是全仓库最大的单文件（生产代码约 1419 行 ＋ 内联测试约 1536 行），也是少数没有模块头注释的核心文件。

"拆不拆"已有三次正式评估，结论一致为**不拆**：2026-09-14 全量地基审计队列 8a 判"无干净缝（判定不动）"；2026-09-21 `extract-ai-logic-seams` 设计确认"恢复与提交共享同一套清单/前滚机制，没有不拖家带口的真缝"；2026-09-23 开发前全面工程复核明确"事务一致性强相关，不因总行数机械拆分"。

但"不拆"不等于"没法整理"：该文件目前没有模块头（职责、维持哪些安全不变式、各区如何定位），没有任何分区标记，"为何保持单文件"的结论只散落在审计文档里。对这样一个维系全部用户数据的文件，维护者（人或 AI）每次都要通读千余行才能重建上下文——这是可维护性的真实缺口。

用户指示（2026-09-27）：稍微整理；如果真不好整理，就不要整理，不要为了整理而整理。

## What Changes

- **仅注释层整理，零行为变化**（只动 `operations.rs` 一个文件）：
  - 补模块头（`//!`）：文件职责、**安全不变式清单**（逐条经代码与测试核实后才写入）、分区地图、以及"为何保持单文件"的结论记录；
  - 按现有函数聚类插入分区横幅注释，**不重排任何代码**；
  - 补齐关键条目的缺失文档注释（只增量；不改既有注释语义）。
- **规格**：新增能力 `operations-module-map`，把"模块地图须存在且可核对、后续拆分须重估共享机制前提"固化为持久契约；不改任何既有规格的 Requirement。
- **明确不做**（防止为整理而整理）：
  - 不拆分文件——三次评估均判无干净缝，硬拆会制造假边界；
  - 不把内联测试搬出——全仓 Rust 测试均为内联惯例（无外部测试文件先例），且主测试区之外还有散落的 `#[cfg(test)]` 测试辅助，只搬大块会形成测试脑裂；
  - 不抽取文件系统工具到共享模块——这些函数已 `pub(crate)` 经 `mod.rs` 复用于讨论档案存储，搬家只增加改动面、无功能收益；
  - 不改任何函数、签名、常量、测试与数据格式。
- 验收：全量工程门禁全绿（`cargo test` / `cargo fmt --check` / `cargo clippy --all-targets -- -D warnings`）；diff 审计确认除注释与空行外零变更。

## Capabilities

### New Capabilities
- `operations-module-map`：作品数据写入核心（`operations.rs`）的模块地图契约——模块头须承载职责、安全不变式清单、分区地图与保持单文件的理由；每条不变式可核对到实现 / 测试 / 既有规格；后续拆分提案须重新评估"恢复与提交共享同一套清单/前滚机制"这一前提。
