# 按需补读通道：失败收束与拆分·验证记录

> 2026-09-27。离线证据为主；本 change 为后端失败路径与结构拆分，失败触发条件（授权写盘失败、装配缺失）均以确定性集成测试覆盖，不要求真机轮（设计已声明）。真实链路三项保持手动运行约定。

## 一、修复对象与复现证据

三条故障路径（oracle 评审发现、主控逐行核实并**当场复现坐实**后立项）：

| 路径 | 修复前（已复现） | 修复后 |
|---|---|---|
| 授权档案写入失败（用户点了「允许」但存档失败） | 不回填；轮次无反馈，挂到停滞看护 180 秒后以「生成长时间无响应」错误收场（探针测试断言缺陷行为通过，实测 180.43 秒） | 立即回填与「用户拒绝」同构的结构化结果（`{granted:false, recovery:…}`）；轮次即刻走有限回答（测试实测约 1.5 秒完成）；错误如实返回前端并提示「授权未能保存，本轮按未授权继续」 |
| 授权请求无接收通道（装配降级） | 只记日志；待决已插入、轮次进入无时限等待（授权等待豁免停滞看护） | 不插入待决、不进入等待，立即回填结构化拒绝；轮次走有限回答；对任意 call_id 的迟到决定按「没有该身份的待决授权请求」失败关闭 |
| 驱动未接线（实际不可达的防御分支） | 丢弃＋日志，与模块注释承诺不符 | 注释如实化（无驱动即无事件源、无回填对象）；行为零变化 |

复现探针（立项前，断言缺陷行为、通过后已还原）要点：授权卡挂起后删除讨论档案构造确定性写失败 → `resolve(true)` 返回 Err 且轮次 180 秒后停滞收场。

## 二、回归测试（转正）

- `grant_write_failure_backfills_denial_and_round_finishes`：删档案写失败 → resolve Err；轮次 Ok 且文本以「未获授权，有限回答」开头、含恢复提示；档案未被伪造重建；10 秒超时内完成（回填失效会响亮失败）。
- `missing_reading_request_sink_fails_closed_immediately`：不装接收通道 → 驱动收到 `granted:false` 拒绝、轮次有限回答完成；`resolve_reading_request` 对任意 call_id 返回 Err（待决未插入）；档案零写入。
- 既有语义保持：`reading_request_suspends_round_and_resolution_continues`、`suspended_round_can_be_cancelled_and_late_resolution_is_dropped`（迟到决定丢弃、不动档案）等全部通过。

## 五、边界与如实说明

- 无接收通道拒绝采用「与用户拒绝同构」的结果形状（`granted:false`＋恢复提示），优于设计原设想的错误形状——已同步修正 design D2 措辞（端到端走通有限回答并保留恢复提示）。
- 前端「授权未能保存，本轮按未授权继续」为该 catch 分支无条件提示：对主路径（允许＋写失败）完全准确；对罕见的迟到决定场景措辞略宽（「按未授权继续」与实际「轮次已取消」有差）——瞬态提示、语义保守（不伪造授权），列为已知轻微不精确。
- 未执行真机轮：失败触发条件在真机上不可控（需制造磁盘故障）；集成测试已确定性覆盖。真实链路三项保持手动约定。
