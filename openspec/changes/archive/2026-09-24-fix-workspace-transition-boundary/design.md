## Goals / Non-Goals

**Goals:**

1. 保存、读取、授权、提交之间没有可以产生无人保存正文的空隙。
2. 未成功的候选不改变当前作品身份、当前文档、树、正文和撤销历史；已成功保存的事实仍如实显示。
3. 所有异步回调只影响发起时的作品装载及有效请求；包括错误提示、确认框、刷新通知与 finally 解锁。
4. 打开、新建、最近作品、返回欢迎页、同作品切文档共用明确的受理规则，用户知道何时不能再次操作。

**Non-Goals:**

- 不允许边切换边继续写后再补存；不增加强制切换、进度百分比、超时自动离开、自动重试或用户可见操作队列。
- 不改 AI 文档写入边界、讨论绑定、补读权限算法、讨论档案或 AI 传输生命周期。F03–F09 中除 F08 外均属后批；F10–F14 不纳入。
- 不重写后端事务、不改存储格式、不升级 Tiptap、不做通用事务框架、不重做页面。少量忙碌提示和现有控件禁用是本修复的必要接线。
- 不修复窗口关闭失败重试、讨论保存排空或会话启动取消。已进入销毁/卸载时使本 change 的迟到回调失效，不意味着后批关闭问题已经解决。

## Decisions

### 1. 单次受理，不排队，不后点覆盖（已确认）

采用一个窄的工作区切换协调入口，负责受理和完成，不掌管业务存储。一次只接受一个切文档、打开/重开作品、新建提交或返回欢迎页请求。受理时立即取得唯一操作标识，必须早于第一个 await；当前文档点击的“无需切换”判断也在忙碌判断之后。

- A 正在切到 B 时再点 C：C 不受理、不排队，最终只到 B；用户可在完成后再点 C。
- A 正在切到 B 时再点 A：这不是取消 B，也不是后点优先；保持提示，最终仍到 B。
- 空闲时点当前 A：关闭列表即可，不保存、不读正文、不初始化 AI。
- 打开未完成时不能另行新建/打开/返回欢迎页；新建提交期间不能用表单取消绕过在途结果；禁用入口同时由处理器复核，不能只依靠 disabled。
- 模块标签在切换保护期间暂停导航，避免目标提交后把用户拉回写作页。原先设置页的离开确认规则不变，不借此重做设置流程。

理由：比“后点优先”少一层用户预期和取消语义，不需要补存队列。代次保护仍必须存在，不能因为 UI 禁用就假设旧回调不存在。

### 2. 保护阶段与取消边界（已确认）

| 阶段 | 编辑与页面 | 可取消的既有入口 | 下一步 |
|---|---|---|---|
| 目录选择/新建表单填写 | 不替换当前工作区；尚未进入正文切换保护。系统目录选择由系统处理焦点 | 目录选择取消；尚未提交的新建表单取消 | 选定目标或提交创建后进入保护 |
| 等待组合输入结束 | 只让已经开始的中文组合输入自然完成，不强制 blur、不销毁编辑器、不把尚在选字的拼音保存为正文；不启动保存/离开确认 | 不增加取消按钮；输入法自身确认或取消选字照常 | 最终正文更新完成后暂停所有正文修改 |
| 已暂停，准备候选元数据/离开确认/保存 | 旧正文仍显示，修改入口和额外导航不可用 | 现有离开三选项中的“取消”仍可用，不能被整体 inert 遮住 | 授权并且所需保存成功才读取目标正文 |
| 读取、校验、准备目标编辑器 | 旧工作区仍显示且暂停编辑，不显示候选为当前 | 不新增“取消读取”；返回欢迎页不是取消捷径 | 成功共同提交；失败恢复旧工作区 |
| 成功/失败/取消 | 仅由本操作解除自己的保护；恢复原有可用状态而非一律 enable | 可重新操作 | 失效结果不执行任何成功动作 |

打开作品仍先验证候选元数据再询问离开，但选定目标后、开始候选读取前就进入保护；不把选择目录的整个停留时间冻结成写作时间。最近作品点击直接进入同一保护流程。新建表单填写不是创建；点击创建才受理，失败保留表单值。若后端已创建文件夹而正文装载失败，明确提示“作品已创建，但未能打开：<原因>。可使用‘打开作品’重试。”，不删除该文件夹、不重复创建、不记录打开成功。

返回欢迎页空闲时：受理 → 等组合输入结束 → 暂停编辑 → 原有离开确认/保存 → 同步使作品装载失效并卸载两侧 → 显示欢迎页。取消或保存失败不卸载。若正在切 B，返回请求不受理也不排队；B 完成后需再点返回。程序卸载/销毁另有失效入口，不能让迟到的 B 把欢迎页重新打开成编辑器。

### 3. 暂停必须落到正文修改边界，不只遮住控件

给现有富文本适配器补充窄的“等待组合完成／暂停修改／恢复原状态”能力，实施接口为 `pauseEditing(): Promise<() => void>`。通过真实内核组合态与事件生命周期等待最后一次正文更新；不靠固定延时猜输入法完成。合成事件回归已执行，原生输入法行为仍待人工验收。

暂停覆盖：文字输入/删除/换行、格式与链接修改、撤销/重做、查找替换、粘贴/剪切、拖放及快捷键直接调用。控件禁用负责解释状态；内核与命令入口负责兜底拒绝正文修改。只读选区/滚动/复制不必全屏封锁，AI 面板不全局锁死，AI 输出依旧永不写正文。

异步剪贴板命令在发起时捕获编辑器实例与修改许可代次，完成后再次检查；暂停开始就使旧许可失效，即使切换失败后恢复为同一实例也不能把旧粘贴/剪切补执行。剪切若已复制但不再允许删除，只保留复制结果、不删除原文，不伪称已剪切；可在现有状态区说明“切换期间未执行剪切，原文已保留”。不队列化用户在暂停期敲下的字或命令，提示“正在切换到《B》，暂时不能编辑，请稍候。”。

若受理切换时普通手动保存已在进行：暂停并同步当前结构化状态，等待那次保存返回，再检查是否仍 dirty；必要时在暂停状态下保存剩余修改，只有 clean 或用户明确选择不保存才继续。普通手动保存本身不冻结编辑，也不破坏原快照语义。提交前再次核对实例、身份与未保存判断；发现保护被绕过时中止切换、保留输入，而不是强制销毁或进入无限补存。

### 4. 准备、共同提交与可区分结果

会话层把“读/解析/校验目标并准备候选”与“安装为当前”拆开。准备期只产生私有候选数据/脱离可见容器的候选实例，不改 currentState、当前文档、树、记忆、AI 或交互模块；创建目标实例失败也保留旧实例。空树是明确合法空态，不是读取失败的替代品。

内部结果使用可区分的状态：已准备、已提交、失败、取消、失效、忙碌未受理；可用判别联合表达，失败携带原因。无论使用结果值还是外层抛错适配，读取失败/失效绝不能正常走成功分支。`showProject`、`onProjectReady`、打开助手与表单必须承接同一个最终 Promise（可等待的完成结果），不再允许 `void` 伪装为完成。底层不重复 alert，由仍有效的发起入口负责中文错误。

打开/新建共同提交点：

1. 候选元数据、树、目标正文及目标编辑器均准备成功，确认原身份及本操作仍有效；所有可能失败的读取已结束。
2. 一个没有 await、对外不暴露半套状态的提交段安装编辑器与文件管理的同一作品身份/树，设置当前文档或合法空态，再发布视图和模块导航。先准备可回收候选，旧实例在确认可替换后才销毁；不得让任一订阅在两侧身份错配时启动副作用。
3. 成功分支才更新文档记忆、触发恰一次 `beginProject`、切到写作模块、调用一次最近作品记录。最近作品记录本身继续采用既有失败不阻塞策略：记录失败不回滚已打开作品、不再次初始化 AI，也不冒充正文装载失败。AI 初始化指发起作品级初始化一次，不把异步讨论列表全部加载完当作正文打开门槛。
4. 单文档切换与树回落只发布文档视图/记忆，不触发 `beginProject` 或 `endProject`。取消、失败、失效、忙碌未受理均没有新作品成功副作用。

同作品重开：候选元数据可以在授权前读，但目标正文必须在“保存并离开”真实完成后重读；必要时重取同作品树以避开既有结构操作的旧快照。不得把授权前正文缓存直接提交。选择“不保存并离开”也只在候选准备成功后销毁旧输入；失败仍留下未保存正文。

### 5. 原身份贯穿文件管理的所有 await

分开三个概念：作品路径是磁盘地址；作品装载代次表示“这一次打开”；请求序号表示“这一次读取/操作”。作品成功建立新装载、同路径重开、卸载/销毁都会更新装载代次。协调操作标识从受理就开始生效，不延迟到读正文时。

- 文件管理动作、行内移动确认、重命名、回收站恢复和可见性查询从入口捕获原路径、装载代次、节点身份与操作序号。后续 IPC 使用捕获路径，不在 await 后读取可变 `projectPath`。
- 每次树读取分配刷新序号；仅当前装载最新有效刷新能更新树、渲染、通知 `onTreeChanged`、触发编辑器同步或权限重算。最新刷新失败保留现有树并显示自己的错误，不用更旧的迟到成功“兜底”。状态提示另按操作所有者管理，旧成功/失败/finally 不能清掉新操作的忙碌或错误。
- 可见性关闭的 `documentUsage` 返回后、弹确认前、确认后发写入前都检查原身份。失效则停止，不向 B 弹 A 的确认、不向 B 写 A 的文档 ID。已经发出的后端写操作可能在原作品完成，不能宣称取消磁盘写入或转向新作品；只禁止其续接污染当前界面。权限算法和影响文案本身不改。
- 宿主接收树时也检查身份。切换保护期间不接受会改变当前文档/树的刷新提交；对仍属于原装载的刷新最多暂存最新候选，成功离开后丢弃，失败/取消恢复后重新核验再走既有树接受规则，不在失败恢复瞬间偷偷替换旧文档。已经开始的原作品结构写入不得被转移；同作品重开读取前需等这些已发出的写操作结束并重取树，不新增对外操作队列。
- 树回落需要读另一文档时，同样先准备再共同接受树/文档；失败保留已接受的旧树与旧实例，显示读取错误。磁盘上已完成的删除不回滚；下次有效刷新仍按现有删除确认规则处理，不把 UI 保留旧状态说成删除撤销。用户拒绝丢弃时不接受该树，维持既有规格。
- A→B→A 必须以两次 A 的不同装载代次区分。旧成功、旧失败以及旧 finally 即使路径相同也不再有效。

### 6. 最少的状态提示与焦点处理（方案已确认，完整人工核收待验）

复用当前页面的状态位置，必要时增加一行状态文本，不开新的进度弹窗，不覆盖保存状态的真实含义。持续提示不只靠颜色，使用可被辅助技术读到的状态文本；禁用入口要能看出原因。

| 情况 | 建议文案 |
|---|---|
| 正在选中文字 | 请先完成正在输入的文字，随后继续切换。 |
| 保存并切文档 | 正在保存《A》，随后切换到《B》。暂时不能编辑。 |
| 读取目标文档 | 正在打开《B》，暂时不能编辑，请稍候。 |
| 打开作品 | 正在打开作品《B》，请稍候。 |
| 返回欢迎页 | 正在离开作品，请稍候。 |
| 额外导航未受理 | 正在处理上一次切换，请完成后再操作。 |
| 保存失败 | 保存失败，未切换：<原因>。当前内容已保留。 |
| 目标读取失败 | 未能打开《B》：<原因>。仍保留当前文档，可继续编辑。 |

暂停期间保留旧正文、文档名和作品名，目标只出现在状态提示，不把候选标题提前显示为当前。取消/失败恢复旧编辑位置与选区、撤销历史及控件原先状态；不因恢复抢走 AI 输入框等原有焦点。成功按现有写作页行为进入目标；无需额外成功确认。

## Risks / Trade-offs

- [慢读取时不能继续写，也不能临时改目标] → 明示状态、不排队、不偷偷丢点击；这是已确认的简化取舍，不承诺新取消/超时功能。
- [组合结束事件与最终正文更新顺序不同] → 内核侧等待实际结束与内容稳定，Windows WebView2 微软拼音真机复核；合成事件仅验证协调逻辑。
- [仅靠 UI 禁用漏过程序化修改] → 适配器/内核写入口同样检查保护与修改许可，覆盖异步剪贴板返回。
- [成功保存后目标读取失败] → 保留原实例与历史，但显示已保存而不是伪造 dirty；保存失败则保持未保存与原因。
- [旧结构操作已经写盘] → 不承诺回滚磁盘，捕获路径并隔离后续 UI；同作品重开读取前等待已发写入，失败恢复后的树更新走明确的原身份检查。
- [共同提交执行中出现可预期异常] → 在破坏旧实例前完成读取、校验和候选构建；提交段保持简单且无 await，测试候选构建失败。不要把所有 DOM/OOM 等不可恢复故障包装成通用事务保障。
- [修改等待链牵连其他批次] → 只保留 AI 成功初始化和切文档不重置的不变量；停止、退出排空、关闭重试另批，不顺手修复。
