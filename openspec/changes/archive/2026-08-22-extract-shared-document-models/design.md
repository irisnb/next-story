## Context

结构化文档使用 ProseMirror 风格的位置模型。当前 `structured-notebook.ts`、`format-commands.ts` 和 `editor.ts` 分别实现节点尺寸或位置遍历，`collectLines` 与 `collectBlocks` 还重复了列表和段落的递归位置计算。选区纯文本序列化、格式状态分析和链接定位都依赖这些计算，但本 change 必须保持它们的外部结果不变。

## Goals / Non-Goals

**Goals:**

- 建立一个唯一的节点位置尺寸函数，供所有相关调用方使用。
- 建立一个共享的有序块遍历结果，能够支持选区序列化、格式分析和链接定位。
- 迁移调用方时保留现有导出函数、返回结构、JSON 格式和用户可见行为。
- 用测试锁定根节点、文本节点、空块、嵌套列表和链接位置的边界行为。

**Non-Goals:**

- 不改变文档 JSON schema、位置编号规则或序列化文本规则。
- 不合并选区快照相等判断、存储适配、localStorage fallback 或 AI 面板 DOM 查询。
- 不拆分编辑器/operations 模块，不引入新的运行时依赖，不改变 AI 请求或作品写入权限。

## Decisions

- **共享模块边界**：新增或整理一个前端内部文档模型模块，集中导出节点尺寸和块遍历所需的纯函数。相比继续把实现放在 `structured-notebook.ts` 并让其他模块深度依赖其内部类型，独立边界更清楚；相比保留各模块副本，单一实现能避免位置规则漂移。
- **统一遍历结果**：遍历器返回包含块范围、深度、文本节点、纯文本和段落属性等字段的内部记录。`collectLines` 和 `collectBlocks` 继续各自映射为原有结果类型，而不是改变其公开接口。相比让每个消费者自行递归，统一遍历可以保证位置计算只存在一份；相比强行合并两个公开类型，内部记录不会破坏现有调用方。
- **保持纯函数**：共享模型只读取文档节点并返回新对象，不持有编辑器状态、不访问 DOM、不读写存储。这样可以在 Node 测试中独立验证，并保留 AI 输出不得写回用户文档的边界。
- **迁移顺序**：先为共享函数补充单元测试，再迁移 `structured-notebook.ts`、`format-commands.ts` 和 `editor.ts`，最后运行原有序列化、格式、链接和富文本测试。迁移期间不做无关重命名或格式化。

## Risks / Trade-offs

- [Risk] 统一遍历结果字段不完整，导致格式分析或链接定位行为变化 → 先列出三个消费者当前读取的字段，并用迁移前后的公开结果回归测试覆盖。
- [Risk] 嵌套列表位置偏移在重构中发生一位误差 → 增加多层列表、空段落、空列表项和边界选区测试，并保留现有选择序列化样例。
- [Trade-off] 内部记录可能比单个消费者所需字段更多 → 接受少量内存与代码复杂度，以换取唯一位置算法和可测试边界。
- [Risk] 重构过程中顺手修改公开契约 → 将任务限定为实现替换；任何行为变化必须另开 change。

## Migration Plan

1. 创建共享模型与纯函数测试。
2. 逐个迁移三个调用模块，保留兼容导出和既有返回类型。
3. 运行定向测试、类型检查、lint、构建和完整项目检查。
4. 若回归失败，优先回滚调用方迁移；共享模块只有在全部消费者通过后才保留。

## Open Questions

- 共享模块最终命名可在实现时依据现有模块依赖选择，但必须保持一个公开的内部位置模型来源，不得恢复重复实现。
