# 设计：按需补读（阶段 6 / B）

## Context

- 阶段 5 A 已交付自动附带材料；生产 `sidecar/driver/driver.mjs` 只有文本生成协议（start_session / send_message / replay / cancel / end 与 delta / message_sent / message_done / message_failed）。
- 阶段 1 离线验证（`adapter.mjs`）证明了 DSH 工具循环可行，但协议已分叉：替身有 `tool_request` / `tool_decision` / `approval_wait`，生产驱动与 Rust 不认识（P2-5）。
- `capability_gateway.rs` 只声明 `READ_ONLY_STORY_TOOLS`（story-list / story-read / story-snapshot），`CoreCapability::ToolCall` 仍被拒绝（P2-10）。
- 工具命名两套（P2-6）；Rust 网关缺 Agent 可调用的搜正文工具（P2-7，现有 `story_search.rs` 是阶段 5 预取逻辑）；`max_tokens` 无配置通道（P2-8）；禁用清单两端各自维护（P2-9）。
- DSH 源码核对事实：`ReactLoopAgent` 循环无总步数上限，仅 `maxParallelToolCalls`（默认 10）；有完整的 abort / 取消 / 维护态机制；上下文压缩由 `compaction-basic` + tool-result-pruner 承接；turn / step / tool 事件流可从 session 事件观测。
- `resident-ai-session` 规格「常驻模式下安全边界原样维持」禁止任何工具类插件（P1-9 与本 change 直接冲突，必须修改）。
- 安全地基已就绪：`strict_read_*` 严格只读入口（P0-1 修复归档）、讨论档案材料出处元数据、按会话串行命令队列。

## Goals / Non-Goals

**Goals：**

- 生产链路接通受控只读工具循环：模型经工具调用 → 驱动桥接 → 宿主执行 → 结果回填。
- 讨论级授权模型：请求 / 允许 / 拒绝 / 关闭 / 跨重启持久化 / 待决请求恢复。
- 读取约束落地：已保存正文、轮内版本固定、跳过不可读、宿主侧熔断。
- 参考记录扩展阅读程度；关闭可见性前提示受影响讨论。
- 审计队列 7 必含项：P1-9、P2-5、P2-6、P2-7、P2-8、P2-10（顺带 P2-9）。
- 失败关闭：隐藏 / 回收站 / 越权 / 待恢复事务 / 未授权下工具读取全部拒绝且零副作用。

**Non-Goals：**

- 语义 / 向量检索；多文档未保存快照读取；记忆、后台预加载、全文摘要等 Agent 循环其他能力。
- 任何写入口；及时召唤首轮取材；产品化阅读配额（篇数 / 字数上限）。

## Decisions

### D1：授权请求是专用控制工具 `story-request-reading`

模型在材料不足时调用 `story-request-reading { reason }` 发起授权请求；宿主拦截该调用，转为面向用户的授权提示；用户决定后以工具结果（granted / denied）回填，模型继续或转有限回答。

- 理由：机器可读、与 DSH 工具循环天然契合（暂停 = 挂起的工具调用，恢复 = 工具结果返回），原因字段强制结构化。
- 替代方案：检测模型文本（脆弱、不可靠）；宿主预扫问题猜测需求（违背「确实需要时再问」）。

### D2：工具执行全部在 Rust 宿主，node 驱动只桥接

驱动协议新增 `tool_call`（驱动 → 宿主）与 `tool_result`（宿主 → 驱动）事件。node 进程注册 Agent 工具面（story-list / story-read / story-search / story-request-reading），但实现仅为转发；MUST NOT 自行读取作品文件。执行器只注入窄化 `StrictStoryReader` 接口（P0-1 修复既定方向），类型层面不暴露保存 / 恢复 / 迁移 / 删除函数。

- 理由：Rust 是作品数据唯一保管者；协议面天然无写入通道；替换 DSH 版本时桥接层不变。

### D3：授权真相在讨论档案，宿主逐次校验

授权状态（未授权 / 已授权）、待决请求与读取出处都持久化在 `conversation_store` 讨论档案；驱动与 DSH 不持有权限。宿主每次收到 `tool_call` 都重新校验：讨论授权状态 + 作品身份 + 回收站 + AI 可见性 + 版本 + 待恢复事务（严格只读失败关闭）。

- 理由：关闭授权立即生效、崩溃恢复不依赖进程内存、闸门不依赖模型自制力。

### D4：轮内版本固定

宿主按（讨论, 轮, 文档）维护版本固定表：`story-list` 返回各文档当前版本；`story-read` 必须携带版本；首次读取成功即固定该轮版本；同轮后续读取版本不匹配返回结构化错误 `story_version_changed`（本轮停读该文档，下一轮读新版）。

- 理由：避免一次回答拼接两个版本的不存在内容；决策来自产品确认（2026-09-17）。

### D5：宿主侧失控保险丝

宿主按轮计数（补读工具调用次数 + 累计时长），超阈值后对该轮后续 `tool_call` 一律返回结构化「补读已停止」错误，模型基于已有材料收束回答。阈值配置化，初始值由离线 + 真实链路验证确定；不写入产品承诺，不向用户呈现篇数 / 字数配额。

- 理由：DSH 框架无总步数上限（源码核对）；上下文压缩解决「装不下」不解决「不停调用」；放在宿主因为宿主看得见每次调用且是强制执行点。
- 替代方案：改 DSH 源码加步数上限（升级负担）；只靠用户手动停止（异常时无人盯着）。

### D6：工具命名统一为 dash 风格

Agent 工具面：`story-list` / `story-read` / `story-search` / `story-request-reading`。`story-snapshot` 保留给系统自动取材路径，不进入 Agent 工具面（本阶段补读只读已保存正文）。验证替身 `adapter.mjs` 的 `story.list` 等旧名一并统一。

- 理由：与 Rust 网关既有声明一致，改动面最小；dash 风格与 DSH 禁用工具清单一致。

### D7：驱动协议单一真相源

新增 `sidecar/driver/protocol.json`（机器可读：事件名、方向、字段），`driver.mjs` 与 `adapter.mjs` 共用；Rust 侧契约测试解析同一文件，断言与 `dsh_driver.rs` 常量一致。验证替身补齐生产已有事件的断言（含 `message_sent`）。

- 理由：P2-5 的教训是替身协议漂移让验证失真；单一文件 + 双端测试是最小可信方案。

### D8：等待授权期间从简处理

授权等待发生在会话内：轮次挂起、不产生模型请求，等待通常以分钟计。等待期间退出应用时，该轮按既有「中断轮」语义处理（与生成中退出一致），不新增跨重启待决状态与恢复流；重开后用户经授权开关开启并重试或重发即可。调度规则不变：挂起轮次沿用既有占用语义，不新增名额释放与恢复准入规则。等待中轮次可被停止生成取消。

- 理由：为「关应用时恰好停在等授权」这一个罕见瞬间造三件永久机器（待决持久化、重开恢复、自动重跑）不值；既有中断机制已体面接住该场景（2026-09-18 纠偏决策）。
- 替代方案：跨重启保留待决请求并在选择后自动重跑——体验最顺但机器最重，被否。

### D9：同轮同版去重

宿主按轮记录已提供的（文档, 版本, 范围）：同轮内重复请求同版本同范围内容时返回简短「已提供过」提示（附出处），不重复装入全文；跨轮不屏蔽重读——会话历史与 DSH 压缩决定模型是否仍持有旧内容，压缩后重读是合法需要——不必要重复由提示词约束。

- 理由：开发指引阶段表明确要求「去重和识别版本」、阶段 0 设计要求「同版全文避免重复装入」（2026-09-18 纠偏补回）；同轮去重可由宿主确定性执行，跨轮去重无法与 DSH 压缩正确配合。

### D10：max_tokens 配置链

LLM 配置增加可选 `max_tokens` 字段 → `dsh_driver.rs` 透传 → `driver.mjs --max-tokens`。缺省维持现有默认 131072。

### D11：story-search 复用既有字面检索内核

`story-search` 复用 `story_search.rs` 内核（NFKC 规范化等），Agent 提供检索词；每次调用施加与 A 部分一致的输出硬上限（初值沿用 5 文档 / 10 片段 / 前后各 120 字符）；Agent 可迭代多次调用，总量由 D5 熔断兜底。

### D12：阅读程度由宿主判定

宿主按轮累计各文档读取范围对照已保存正文长度判定：仅检索命中 = 搜索片段；读取过但未覆盖全文 = 局部阅读；覆盖全文 = 完整阅读。出处只存最小元数据。

### D13：召唤首轮与未授权讨论由宿主硬门禁

及时召唤首轮与未授权讨论的补读 `tool_call` 一律宿主结构化拒绝（提示词同时说明「材料不足先请求授权；召唤首轮只用选区」）。强制点在 Rust，不依赖提示词遵从。

### D14：禁用清单单一真相源

`gen-config.mjs` 的 DENY_IDS 与 `capability_gateway.rs` 注释清单由同一份清单文件生成两端配置与测试（P2-9）。

## Risks / Trade-offs

- [作品正文是不可信输入，可能含注入指令诱导工具滥用] → 工具面只有只读四件套；宿主逐次校验授权 / 可见性 / 版本；无写 / 命令 / 网络面；D5 熔断限总量。
- [授权后模型读得过多：上下文膨胀与费用] → DSH 压缩承接 + D5 熔断；真实链路验证校准阈值。
- [模型绕过请求工具直接调 story 工具] → D13 结构化拒绝并引导先请求授权。
- [等待授权期间驱动进程崩溃] → 该轮按既有崩溃恢复语义处理为中断；授权状态在档案（D3），不依赖驱动存活。
- [工具结果过大] → `story-read` 支持范围分段与单次上限；`story-search` 每次调用输出硬上限（D11）。
- [旧档案兼容] → 新字段全部可选，缺省视为未授权；读取容错沿用既有规则。
- [替身与生产协议再漂移] → D7 单一真相源 + 双端契约测试。

## Migration Plan

任务顺序（见 tasks.md）：协议真相源与命名统一 → 网关真实授权与宿主执行器 → 驱动工具通道接入 → 档案字段与前端授权 UI → 熔断与失败关闭测试 → 离线与真实链路回归。回滚：change 归档前整体还原即可；讨论档案新字段向后兼容，不阻塞旧版本读取。

- `story-search` 每调用输出上限是否调整：初值沿用 A 部分常数，验证后可调。
