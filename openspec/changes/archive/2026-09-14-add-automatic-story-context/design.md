## Context

阶段 4 已提供 Rust/Tauri 统一受控只读作品入口与文档级 AI 可见性事实源，但常规讨论仍未自动获得作品材料。本 change 把阶段五的 A 部分（关注文档现场 + 允许目录投影 + 后端跨文档字面检索）接入常规首轮与追问，材料准备放在 Rust/Tauri 请求链路中，避免前端或 DSH 绕过权限；讨论的关注文档与当前查看文档保持独立。

## Goals / Non-Goals

**Goals:**
- 常规首轮和追问按发送时刻冻结关注文档、未保存快照和允许读取的目录结构。
- 后端执行受权限控制的同作品跨文档字面检索，提供候选片段、来源和版本。
- 记录实际进入模型上下文的材料出处与限制状态，并显示轻量参考说明。
- 明确处理关注文档显式切换、材料超限、及时召唤隔离及权限变化后的历史语义。
- 与阶段 4 对齐：使用后来被隐藏材料的讨论永久只读，旧出处脱敏。

**Non-Goals:**
- Agent B 自主工具补读、语义/向量检索、摘要、记忆、文件自动上传。
- 及时召唤的完整作品取材、任何作品写入、通用文件/命令/网络工具。
- 调用模型做候选词提取或从作品反向抽词；中文分词 / 实体识别。

## Decisions

- **阶段五只做 A**：实现关注文档现场、允许目录投影和后端跨文档字面检索。不注册 Agent 补读工具，不实现语义/向量检索，不实现文件上传；这些属于后续阶段，需单独 OpenSpec change 定义。
- **关注文档显式绑定**：切换查看文档不改变讨论关注对象；只有明确操作才切换并产生可见提示；切换在下一轮生效，不影响已发送或正在生成的轮次；每个讨论独立持有自己的关注文档。
- **复用既有身份契约**：不另造第二套 ID。前端沿用 `SelectionSnapshot` 的 `projectPath` / `documentId` / `documentVersion` / `bodySnapshot`（`bodySnapshot` 为 `canonicalNotebookJson` 输出的合法 Tiptap JSON 字符串）；Rust 侧沿用 `story_material.rs` 的 `ReadMaterialRequest.work_id`（作品根规范化路径 = `projectPath`）、`document_id`（稳定节点 ID）、`expected_version`/`MaterialSnapshot.version`（FNV-1a 内容派生散列 = `documentVersion`）、`MaterialSnapshot.content`（= `bodySnapshot`）。无选区直接提问仍可提供关注文档快照；关注文档未在编辑器中打开时，只使用其当前允许的已保存版本（不产生未保存快照）；快照校验失败拒绝且 MUST NOT 静默回退到磁盘稿。材料身份在冻结时点固定，排队前 MUST 重新校验权限，后续编辑 MUST NOT 改变该轮材料。
- **后端统一取材**：前端只传递讨论身份、关注文档身份和必要快照；Rust/Tauri 统一执行可见性、回收站、版本和作品校验，再组装 DSH task 文本。
- **候选词确定性提取（内部初始值）**：候选词只从本轮用户新增问题文本确定性提取，不调用模型、不从作品反向抽词。提取算法：规范化采用 Unicode NFKC 归一 + 英文小写 + 连续空白折叠，并保留规范化到原文的字符位置映射；抽取两类连续片段——中文连续片段（按原样抽取，不做中文分词 / 实体识别，整段中文可能漏检，不承诺中文分词）与拉丁字母 / 数字连续片段；每个片段至少 2 个 Unicode 字符；去重按首次出现顺序，至多取 8 个词。8 候选词 / 5 文档 / 10 片段 / 命中前后各 120 Unicode 字符均为**检索输出的硬上限**（只约束检索返回多少），不是模型上下文上限；模型上下文上限不由阶段五猜测或计算，交给既有 DSH/provider 处理（见「超限交给既有链路处理」决策）。以下数值均为内部初始值，需真实效果验证，非产品效果保证。
- **字面检索范围与规范化**：检索范围限定为同作品、非回收站、当前允许 AI 查看、已保存正文的文档，并排除关注文档以免重复。搜索只在正文中进行：标题不冒充正文，标题只用于来源显示（`StoryMaterial.document_name`），不作为候选词来源。命中片段按树顺序与文档内原文位置稳定排序；每个命中取前后各 120 个 Unicode 字符，重叠窗口合并；结果至多取 5 个文档、10 个片段。候选词数或结果片段数达到上限时记录为受限（本次检索受限），MUST NOT 宣称完成全量检索。未命中记录为 `not_found`，不是"作品中不存在"。
- **超限交给既有链路处理，不前置猜测容量**：阶段五不计算、不猜测模型上下文容量（不新建模型容量表，不凭固定数值估计 token 预算）。常规请求照常组装（关注文档现场 + 目录投影 + 检索片段），材料总量只受检索输出硬上限约束（至多 8 候选词 / 5 文档 / 10 片段 / 命中前后各 120 字符）；上下文是否超限交给既有 DSH 框架压缩与 provider 处理。仅当 provider/DSH 返回明确超限错误（`context_window_exceeded` / `request too large`，映射为 `request_too_large`）时，如实记录该轮失败，且 MUST NOT 伪称该轮未发送。不手工截断历史或本轮材料，不做选择器 / 自动缩减重试 / 文件上传。
- **材料状态诚实记录，仅凭回执标记已发送**：每轮材料的生命周期状态显式区分 `prepared`（已组装、想发送）/ `accepted`（DSH 已接收并进入处理）/ `omitted`（因限制未纳入）/ `rejected`（权限或校验拒绝）/ `failed`（明确失败）/ `unknown`（无法确认是否送达 provider）。`entered_model_context` 只表示「材料已组装进提交的请求」（想发送），语义不变。provider 级发送回执落地为 **`message_sent` 协议事件**：驱动在本轮范围内首次观测到 provider 侧回应证据（第一个 `assistant/chunk` 的 text-delta，或 `assistant/message`）时发出一次、先于终态；取消/失败于任何回应证据之前时不发，仅组装未到 provider 也不发。宿主把它折算为轮级 `sent_confirmed` 标记（`MaterialProvenance.sent_confirmed` / 结果 `sent_confirmed`）：只有收到 `message_sent` 才为 true，未观测到回执保持未确认（不是「未发送」），绝不伪造。检索结果 `not_found` 与 `no_query_terms` 是检索结果状态，不是正文或材料内容。
- **历史与新权限分离**：权限关闭不删除旧会话及当时的材料出处；新的读取必须遵守当前权限。含受限旧材料的讨论永久只读，重新可见不解除；查看旧讨论时旧出处脱敏，不泄露被隐藏文档身份。
- **召唤隔离**：材料准备仅作用于常规直接提问和常规追问，不改变及时召唤快车道。
- **真实链路 max_tokens 传输修正**：真实链路验证发现 DSH 默认 `max_tokens=256000` 会遭严格校验端点拒绝（智谱 coding 接口允许 [1,131072]，超范围直接 400 `INVALID_REQUEST`）。`driver.mjs` 增加 `--max-tokens` 启动参数，默认 131072（已知最严校验范围内），宿主可按端点覆盖。这是传输层修正，不构成对模型上下文容量的猜测或承诺。

## Risks / Trade-offs

- [检索漏读或误命中] → 标记为候选片段，记录检索范围，不把未命中解释为不存在；中文连续片段整段漏检是已知限制，不承诺中文分词。
- [未保存快照与磁盘版本混用] → 每轮冻结材料身份和版本，统一校验快照哈希；校验失败拒绝，不静默回退。
- [权限变化导致旧材料重新进入模型] → 新请求重新授权；恢复时检查材料出处和当前权限；受限讨论永久只读。
- [长篇材料增加等待] → 分离现场材料与命中片段，测量取材/排队/模型等待；上下文是否超限交给既有链路，不前置猜测。
- [无法观测 provider 是否真正发送] → 已落地 `message_sent` 回执（首轮 provider 侧回应证据，一次、先于终态）；宿主折算为 `sent_confirmed`，只有收到回执才标记，未确认时如实显示「送达未确认」。
- [回执语义边界] → `message_sent` 证明 provider 收到并开始回应，不证明完整送达/处理完成；取消发生在回应证据之后时回执已发出（诚实反映），之前则无回执。
