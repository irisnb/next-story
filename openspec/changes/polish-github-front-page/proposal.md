# 提案：GitHub 门面重整——README 访客导向改写与开发者手册外移

## Why

v0.1.0 已公开发布，GitHub 仓库首页是产品的第一门面。现行 README 把内部开发账本堆在首页：17 行全「已完成」的里程碑表、「已撤出、非待办」清单、76 项规格计数、约百行构建手册与文件索引——外部访客难以在三屏内判断「这是什么、能干什么、去哪下载」，与同类项目（思源笔记、pot-desktop 等）的门面差距明显。2026-10-29 用户两轮拍板：①README 重整、内部账本移出（截图直出维持 2026-10-24 拍板不上，本次复确认）；②README 采用**双受众叙事**——创作者一段说清产品（官网承接细节），开发者获得一等分区讲述「AI＋本地文件读写边界」这个普遍问题的解法，并把**框架能做什么、基础功能有哪些**在一篇架构文档里说明白（不动许可、不做框架抽取）。

## What Changes

- **README 全量改写**为双受众导向结构（约 266 行 → 约 140 行）：
  - 保留：居中标志与定位语、徽章排、简介与官网链接、下载区（含 SmartScreen 提示）、协作与协议。
  - 简介为创作者一段说清「这是什么、给谁、AI 不碰你的稿子」，产品细节由官网承接。
  - 「已实现能力」改写为「核心特性」五分组（写作空间与项目 / AI 陪想 / 讨论管理 / 制作模块 / 导入导出与基础），保留主要用户可见能力的具体细节（编辑器格式完整列举、宽度三档数值、两种问法与生成控制、讨论列表管理、制作模块双标签与零卡链路、导入导出格式），三条稀有能力（未保存快照可问、授权补读、参考出处可查）前置呈现；去除内部实现细节（`story-read` 等工具名、存储路径、规格与归档计数）。
  - **新增「给开发者」一等分区**：点出普遍问题（AI＋本地文件：怎么让模型看得见内容又不给它写权限）→ Next Story 的解法概览（保管者/使用者分离、受控只读接口、文档级可见性与授权补读、AI 无写能力）→ 架构示意图（非界面截图，不违反截图不直出拍板）→ 深读链接 `docs/ARCHITECTURE.md` 与 `docs/DEVELOPMENT.md`。
  - **删除「当前里程碑」表**（2026-10-29 推翻 2026-10-24 版规格中「里程碑覆盖全部已归档能力」的职责；能力清单真相源归 `openspec/specs/`，README 留一行链接）。
  - 「当前没有的能力（已撤出，非待办）」改写为产品语言的「如实说明」：只保留访客能理解的三条——作品正文为手动保存（无自动保存/备份）、全应用仅一份 API 配置、仅发行 Windows 版；删除内部治理概念清单（附近上下文、思考收束等）。
  - 开发者速览（依赖安装两条命令＋命令小表）并入「给开发者」分区。
- **新建 `docs/ARCHITECTURE.md`**：向开发者**把框架能做什么、基础功能有哪些说明白**——保管者/使用者分离、框架基础能力清单六组（内容保管 / 受控只读接口 / 可见性与授权 / 常驻会话可靠性 / 材料可追溯 / 隔离边界）、每组能力的已归档规格依据；口径以 `openspec/specs/` 为准，不宣称未实现能力。
- **新建 `docs/DEVELOPMENT.md`** 承接外移内容：开发环境准备、依赖安装、`npm run check` 全科目说明、Windows 打包三步、简明文件索引、数据保存明细表与 API Key 安全说明；并新增**发布流程**一节，写明 Release 说明必须以 `--notes-file` 传 UTF-8 文件、禁止 PowerShell 内联中文参数（2026-10-24 首发乱码根因，根治复发）。
- **不变项**：README 不直出界面截图（维持 2026-10-24 拍板）；命名口径（项目 / 讨论 / 新建讨论）；平台口径仅 Windows；图片资产自包含规则；许可表述（保留所有权利，不动）。
- **不改任何产品行为与应用代码**；本 change 不含已完成的 Release 乱码修复（该操作 2026-10-29 已直接完成：`gh release edit v0.1.0 --notes-file` 覆盖为正确 UTF-8 文案）。

## Capabilities

### New Capabilities

- `repo-architecture-doc`: 主仓库架构文档 `docs/ARCHITECTURE.md` 的职责——向开发者说明框架能做什么、基础功能有哪些：保管者/使用者分离、六组基础能力清单（内容保管 / 受控只读接口 / 可见性与授权 / 常驻会话可靠性 / 材料可追溯 / 隔离边界），每组能力的已归档规格依据；口径以 `openspec/specs/` 为准。
- `repo-dev-docs`: 主仓库开发者文档 `docs/DEVELOPMENT.md` 的职责与内容边界——开发环境准备、依赖安装、检查科目、打包流程、文件索引、数据保存明细、API Key 安全说明、发布流程（含 `--notes-file` UTF-8 规则）。

### Modified Capabilities

- `repo-readme`: README 结构要求变更——改双受众导向结构：新增「给开发者」一等分区（普遍问题→解法概览→架构示意图→深读链接），核心特性分组短句且三条稀有能力前置，如实说明用产品语言，废止「里程碑覆盖已归档能力」要求（改为单行链接 `openspec/specs/` 与 Releases），开发者速览并入给开发者分区；截图不直出、事实口径、命名口径、平台口径、图片资产自包含等既有要求维持。

## Impact

- 主仓库文件：`README.md` 全量改写；新增 `docs/ARCHITECTURE.md` 与 `docs/DEVELOPMENT.md`。
- 不涉及应用代码、CI 配置与构建脚本；`npm run check` 不受影响。
- 对外效果：创作者三屏内获得「是什么—能干什么—如实边界—去哪下载」；开发者获得「AI＋本地文件读写边界」的完整架构叙事与能力清单，可读可学（许可维持现状，不含开放与抽取决策）。
- 流程效果：发布说明编码规则落入版本化文档，杜绝乱码复发。
