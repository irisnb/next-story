# validate-prompt-foundation：提示底座两段过时限制的小范围修正

> 决策来源：用户 2026-10-06 拍板「两条过时限制可以删除/修正，先修正才是正事，不先做 ABC 实验」。原隔离实验提案（A/B/C 三组变体实验）**当前不实施**，其实验设计底稿 `方向/提示底座验证-实验提案草案-2026-10-05.md` 顶部已加状态注记；本 change 沿用原名、内容改写为小范围生产修正。**尚未获 apply 授权前不写代码。**

## Why

红线层提示词（`generate.rs` `constitution_prompt()`）里有两段措辞**落后于已实现的能力**，与实况打架：

1. **旧读取禁止列表**（八连「不能声称读取或使用……选区前后文/当前文档全文/摘要/作品元数据/AI 内容库/历史会话/记忆/用户确认的作品事实」）：写于阶段五 A／阶段六之前。现在系统**确实会**随常规请求自动附带关注文档现场材料（已保存正文或经校验快照）、允许目录投影与跨文档字面检索片段，经授权还可补读——一刀切「不能声称读取」既否认了实际提供的材料，也诱导模型对自己明明收到的内容说「没读过」，恰好伤害诚实维度。
2. **旧追问锚定段**（「追问仍锚定首次冻结选区；只把已有轮次当作当前临时线性对话……」）：写于旧选区锚定流程时代。现在有直接提问（可能无选区）、关注文档显式切换、召唤快车道——强制每轮追问锚定首次冻结选区会错误绑死新问题。

用户已看过两段候选新文字（2026-10-05 草案 §3.1），本次拍板直接采用、先行修正；效果不做实验预验证，合入后经日常使用观察。

## What Changes

- **只改一处生产字符串常量**：`src-tauri/src/llm_config/generate.rs` 的 `constitution_prompt()` 内做两段**精确逐字替换**（替换前语义＝草案旧段一/旧段二，替换后＝草案新段一/新段二，全文见 design「精确改动文本」），并同步该函数的 doc 注释。其余一切逐字不动：身份句、不直接修改用户文档、不代写正文、不润色、不提供替换文本、不判断故事好坏/正确错误/高级低级、纯文本回答条款、入口层立场句、工具使用层、驱动 persona（`cordis.driver.yaml` 不改）。
- **权限与取材流程零改动**：受控只读边界、自动现场材料、按需补读、快车道、消息结构（提示词仍在首轮 user 消息文本内）全部不变。
- **定向测试改写**：现有三个把旧措辞逐句钉死的组装测试改为**诚实材料边界断言**（新段落关键句存在＋旧措辞不存在＋永久边界条款一条不删）；崩溃恢复重放前缀补新段落断言。测试计划见 design。
- **主 spec 修订**：`dsh-headless-generation`（组装提示的诚实材料边界与追问语义）、`selection-ai-summon`（追问锚定语义）各一个既有 requirement 走 MODIFIED；**删除本 change 内未实施的 `prompt-foundation-experiment` 实验 delta**（不新建实验能力）。
- **不做**：不增加函数可见性、不建实验代理/测试平台、不发起任何付费模型调用、不做 A/B/C 实验、不改前端与 sidecar、不加依赖。

### Modified Capabilities
- `dsh-headless-generation`: 既有 requirement「DSH headless 生成与现有链等价」补入诚实材料边界与追问围绕当前问题的提示词语义（取代一刀切读取禁止与强制锚定）。

## Impact

- **生产代码**：`generate.rs` 一处字符串常量（两段文字）＋doc 注释；无逻辑、签名、可见性、依赖变化。前端与 `sidecar/` 零改动（旧措辞在 `src/`、`sidecar/` 无其他出现，已核）。
- **测试**：`generate.rs` 测试模块内三个钉死测试改写＋恢复前缀测试补断言；全部既有测试（含协议、编排、取材）必须保持绿。
- **验证门禁**：`npm run check` 全绿（无新增真实模型调用）。
- **行为影响面**：所有走 `compose_system_prompt` 的路径——直接提问首轮、召唤首轮、崩溃恢复重放前缀、legacy 一次性链；追问轮本就无提示前缀，结构不变。
