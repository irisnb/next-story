# 前端 UI 全量更新：设计与实施方案

日期：2026-10-09。状态：设计整理与 OpenSpec propose，待范围审阅；未实施。

> **2026-10-10 状态注记**：本方案已随唯一 change `update-frontend-ui-v5` 实施并归档（`openspec/changes/archive/2026-10-10-update-frontend-ui-v5/`，2026-10-10）。下文「未实施」「实现任务全部未完成」等为该规范撰写时（propose 阶段）的历史状态，保留不改；现行行为以 `openspec/specs/` 为准。

## 1. 结论与审阅入口

正式 UI 采用已认可的整套原型 v5；发送按钮采用黑色实心底＋作者个人 PNG 浅色彩蛋；应用图标采用独立图标 v3 的 04「开口」。三项放在唯一 change `update-frontend-ui-v5` 内实施，包含取消应用内浮动讨论窗口及其规格迁移。

本文件是唯一完整设计实施规范。OpenSpec 的 proposal、design、delta specs、tasks 分别记录范围、实施决策、行为合同与工作顺序，引用本文件，不另复制一套详细设计规范。设计认可不等于实现授权：本轮仅写文档，用户审阅范围后才 apply。

设计依据：`前端UI暂存-2026-10-09/README.md` 的「当前拍板」、`原型-v5/index.html` 与最终覆盖层、`手绘按钮预览-v0/README.md`、`Next-Story图标方案-v3/04-aperture.svg`；历史反馈见同目录 `保存反馈.md`，前期框架见 `前端UI全量更新-第一批设计稿与原型验证记录-2026-10-08.md`。最终效果以 v5 整体及两项定案素材为准，不能只照基础 styles.css。

## 2. 范围、命名与待定事项

覆盖首页/创建与打开入口、公共顶栏、写作、文档管理、制作、设置，以及菜单、对话框、提示、空白/等待/失败/只读状态、Windows 应用图标。功能接回已有真实服务，保留既有可靠性保护。

| 名称 | 决定与执行口径 |
| --- | --- |
| 项目 | `保存反馈.md` 第 2 条已记录用户决定将界面「作品」改为「项目」。当前 AGENTS 与历史规格仍称「作品」，本轮不修改它们；实施前在同一 change 内统一方向词汇与宪法对应条款，再统一用户可见界面。代码 `project` 和存储格式不改名。不得混用或将历史引用当作新界面文案。 |
| 文档管理 | 四页导航使用此名；旧「文件管理」作为模块代码/历史规格名称保留，不并列出现在新界面。 |
| 制作 | 导航简称；正文说明可称「制作模块」，指同一模块。 |
| AI 陪想 | 新名称尚未决定，暂沿用；不强制用户现在起名，不阻塞本方案审阅。 |

需要批准的是本方案与唯一 change 的整体实施范围；v5、黑底按钮、04 图标、取消浮动窗口及命名决定均不重新选型。新建默认落点、树排序策略、深层级/长名的额外产品规则未单独拍板，本 change 沿用现有规则，增加极端内容的可用性验收；不借视觉重做另定规则。

不扩大到新 AI 能力、职责未知的小助手、后台摘要/记忆/预加载/Agent 循环、模型供应商目录或自动写正文。制作页已有实现，不用原型演示数据替代。

本提案需确认的行为收口：推荐切换编辑器文档时保留按讨论草稿，清除未发送实时选区与待附带重点提示。现行`persistent-ai-panel-entry`规定切文档清未发送输入；代码`ai-panel-reducer.ts`已按conversationId保存草稿，但存储机制不等于用户批准。本方案显式调整旧合同，随整体范围批准；关注文档绑定、在途请求、已发送冻结材料与召唤快照保留。

导航以最终v5整体认可为基线。10-08记录§11.1关于导航视觉分量未定是历史状态，本轮不额外增强，也不改写历史记录；后续变化需新的用户反馈。

## 3. 视觉体系与公共组件

采用克制的中性灰白、近黑文字和主操作，细分隔线、轻圆角、充足留白。正式替换旧 `design-tokens` 的新粗野主义、黑色只作结构线、重框硬阴影规则。编辑正文靠空间和阅读节奏突出，不能保留旧重框再叠新样式。

| 基础项 | v5 基线与实施要求 |
| --- | --- |
| 文字/弱文字 | #202020 / #737373；弱文字仍须可读，错误与禁用不能混淆。 |
| 线/浅面 | #e4e4e4 / #f6f6f6；稿纸外背景约 #f5f5f5；主要面白色。 |
| 圆角 | 基础 .4rem，组件按原型层级统一；不使用旧硬偏移阴影。 |
| 字体 | 中文界面沿用原型 Microsoft YaHei UI / Microsoft YaHei，Windows 回退 Segoe UI；品牌英文字标 Georgia。正文字体与文档格式保持既有编辑器行为，不强制重写正文样式。 |
| 字阶 | 通用14px，辅助12px，页面标题约25px，项目名21–23px；图标一般18px、工具图标20px。最终以三尺寸最终原型比对为准。 |
| 交互 | 黑底白字为主操作/激活；中性浅底为悬停，选中同时用文本/形状/aria状态表达；焦点环明确可见。 |

统一 CSS 令牌承载颜色、尺寸、圆角、阴影、字阶与间距，Basecoat 1.0.2（MIT）作为已核实组件基础。正式接入采用可构建的本地资源或固定版本依赖并保留许可，不依赖 CDN、Temp 或运行时外网。不直接移植原型多层覆盖文件与演示 JS；整合成可维护的正式组件样式，避免两套事件处理重复接线。

按钮/输入/菜单/标签/对话框状态统一：默认、hover、active、focus-visible、disabled、busy、error。所有图标按钮有中文可访问名称；hover 与键盘聚焦只出现一个中文浮层提示，同一触发路径不能同时带原生 title。长名称的完整名称 title 保留。浮层关闭、切页、触发元素隐藏时移除提示；菜单 Escape 关闭并恢复焦点。尊重减少动态效果偏好，不加常驻动画。

## 4. 首页、顶栏与页面切换

首页保留 v5 的左右分区：左侧开始入口，右侧最近项目；创建/打开/最近条目接回真实创建、文件选择、路径检查、缺失与失败流程。演示路径、内容、成功提示不得进入正式默认状态。最近列表无数据时提供清晰入口，失败保留可重试路径。

顶栏固定三列 `minmax(0,1fr) auto minmax(0,1fr)`：左侧项目名及返回入口，中间四页导航，右侧保存状态与 AI 入口。导航顺序为写作、文档管理、制作、设置，切页不因两侧宽度变化而漂移。项目名更醒目，长名截断且可查看全名，不挤导航/按钮。保存状态必须来自真实状态，保留失败、未保存与保存中反馈。

页面切换继续走原有正文保存、中文输入组合与设置未保存修改保护；保存失败不假装离开成功，取消离开保留输入和选区。制作页使用独立制作会话；日常 AI 不覆盖制作页、不修改链路配置。

## 5. 写作页

文档栏承担当前文档与切换，正文稿纸居中，左侧窄竖工具栏、右侧 AI 面板。切文档继续先保存，清除编辑器未发送实时选区与待附带重点提示；按讨论保留草稿、在途请求、历史、关注文档绑定及已发送冻结材料/召唤快照。查看文档不自动改变讨论绑定的关注文档。项目卸载或替换则停止或使旧范围请求失效、清运行态，保留讨论档案。

工具尽量单列图标，短横线分组；数值控件旁就近开菜单，段落样式折叠，缩进统一入口。沿用所有已实现格式能力，保留链接、字母/罗马编号及既有受控粘贴规则（图片不进入文档，也不产生 `[图片]` 占位，不新增图片插入功能）；图文混合仅保留可可靠提取的文字，纯图片不改变文档，均显示相应中文提示，依据已归档的 `controlled-rich-text-paste` 规格。矮窗中溢出工具收进底部省略菜单，高窗自动回到工具栏；不复制有独立状态的第二套工具，不删功能。工具/菜单操作保留编辑器选区，不因点按钮丢失格式作用对象。显示偏好入口移至设置。

写作宽度仍为窄640、标准720、宽860，默认720；空间足够时固定单栏，不随面板开合拉宽行长，空间不足时收缩到可用宽度，不横向滚动。留白偏好独立保留并持久化。宽度、背景与留白不进入文档结构、AI材料或导出。

## 6. 单 AI 面板、多讨论

取消多窗口同时显示、讨论窗口拖出浮动、浮窗移动/几何缩放、吸附、并排对照与恢复窗口布局入口。保留边栏宽度分隔条及选区旁单动作AI浮动按钮。讨论仍可多个并存且并发生成；显示只有一个当前讨论视图，讨论身份和请求状态不能依赖视图是否挂载。

| 动作 | 结果 |
| --- | --- |
| 顶栏打开 AI | 先打开右边栏，显示当前讨论；不直接进入全宽。 |
| 最大化/恢复边栏 | 面板内固定108px按钮；最大化临时隐藏正文显示，恢复回并排。图标为矩形/双矩形，中文明标签。 |
| 顶栏收起或面板 × | 隐藏面板、退出最大化、收起讨论列表；保留消息与未发送输入，生成/排队继续。 |
| 切换讨论 | 只换当前视图；原讨论生成、队列、授权等待、历史及草稿保留，迟到结果只进入所属讨论。 |
| 新建/及时召唤 | 产生独立讨论并成为当前显示；旧讨论继续保留，必要时继续生成。 |
| 停止 | 显式停止对应讨论当前轮或移出队列；已完成内容保留，不删除讨论。 |
| 重开 | 显示对应历史和真实状态；不自动重发。 |
| 删除 | 独立确认/撤销语义沿用，生成中先停止再删；不由关闭或切换触发。 |

头部动作顺序固定「讨论→最大化/恢复→×」，展开与全宽状态的三个按钮边界位移≤1 CSS px。关闭后重开右边栏，正文可见，不残留旧浮层。

讨论列表在面板内部覆盖显示，保留按时间分组、置顶、重命名、删除确认与撤销、标题/文档过滤，以及真实生成/排队/失败等状态。并排模式不遮正文；全宽模式沿用同一面板列表。停靠/浮动位置标签退场，状态改为讨论状态，不把未显示讨论标成已停止。

当前关注文档、下一轮生效提示、本次参考了什么、选区重点提示与移除、直接提问、线性追问、编辑失败问题重发、重试、只读限制、前往设置、补读允许/拒绝/撤销授权等入口均接回现有 action。发送按钮外观变化不改变发送资格、材料冻结、中文输入或重复提交保护；按钮禁用/生成中使用真实状态，停止另有明确按钮。

全局并发上限保持4，前后端同值，同讨论至多一轮，先到先服务；隐藏当前视图不释放名额。180秒无协议事件看护与授权等待豁免保留。崩溃恢复须恢复所有在途讨论的业务状态，不只恢复当前可见视图。退出应用及切项目的已有停止、保存排空和失效保护不等同于普通隐藏面板，按原可靠性规则继续执行。

会话启动/历史重放也归讨论业务：隐藏、×收起、切换当前讨论与显示视图重建不使有效尝试失效，不取消队列、不释放请求锁或并发名额。显式停止、删除、离开项目、实际应用销毁与退出仍使对应尝试失效；迟到完成的会话立即结束、不注册、不再发送，不覆盖「已停止」终态。流式事件与发送回执继续按身份处理；恢复保留材料权限降级、三步业务结果检查、半成品会话清理、命令串行与唯一身份保护，禁止以重发问题伪造恢复。

依据为10-08设计记录§11.2的切换继续生成与取消浮动决定、主规格`discussion-windows/spec.md`的收起保生成合同，以及暂存README的v4修订说明中的×收起定义。排队继续与启动/重放不因显示失效在本change显式写入；命名依据为保存反馈第2条与其后v1修订说明（暂存`原型-v1/DESIGN-NOTES.md`），实施时统一。

重开优先有效运行态：本次运行期仍有效的讨论只选择其身份并显示真实生成、排队或授权状态，不用档案覆盖，也不改为中断。尚未加载且无有效运行态的历史讨论才按需读完整档案，将档案未完成轮标为中断；不自动重发或重复生成。隐藏/切换不是业务离开，只有停止对应轮次、删除、离开项目及退出等业务失效才丢弃旧结果。

## 7. 文档管理

文件夹与文档同父级混排，类型图标、层级缩进、选中行与展开入口清晰。顶部并列新建文档、新建文件夹、导入、导出；右键与行省略号打开同一动作菜单，支持键盘及边界内定位。

每篇文档有直接「允许 AI 查看/不允许 AI 查看」二元胶囊开关，文件夹无继承/等级/优先级。操作开关不得触发行双击进入写作；鼠标、Enter、Space 后焦点保持。状态以保存结果为准，失败回原状态；关闭可见性前的受影响讨论提示、旧讨论永久只读、出处脱敏、装载代次保护保留。

回收站为固定入口，进入独立二级页；不带含糊数字、不混入主树。恢复与结构校验沿用后端。导入继续 DOCX/Markdown/FDX 预检确认，只新增文档；导出继续 Word/PDF/Markdown 的真实范围与保存对话框，不拿 toast 代替文件产生。长名称、深层级、空树和大量节点通过换行/截断完整名、滚动与菜单定位保证可用，不新增排序或创建落点规则。

## 8. 制作页

左侧全局链路库，右侧默认导图/制作对话双标签。当前启用版本、正在查看版本、正在制作对象三态明确区分；浏览链路不切换制作对象，保存版本不等于启用，启用/停用从下一轮生效，在途轮沿用发起时版本。日常讨论与制作对话、试问的会话/材料保持隔离。

顶部短说明默认可见，「了解更多」展开详细解释。上图「提示词怎样组装」：分区标题「自定义要求与姿态」，副标「规定回应的方向与说话方式」（内含要求卡、姿态卡），与固定底座、每轮动态分别汇入组装，再到提示词；卡之间不连执行顺序线。标题与副标依据原型v5/v2.js及保存反馈，不沿用旧标题「自定义要求」。固定底座与动态只读，不伪装可修改。卡片选中时右侧就近详情，完整详情与修改/删除/添加继续转真实制作对话；大量卡与长正文可滚动，不为塞入图强行裁掉信息。

下图「Next Story 怎样回应你的问题」默认五步：写作页提问→准备获准材料→组装提示词→AI生成回应→讨论内显示。按需补读允许/拒绝分支、获准材料与边界折叠进「展开详情」。明确是只读工作说明，不代表本轮运行状态或 AI 内部思考过程。该边界来自既有正式规格，正式实现保留；原型v2.js已移除旧map-explainer，不能声称原型当前已有这一行说明。说明只承诺已有关注文档现场材料、允许目录、字面检索及授权补读，不承诺全文认知/附近上下文/记忆。

链路启停/删除/版本查看、卡详情、制作保存确认、制作试问与结果全部使用 `src/making`、链路库和后端真实协议。任何链路快捷入口只复用已支持的完整版本启用动作，并保留下一轮生效与在途不变提示；不新增自动姿态切换或日常聊天改配置。

## 9. 设置页

同一页按用途分组：AI连接与写作显示。API地址、密钥、手填模型名、保存、连接测试及结果直接可见；现有可选参数（含最大输出token数）继续可达，适合折叠在高级参数，不因原型未展示删除。模型名称遵循真实可调用规则，不新增伪模型列表。

密钥维持安全存储与已保存掩码，空输入复用旧密钥；不回读明文、不写入截图/日志。连接测试仅代表该次真实测试结果，不能用演示成功替代。宽度、背景、留白仅改变显示，保持现有持久化键和存储回退；离页/关窗仍保护未保存连接配置。

## 11. 尺寸、实现责任与迁移

三档验收1024×670、1280×720、1440×900。1024×670也是当前 Tauri 默认/最小外窗配置；真正 WebView 可用区受系统标题栏/DPI影响，须实测，不能把浏览器视口尺寸当成桌面客户区保证。最小尺寸默认正文与AI并排，窄档AI默认约330、常规默认约370；保留鼠标拖分隔条及聚焦后左右箭头调宽（原型每次20px），分隔条具separator语义、中文名称和垂直方向。原型最小300px、最大50vw，正式实现按真实可用区响应；正文不足则收缩，不整页 transform 缩放、不横向滚动。宽度仅运行期保留，不写讨论档案。依据10-08记录§11.2的宽度可调决定及v5/index.html、app.js的分隔条合同。矮窗允许区域纵向滚动和工具收纳；菜单、输入和停止始终可达。Windows 100%与常用高DPI缩放列入真机检查。
