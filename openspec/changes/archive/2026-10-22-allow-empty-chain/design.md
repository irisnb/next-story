# allow-empty-chain 设计

## Context

链路系统现状（`chain-library` / `making-module-page` / `chain-assembly` / `making-conversation`，均已归档）：

- 链路诞生只有「新建链路」按钮一个入口：`chain_create(name)` 建出**零版本**链路（`src-tauri/src/chain_library.rs:1135`；前端 `src/making/making-module.ts:719`）。规格从未定义这个零版本状态。
- 版本只能经 `chain_save_version` 追加（`chain_library.rs:1146`），`validate_cards`（`chain_library.rs:421`）拒绝空清单：「至少需要一张卡」。制作对话保存（`src/making/making-session-controller.ts:598`）与删卡保存（`making-module.ts:532`）共用该命令。
- 启用指针 `ActiveRef { chain_id, version_id }` 必须指向具体版本（`chain_library.rs:103`），零版本链路无法启用。
- 由此形成用户拍板要拆掉的死角：**空链路建得出来、用不了**——要让它可用必须先给至少一张卡。

数据模型天然容纳本变更：`Chain.versions` 与 `ChainVersion.cards` 均 `#[serde(default)]`，空数组在格式 v2 下合法读写，零迁移。

## Goals / Non-Goals

**Goals:**

- 链路诞生即含零卡第 1 版；零卡版本可保存、可启用、可回退、可试问。
- 删卡可删到最后一张（产生零卡新版本，不动启用指针）。
- 停用与启用空链路语义分工清晰、显示诚实：状态条明示「未附加自定义」；「本次参考了什么」零卡轮次不显示链路行。

**Non-Goals:**

- 不改存储格式版本（v2 不动）、不改版本不可变与回退、「保存不等于启用」、下一轮生效、全局启用指针一条。
- 不新增「零卡版本」以外的版本形态；不引入链路模板、复制、导入。
- 不改试问与对照机制（零卡版本试问天然等同裸问，走既有不带卡对照路径语义）。
- 不改日常陪想、AI 面板、写作页任何行为（零卡启用轮次对模型的实际效果与停用等同）。

## Decisions

### D1：链路诞生即含零卡第 1 版（唯一诞生形态）

`chain_create` 建链路时追加 `index=1、cards=[]、change_note="新建链路"、created_at=链路创建时刻` 的第 1 版。不变式：**每条链路至少一个版本，版本可零卡**；零版本状态从此不存在，启用指针永远有目标可选。

存量零版本链路（现行实现建的本地数据）：链路库读取时在内存补同规格第 1 版，随链路库下一次写入落盘；补版不改变任何既有版本编号（零版本链路本来没有版本）。

- 备选否决：启用时隐式建版——启用动作顺带产生新版本是隐式状态变更，违背显式原则；保留零版本+可启用——指针无目标可指，语义空洞，且把「空着不能用」换个形态留下。
- 制作对话不经诞生路径（它只对已绑定链路 `chain_save_version`），无需适配。

### D2：`validate_cards` 放宽空清单，其余不变

空清单合法；卡类型、标题、触发描述、三类长度上限（触发 ≤400、正文 ≤2000、版本合计 ≤6000）对在场卡照常执行，空清单合计自然为 0。删到最后一张走既有 `chain_save_version(剩余卡=[])` 路径产出零卡新版本，「删除不改启用指针、基线校验」等既有不变式原样保留；前端移除最后一张卡删除入口的禁用逻辑与「至少保留一张」文案，后端不再兜底拒绝。

### D3：零卡启用轮次复用停用的空挂载管道

启用零卡版本时，每轮冻结的 `posture` 与 `chain_cards` 为 null/空渲染，注入空段——与「未启用链路」共用 `chain-assembly` 既有空挂载行为，信封制度性内容完整。轮档案仍如实记录该轮链路版本（冻结来源同源不变式照旧），供显示层判定与历史诚实；显示层按「该版本卡清单为空」过滤（见 D4）。旧驱动兼容矩阵不受影响（两字段本就可 null）。

### D4：诚实显示口径

- 状态条：启用零卡版本时显示「当前链路：名称·第N版（未附加自定义）」；停用时维持「当前未启用链路，使用日常陪想」。两个状态一句话分清：停用＝链路系统不参与；启用空链路＝链路在岗、当前零自定义。
- 「本次参考了什么」：零卡轮次不显示链路行（链路未附加任何内容，显示反成误导）；有卡轮次照旧显示「本轮链路：名称·第N版」。
- 导图：零卡版本下「自定义提示词」分区无卡行，仅显示「添加回应要求」「添加回应风格」两个常驻入口；既有「不显示占位假卡」禁令天然覆盖空态。

### D5：制作守则补充零卡认知

制作守则增加：链路可零卡、卡草稿清单可为空；用户表达「把这条链路清空」类意图时，助手产出零卡新版本草稿（变更说明写明「清空」），仍经用户确认保存；「草稿代表新版本的完整卡清单」原则下，空清单即合法完整清单。

## Risks / Trade-offs

- [启用空链路与停用对模型效果等同，用户可能混淆] → 状态条措辞分工（D4）＋提案明示语义差异；不新增解释弹窗，轻量交代。
- [版本历史可能出现连续零卡版本（反复删光/重建）] → 无害：不可变历史本就如实记录每次保存，不做清理或折叠。
- [旧版应用读新数据中的零卡版本] → 格式 v2 空数组解析无恙，仅旧版保存时被其「至少一张」校验明确拒绝（失败关闭、不静默），符合既有降级防护口径。
- [读取时内存补版若与磁盘不一致] → 补版只在内存，链路库下次写入原子落盘；写入失败按「静默失败禁止」如实报错，运行态不受影响。

## Migration Plan

- 无存储格式变更、无数据迁移脚本：新链路诞生即 v1 零卡；存量零版本链路读取时规范化（D1）。
- 回滚：代码按 change 原子 revert。回滚后旧代码读到零卡版本时展示正常、保存被拒（失败关闭）；验证记录说明该路径。
