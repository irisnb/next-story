# repo-readme Specification

## Purpose

主仓库 README 的顶配结构、核心特性分组、事实与命名口径与图片资产规则。

## Requirements

### Requirement: README 顶配结构
README SHALL 采用双受众导向顶配结构，依次包含：居中标志与定位语、徽章排、简介（创作者一段说清，含官网链接）、核心特性、如实说明、下载入口（含 SmartScreen 提示）、给开发者、协作与协议；README MUST NOT 直出堆放界面截图——界面演示收于官网按需画廊，README 仅留官网链接（2026-10-24 用户拍板维持，2026-10-29 复确认；架构示意图非界面截图，不受此限）。

#### Scenario: 结构完整
- **WHEN** 打开仓库首页查看 README
- **THEN** 依次可见居中标志与定位语、徽章排、简介（含官网链接）、核心特性、如实说明、下载入口、给开发者分区与协作与协议，无界面截图直出

### Requirement: 事实口径
README 的能力与状态描述 MUST 以 `openspec/specs/` 已归档规格为准；已撤出当前项目范围的功能（思考收束、安全返回写作、AI 内容库、用户确认的作品信息、附近上下文、全文摘要、语义/向量检索、后台预加载、记忆、Agent 循环等）MUST NOT 列为「未来方向」或待办，如需提及 MUST 标注「已撤出、非待办」；平台口径 MUST 只写 Windows 发行，MUST NOT 出现 macOS/Linux 支持表述。

#### Scenario: 撤出功能不列为未来方向
- **WHEN** 核对 README 全部方向性表述
- **THEN** 已撤出功能不出现在「未来方向」「待办」「即将」等语境

#### Scenario: 平台口径
- **WHEN** 核对 README 平台相关表述
- **THEN** 仅表述 Windows 发行（CI 双平台检查事实句须附「只发行 Windows」澄清）

### Requirement: 命名口径
README MUST 使用统一命名：承载文件夹与文档的容器叫「项目」；会话记录叫「讨论」；新建入口叫「新建讨论」；MUST NOT 出现「新建对话」或以「作品」作容器名。

#### Scenario: 命名统一
- **WHEN** 全文检索 README
- **THEN** 无「新建对话」字样，容器统称「项目」

### Requirement: 核心特性分组呈现
README 的能力呈现 SHALL 为「核心特性」分节，按五分组组织：写作空间与项目、AI 陪想、讨论管理、制作模块、导入导出与基础；每组为面向用户的短句列表，主要用户可见能力 SHALL 保留足够细节让访客判断能力规模——包括编辑器格式与功能的完整列举、写作宽度三档数值、最近项目列表行为、AI 两种问法与生成控制（追问/取消/停止/排队/压缩）、三条稀有能力、会话列表分组与重命名置顶过滤、制作模块双标签与零卡链路、导入导出格式清单；能力表述 MUST 以 `openspec/specs/` 已归档规格为准（逐条可追溯）；MUST NOT 出现内部实现细节——包括后端工具名（如 `story-read`）、存储路径、规格/归档计数（如「76 项规格」）、内部阶段或项目术语（如「阶段五 A」「快车道」「已撤出」）。

#### Scenario: 分组完整
- **WHEN** 查看 README 核心特性区
- **THEN** 五个分组齐全，每组为面向用户的短句列表

#### Scenario: 细节充分
- **WHEN** 查看 README 核心特性区
- **THEN** 编辑器格式列举、宽度三档数值、讨论列表管理、制作模块双标签等具体能力均可见，不因精简而缺失主要已归档用户可见能力

#### Scenario: 无内部实现细节
- **WHEN** 全文检索 README
- **THEN** 不出现后端工具名、存储路径、规格/归档计数与内部阶段术语

#### Scenario: 表述可追溯
- **WHEN** 将核心特性任意一条与 `openspec/specs/` 对照
- **THEN** 均能找到对应已归档规格依据

### Requirement: 稀有能力前置
README 核心特性 SHALL 前置呈现三条同类产品少见的已实现能力：未保存快照可问（正在写、未保存的内容经校验后 AI 可见）、授权补读（AI 请求多读几篇，用户允许才读、随时可关）、参考出处可查（AI 本次参考了什么，轻量可看不打断对话）。

#### Scenario: 稀有能力可见
- **WHEN** 查看 README 核心特性的 AI 陪相关分组
- **THEN** 上述三条能力以用户语言呈现，未被埋没在长列表末尾

### Requirement: 如实说明用产品语言
README SHALL 设「如实说明」分节，仅以产品语言呈现访客可据以决策的边界：作品正文为手动保存（无自动保存、自动备份或版本快照；讨论档案由应用自动保存，与正文不同）、全应用仅一份 OpenAI 兼容 API 配置（无多服务方/多模型选择界面）、仅发行 Windows 版；MUST NOT 罗列内部治理概念或内部撤出清单（如「附近上下文」「思考收束」「安全返回写作」「已撤出非待办」等表述）。

#### Scenario: 边界如实且可懂
- **WHEN** 查看 README 如实说明区
- **THEN** 上述三条边界齐备且以产品语言表述，无内部治理词汇

### Requirement: 给开发者一等分区
README SHALL 设「给开发者」分区，依次包含：普遍问题一句话（AI＋本地文件应用如何让模型看见内容又不给它写权限）、Next Story 解法概览（保管者/使用者分离、受控只读接口、文档级可见性与授权补读、AI 无写能力）、架构示意图（ASCII 代码块，非界面截图）、深读链接（`docs/ARCHITECTURE.md` 与 `docs/DEVELOPMENT.md`）；分区收尾 SHALL 含开发者速览——依赖安装两条命令（`npm install`、`npm ci --prefix sidecar`）与常用命令速览小表；完整开发手册 MUST NOT 在 README 内联展开。

#### Scenario: 开发者分区完整
- **WHEN** 查看 README 给开发者分区
- **THEN** 可见问题引入、解法概览、架构示意图、两份文档深读链接与开发者速览

#### Scenario: 架构图不违反截图拍板
- **WHEN** 检查给开发者分区的架构示意图
- **THEN** 示意图为文字示意（ASCII/代码块），非应用界面截图

### Requirement: 图片资产自包含
README 引用的图片 MUST 放置于主仓库 `assets/` 目录并使用相对路径（主仓库自包含，克隆可见）；与官网仓库的图片为两份副本，图片更新时 MUST 两处同步。

#### Scenario: 资产自包含核对
- **WHEN** 检查 README 图片引用路径
- **THEN** 均指向主仓库 `assets/` 相对路径

#### Scenario: 双仓副本同步
- **WHEN** 官网图片更新
- **THEN** 主仓库 `assets/` 内对应副本同步更新
