## Why

现有回答可靠性测试器在处理“模型引用原文中的否定句”时可能误报。例如模型回答“林悦明确说‘我没有偷那本书’”，评分器只识别到引用状态，没有确认引用内容本身完成了预期否定，因而错误进入 `NEEDS_REVIEW`。现在需要修复这个已被真实运行证据确认的评分器误报，避免把明确正确的回答持续交给人工复核。

## What Changes

- 让评分器分析目标短语在引用中的否定关系，而不是把所有引用都视为未确定。
- 当引用内容明确否定目标事实，且回答中没有相反的直接断言时，允许满足 `mustNegate` 的事实边界。
- 当回答在引用否定之后又作出相反的直接断言时，继续保持失败或人工复核的保守结果。
- 增加覆盖直接否定、否定引用、引用后反向断言和多次出现的回归测试。
- 保留现有四态自动结果和独立人工复核结果，不引入 LLM 评分器。

### Modified Capabilities

## Impact

- 影响 `sidecar/reliability/screening.mjs` 及其单元测试。
- 可能更新回答可靠性测试器的使用说明和归档规格中的判分描述。
- 不修改生产 DSH driver、前端、Rust 后端、用户作品或 API 配置。
