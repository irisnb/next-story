# 设计：应用级真实链路验证收尾（审计队列 8b）

## Context

- 三笔欠账的现状：
  - **等待基线**：仪器已在（`src/ai-timing.ts`，四点计时＋devtools `globalThis.__waitTiming.exportJson()`），但从未采到数据——2026-09-11 验证时导出需应用内开发者工具，用户不便操作，应用关闭数据即失；且 `records` 以讨论 id 为键，同讨论新一轮提交**覆盖**上一条在途记录，多轮采集必丢数据。
  - **并发上限**：前端 `DEFAULT_MAX_CONCURRENT`（`ai-request-scheduler.ts:26`）与后端 `DEFAULT_MAX_CONCURRENT_GENERATIONS`（`dsh_driver.rs:714`）均暂定 2，规格明确「不表述为实测容量结论，真实接入验证取得基线后确定并记录」。
  - **应用级真实材料链路**：阶段 5A／6 的材料能力只有离线测试与 Rust 级真实链路 3 场景（2026-09-21 智谱 coding 端点 `glm-5.3` 通过）；8a／8a-2 对编排层动了刀（拆出网关／生命周期／材料模块），真实链路未回归。
- CI 基线：2026-09-21 已恢复绿灯（阶段 6 遗留的 fmt＋clippy 债已清）；发现并定位一处时序不稳定测试（见 D5）。
- 验证端点：智谱 coding 端点 `glm-5.3`（阶段 6 真实链路连续基线）；`glm-5.3-flash` 复跑（补充三）不占队、配额恢复随时补。

## Goals / Non-Goals

**Goals:**

1. 在真实应用＋真实作品＋真实模型下，验证材料链路（自动现场材料／目录投影／跨文档检索／按需补读授权流／出处落档）端到端成立，兼回归 8a／8a-2 的编排行为。
2. 采到等待分项数据并如实呈报用户（不承诺秒数、不定目标）。
3. 实测确定并发上限数值，落地到前后端常量与规格记录。
4. 让等待计时可被非技术用户一键导出、多轮不丢。
5. 消除 `mid_round_save_maps_to_story_version_changed` 的时间赌注。

**Non-Goals:**

- 不新增任何面向创作的产品能力；不做等待目标数值约定（数据呈报后另行与用户约定，方向版 7.7）；不把并发上限做成用户设置或环境变量；不重复执行 Rust 级真实链路 3 场景；不做「好问题验收」（事项 3，本 change 归档后解锁）；不做驱动被外部强杀场景的用户实测（用户 2026-09-11 已判定不现实，保留实现与单元测试作安全网）。

## Decisions

### D1 验证会话形态：代理驱动真实应用＋用户抽查（2026-09-21 用户确认修订）

> 原设计为「用户亲自操作，编排者记录（沿用 09-11 先例）」；应用户要求改为代理驱动。验证方法在 `validation.md` 如实记录，不冒充用户亲手操作。

- 构建用本地 release 测试版，以 WebView2 调试通道（`--remote-debugging-port`）启动；编排者经 CDP 协议在**真实应用**内读界面、点击、输入、截图留证——应用、配置、模型、数据全真，仅操作者由脚本代行。
- 原生对话框（建作品选位置、导出保存对话框）超出调试通道能力，由用户协助点击（预计 3–5 次）。
- 每场景有可观察判据（回答含指定关键词、出处面板出现指定文档、排队文案只在对应窗口出现等），不判「回答质量好坏」——质量评估属「好问题验收」。
- 关键场景（A1／A3／B1 等）由用户在场抽查确认；体感类观察不由脚本冒充。
- 驱动仪器为 change 内验证工具（`verification/driver.mjs`），随 change 归档，D 组重建后复用。
- 结果与全部实测数据记入本 change 的 `validation.md`（含验证方法说明）；审计文档第八节同步回记。

### D2 导出入口：开发者向、图标级、一键落盘

- **位置与视觉**：停靠区头部或会话列表面板的低视觉权重入口（apply 阶段出最小设计稿与用户确认，不进主用户流、不加常驻文案）。
- **行为**：点击→把全部已保留计时记录（含在途）导出为 JSON 文件保存到用户选择位置（默认文件名含日期时间）→成功轻提示；提供清空（导出后手动清，防内存历史无限增长的心理负担）。
- **备选与否**：自动落盘（每次请求后追加写系统文件夹）被否——常驻写文件与「AI 路径不写作品目录」的直觉边界易混淆，且采集节奏应由用户控制；沿用 devtools 被否——09-11 已实证走不通。
- **生命周期**：长期保留为开发者向仪器（规格「等待分段记录」的导出义务），不是临时脚手架。

### D3 计时历史保留：完成后归档＋有界 FIFO

- 结构改为：在途记录仍按讨论存 Map；轮次到达终态（完成／失败／取消）或被新一轮提交顶替时，整条移入历史列表；历史容量上限 500 条，超出丢最旧。
- `exportJson()` 输出＝历史全量＋当前在途，派生 summary 同步覆盖两者；devtools 的 `__waitTiming.exportJson()` 保持兼容。
- 「首次真实模型回应＝首个流式增量或完成事件」的既有定义不变（`ai-timing.ts` 头注释／design D7 约定）。

### D4 并发上限实测：分档探测、用户拍板、双层同值落地

- 方法：测试构建下按 2→3→4 档临时调常量（apply 时以临时改动出测试构建，不引入配置面）；每档同时发起 N 路常规首轮（不同讨论），观察：端点限流／报错（如实提示即为链路正确）、每路首字与完成分项（计时导出）、超上限请求排队与停止隔离。
- 每档至少 3 轮，异常即停（不烧钱硬测）；最终数值由用户确认后写入两端常量，实测依据记入 `validation.md` 与规格。

### D5 不稳定测试：文件标记握手，删掉全部时间赌注

- `multi_step_driver` 脚本新增两种步骤原语：`{mark: <path>}`（同步建标记文件后继续）与 `{waitFor: <path>, timeoutMs}`（25ms 轮询直到文件存在；超时 emit `message_failed`、code `wait_marker_timeout`——测试响亮失败可诊断）。
- 测试改造：步骤序列＝[首读（无版本）→ `{mark: A}` → `{waitFor: B, timeout}` → 固定版读取]；保存线程轮询等 A 出现→执行 `save_document`→创建 B。首读完成与保存完成两个事件从此**由握手保证顺序**，与机器速度无关。
- 标记文件用绝对路径放测试临时目录；原 700ms／1500ms 数字删除。

### D6 E2E 场景清单（执行脚本，apply 时按此逐条走）

- **A 材料链路**：A1 常规首轮自动现场材料（关注文档内容被引用＋出处可见）；A2 跨文档字面检索命中；A3 授权流·允许（授权请求→允许→工具循环→回答引用→读取出处落档「本次参考了什么」）；A4 授权流·拒绝（不补读、有限回答）；A5 授权关闭后行为；A6 及时召唤首轮不取材不补读；A7 非关注文档补读只读已保存正文；A8 隐藏文档不出现在目录与检索（知情边界抽查）。
- **B 编排回归（8a／8a-2）**：B1 双讨论并发各自流式不串台；B2 常规生成中召唤快车道；B3 超上限排队只在对应窗口、名额释放按序开始；B4 停止隔离；B5 应用重启后讨论恢复重放。
- **C 等待基线**：C1 单路常规首轮×3（分项）；C2 排队场景分项；C3 授权等待单独标注（用户驱动，不计入模型等待）。全部经 D2 入口导出留档。
- **D 并发档位**：按 D4。

### D7 前端讨论身份接线（2026-09-21 验证中发现缺陷的修复，用户确认扩入；模块化按用户指示）

**缺陷链（A3 实测发现，五环证据见验证记录）**：前端 `aiSendMessage` 参数面从未包含讨论身份 → 后端 `ai_send_message` 的 `(Some, Some)` 分支永不命中 → 每次发送 `clear_session` 清路由 → 模型工具调用失败关闭为 `on_demand_reading_unauthorized` → `story-request-reading` 永远到不了请求路径 → 授权弹窗永不出现。阶段 6 的 Rust 级真实链路测试直接向通道注册轮次，绕过了前端发送路径，故未暴露。

**修复设计（纯前端；后端参数早已就位）**：

1. **新模块 `src/ai-conversation-identity.ts`**（约 40 行，独立成文不堆热点）：
   - `ConversationIdentity` 类型：`{ conversationId, conversationProjectPath }`；
   - `resolveConversationIdentity(conversationId, projectPath)` 纯函数：任一为空白返回 null（镜像后端 `!trim().is_empty()` 守卫语义）；
   - 独立单元测试。
2. **`project-api.ts`**：`aiSendMessage` 的 identity 对象新增可选 `conversation?: ConversationIdentity` 字段，映射为扁平线上参数 `conversationId`／`conversationProjectPath`（Tauri 自动转 snake_case 对齐后端）。既有 8 个字段不动（签名兼容，零调用面破坏）。
3. **`ai-session-transport.ts`**（会话身份收敛层，文档自述「会话身份与传输状态收敛在本模块」）：依赖注入新增 `getCurrentProjectPath?: () => string | null`（照 `ai-feature-on-demand-reading.ts` 同款注入先例）；三处 `deps.sendMessage` 调用点（首轮／召唤／追问）统一经 `resolveConversationIdentity` 解析并携带讨论身份。**不在三个 sender 各自接线**（避免三处复制同一逻辑）。
4. **组合根 `ai-feature.ts`**：装配传输层时传入 `getCurrentProjectPath`（`AiFeatureContext` 既有访问器，一处一行）。
5. **测试**：传输层测试断言三类发送都带 `conversationId`／`conversationProjectPath`（含路径为 null 时不带的守卫路径）；新模块直测；既有网关／sender 测试不受影响（签名兼容）。

**备选与否**：在三个 sender（`ai-feature-direct-question` 等）各自拼装身份被否——三处复制、且身份解析守卫会漂移；经 `GenerateAiRequest` 中间表示携带被否——该结构是「请求内容」语义，讨论身份是「传输路由」语义，归传输层。

### D8 规格与文档落地

- `ai-request-scheduling` 两条 requirement 修改（见 specs delta）：上限数值条款落「实测确定＋前后端同值＋记录义务」；等待分段记录条款扩「多轮历史保留＋一键导出、不上报外部」。
- `AGENTS.md` 诚实边界、README 状态段、审计文档回记——「尚未完成的验证」收账，实测数据如实标注「样本、非承诺」。

## Risks / Trade-offs

- [真实模型行为不定（偶发限流／长尾延迟）] → 判据只认链路事实（限流如实提示＝链路正确）；单场景可重试；重试机制内不判失败。
- [并发高档位烧钱] → 每档封顶轮次、异常即停、由低到高。
- [导出入口增加 UI 面] → 开发者向最小形态，designer 出稿＋用户确认，不进主用户流。
- [历史保留引起内存增长] → 500 条 FIFO 上界＋导出后可清空。
- [握手原语增加假驱动脚本复杂度] → 两个原语各十余行、语义单一；超时路径响亮失败。
- [等待数据被误读为产品承诺] → 记录与文档统一标注「实测样本」；目标数值明确留待后续约定。

## Migration Plan

- 全部为增量改动（导出入口、计时历史、测试改造、常量定值）；无数据迁移。上限常量变更后全量回归（前端／Rust／离线／构建）。回滚＝revert 对应提交，验证数据已留档不受影响。
