## Why

现有常驻 DSH driver 回归测试能够确认会话协议、流式输出和生命周期正常，但不能可靠判断模型是否忠实理解剧本材料。近期长上下文测试还暴露出关键词判分会误读否定句、原文引用和不确定回答，因此需要一个可重复运行、保留证据并能保守初筛的离线核心测试器。

## What Changes

- 新增 Node/TypeScript 体系下的离线回答可靠性测试运行器。
- 新增结构化测试案例格式，支持材料版本、材料哈希、单轮/多轮问题、预期事实边界、允许的不确定表达、错误结论和原文依据位置。
- 复用现有 DSH driver 协议，使用真实 driver 执行固定案例，不把协议回归测试和回答可靠性测试混为一体。
- 保存每次运行的完整回答、必要的 DSH 事件摘要、运行配置摘要、耗时、退出状态和错误信息。
- 新增保守自动初筛，区分可能通过、可能失败、需要人工复核和运行失败。
- 首批覆盖版本冲突、否定与未知、事实/推测区分、多轮历史和上下文压缩后事实保持等核心场景。
- 不新增用户界面，不把测试器接入实时用户对话，不引入 Python、Phoenix 或其他重量级评测平台。
- 不修改用户作品、模型回答或现有常驻会话的产品行为。

## Capabilities

### New Capabilities

- `answer-reliability-testing`: 定义离线回答可靠性测试案例、真实 DSH 运行、证据保存和保守初筛行为。

### Modified Capabilities

无。现有常驻 AI 会话、DSH driver 和用户侧 AI 面板的规格不改变。

## Impact

- 影响 `sidecar/driver` 周边的测试工具和测试材料目录，复用既有 JSONL driver 协议。
- 可能新增 Node/TypeScript 测试脚本、案例文件、证据输出格式及对应测试。
- 不新增生产运行时依赖；是否采用 DeepEval 等外部评测库留待后续独立评估。
- 测试运行需要用户主动提供 API Key 和模型配置；API Key 不得进入案例、报告或证据文件。
