# Proposal: 多窗口与及时召唤快车道（阶段 3）

## Why

阶段 0 已确认：用户需要多个讨论窗口同时显示、移动、并排对照，且常规生成进行中及时召唤能独立发起（快车道）。阶段 2 已归档，讨论身份、按讨论隔离与保存重开已具备；但界面仍一次只显示一个讨论，不同讨论的流式增量无法归属到各自的显示目标，首轮请求仍被作品级预检串行化，用户没有停止生成的入口；阶段 1 留下的真实链路验证（真实事件字段、并发路由、等待基线、并发上限）也仍未完成。本变更把窗口层与请求调度层一起补齐，并在真实链路上验证，为阶段 4–6 的读稿能力提供稳定底座。

## What Changes

- **多讨论窗口呈现**：每个讨论在右侧停靠区拥有自己的窗口；新讨论打开自己的窗口，**不替换**已有讨论（**BREAKING**：替换当前「一次只显示一个讨论、其余只存档案」的显示模型）。窗口可拖出停靠区成为应用内浮动窗口，可移动、调整大小、与其他窗口并排对照；同一讨论至多一个窗口，重开时聚焦已有窗口；窗口标题显示当前关注文档。窗口是讨论的显示容器，讨论不依赖窗口存活。
- **窗口状态动作语义**（阶段 0 已确认行为的落地）：关闭窗口只结束显示、不删除讨论，生成中则自动停止本轮生成；停止生成只结束对应讨论的当前生成，已完成内容保留；重新打开不自动重发、不重复生成；删除讨论仍是独立动作；位置与大小仅本次运行保留，关闭或重启后恢复默认停靠布局。生成中的窗口切走再切回仍显示进行中状态（阶段 2 遗留的窗口级细节）。
- **快车道与请求调度**：不同讨论的请求独立发起、互不等待，不再有全局忙碌锁；常规生成进行中，及时召唤可在另一窗口独立开始；超出实际能力时按先到先服务排队，只在对应讨论窗口显示排队状态；同时生成上限不预设固定数字，按真实接入实测确定；服务商限流时如实提醒用户，不做自动重试风暴。
- **停止生成入口**：新增用户可见的停止动作，接线既有取消能力（`ai_cancel_message`）；取消、停止、关闭窗口只影响对应讨论。
- **真实链路验证与等待基线**：在真实 DSH 与真实模型配置下验证并发路由、停止隔离、迟到结果、关闭窗口停止生成与崩溃恢复；分开记录「提交→第一次实际模型回应」「提交→完整回答」「应用内排队 / 取材 / 额外模型往返分别造成的等待」；不承诺固定秒数，实测数据如实交付用户后再约定目标。
- **崩溃恢复扩展**：驱动进程意外退出后的重放恢复覆盖所有打开的讨论窗口，不只当前一个。
- **会话列表重做**：讨论列表改为按最后活动时间分组（置顶 / 今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 更早）的紧凑列表，条目间用轻分隔线区分；入口按钮常驻（不再按讨论数量忽隐忽现）；图标改为统一描边图标系统；支持重命名、置顶、删除确认与撤销、按标题与关注文档名过滤、空状态；明确不做「只显示最近 N 条 + 查看更多」的截断。为支撑重命名与置顶，讨论档案扩展可选的自定义标题与置顶标记字段（向后兼容）。批量管理可后置，先以逐条删除 + 撤销兜底。
- **窗口与会话列表视觉**：由 designer 自主出稿（用户不参与决策），设计稿已产出（`ui-design/README.md` 与三份自包含可视稿）；实现按稿落地。全应用视觉全量更新仍留在后续事项。
- **文档同步**：归档后更新 AGENTS.md 与 README 的实现摘要；同步方向文档中过期的阶段状态（阶段 2 已完成、阶段 3 状态）。
- **不在本范围**：会话内快捷跳转（后续）、真实工具读取与作品补读（阶段 4–6）、AI 可见性设置（阶段 4）、全应用视觉全量更新（后续事项）。AI 仍无任何写作品文档的通道。

## Capabilities

### New Capabilities

- `discussion-windows`: 多讨论窗口的呈现与动作——停靠与浮动、移动、缩放、并排对照、窗口与讨论绑定（一讨论至多一窗口）、关闭/停止/重开/删除语义区分、布局仅运行期保留。
- `ai-request-scheduling`: 请求并发与排队——独立发起、无全局忙碌锁、同时生成上限与先到先服务排队、排队状态按窗口呈现、限流如实提示、等待分段记录。
- `conversation-list`: 讨论列表的时间分组与排序、紧凑行呈现、重命名、置顶、删除确认与撤销、过滤与空状态。

### Modified Capabilities

- `ai-thinking-panel`: 从「单面板一次只显示一个讨论」改为「停靠区承载多个讨论窗口」；对话布局、滚动与请求状态按窗口呈现；面板开合与窗口关系明确。
- `ai-panel-state-structure`: 显示状态从单一当前讨论改为打开的窗口集合；流式增量按讨论身份路由；崩溃恢复覆盖所有打开窗口；订阅支持窗口重建。
- `ai-panel-dom-contract`: DOM 契约支持多个窗口实例的创建与销毁。
- `ai-panel-rendering-boundaries`: 显示决策按窗口/讨论参数化，仍保持单一状态事实源与纯派生。
- `persistent-ai-panel-entry`: 「不得创建第二个 AI 面板」调整为「多个窗口共享同一对话事实源」。
- `selection-ai-summon`: 召唤在常规生成进行中独立发起（快车道），并在自己的窗口打开。
- `ai-feature-orchestration`: 首轮预检从作品级改为按讨论/调度；编排接入调度、停止与窗口生命周期。
- `resident-ai-session`: 用户可见停止生成接线；崩溃恢复覆盖所有打开讨论；流式与终态按讨论身份归属到对应窗口。
- `clear-current-ai-conversation`: 「新建对话」在停靠区打开自己的窗口，不替换已有窗口。
- `conversation-persistence`: 档案扩展可选自定义标题与置顶标记字段，支持重命名与置顶持久化；删除支持提示期撤销。
- `project-mission-governance`: 归档后更新 AGENTS.md 当前实现摘要。
- `project-readme`: 归档后更新 README 已实现/未实现表述。

## Impact

- 前端核心改动：`index.html`（单面板静态 DOM 改为按窗口创建）、`src/dom.ts`、`src/ai-panel.ts`、`src/ai-panel-state.ts`、`src/ai-panel-reducer.ts`、`src/ai-panel-view-model.ts`、`src/ai-panel-scroll.ts`、`src/ai-feature*.ts`、`src/ai-request.ts`、`src/ai-session-transport.ts`、`src/selection-entry.ts`、`src/ai-panel-conversation-list.ts`、`src/conversation-archive.ts`。
- 新增模块：窗口管理（停靠/浮动/布局/生命周期）与请求调度（并发上限/排队/排队状态）。
- 关键修复：流式增量携带讨论身份并按讨论路由（现在统一写入「当前活动讨论」，并发会串台）；首轮预检从作品级单飞改为按讨论；全局代次不再因开新讨论而作废其他讨论的预检。
- 后端与驱动：Rust `dsh_driver` 与 sidecar 已支持多会话并发，本变更以真实链路验证为主，实测暴露缺口再补；取消能力 `ai_cancel_message` 接线到前端；`conversation_store` 扩展可选标题与置顶字段。
- 不新增 Tauri 系统级窗口：窗口为应用内 DOM 窗口。
- 测试：前端单测扩展（多窗口状态、调度、流式归属）；真实链路验证记录；既有前端、Rust 与离线验证回归保持通过。
- 设计稿：`openspec/changes/add-multi-window-and-fast-lane/ui-design/`（设计方案说明 + 三份自包含可视稿）。
- 文档：AGENTS.md、README、方向文档阶段状态。
- 边界不变：AI 仍无任何作品写入通道；窗口只是显示容器，不新增读取或写入作品的能力。

## 决策记录（propose 时定）

- **窗口形态**：应用内窗口（用户确认「是应用内」）；保留并排对照（用户确认），不做「一次只显示一个」的替代形态。默认停靠、需要时脱离。
- **快车道**：及时召唤独立发起、无全局忙碌锁、不设讨论间优先级（先到先服务）；超出能力时排队并只在对应窗口显示排队状态。
- **限流表现**：如实提醒用户，不建自动退避重试机制（用户确认「提醒用户，但一般不会发生」）。
- **并发上限**：不预设固定数字；真实接入实测后确定（方向版 7.6），实测值记录在实现与验证记录中。
- **等待**：不承诺固定秒数；三类等待分开记录，实测后与用户约定目标（方向版 7.7）。
- **停止 / 关闭 / 重开 / 删除**：沿用阶段 0 已确认的窗口状态动作语义（方向版 7.3）；关闭生成中的窗口自动停止该轮生成。
- **窗口与会话列表视觉**：designer 自主出稿（用户明确不参与决策），设计稿已产出（`ui-design/`）；实现按稿落地。全应用视觉全量更新留在后续。
- **会话列表重做**：并入本变更（用户要求顺带完成）；重命名与置顶通过档案扩展字段持久化（向后兼容，缺失按默认）；批量管理可后置，先以逐条删除 + 撤销兜底。
- **真实验证并入本阶段**：真实 DSH + 真实模型下取得并发与等待基线；验证结果如实记录，不伪造延迟结论；验证需要用户在场。
