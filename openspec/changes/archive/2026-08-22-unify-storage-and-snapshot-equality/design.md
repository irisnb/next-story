## Context

前端目前有两套等价的选区快照比较逻辑，以及两套相似但不一致的存储接口和 `localStorage` 探测逻辑。作品上次文档记忆可注入存储，编辑器留白偏好却在 `editor.ts` 内部直接读取浏览器存储，导致测试边界不对称。此次只做前端边界收敛，不能改变已有键名、默认值或用户可见行为。

## Goals / Non-Goals

**Goals:**

- 提供单一、纯函数的选区快照身份比较。
- 提供统一的 `StorageLike` 接口，支持 `getItem`、`setItem`、`removeItem`。
- 提供唯一的浏览器存储解析入口；浏览器环境缺失或访问被拒绝时返回 `null`，不抛出异常。
- 让留白偏好依赖可注入，并覆盖其真实读写路径。
- 保持作品记忆、留白偏好和 AI 面板现有行为不变。

**Non-Goals:**

- 不改变任何存储键名、数据格式、默认留白档位或作品记忆回退规则。
- 不修改 AI 面板 DOM 查询契约、编辑器模块结构、Rust/Tauri 代码或 AI 数据流。
- 不改变选区快照字段、选区归一化规则或 UI 文案。

## Decisions

### 1. 新建共享前端边界模块

新增一个小型共享模块，导出 `StorageLike`、`resolveLocalStorage()`、选区快照类型和 `sameSelectionSnapshot()`。选择独立模块而不是继续放入 `editor.ts`，因为这些能力横跨文档记忆、编辑器偏好、AI 面板和选区入口，且不属于编辑器控制器本身。

### 2. 存储解析统一返回适配接口或 null

`resolveLocalStorage()` 只检查 `globalThis.window`/`localStorage` 是否存在，并在读取属性或存储操作抛出安全异常的环境中返回 `null`。调用方继续负责“无存储时不持久化”的业务回退。相较于返回原始浏览器对象，这样可以让所有调用方依赖同一个最小接口，也能在测试中替换完整假实现。

### 3. 选区相等使用四个既有身份字段

共享比较函数继续比较 `documentId`、`from`、`to` 和 `selectedText` 四个字段。这样保持现有 AI 面板滚动与选区入口的身份语义，不把方向、UI 状态或其他临时字段误纳入快照身份。

### 4. 通过 EditorDependencies 注入留白存储

在编辑器依赖中增加可选的留白存储字段；未注入时由 `setupEditor` 调用共享解析入口。测试可直接注入 Map-like 存储，生产路径仍使用浏览器 `localStorage`。这是可测试性改进，不改变运行时默认路径。

## Risks / Trade-offs

- [接口迁移遗漏] → 全仓搜索旧接口和本地比较函数，并运行完整前端测试与类型检查。
- [浏览器存储异常被错误传播] → 解析入口捕获访问异常，调用方对 `null` 采用现有默认行为。
- [快照语义意外变化] → 共享函数测试四字段相同/不同边界，并保留现有 AI 面板滚动和选区入口回归测试。
- [测试夹具过度共享造成耦合] → 只共享最小内存存储工厂，不共享测试专属断言或业务数据。

## Migration Plan

1. 先补共享存储、解析和快照比较的失败测试。
2. 新增共享模块并迁移生产调用方。
3. 为留白偏好增加依赖注入并迁移其测试夹具。
4. 运行定向测试、类型检查、lint、构建和完整前端测试。
5. 若出现回归，回滚调用方迁移，保留原有键名和旧行为。

## Open Questions

无。接口、字段和 fallback 行为均沿用当前实现语义。
