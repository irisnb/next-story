# rust-dependency-security-hygiene 规格（增量）

## MODIFIED Requirements

### Requirement: Rust 依赖安全警报的修复路径
Rust 生产依赖树出现在册安全警报时，SHALL 按以下顺序选择修复路径：官方修复版落在受影响包既有语义范围内时，定向最小更新 `Cargo.lock`；受上游包版本要求锁死而无法统一时，钉上游已包含所需修复的 git 提交，并把自身直接依赖的版本下限提到修复版所在区间，使 `Cargo.lock` 全树对受影响包只解析出**单一版本且不低于官方修复门槛**；上述两条路径穷尽（既无范围内修复版，又无含修复的上游兼容主线提交，可用上游线仅预发布）时，SHALL 有据挂账：在长期账本登记包名、警报、路径穷尽证据链、实际暴露面评估与复评触发条件。MUST NOT 以保留双版本、降级处理或忽视告警的方式绕开统一；挂账是路径穷尽时唯一允许的暂存处置，MUST NOT 以 `[patch]` 跨版本强改、采用预发布版本或静默容忍替代。

#### Scenario: 范围内定向更新
- **WHEN** Rust 树出现在册安全警报且修复版满足既有语义范围
- **THEN** 仅 `Cargo.lock` 中该包条目被更新到修复版，`Cargo.toml` 保持不变

#### Scenario: 上游锁死时钉 git 并提下限统一全树
- **WHEN** 传递依赖的上游包版本要求锁死受影响包（如 docx-rs 要求 `zip ^8.6.0` 而修复版在 9.x）且上游主线已含修复
- **THEN** 上游包改为钉定 git 提交（记录提交号与理由），自身直接依赖下限提升到覆盖最高修复门槛的版本，`cargo tree` 确认全树仅存在一个满足修复门槛的版本

#### Scenario: 路径穷尽时有据挂账
- **WHEN** 受影响包的修复门槛超出全部消费链的版本范围，上游无含修复的兼容主线提交、仅存在预发布线（如 tauri-plugin-updater 2.11.x 硬性要求 `zip ^4` 而 zip 修复门槛 ≥9.0.5，上游稳定线之上仅 3.0.0-alpha）
- **THEN** 长期账本登记该警报的路径穷尽证据、实际暴露面评估（如「更新包先 minisign 验签后解压、输入仅自家固定端点」）与复评触发条件（如「插件稳定版要求 zip ≥9，或随 tauri 2.12 升级并重测」）；不 `[patch]` 强改、不采用预发布、不静默容忍
