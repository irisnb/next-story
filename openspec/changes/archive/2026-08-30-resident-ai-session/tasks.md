- [x] 1.1 编写并运行 DSH JS API 探底脚本（`sidecar/` 下独立脚本，不进产品代码，允许调用真实模型，证据存档 `docs/`），按 design.md D1 验收矩阵逐项验证：① 容器可编程启动；② 会话建立 + 多轮增量收发；③ 流式事件；④ compaction 在无 JSONL 持久化的常驻容器内触发且无磁盘残留（含压缩产物不含用户内容/Key）；⑤ 无生成的带角色历史注入可行性；⑥ `cancel` 干净终止（被取消轮次不残留会话）；⑦ 容器不装载工具类插件 + 负向能力验证（写文件/执行命令/访问作品文件/未知工具全部失败）；⑧ 优雅退出、无孤儿进程、无残留锁文件；结论回填 design.md

## 2. Sidecar 常驻驱动脚本（Node）

- [x] 2.1 新建常驻驱动脚本：boot DSH 容器，只装配文本生成所必需的插件（**默认拒绝**：不装载任何工具类/文件系统类/命令执行类/网络类/子代理类插件，禁用工具清单整体不可达）
- [x] 2.2 实现 stdin/stdout 行分隔 JSON 协议：`start_session` / `send_message` / `replay_history` / `replay_done` / `cancel_message` / `end_session` / `shutdown` 入站，`ready` / `session_started` / `delta` / `message_done` / `message_failed` / `replay_ok` / `session_ended` / `error` 出站；含协议版本、单帧上限、未知消息丢弃、持续异常上报
- [x] 2.3 实现流式转发：DSH 生成输出转带 `seq` 的 `delta` 事件，完成时按探底结论发携带全文的 `message_done`（或声明 delta 累积为最终内容）；失败以 `message_failed` 显式终态结束
- [x] 2.4 实现 API Key 注入（内存/环境变量，不落盘不进日志）与 stderr 诊断日志分离
- [x] 2.5 探底脚本扩展为升级回归脚本：覆盖 2.1–2.4 全部协议面，供将来 DSH 升级时秒级回归

## 4. 前端：增量发送、流式渲染、会话生命周期

- [x] 4.1 改造 `ai-panel-conversation.ts` / `ai-panel-reducer.ts`：移除每轮全量历史重发，改为增量发送 + 记录会话身份；保留显示历史与轮次状态机
- [x] 4.2 实现流式渲染：delta 逐字追加、完成事件为最终事实（按探底结论：done 全文或有序 delta 累积，单一来源）、`message_failed` 显式失败终态（部分文本只作显示草稿）、消息事件幂等、生成期间禁止再次发送（沿用单请求锁）
- [x] 4.3 接入会话生命周期事件：新建对话 / 切换作品 / 卸载作品时通知后端结束会话；收起面板保留对话（沿用现有语义）

- [x] 4.5 超限兜底 UI：`request_too_large` 映射为中文提示新建对话；确认无任何静默截断路径
