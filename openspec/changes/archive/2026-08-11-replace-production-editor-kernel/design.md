## Context

当前草稿本和正文本各由一个原生 `textarea` 承载。`src/editor.ts` 直接读取两个控件的完整字符串，将它们交给 `EditorSaveState` 比较当前内容与最近成功保存基线，并通过既有 IPC 一次保存 `draft` / `main` 两个字符串。选区 AI 通过 `selectionStart`、`selectionEnd`、`selectionDirection` 和 textarea 镜像坐标算法捕获原文、判断焦点端并定位浮动入口。

隔离原型已经在 Windows Tauri 2 / WebView2、微软拼音和 20 万字文本下验证 Tiptap/ProseMirror 与现有“纯文本投影 + 冻结选区快照 + AI 不写回”边界兼容。本 change 把已验证方向接入生产链路，但不改变磁盘格式、IPC、双本子模型或 AI 任务范围。

主要约束如下：

- 草稿本和正文本仍是用户亲手产生内容的唯一两个文本本子，代码标识仍仅为 `draft` / `main`。
- 磁盘事实源仍为两个 `.txt` 文件；前端保存状态仍以两个完整字符串为基线。
- Tiptap 内部文档结构不是新的作品事实源，也不得持久化到项目目录。
- AI 只能读取点击入口时冻结的选区快照，不能直接修改任一本子。
- 本轮必须能够单独回滚到 textarea 实现，不要求项目数据迁移。

## Goals / Non-Goals

**Goals:**

- 用 Tiptap/ProseMirror 稳定承载两个生产写作区，并保持现有纯文本行为和项目兼容性。
- 建立唯一的纯文本编辑器适配边界，集中处理导入、导出、变更通知、焦点、选区和坐标。
- 保持 `EditorSaveState`、离开协调、项目 IPC 和 Rust 文件事务的既有职责及字符串语义。
- 让选区 AI 不再依赖 textarea 专属接口，同时保持冻结原文、UTF-16 起止位置、本子标识和后续请求隔离。
- 用自动化检查与 Windows 桌面真机检查覆盖中文输入法、撤销重做、长文本和坐标行为。

**Non-Goals:**

- 不开放任何富文本格式、格式命令或工具栏。
- 不把 ProseMirror JSON、HTML 或节点结构保存为作品数据。
- 不升级项目格式版本，不迁移或复制旧项目文件。
- 不改变自动保存策略；本轮仍只使用既有手动保存与离开保护。
- 不增加 AI 上下文、AI 会话持久化、AI 写回或“应用到正文”入口。
- 不顺带重构 Rust 项目存储、LLM 配置或 AI 提示词。

## Decisions

### 1. 采用已验证的 Tiptap 2 / ProseMirror 依赖组合

生产依赖使用隔离原型已验证的 Tiptap 2.27.x 系列及其 ProseMirror 依赖，并由项目锁文件固定实际版本。只启用本轮需要的文档、段落、文本和历史能力，不启用标题、标记、列表、链接或其它格式扩展。

选择 Tiptap 而不是直接操作 ProseMirror，是因为 Tiptap 提供较窄的编辑器生命周期和命令接口，同时保留 ProseMirror 的事务、选区与 `coordsAtPos` 能力。选择 Tiptap 而不是 Lexical，是因为两者原型关键项均通过，而 Tiptap 在 20 万字真机测试中输入延迟略低，ProseMirror 的选区映射原语也更适合后续独立 change。

### 2. 建立单一纯文本投影适配器

新增与 UI 控制器分离的编辑器适配器，向上只暴露本轮需要的窄接口：创建与销毁、读取完整纯文本、以完整纯文本初始化、订阅用户编辑、聚焦、读取选区快照所需数据、读取焦点端坐标。

纯文本导入按照换行分割为段落，空行以空段落表示；导出按照相同规则恢复纯文本。适配器必须用测试固定空字符串、开头/结尾空行、连续空行、中文、emoji 和跨段选区的行为。应用其它模块不得直接把 ProseMirror JSON 或 HTML 当作本子内容，也不得各自实现第二套序列化规则。

内部文档只是一种运行期编辑表示。打开项目时以后端返回的字符串初始化；保存、脏状态比较和离开保护始终使用适配器导出的完整字符串。

备选方案是继续直接读写编辑器 DOM 或使用 HTML 作为中间格式。该方案会让浏览器自动规范化标签和空白，难以证明与 `.txt` 的字符等价，因此不采用。

### 3. 每个本子保留独立编辑器实例和历史

草稿本与正文本各持有一个 Tiptap 实例。标签切换只改变当前可见和可交互的实例，不通过销毁后重建来切换，也不把一个实例的文档反复替换成另一本文字。这样可自然保留两个本子的未保存内容、光标、选区和各自撤销历史，并避免标签切换被记录成用户编辑。

作品卸载、成功打开另一作品或控制器销毁时，两个实例都必须解除事件监听并销毁。打开新作品时创建新的双实例和新的保存基线，旧实例不得继续触发保存状态或 AI 入口更新。

备选方案是只维护一个 Tiptap 实例并在切换时替换整份文档。该方案会混合撤销历史、选区和事务来源，增加跨本子覆盖风险，因此不采用。

### 4. 编辑事务只通过纯文本结果更新保存状态

适配器只在用户可见纯文本发生变化时通知 `src/editor.ts`。控制器每次收到通知后读取两个本子的当前纯文本，并继续调用现有 `EditorSaveState.setCurrent(draft, main)`。手动保存仍冻结两个字符串快照并复用现有单并发保存规则；保存期间的新事务只改变当前值，不改变已冻结快照或成功基线。

初始化、项目打开和受控的内部状态同步不得伪装成用户编辑，也不得制造未保存状态。保存成功只推进到本次快照；若保存期间继续输入，完成后仍显示“有未保存修改”。

备选方案是让保存状态直接比较 ProseMirror 文档对象或 JSON。该方案会把未持久化的内部结构变成事实源，并为第二轮提前建立隐性格式契约，因此不采用。

### 5. 选区快照继续使用纯文本 UTF-16 偏移

选区适配器从当前 Tiptap 实例读取 ProseMirror 选区的有序范围和头部位置（浏览器焦点端），再通过唯一纯文本投影把范围转换为 `SelectionSnapshot`：`notebook`、原样 `selectedText`、`start`、`end`。`start` / `end` 继续使用 JavaScript 字符串的 UTF-16 偏移，并保持 `start <= end`；选区方向只影响入口锚点，不改变冻结范围。

点击`及时召唤`或`思维扩展`后立即复制并冻结快照。首次请求、预备态、重试和追问继续只持有该快照，不保存对编辑器实例、ProseMirror selection 或实时文档的引用。

适配器必须用中文、emoji、换行、跨段和正反向选区测试证明 `selectedText === 当前纯文本.slice(start, end)`。如映射无法满足该恒等式，本轮不得进入实现完成状态。

### 6. 使用 ProseMirror 几何能力替代 textarea 镜像

AI 入口以 ProseMirror 选区头部作为焦点端，并使用编辑器视图提供的坐标能力取得该位置的几何信息。现有入口布局函数继续负责窗口/编辑器边界、避免遮挡、菜单空间和替代位置决策；textarea 镜像复制全文或样式的算法退出生产路径。

选区或滚动事件仍按渲染帧合并。一次更新只读取一次焦点端几何，并复用结果完成可见性和位置判断。菜单打开后继续冻结触发器位置；本子、页面或作品上下文失效时立即隐藏。

### 7. 粘贴只接收纯文本

普通粘贴和“粘贴为纯文本”都只把剪贴板中的纯文字写入文档。本轮不保留 HTML、字体、颜色、标题、列表或其它外部格式。复制与剪切对外提供用户实际选中的可见纯文本。

这样可确保用户从网页或文字处理软件粘贴时不会把未公开格式带入内部文档。富文本白名单和结构化粘贴留到第二轮 change 决定。

### 8. 自动化测试与桌面真机验收分层

纯文本投影、保存状态、选区映射、入口决策和生命周期使用前端自动化测试；现有 Rust 项目读写测试用于证明后端契约没有变化。真实 IME 组合输入、WebView2 快捷键、长文档输入与选区、窗口滚动坐标必须在 Windows Tauri 桌面应用中人工复核，因为浏览器模拟不能证明微软拼音组合行为。

20 万汉字沿用原型门槛：连续输入延迟 p95 不高于 50ms，载入后的进程增量内存不高于 300MB，并且全程无文本损坏或选区漂移。实际验收记录进入本 change 的实现证据，而不是写入正式作品数据。

## Risks / Trade-offs

- [纯文本与块文档的空行语义不完全一致] → 由唯一投影适配器和边界样例测试固定映射；任何无法无损表示的情况在实现阶段阻止归档，不以 HTML 兜底。
- [ProseMirror 位置与 UTF-16 纯文本偏移存在边界差异] → 集中实现位置转换，并用 emoji、换行、空段落、跨段和反向选区验证切片恒等式。
- [输入事务过于频繁导致全量字符串比较成本上升] → 保持单次事务单次投影与单次保存状态更新，禁止入口定位复制全文；以 20 万字真机门槛决定是否需要本 change 内的针对性优化。
- [两个编辑器实例增加内存] → 用原型已验证的 300MB 增量预算验收；换取本子状态和撤销历史隔离。
- [Tiptap 默认扩展意外开放格式] → 采用最小扩展集合，并测试外部 HTML 粘贴后只保留纯文本。
- [IME 行为无法由常规单元测试证明] → 将微软拼音真机实敲列为归档前强制门槛，记录输入、选字、删除、撤销重做和切换焦点结果。
- [迁移影响现有 AI 入口生命周期] → 保留 UI 布局决策层，只替换选区与几何数据源；继续测试请求后编辑、切换本子和迟到结果隔离。
- [依赖升级偏离已验证版本] → 首轮使用原型验证过的 Tiptap 2.27.x 系列并提交锁文件；升级另行验证。

## Migration Plan

1. 加入并锁定最小 Tiptap/ProseMirror 依赖，先建立纯文本投影和编辑器适配器测试。
2. 将双本子控制器接到两个独立 Tiptap 实例，保持 IPC、Rust 文件和 `EditorSaveState` 接口不变。
3. 将选区快照与 AI 入口几何切换到新适配器，移除生产路径中的 textarea 镜像依赖。
4. 更新现有前端测试夹具与样式，运行类型检查、前端测试、构建和 Rust 测试。
5. 在 Windows Tauri / WebView2 中完成微软拼音、剪贴板、撤销重做、双本子、保存离开、AI 入口和 20 万字验收。

本轮无项目数据迁移。若实现或真机验收失败，可回退前端编辑器依赖与适配代码，恢复原 textarea 生产实现；由于 `.txt`、IPC 和项目版本从未改变，用户作品无需执行数据回滚。

## Open Questions

无阻塞问题。撤销分组的细微手感以 Tiptap 已验证默认行为作为第一轮基线；只有出现文字错误、异常撤销步骤或明显妨碍写作的结果时，才在本 change 内调整，不把偏好性微调扩大为新功能。
